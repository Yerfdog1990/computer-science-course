# Database Encryption - Overview

## Introduction
Database encryption is a key way to protect data within your database. However, no single encryption solution is correct for every database. The encryption requirements of your application will dictate which encryption solution you select.

## Key Considerations
- **Performance Impact**: The more data you encrypt and the stronger the encryption, the more CPU power will be required to encrypt and decrypt data
- **Balance**: It's crucial to balance encryption requirements with increased system load
- **Requirements-based Selection**: Choose encryption solutions based on specific application needs

## Hashing versus Encryption

### Encryption
- Uses various algorithms that provide values that can be decrypted with the correct decryption key
- Each encryption option provides different strength levels
- Stronger encryption levels result in increased CPU load on Microsoft SQL Server

### Supported Encryption Algorithms (Microsoft SQL Server)
From weakest to strongest:
1. **DES** (Data Encryption Standard)
2. **TRIPLE_DES**
3. **TRIPLE_DES_3KEY**
4. **RC2**
5. **RC4**
6. **RC4_128**
7. **DESX**
8. **AES_128** (Advanced Encryption Standard)
9. **AES_192**
10. **AES_256**

**Note**: The algorithm list has remained unchanged since Microsoft SQL Server 2005 through SQL Server 2014.

## Algorithm Details

### DES Algorithm Warning
- The DES algorithm was incorrectly named when implemented in Microsoft SQL Server 2005
- Data encrypted with the DESX algorithm actually uses TRIPLE DES algorithm with a 192-bit key
- The DES algorithm will eventually be removed from Microsoft SQL Server
- Future development should avoid using the DES algorithm

### Triple DES (3DES)
- Common names: Triple DES or 3DES
- Uses DES algorithm three times for each block of data
- Uses three encryption operations to encrypt/decrypt data three times for each 64-bit block

#### Keying Options
1. **Strongest Option**: Each of the three keys has different 56-bit values (total 168 bits)
   - Represented as: TRIPLE_DES_3KEY or DESX algorithm
2. **Medium Option**: Keys k1 and k3 use same values, k2 uses different values (112 key bits)
   - Represented as: TRIPLE_DES algorithm
3. **Weaker Option**: All keys use same values (backward compatible with DES)

### RC Algorithms
Microsoft SQL Server supports two of the four common RC algorithms:

#### RC2
- Uses 40-bit key size
- Considered a weakened algorithm

#### RC4
- Supports key sizes from 40 bits to 2048 bits
- Microsoft SQL Server offers 40-bit and 128-bit configurations
- **Warning**: RC4 algorithm has known weaknesses
- Microsoft has deprecated RC4 algorithms for future SQL Server releases
- New database applications should avoid using RC4

### AES (Advanced Encryption Standard)
- Considered the strongest and most secure option
- Available in three key sizes:
  - AES_128 (128-bit key)
  - AES_192 (192-bit key)
  - AES_256 (256-bit key)
- Recommended for new applications requiring strong encryption

## Performance Considerations
- **CPU Load**: Stronger encryption requires more processing power
- **Data Volume**: More encrypted data means more encryption/decryption operations
- **Application Impact**: Consider the overall impact on database performance and application responsiveness

## Best Practices
1. **Assess Requirements**: Determine specific encryption needs for your application
2. **Choose Appropriate Strength**: Balance security requirements with performance considerations
3. **Plan for Future**: Consider deprecated algorithms and plan migration strategies
4. **Test Performance**: Evaluate encryption impact on database performance before implementation
5. **Document Choices**: Maintain records of encryption algorithms and key management strategies

## Summary
Database encryption provides essential data protection but requires careful planning and consideration of performance implications. The choice of encryption algorithm should be based on specific security requirements, performance constraints, and future compatibility considerations.
