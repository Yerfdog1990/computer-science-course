# Encrypting Data with MPIO Drivers

## Introduction
Multipath Input Output (MPIO) drivers are used when SQL Server is connected to a Storage Array via either fiber channel or iSCSI (Internet Small Computer System Interface). These drivers provide redundant connections between servers and storage arrays for high availability.

## MPIO Architecture Overview

### Storage Network Configuration
**Typical Setup**:
- **Multiple Paths**: Server connected to storage array via multiple cables
- **Redundant Connections**: Multiple HBAs and storage controllers
- **Fault Tolerance**: Protection against HBA, cable, or controller failures
- **Common Design**: Two switches connecting each HBA to each storage controller

### Connection Diagram
A redundant storage network typically includes:
- **Server**: Multiple Host Bus Adapters (HBAs)
- **Switches**: Two switches for redundancy
- **Storage Array**: Multiple controllers
- **Multiple Paths**: Each HBA connected to each storage controller

## MPIO Driver Encryption Capabilities

### PowerPath Encryption
**EMC PowerPath**: Only MPIO driver with encryption capabilities (as of 2011)
- **RSA Integration**: Leverages EMC's acquisition of RSA
- **Traffic Encryption**: Encrypts all traffic between server and storage array
- **Block-Level Encryption**: Encrypts data portion of write requests
- **Address Preservation**: Block addresses remain unencrypted

### Supported Storage Arrays
PowerPath supports various storage vendors:
- **EMC Storage Arrays**: Native support
- **IBM ESS**: Supported
- **Hitachi**: Supported
- **HP StorageWorks**: Supported
- **HPXP**: Supported
- **Other Arrays**: Version-dependent support

### Installation Requirements
**PowerPath Version**: 5.2 or later required for encryption features

## Advantages and Disadvantages

### Advantages
- **Transparent Encryption**: No code changes required
- **Comprehensive Protection**: All data written encrypted automatically
- **Application Independence**: Works with stored procedures and application layer unchanged
- **Storage-Level Security**: Data encrypted before reaching storage devices

### Disadvantages
- **CPU Overhead**: Encryption work performed by SQL Server CPU
- **Performance Impact**: Increased CPU load with higher IO and SQL Server load
- **Certificate Management**: Additional complexity for key management
- **Enterprise Key Management**: Requires RSA Key Manager (RKM) infrastructure

## PowerPath RSA Encryption Setup

### Prerequisites
**Required Components**:
1. **RKM Server Software**: RSA Key Manager server installation
2. **Certificates**: PKI certificates for authentication
3. **Secure Network Zone**: Isolated network segment
4. **PowerPath Version**: 5.2 or later with RSA encryption module

### Certificate Requirements
**Specific Certificate Specifications**:

#### Server Certificates
- **Format**: Password-protected PKCS#12 file
- **Contents**: Public key certificate and private key
- **Purpose**: Secure SSL communications between PowerPath host and RKM

#### Authentication Certificates
- **Format**: PEM (Privacy Enhanced Mail) encoded
- **Purpose**: Host authentication against RKM server
- **Trust**: Root certificate for trusted connections

### Network Security Configuration

#### Secure Zone Setup
**Physical and Logical Isolation**:
- **Hardware Firewalls**: Isolate secure zone from rest of network
- **Access Restrictions**: Limited access to authorized systems only
- **User Authentication**: Combined authentication and firewall protection
- **Ultra-Secure Environment**: Most secured, isolated portion of company network

#### Network Access
**RKM Server Access**:
- **Default Port**: HTTPS on TCP port 443
- **Configurable**: Port can be changed during setup
- **Web Interface**: Protected by standard SSL encryption
- **Firewall Rules**: Block unauthorized requests to secure zone

### Installation Process

#### PowerPath RSA Module Installation
**Upgrade Existing Installation**:
1. **Launch Installer**: Run PowerPath installer on server
2. **Modify Option**: Select "modify" from installation options
3. **Enable Feature**: Check "Encryption with RSA" option
4. **Complete Installation**: Follow wizard to completion
5. **Reboot Server**: Required after installation

#### New Installation
**Additional Steps**:
1. **PowerPath Key**: Provide license key during installation
2. **Installation Folder**: Specify target directory
3. **RSA Module**: Enable encryption feature during setup

## RSA Key Manager (RKM) Configuration

### Key Class Management

#### Crypto Policy Creation
**Purpose**: Predefined encryption specifications for key classes

**Configuration Steps**:
1. **Access RKM Admin**: Log into RKM administration website
2. **Crypto Policy Tab**: Navigate to Crypto Policy section
3. **Create Policy**: Click "Create" button
4. **Specify Parameters**: Set algorithm, key size, cipher mode, duration
5. **Save Policy**: Store policy for use with key classes

#### Key Class Creation
**Five-Page Wizard Process**:

**Page 1: Basic Information**
- **Class Name**: Assign descriptive name
- **Identity Group**: Specify authorized users
- **Key Duration**: Set expiration settings
- **Crypto Policy Option**: Optional duration control via crypto policy

**Page 2: Encryption Settings**
- **Algorithm**: Specify encryption algorithm
- **Key Size**: Set key length
- **Cipher Mode**: Configure encryption mode
- **Duration**: Set key lifetime
- **Key Reuse**: Configure new key creation vs. reuse

**Page 3: Attributes** (Optional)
- **Custom Attributes**: Assign additional properties
- **Metadata**: Add descriptive information

**Page 4: Attribute Specifications** (Optional)
- **Attribute Values**: Define specific attribute settings
- **Validation Rules**: Set attribute constraints

**Page 5: Review**
- **Settings Summary**: Review all configuration
- **Confirmation**: Finalize key class creation

### Client Configuration

#### Client Registration
**Create Client Entry**:
1. **Clients Tab**: Navigate to Clients section in RKM
2. **Create Button**: Add new client configuration
3. **Server Information**: Enter IP Address, Hostname, Application Name
4. **User Identity**: Select authentication identity

#### Version Compatibility

- **Driver Version**: Client version must match MPIO driver

## Volume Encryption Management

### PowerPath Command Line Utility
**Enable Encryption**:
```bash
powervt xcrypt –on –dev harddisk2
```

#### Command Components
- **powervt**: PowerPath command line utility
- **xcrypt**: Command for encryption management
- **–on**: Switch to enable encryption
- **–dev**: Parameter to specify device
- **device_name**: Target device for encryption

### Volume Status Checking
**Query Encryption Status**:
```bash
powervt xcrypt –info –dev harddisk2
```

#### Return Values
- **"encrypted"**: Volume is encrypted by PowerPath
- **"encrypted with HBA assist"**: Volume encrypted with HBA offloading
- **"not encrypted"**: Volume is not encrypted

### Advanced Configuration

#### Multiple Key Classes
**Complex Environment Requirements**:
- **Different Encryption Levels**: Various LUNs may need different encryption strengths
- **Key Class Assignment**: Associate specific LUNs with specific key classes
- **Configuration Process**: Multi-step setup for different encryption levels

#### Manual Configuration Process
**rkm_keyclass.conf File**:
1. **Locate File**: Default location "C:\Program Files\EMC\RSA\Rkm_Client\config"
2. **Edit Configuration**: Modify PowerPathDefaultKeyClass parameter
3. **Repeat Process**: Update for each different key class needed
4. **Documentation**: Maintain records of LUN-to-KeyClass mappings

#### Limitations
**Query Challenges**:
- **No Direct Query**: No way to query which Key Class is used for each LUN
- **Metadata Storage**: PowerPath stores Key Class information in LUN metadata
- **Documentation Critical**: Manual tracking required for complex configurations

## Performance Considerations

### CPU Impact
**Encryption Overhead**:
- **SQL Server CPU**: Encryption work performed by database server CPU
- **Load Scaling**: CPU requirements increase with IO volume
- **Performance Monitoring**: Track CPU utilization after encryption enablement

### Storage Performance
**I/O Impact**:
- **Encryption Latency**: Additional processing time for each I/O operation
- **Throughput Changes**: Potential reduction in storage throughput
- **Benchmark Testing**: Evaluate performance impact before production deployment

## Best Practices

### Planning and Design
1. **Assess Requirements**: Determine encryption needs and performance constraints
2. **Architecture Review**: Evaluate storage network design for encryption support
3. **Capacity Planning**: Account for CPU overhead in server sizing
4. **Network Design**: Plan secure zone configuration

### Implementation Strategy
1. **Pilot Testing**: Validate configuration in non-production environment
2. **Performance Baseline**: Establish performance metrics before encryption
3. **Gradual Rollout**: Implement encryption incrementally
4. **Monitoring Setup**: Configure performance and error monitoring

### Operational Management
1. **Certificate Management**: Plan for certificate lifecycle and renewal
2. **Key Rotation**: Establish key rotation procedures
3. **Backup Strategy**: Include encryption keys in backup procedures
4. **Disaster Recovery**: Test recovery procedures with encrypted volumes

### Security Considerations
1. **Secure Zone Design**: Implement proper network isolation
2. **Access Control**: Limit administrative access to encryption configuration
3. **Audit Trail**: Enable comprehensive logging and monitoring
4. **Compliance Documentation**: Maintain records for regulatory requirements

## Summary
MPIO driver encryption provides transparent storage-level data protection without requiring application changes. However, it requires significant infrastructure investment in enterprise key management systems and careful performance planning. The solution is best suited for organizations with existing EMC storage infrastructure and enterprise key management capabilities.
