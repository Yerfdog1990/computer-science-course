# Database Languages

## Overview

A database system provides two core types of languages:

| Language Type | Purpose |
|---|---|
| **Data Definition Language (DDL)** | Specifies the database schema (structure) |
| **Data Manipulation Language (DML)** | Expresses database queries and updates |

> In practice, DDL and DML are **not two separate languages** — they form parts of a **single database language**. The most widely used example is **SQL (Structured Query Language)**.

---

## 1. Data Definition Language (DDL)

### What is it?
A **Data Definition Language (DDL)** is a special language used to specify a database schema through a set of definitions.

---

### Example: Creating a Table in SQL

```sql
CREATE TABLE account (
    account-number  CHAR(10),
    balance         INTEGER
);
```

**What this does:**
- Creates a new table called `account`
- Defines two columns: `account-number` (text, up to 10 characters) and `balance` (whole number)
- Updates a special set of tables called the **data dictionary**

---

### The Data Dictionary
When a DDL statement is executed, it updates the **data dictionary** (also called a **data directory**).

> A **data dictionary** contains **metadata** — that is, *data about data*.

- The **schema of a table** is an example of metadata
- The database system **consults the data dictionary** before reading or modifying actual data

---

### Data Storage and Definition Language
A special type of DDL — the **data storage and definition language** — specifies the storage structure and access methods used by the database system.

- These statements define the **implementation details** of the database schemas
- These details are usually **hidden from users**

---

### Consistency Constraints in DDL
The DDL provides facilities to specify **consistency constraints** — rules that data values stored in the database must satisfy.

**Example:**
> The balance on an account should never fall below $100.

```sql
CREATE TABLE account (
    account-number  CHAR(10),
    balance         INTEGER CHECK (balance >= 100)
);
```

- The database system **checks these constraints every time the database is updated**
- Any update that violates a constraint is **rejected**

---

## 2. Data Manipulation Language (DML)

### What is it?
A **Data Manipulation Language (DML)** is a language that enables users to **access or manipulate data** as organized by the appropriate data model.

### The Four Operations of Data Manipulation

| Operation | Description |
|---|---|
| **Retrieval** | Fetching information stored in the database |
| **Insertion** | Adding new information into the database |
| **Deletion** | Removing information from the database |
| **Modification** | Changing information stored in the database |

---

### Types of DML

#### 1. Procedural DML
- Requires the user to specify **what data are needed AND how to get them**
- The user must describe the step-by-step process for data access

#### 2. Declarative DML (Non-Procedural DML)
- Requires the user to specify **what data are needed, without specifying how to get them**
- The database system figures out an **efficient means of accessing the data**
- **Easier to learn and use** than procedural DML

> The DML component of **SQL is nonprocedural (declarative)**.

---

### Query Language
- A **query** is a statement requesting the **retrieval of information**
- The portion of a DML that involves information retrieval is called a **query language**
- The terms *query language* and *data manipulation language* are commonly (though technically loosely) used interchangeably

---

### Example Queries in SQL

#### Example 1: Retrieving Data from a Single Table

Find the name of the customer whose `customer-id` is `192-83-7465`:

```sql
SELECT customer.customer-name
FROM customer
WHERE customer.customer-id = '192-83-7465';
```

**What this does:**
- Looks through the `customer` table
- Finds all rows where `customer-id = 192-83-7465`
- Displays the `customer-name` attribute of those rows

**Result:**
```
Johnson
```

---

#### Example 2: Retrieving Data from Multiple Tables

Find the balance of **all accounts** owned by the customer with `customer-id = 192-83-7465`:

```sql
SELECT account.balance
FROM depositor, account
WHERE depositor.customer-id = '192-83-7465'
  AND depositor.account-number = account.account-number;
```

**What this does:**
- Looks through both the `depositor` table and the `account` table
- Finds all accounts linked to customer `192-83-7465` via the `depositor` table
- Retrieves and displays the `balance` for each matching account

**Result:**
```
500
900
```
*(Accounts A-101 and A-201 both belong to customer Johnson with ID 192-83-7465)*

---

### Abstraction in DML
The levels of abstraction (Physical → Logical → View) apply not only to defining data, but also to **manipulating data**:

| Level | Role in Data Manipulation |
|---|---|
| **Physical Level** | Efficient algorithms are defined to access data |
| **Higher Levels (Logical/View)** | Emphasis is on **ease of use** for humans |

> The **query processor** component of the database system translates DML queries into sequences of actions at the **physical level** of the database system.

---

## 3. Database Access from Application Programs

### What are Application Programs?
**Application programs** are programs used to interact with the database. They are usually written in a **host language** such as:
- COBOL
- C / C++
- Java

**Examples in a banking system:**
- Programs that generate **payroll checks**
- Programs that **debit** or **credit** accounts
- Programs that **transfer funds** between accounts

---

### How DML Statements are Executed from a Host Language

To access the database, DML statements must be executed from within the host language program. There are two approaches:

---

#### Approach 1: Application Program Interface (API)

A set of procedures is provided that can be used to:
- **Send DML and DDL statements** to the database
- **Retrieve results** back into the host language program

**Common Standards:**

| Standard | Language | Description |
|---|---|---|
| **ODBC** (Open Database Connectivity) | C | Defined by Microsoft; widely used API standard |
| **JDBC** (Java Database Connectivity) | Java | Provides database connectivity features for Java |

**Example using JDBC in Java:**
```java
Connection conn = DriverManager.getConnection("jdbc:mysql://localhost/bankdb", "user", "pass");
Statement stmt = conn.createStatement();
ResultSet rs = stmt.executeQuery("SELECT customer-name FROM customer WHERE customer-id = '192-83-7465'");
while (rs.next()) {
    System.out.println(rs.getString("customer-name"));
}
```

---

#### Approach 2: Extending Host Language Syntax (Embedded DML)

- The host language syntax is **extended** to embed DML calls directly within the program
- A special character **prefaces DML calls** to distinguish them from regular code
- A preprocessor called the **DML precompiler** converts the DML statements into **normal procedure calls** in the host language before compilation

**Example of Embedded SQL in C:**
```c
EXEC SQL
    SELECT customer-name
    INTO :cust_name
    FROM customer
    WHERE customer-id = '192-83-7465';
END-EXEC;
```
> `EXEC SQL` is the special prefix that signals the DML precompiler to process the following statement as a SQL query.

---

## Summary

| Component | Description | Example |
|---|---|---|
| **DDL** | Defines database schema and structure | `CREATE TABLE`, `ALTER TABLE` |
| **DML** | Manipulates (retrieves, inserts, updates, deletes) data | `SELECT`, `INSERT`, `UPDATE`, `DELETE` |
| **Data Dictionary** | Stores metadata about the database schema | Consulted before every data operation |
| **Procedural DML** | User specifies *what* and *how* | Step-by-step data access instructions |
| **Declarative DML** | User specifies only *what* (e.g., SQL) | `SELECT ... FROM ... WHERE ...` |
| **ODBC/JDBC** | APIs for accessing DB from application programs | C (ODBC), Java (JDBC) |
| **Embedded DML** | DML calls embedded in host language code | `EXEC SQL ... END-EXEC` in C |
