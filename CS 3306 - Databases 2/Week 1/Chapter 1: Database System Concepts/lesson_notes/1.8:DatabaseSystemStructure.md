## Database System Structure

A database system is partitioned into several modules, each handling a specific responsibility. These modules are broadly divided into two main functional tiers: 
1. the **Storage Manager** 
2. the **Query Processor**

---

## 1. Overview of System Partitioning

Because corporate databases often scale from hundreds of gigabytes to multiple terabytes, they cannot fit into a computer's main memory. Consequently, data is stored on disks and moved to memory only when needed.

Since disk access is significantly slower than the CPU, the database system must be structured to minimize data movement. The system's goal is to provide **high-level views** that hide these physical complexities while ensuring rapid processing.

---

## 2. The Storage Manager

The storage manager is the program module that acts as the interface between low-level data stored on the disk and the high-level queries or application programs submitted to the system. It translates Data Manipulation Language (DML) statements into commands that the operating system’s file system can understand.

### A. Key Components
* **Authorization and Integrity Manager:** Ensures that users have the correct permissions to access specific data and verifies that all data satisfies predefined integrity constraints.
* **Transaction Manager:** Guarantees that the database remains in a consistent state even if the system fails. It also manages concurrent access to prevent conflicts between simultaneous users.
* **File Manager:** Handles the allocation of space on disk storage and manages the data structures used to represent that information.
* **Buffer Manager:** A critical component that decides which data should be cached in main memory and handles the fetching of data from the disk. This allows the system to process datasets much larger than the available RAM.

### B. Physical Data Structures
The storage manager maintains several essential structures:
* **Data Files:** The actual storage of the database content.
* **Data Dictionary:** Stores **metadata** (data about data), including the database schema and structure.
* **Indices:** Specialized structures that provide high-speed access to specific data items.

---

## 3. The Query Processor

The query processor simplifies data access by translating nonprocedural, high-level requests into efficient sequences of physical operations.

### Key Components
* **DDL Interpreter:** Processes Data Definition Language (DDL) statements (like creating tables) and records these definitions in the data dictionary.
* **DML Compiler:** Translates DML statements into an **evaluation plan**—a set of low-level instructions for the engine.
    * **Query Optimization:** Since a single query can be executed in multiple ways, the compiler performs optimization to select the lowest-cost (fastest) evaluation plan.
* **Query Evaluation Engine:** The "worker" module that executes the low-level instructions generated by the DML compiler to fetch or update data.
