## Application Architectures: Detailed Study Notes

In modern computing, most users do not interact with a database system directly at its physical location. Instead, they connect via a network, creating a distinction between **client machines** (where the user works) and **server machines** (where the database resides).

Database applications are generally structured into either two-tier or three-tier architectures to manage this remote interaction.

### 1. Two-Tier Architecture
In a two-tier architecture, the application is divided directly between the client and the server.

* **Client Side:** The application resides on the user's machine. It contains the logic of the program and directly invokes database functionality.
* **Server Side:** The database system runs on the server and processes requests sent by the client.
* **Communication:** The client communicates with the server using query language statements (SQL). To standardize this interaction, application program interface (API) standards like **ODBC** (Open Database Connectivity) and **JDBC** (Java Database Connectivity) are used.
* **Best For:** Smaller-scale applications where direct communication between the user's local software and the database is efficient.

### 2. Three-Tier Architecture
In a three-tier architecture, an intermediate layer is introduced between the user and the database.

* **Client Tier (Front End):** The client machine acts as a simple interface (often a web browser or a forms interface). It does **not** contain direct database calls.
* **Application Server Tier (Middle Tier):** The client communicates with an application server. This layer houses the **business logic**—the specific rules that determine what actions the system takes under various conditions.
* **Database Tier (Back End):** The application server communicates with the database system to retrieve or update data as requested by the business logic.
* **Advantages:**
    * **Centralized Logic:** Business rules are stored in one place rather than being distributed across thousands of client machines.
    * **Security:** Users never have a direct connection to the database, adding a layer of protection.
    * **Scalability:** This model is highly appropriate for large-scale enterprise applications and the World Wide Web.

---

**Summary Comparison Table**

| Feature | Two-Tier Architecture | Three-Tier Architecture |
| :--- | :--- | :--- |
| **Primary Layers** | Client & Server | Client, Application Server, & Database |
| **Business Logic** | Located on the Client machine | Located on the Application Server |
| **Database Connection** | Direct from Client to DB | Indirect (via Application Server) |
| **Standard Use Case** | Local/Departmental Apps | Web-based/Enterprise Apps |
