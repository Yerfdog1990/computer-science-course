## 3.6 The Tuple Relational Calculus 

The **Tuple Relational Calculus (TRC)** is a **declarative** (nonprocedural) language. This means you describe **what** you want to find, rather than **how** to find it. It is based on a subset of first-order logic.

A TRC query follows this structure:
$$\{t \mid P(t)\}$$
* **$t$**: A tuple variable representing the resulting rows.
* **$P(t)$**: A formula (predicate) that must be true for $t$ to be included in the result set.

---

### 3.6.1 Core Concepts & Symbols

To build detailed TRC expressions, we use several logical connectors and quantifiers:

| Symbol | Meaning | Logical Use |
| :--- | :--- | :--- |
| $\wedge$ | **AND** | Both conditions must be true. |
| $\vee$ | **OR** | At least one condition must be true. |
| $\neg$ | **NOT** | The condition must be false. |
| $\Rightarrow$ | **IMPLIES** | If condition A is true, then B must also be true. |
| $\exists$ | **Existential Quantifier** | "There exists at least one..." |
| $\forall$ | **Universal Quantifier** | "For all..." or "Every..." |



---

### 3.6.2 Detailed Query Examples

To illustrate these, let's use the standard banking schema:
* **loan** (`loan-number`, `branch-name`, `amount`)
* **borrower** (`customer-name`, `loan-number`)
* **depositor** (`customer-name`, `account-number`)
* **branch** (`branch-name`, `branch-city`, `assets`)

#### 1. Finding Specific Rows (Selection)
Find all details of loans greater than \$1200:
$$\{t \mid t \in \text{loan} \wedge t[\text{amount}] > 1200\}$$
*Explanation:* This looks for every tuple $t$ in the `loan` table where the `amount` column is greater than 1200.

#### 2. Projecting Specific Columns
Find only the **loan numbers** for loans over \$1200:
$$\{t \mid \exists s \in \text{loan} (t[\text{loan-number}] = s[\text{loan-number}] \wedge s[\text{amount}] > 1200)\}$$
*Explanation:* Since $t$ is the output, we "tie" $t$'s `loan-number` to a tuple $s$ that actually exists in the `loan` table and meets the price criteria.

#### 3. Joining Multiple Tables
Find names of customers with a loan at the **Perryridge** branch:
$$\{t \mid \exists s \in \text{borrower} (t[\text{customer-name}] = s[\text{customer-name}] \wedge \exists u \in \text{loan} (u[\text{loan-number}] = s[\text{loan-number}] \wedge u[\text{branch-name}] = \text{"Perryridge"}))\}$$
*Explanation:* We find a tuple in `borrower` ($s$) to get the name, then find a matching tuple in `loan` ($u$) to verify the branch name.

#### 4. The "For All" Condition (Universal Quantification)
Find customers who have an account at **every** branch in **Brooklyn**:
$$\{t \mid \exists r \in \text{customer} (r[\text{customer-name}] = t[\text{customer-name}]) \wedge (\forall u \in \text{branch} (u[\text{branch-city}] = \text{"Brooklyn"} \Rightarrow \dots ))\}$$
*Explanation:* This uses **implication** ($\Rightarrow$). It says: "If a branch is in Brooklyn, then this customer MUST have an account there."

### 3.6.3 Formal Rules for Formulas

A TRC formula is built using **Atoms**:
1.  **Relation Atom:** $s \in r$ (Tuple $s$ is in relation $r$).
2.  **Comparison Atom:** $s[x] \Theta u[y]$ or $s[x] \Theta c$.
    * $s, u$ are tuple variables.
    * $x, y$ are attributes.
    * $c$ is a constant.
    * $\Theta$ is an operator ($=, \neq, <, \leq, >, \geq$).

**Free vs. Bound Variables:**
* **Free Variable:** The variable $t$ in $\{t \mid P(t)\}$ is free because it is not restricted by a quantifier within $P(t)$. It represents the final result.
* **Bound Variable:** Variables like $s$ and $u$ in $\exists s \in r$ or $\forall u \in r$ are bound to that specific quantifier.

---

### 3.6.4 Safety of Expressions

A query is considered **Safe** only if its result is a subset of the **Domain** of the formula.
* **Domain ($dom(P)$):** All constants appearing in the query itself plus all values existing in the relations mentioned.
* **Unsafe Example:** $\{t \mid \neg(t \in \text{loan})\}$
    * This is unsafe because it could return every possible tuple in the universe that *isn't* in the loan table (e.g., your name, the weather, etc.), leading to an infinite result.

---

### 3.6.5 Comparison: Algebra vs. Calculus

| Feature | Relational Algebra | Tuple Relational Calculus |
| :--- | :--- | :--- |
| **Approach** | Procedural (Step-by-step) | Declarative (State the goal) |
| **Basic Units** | Sets/Relations | Tuple variables |
| **Operators** | $\sigma, \Pi, \cup, \bowtie$ | $\wedge, \vee, \exists, \forall$ |
| **Equivalence** | Equivalent to safe TRC | Equivalent to basic RA |
