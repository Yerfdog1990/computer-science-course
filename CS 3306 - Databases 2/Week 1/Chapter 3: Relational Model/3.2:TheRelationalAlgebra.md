## 3.2 The Relational Algebra

The relational algebra is a **procedural query language**. It consists of a set of operations that take one or two relations (tables) as input and produce a new relation as their result.

Operations are categorized into:
* **Unary Operations:** Operate on a single relation (e.g., Select, Project, Rename).
* **Binary Operations:** Operate on pairs of relations (e.g., Union, Set Difference, Cartesian Product).

---

### 3.2.1 Fundamental Operations

#### 3.2.1.1 The Select Operation ($\sigma$)
The **select** operation identifies tuples (rows) that satisfy a specific predicate (condition).
* **Notation:** $\sigma_P(r)$, where $P$ is the selection predicate and $r$ is the relation.
* **Comparisons:** $=, \neq, <, \leq, >, \geq$.
* **Connectives:** And ($\wedge$), Or ($\vee$), and Not ($\neg$).

**Example Queries:**
1.  **Find loans from the "Perryridge" branch:**
    $$\sigma_{\text{branch-name} = \text{"Perryridge"}}(\text{loan})$$

    **Table: Result of $\sigma_{\text{branch-name} = \text{"Perryridge"}}(\text{loan})$**

    | loan-number | branch-name | amount |
    | :--- | :--- | :--- |
    | L-15 | Perryridge | 1500 |
    | L-16 | Perryridge | 1300 |

2.  **Find loans over $1200 at Perryridge:**
    $$\sigma_{\text{branch-name} = \text{"Perryridge"} \wedge \text{amount} > 1200}(\text{loan})$$

#### 3.2.1.2 The Project Operation ($\Pi$)
The **project** operation returns the argument relation with specific attributes (columns) removed. It eliminates duplicate rows to maintain set properties.
* **Notation:** $\Pi_{A_1, A_2, \dots, A_n}(r)$

**Example Query:**
* **List all loan numbers and amounts:**
  $$\Pi_{\text{loan-number, amount}}(\text{loan})$$

  **Table: Result of $\Pi_{\text{loan-number, amount}}(\text{loan})$**

  | loan-number | amount |
  | :--- | :--- |
  | L-11 | 900 |
  | L-14 | 1500 |
  | L-15 | 1500 |
  | L-16 | 1300 |
  | L-17 | 1000 |
  | L-23 | 2000 |
  | L-93 | 500 |

#### 3.2.1.4 The Union Operation ($\cup$)
Combines tuples from two relations. For $r \cup s$ to be valid:
1.  **Arity:** $r$ and $s$ must have the same number of attributes.
2.  **Compatibility:** Attribute domains must be the same for all $i$.

**Example Query:**
* **Find names of all customers who have either an account, a loan, or both:**
  $$\Pi_{\text{customer-name}}(\text{borrower}) \cup \Pi_{\text{customer-name}}(\text{depositor})$$

  **Table: Union Result (Duplicates Removed)**

  | customer-name |
  | :--- |
  | Adams, Curry, Hayes, Jackson, Jones, Smith, Williams, Lindsay, Johnson, Turner |

#### 3.2.1.5 The Set-Difference Operation ($-$)
Finds tuples in one relation but not in another.
* **Query:** Customers with an account but no loan.
  $$\Pi_{\text{customer-name}}(\text{depositor}) - \Pi_{\text{customer-name}}(\text{borrower})$$

  **Table: Result**
  | customer-name |
  | :--- |
  | Johnson, Lindsay, Turner |

#### 3.2.1.6 The Cartesian-Product Operation ($\times$)
Combines every tuple of one relation with every tuple of another.
* **Schema naming:** If relations $r$ and $s$ have the same attribute name, they are prefixed ($r.\text{attribute}$ vs $s.\text{attribute}$).

**Complex Query Example:**
* **Find names of customers with a loan at Perryridge:**
  $$\Pi_{\text{customer-name}}(\sigma_{\text{borrower.loan-number} = \text{loan.loan-number}}(\sigma_{\text{branch-name} = \text{"Perryridge"}}(\text{borrower} \times \text{loan})))$$

#### 3.2.1.7 The Rename Operation ($\rho$)
Used to give a name to the result of a relational-algebra expression or to rename attributes.
* **Notation:** $\rho_x(E)$ (returns result of $E$ under name $x$).
* **Application:** Finding the largest account balance.
  $$\Pi_{\text{balance}}(\text{account}) - \Pi_{\text{account.balance}}(\sigma_{\text{account.balance} < d.\text{balance}}(\text{account} \times \rho_d(\text{account})))$$

### 3.2.3 Additional Operations

#### 3.2.3.1 Set Intersection ($\cap$)
Returns tuples that are in both relations.
* **Equivalent Expression:** $r \cap s = r - (r - s)$.

#### 3.2.3.2 Natural Join ($\bowtie$)
Combines a Cartesian product and a selection into one operation, automatically matching attributes with the same name and removing duplicates.


**Example:** Find customer names and loan amounts:
$$\Pi_{\text{customer-name, loan-number, amount}}(\text{borrower} \bowtie \text{loan})$$

#### 3.2.3.3 The Division Operation ($\div$)
Used for "for all" queries. $r \div s$ includes tuples in $r$ that are associated with **every** tuple in $s$.
* **Query:** Customers who have an account at **all** Brooklyn branches.
  $$\Pi_{\text{customer-name, branch-name}}(\text{depositor} \bowtie \text{account}) \div \Pi_{\text{branch-name}}(\sigma_{\text{branch-city} = \text{"Brooklyn"}}(\text{branch}))$$

#### 3.2.3.4 The Assignment Operation ($\leftarrow$)
Allows breaking complex expressions into temporary variables.
* **Example:**
  $$\text{temp1} \leftarrow \Pi_{R-S}(r)$$
  $$\text{result} = \text{temp1} - \text{temp2}$$

### Summary Table of Operations

| Operation | Symbol | Type | Purpose |
| :--- | :--- | :--- | :--- |
| **Select** | $\sigma$ | Unary | Filter rows based on conditions. |
| **Project** | $\Pi$ | Unary | Select specific columns. |
| **Union** | $\cup$ | Binary | Combine unique rows from two sets. |
| **Cartesian Product** | $\times$ | Binary | All possible pairings of rows. |
| **Natural Join** | $\bowtie$ | Binary | Join tables on matching attributes. |
| **Division** | $\div$ | Binary | Handle "for all" requirements. |
