# Restoring Active Directory

## Introduction

When restoring system state data to a domain controller, you must choose between authoritative and nonauthoritative restore modes. Each mode serves different purposes and has specific implications for Active Directory replication throughout the network.

## Restore Types for Domain Controllers

### Nonauthoritative Restore (Default)
- **Description**: Active Directory and other replicated data is restored using information from other domain controllers
- **Purpose**: Safely restore a failed domain controller without overwriting the latest Active Directory information
- **Use Case**: Recovering a single domain controller while preserving current directory data

### Authoritative Restore
- **Description**: Restored data is restored on the current domain controller and then replicated to other domain controllers
- **Purpose**: Restore Active Directory throughout the network using archived data
- **Use Case**: Rolling back Active Directory changes or recovering from directory-wide corruption

## Authoritative Restore Process

### Step-by-Step Instructions

1. **Shutdown Domain Controller**:
   - Ensure the domain controller server is completely shut down

2. **Restart in Safe Mode**:
   - Restart the domain controller server
   - When "Please Select The Operating System To Start" prompt appears, press F8
   - Select "Directory Services Restore Mode"

3. **Restore System State Data**:
   - When system starts in Directory Services Restore Mode, use the Backup utility
   - Restore the system state data and other essential files

4. **Mark Objects as Authoritative**:
   - After restoring data but before restarting the server
   - Use the Ntdsutil tool to mark objects as authoritative
   - Thoroughly check the Active Directory data

5. **Restart and Replicate**:
   - Restart the server
   - When system finishes startup, Active Directory data should begin replicating throughout the domain

## Backing Up and Restoring Data on Remote Systems

### Remote Backup Procedures

1. **Create Network Drives**:
   - Create network drives for remote file systems before starting backup procedure
   - Ensure proper authentication and permissions

2. **Select Proper Backup Options**:
   - Select General option "Back Up The Contents Of Mounted Drives"
   - Without this option, only folder references are backed up, not actual data

### Remote Restore Procedures

1. **Select Restore Locations**:
   - Use My Network Places to select restore locations
   - Can restore to specific systems or mapped network drives

2. **Advanced Restore Options**:
   - When restoring to mapped network drive, select "Restore Junction Points, And Restore File And Folder Data Under Junction Points To The Original Location"
   - Ensures proper restoration of network drive mappings and data

## Disaster Recovery and Preparation

### Comprehensive Recovery Strategy

Backups are only one part of a comprehensive disaster recovery plan. Essential components include:

- Emergency Repair disks
- Boot disks
- Recovery Console installation
- Systematic recovery procedures

### System Recovery Steps

Follow this ordered approach when recovering a system:

1. **Safe Mode Recovery**:
   - Try to start the system in Safe Mode first
   - See "Starting a System in Safe Mode" section

2. **Emergency Repair Disk**:
   - Try to recover using Emergency Repair disk (if available)
   - See "Using the Emergency Repair Disk to Recover a System" section

3. **Recovery Console**:
   - Try to recover using the Recovery Console
   - See "Working with the Recovery Console" section

4. **System Restore from Backup**:
   - Restore the system from backup
   - Be sure to restore system state data and essential files

## Creating an Emergency Repair Disk

### Purpose and Function

The Emergency Repair disk helps recover systems that won't boot by storing:
- Essential system files
- Partition boot sector
- Startup environment for specific system

### When to Create/Update

- Create repair disk for each computer on network (starting with Windows 2000 servers)
- Update when:
  - Installing service packs
  - Manipulating boot drive
  - Modifying startup environment

### Recovery Information Location

- Basic recovery information saved in `%SystemRoot%\Repair` folder during OS installation
- Repair folder contains:
  - Copy of local Security Account Manager (SAM) data
  - Other essential system files
  - **Does not contain** Windows registry backup

### Creation Process

1. **Start Backup Utility**:
   - Start Backup → Welcome tab → Emergency Repair Disk

2. **Insert Disk**:
   - Insert blank 3.5-inch, 1.44-MB disk into floppy drive when prompted

3. **Registry Backup Option**:
   - Select "Also Backup The Registry To The Repair Directory" to backup registry
   - Registry backup saved in `%SystemRoot%\Repair` folder
   - **Note**: Must use Recovery Console to restore registry

4. **Complete Process**:
   - Click OK
   - Remove disk when prompted
   - Label as emergency repair disk for the system

## Creating Setup Boot Disks

### Requirements

- Create boot disks for each Windows 2000 version running on network
- Example: Separate disks for Windows 2000 Professional and Windows 2000 Server

### Alternative to Boot Disks

- If all computers can boot from CD-ROM, boot disks aren't necessary
- Simply insert Windows 2000 CD-ROM when starting system

### Creation Process

1. **Insert Windows 2000 CD**:
   - Place CD in CD-ROM drive

2. **Access Makeboot Utility**:
   - Click Start → Run
   - Type `h:\bootdisk\makeboot a:` (where h is CD-ROM drive, a is floppy drive)
   - Click OK

3. **Create Disk Set**:
   - Need four blank 3.5-inch, 1.44-MB disks
   - Insert blank disk when prompted, press any key
   - Remove disk and label as "1 of 4"
   - Repeat for remaining disks (2 of 4, 3 of 4, 4 of 4)

## Starting a System in Safe Mode

### Purpose

Safe Mode helps recover or troubleshoot system problems by loading only:
- Basic files
- Essential services
- Required drivers
- Mouse, monitor, keyboard, mass storage, and base video drivers
- **No networking services or drivers** (unless using Safe Mode With Networking)

### Safe Mode Startup Process

1. **Start/Restart System**:
   - Start or restart the problem system

2. **Access Advanced Options**:
   - During startup, look for "Please Select The Operating System To Start" prompt
   - Press F8

3. **Select Safe Mode Option**:
   - Use arrow keys to select desired Safe Mode option
   - Press Enter

### Safe Mode Options

| Option | Description |
|--------|-------------|
| **Safe Mode** | Loads only basic files, services, and drivers. No networking. |
| **Safe Mode With Command Prompt** | Loads basic components, starts command prompt instead of GUI. No networking. |
| **Safe Mode With Networking** | Loads basic components plus networking services and drivers. |
| **Enable Boot Logging** | Creates record of all startup events in boot log. |
| **Enable VGA Mode** | Starts system in VGA mode for display compatibility issues. |
| **Last Known Good Configuration** | Starts system using registry information from last shutdown. |
| **Directory Services Recovery Mode** | Starts system in Safe Mode for directory service restoration (domain controllers only). |
| **Debugging Mode** | Starts system in debugging mode for OS troubleshooting. |

### Troubleshooting with Safe Mode

- If problem doesn't reappear in Safe Mode, eliminate default settings and basic device drivers as causes
- Use Safe Mode to remove newly added devices or reverse driver updates
- Safe Mode should be used before trying Emergency Repair disk or Recovery Console

## Using the Emergency Repair Disk to Recover a System

### When to Use Emergency Repair Disk

Use when Safe Mode recovery fails and system has:
- Damaged boot sector
- Corrupted essential system files
- Startup environment problems on dual/multi-boot systems

### Limitations

- **Cannot recover damaged registry** - must use Recovery Console for registry recovery
- Replacement files don't reflect configuration changes made after setup
- May need to reinstall service packs and updates after repair

### Repair Process

1. **Start Setup Program**:
   - Insert Windows 2000 CD or first setup boot disk
   - Restart computer
   - Remove/insert disks as prompted when booting from floppy

2. **Access Repair Options**:
   - Follow Setup prompts
   - Press R for "Repair Or Recover" option

3. **Insert Windows 2000 CD**:
   - Insert CD when prompted (if not already inserted)

4. **Choose Repair Type**:
   - Press R for emergency repair
   - Choose one of:
     - **M for Manual Repair**: Advanced users/administrators can choose specific repairs (system files, partition boot sector, startup environment)
     - **F for Fast Repair**: Windows 2000 attempts to repair all problem areas automatically

5. **Use Emergency Repair Disk**:
   - Insert Emergency Repair disk when prompted
   - Damaged or missing files are replaced from:
     - Windows 2000 CD
     - `%SystemRoot%\Repair` folder on system partition

6. **Complete Repair**:
   - If successful, system restarts and should boot normally
   - If problems persist, may need to use Recovery Console

## Working with the Recovery Console

### Purpose and Capabilities

The Recovery Console is a last-line defense for system recovery, providing:
- Command prompt interface for file, driver, and service problem resolution
- Boot sector and master boot record repair
- Device driver and service enable/disable
- File attribute changes on FAT, FAT32, and NTFS volumes
- File read/write operations on all volume types
- File copying from floppy/CD to hard disk
- Check disk and drive formatting capabilities

### Installation Options

#### As Startup Option (Recommended for Problem Systems)

1. **Insert Windows 2000 CD**:
   - Place CD in CD-ROM drive

2. **Run Installation Command**:
   - Click Start → Run
   - Type `h:\i386\winnt32.exe /cmdcons` (where h is CD-ROM drive)
   - Click OK, then Yes when prompted

3. **Complete Installation**:
   - Recovery Console installed as startup option

> **Note**: Only administrators can install and run Recovery Console. For normal user access, enable Auto Admin Logon policy.

#### Starting from Setup Media (When System Won't Boot)

1. **Start Setup Program**:
   - Insert Windows 2000 CD or first setup boot disk
   - Restart computer
   - Follow prompts, press R for "Repair Or Recover"

2. **Access Recovery Console**:
   - Insert Windows 2000 CD when prompted
   - Press C for Recovery Console
   - Type local administrator password when prompted

3. **Use Recovery Console**:
   - Command prompt appears for entering Recovery Console commands
   - Type `exit` to leave console and restart computer

### Recovery Console Commands

| Command | Description |
|---------|-------------|
| **ATTRIB** | Changes attributes of files or directories |
| **BATCH** | Executes series of commands from text file |
| **CD** | Changes current directory |

| **CLS** | Clears screen |
| **COPY** | Copies single file to another location |
| **DEL** | Deletes one or more files |
| **DIR** | Displays directory listing |
| **DISABLE** | Disables system service or device driver |
| **DISKPART** | Manages partitions on hard disk drives |
| **ENABLE** | Starts or enables system service or device driver |
| **EXIT** | Exits Recovery Console and restarts computer |
| **EXPAND** | Expands compressed file |
| **FIXBOOT** | Writes new partition boot sector |
| **FIXMBR** | Repairs master boot record |
| **FORMAT** | Formats disk |
| **HELP** | Displays list of Recovery Console commands |
| **LISTSVC** | Lists services and drivers available on computer |
| **LOGON** | Logs on to Windows 2000 installation |
| **MAP** | Displays drive letter mappings |
| **MD** | Creates directory |
| **MORE** | Displays text file one page at a time |
| **REN** | Renames single file |
| **RD** | Removes directory |
| **SET** | Displays and sets environment variables |
| **SYSTEMROOT** | Changes to systemroot directory |
| **TYPE** | Displays text file |

### Deleting the Recovery Console

If Recovery Console is installed as startup option and no longer needed:

1. **Access Boot Drive**:
   - Start Windows Explorer
   - Select hard disk drive where Recovery Console was installed (normally boot drive)

2. **Show Hidden Files**:
   - Tools menu → Folder Options
   - View tab → Select "Show Hidden Files And Folders"
   - Clear "Hide Protected Operating System Files" check box
   - Click OK

3. **Delete Recovery Console Files**:
   - Delete Cmdcons folder
   - Delete Cmldr file

4. **Edit Boot.ini**:
   - Right-click Boot.ini → Properties
   - Clear "Read-Only" check box → Click OK
   - Open Boot.ini in Notepad
   - Remove this line: `C:\CMDCONS\BOOTSECT.DAT="Microsoft Windows 2000 Recovery Console" /cmdcons`
   - Save Boot.ini file
   - Change properties back to read-only

## Conclusion

Restoring Active Directory and recovering from system disasters requires a systematic approach with multiple recovery tools and techniques. Understanding the differences between authoritative and nonauthoritative restores, maintaining proper emergency repair disks, and mastering the Recovery Console ensures comprehensive disaster recovery capabilities for Windows 2000 domain controllers and systems.
