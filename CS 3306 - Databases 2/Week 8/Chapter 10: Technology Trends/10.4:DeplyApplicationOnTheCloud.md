## 3. Moodle — Open Source Course Management System (10.4.1)

A vast range of learning materials (videos, podcasts, eBooks) are available online, but they are often **not arranged for easy consumption** and may be **obsolete**. Course Management Systems (CMS) solve this by allowing instructors to create and organize materials.

### About Moodle
- db2university.com uses the **Moodle open source CMS**
- Written in **PHP**
- Considered one of the best open source CMS platforms available
- Developed by **Martin Dougiamas** at Curtin University of Technology, Perth, Australia — **first version in 2001**
- As of writing:
    - **52,000+ registered Moodle sites**
    - **950,000+ registered users**
    - Users from **175+ countries** via moodle.org

### db2university's Journey with Moodle

| Timeline | Milestone |
|---|---|
| **Late 2009** | Students at California State University, Long Beach (CSULB) enabled Moodle 1.9.6 to work with DB2 Express-C as a course project; patch shared with the community |
| **Early 2010** | Work began on enabling **Moodle 2.0** to use DB2 Express-C |
| **At time of writing** | Running **Moodle 2.0 Release Candidate 1** with a custom db2university theme |

> Moodle 2.0 is a **major revision** with fundamental changes in how it interfaces with databases compared to previous versions.

## 4. Enabling OpenID Sign-In (10.4.2)

Research shows that users landing on websites with **complicated or long registration processes tend to leave quickly**.

To keep users engaged, db2university.com enabled **OpenID sign-in** in addition to standard registration.

### What is OpenID?
OpenID allows users who already have accounts with supported providers to **sign in without re-entering registration information**. The site requests the provider — with the user's consent — to share information.

### Supported OpenID Providers:
- Facebook
- Google
- Yahoo
- AOL
- ChannelDB2
- And others

### OpenID Sign-In Process:
```
Step 1: Click "Sign in with OpenID" link
        ↓
Step 2: A popup shows all supported OpenID providers
        ↓
Step 3: Select a provider (e.g., ChannelDB2)
        ↓
Step 4: Input your provider username/email and password
        ↓
Step 5: First time only — provider asks for consent to share information
        ↓
Step 6: Information is shared → automatically registered to db2university!
        ↓
Future logins: Repeat the same steps (consent step skipped after first time)
```

## 5. Running on the Amazon Cloud (10.4.3)

db2university.com is **hosted on the Amazon Cloud (AWS)**, taking full advantage of Cloud computing benefits — including **DB2 HADR for disaster recovery**.

### AWS Resources Used

| Resource | Details |
|---|---|
| **EC2 Instances** | Standard large instance — 64-bit, 4 ECUs, 7.5 GB memory, 850 GB instance storage |
| **EBS Volumes** | 50 GB (data & logs) + 2 GB (DB2 code & config) |
| **S3 Buckets** | 3 GB and 1 GB buckets for backups and log archives |
| **CloudFront** | CDN for delivering course videos and materials from edge servers closer to users |

### EC2 Instance Architecture (US-East Region)

Three EC2 instances are provisioned, each serving a specific role:

```
┌──────────────────────────────────────────────────────┐
│                   US-East Region                     │
│                                                      │
│  ┌────────────────┐   ┌────────────────┐             │
│  │  EC2 Instance 1│   │  EC2 Instance 2│             │
│  │  Moodle App    │   │  DB2 Primary   │             │
│  │  + Web Server  │   │  (HADR Primary)│             │
│  └────────────────┘   └────────────────┘             │
│                                                      │
│  ┌─────────────────────────────┐                     │
│  │  EC2 Instance 3             │                     │
│  │  DB2 HADR Stand-by          │                     │
│  │  (Different Availability    │                     │
│  │   Zone — DR site)           │                     │
│  └─────────────────────────────┘                     │
└──────────────────────────────────────────────────────┘
```

### Storage Architecture

| Storage Type | Purpose |
|---|---|
| **EBS (50 GB)** | Store DB2 data and DB2 recovery logs |
| **EBS (2 GB)** | Store DB2 code and DB2 configuration files |
| **Instance Storage** | Temporarily store DB2 backup images (later moved to S3) |
| **S3** | Long-term retention of backup images, log archives, and EBS volume snapshots |

### CloudFront (CDN)
- Allows users to **download course videos and materials** from an Amazon edge server **closer to their location**
- Files are first copied to an **S3 bucket**, then replicated to edge servers globally

### Software Stack

| Component | Version |
|---|---|
| **Operating System** | Ubuntu Linux 10.04.1 LTS |
| **Database** | DB2 Express 9.7.2 for Linux 64-bit |
| **CMS** | Moodle 2.0 Release Candidate 1 |
| **Language** | PHP 5.3.3 |

> **Note:** DB2 **Express** (not DB2 Express-C) is used because the **HADR feature** is only available starting from the DB2 Express edition.

### Cloud Management
- **RightScale** is used to manage AWS resources
- RightScale is a partner of IBM
- Its software allows environments to be **built quickly using templates and scripts**

## 6. Mobile Application — Retrieving Course Marks on Android (10.4.4)

While Moodle allows students to view their marks on the Web, db2university.com also developed a **custom Android mobile application** using **App Inventor**.

### How the App Works:
1. Student inputs a **mobile access code** — a unique keyword obtained from their Moodle profile
2. Student selects the **course** they are taking or have taken
3. App **displays all marks** for that course

### Technical Architecture:
| Side | Technology Used |
|---|---|
| **Client (Mobile)** | App Inventor for Android |
| **Server** | Web service built with **Ruby / Sinatra** |
