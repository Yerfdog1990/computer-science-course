# Cloud Computing

---

## 1. Background & Context

An IBM survey (2010) of **2,000+ IT professionals** worldwide identified two major technology trends expected by 2015:

1. **Cloud computing** would overtake on-premise computing as the primary way organizations acquire IT resources.
2. **Mobile application development** (iPhone, Android, iPad, PlayBook) would surpass development on other platforms.

---

## 2. What is Cloud Computing?

Cloud computing is **not a new technology** — it is a **new model to deliver IT resources**.

- Gives the illusion of access to an **infinite amount of computing resources on demand**
- Computing power can be **rented with no commitment** — no need to buy servers; pay only for what you use
- Often compared to **utility billing** (water, electricity) — you pay for what you consume

> Cloud computing has drastically altered how computing resources are obtained, enabling one-man companies, large enterprises, and governments to work on projects previously impossible.

---

## 3. Traditional IT Model vs. Cloud Computing Model

| Aspect | Traditional IT Model | Cloud Computing Model |
|---|---|---|
| **Budget Type** | Capital budget required | Part of operating expense |
| **Initial Investment** | Large upfront investment | Start at 2 cents / hour |
| **Capacity Planning** | Plan for peak capacity | Scale on demand |
| **Project Start Time** | ~120 days | Less than 2 hours |

### Key Differences Explained

- **Cost**: Traditional IT requires heavy upfront hardware/software purchase. Cloud shifts this to small on-demand hourly costs.
- **Speed**: Traditional IT requires budget requests, procurement, installation, and configuration (~120 days). Cloud delivers a working, configured system in under 2 hours.
- **Scalability**: Traditional IT requires buying for peak load (e.g., 5 servers if you only need 2 extra for 5 days/month). Cloud lets you rent only what you need, when you need it.

## 4. Characteristics of Cloud Computing

Cloud computing rests on **three core characteristics**:

### 4.1 Standardization
- Builds a large set of **homogeneous IT resources**, mostly from inexpensive components
- The **opposite of customization**

### 4.2 Virtualization
- Provides a method for **partitioning large pools of IT resources** and allocating them on demand
- Resources can be **returned to the pool** after use for others to reuse

### 4.3 Automation
- Allows users to **control provisioned resources** without waiting for an administrator
- Critical in large-scale Cloud environments

> **Real-world examples of Cloud services**: Facebook, Yahoo, Gmail — all deliver standardized, virtual, and automated services. You can create an account and start using them immediately.

---

## 5. Cloud Computing Service Models

There are **three service models**:

### 5.1 Infrastructure as a Service (IaaS)
- The provider manages: **data center, hardware, operating system**
- You don't need to worry about physical infrastructure

### 5.2 Platform as a Service (PaaS)
- The provider manages: **application platform / middleware**
- Example: Providing a DB2 server, WebSphere application server, etc.

### 5.3 Software as a Service (SaaS)
- The provider manages: **the application itself**
- Think of it as an "application store" where you rent apps by the hour
- **Typical example**: Salesforce.com

## 6. Cloud Providers

### 6.1 IBM Smart Business Development and Test on the IBM Cloud
- Cloud services **specifically tailored for development and test**
- Data centers in the **US and Europe**
- Supports **Intel-based 32-bit and 64-bit instances** running:
    - RedHat or SUSE Linux
    - Microsoft Windows
- An **instance** = a virtual server

**Instance tiers (32-bit example):**
| Tier | CPU | Memory | Storage |
|---|---|---|---|
| Bronze | 1 CPU @ 1.25 GHz | 2 GB | 175 GB local |
| Silver | Higher specs | Higher | Higher |
| Gold | Highest specs | Highest | Highest |

**Provisioning process:**
1. Log in to IBM Developer Cloud dashboard
2. Click "Add instances"
3. Choose an instance (e.g., DB2 Express-C 9.7.1 PAYG on SUSE Linux)
4. Select instance type (32/64-bit) and CPU tier
5. Input a string to generate an SSH key
6. Instance is provisioned within minutes (virtual CPUs, memory, OS, and software all installed)

---

### 6.2 Amazon Web Services (AWS)
- **Leading provider** of public cloud infrastructure
- Data centers in **four regions**: US-East, US-West, Europe, Asia Pacific
- Each region has **multiple availability zones** for improved business continuity
- Virtual servers called **Elastic Cloud Compute (EC2) instances**
    - Intel-based (32-bit and 64-bit)
    - Runs Windows or Linux (multiple distributions)

**AWS Storage Options:**

| Storage Type | Description | Persistent? |
|---|---|---|
| **Instance Storage** | Included with instance at no extra cost | ❌ No — lost if instance crashes/terminates |
| **Simple Storage Service (S3)** | File-based storage organized into buckets; accessed via HTTP PUT/GET | ✅ Yes |
| **Elastic Block Storage (EBS)** | Treated like a regular disk; ideal for databases | ✅ Yes |

## 7. Security on the Cloud

Security is a **top concern** for companies considering public Cloud adoption — the idea of confidential data held by a third-party provider raises privacy risks.

### Solutions:

| Approach | Description |
|---|---|
| **Private Cloud** | Data held safely on-premises using hardware/software like IBM Cloudburst™ and IBM WebSphere Cloudburst Appliance |
| **Virtual Private Cloud (VPC)** | Servers in the provider's data center but **not accessible to the internet**; security managed by the company's own infrastructure (offered by Amazon and IBM) |
| **Hybrid Cloud** | Critical data stays in the **private cloud**; development/test data goes on the **public cloud** |

## 8. Databases and the Cloud

Cloud computing is a **new delivery method for IT resources, including databases**.

### IBM DB2 on the Cloud

DB2 is **Cloud-ready** in terms of both licensing and features. DB2 images are available across:
- **Public Cloud**: AWS and IBM Developer Cloud
- **Private Cloud**: VMware or WebSphere Cloudburst Appliance
- **Hybrid Cloud**: Combination of the above

### Licensing Options

| Model | Description |
|---|---|
| **BYOL (Bring Your Own License)** | Use your existing DB2 licenses on the Cloud |
| **PAYG (Pay As You Go)** | Pay only for what you use |
| **DB2 Express-C** | Free to use on the Cloud (Cloud provider infrastructure costs may still apply) |

---

### DB2 Features Advantageous in the Cloud

#### 8.1 Database Partitioning Feature (DPF)
- Based on **shared-nothing architecture** — fits well with Cloud provisioning
- Ideal for **Data Warehousing** with large datasets requiring business intelligence queries
- **Queries are automatically parallelized** across a cluster of servers (transparent to applications)
- Servers can be added on demand; DB2 **automatically rebalances data**, improving performance nearly linearly

#### 8.2 High Availability Disaster Recovery (HADR)
- A robust DB2 feature with **10+ years in the market**
- Works with **two servers**: a primary and a stand-by

| Configuration | Benefit |
|---|---|
| Both servers at the same location | **High Availability** |
| Servers in different locations (e.g., different states/countries) | **Disaster Recovery** |

- **Cloud advantage for DR**: You "rent space" in distributed data centers without paying for physical space, electricity, cooling, or security — and without needing capital budget
- Primary server can be on-premise; stand-by placed on the Cloud (optionally in a VPC for added security)
- System can be **back up and running in under 15 seconds** after a primary server crash

#### 8.3 Compression
- DB2's compression feature **saves on storage costs** in the Cloud
- Depending on workload, compression can also **increase overall performance**
