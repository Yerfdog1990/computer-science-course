# Section 23.3: Spatial and Geographic Data

## Overview
Spatial database systems provide targeted internal mechanisms to efficiently store, index, and query data based on multi-dimensional physical locations and geographic coordinate systems. Traditional indexing mechanisms (such as standard B-trees or hash indexes) are fundamentally one-dimensional and cannot handle multi-dimensional queries, such as identifying overlapping spatial polygons. Efficient processing requires specialized index structures like R-trees.

## Core Spatial Domains
1.  **Computer-Aided Design (CAD) Data**: Stores explicit spatial layouts regarding how physical objects are mechanically constructed (e.g., buildings, automobiles, aircraft) or how micro-electronics are laid out (e.g., complex integrated circuits and electronic devices).
2.  **Geographic Data**: Manages macroscopic planetary data layouts, including road networks, land-usage profiles, topographic elevation indices, political boundaries, and land-ownership cartography. Systems customized for this domain are known as **Geographic Information Systems (GIS)**.

## 23.3.1 Representation of Geometric Information
Geometric data can be structured using normalized, flat relational schemas or non-First-Normal-Form (1NF) complex collections:

### 1. Line Segment
* **Representation**: Formally defined by the explicit coordinates of its two terminal endpoints: $\{(x_1, y_1), (x_2, y_2)\}$. In geographic mappings, these values translate directly to latitude and longitude pairs.

### 2. Polyline (Linestring)
* **Representation**: A continuous, connected sequence of individual line segments stored as an ordered list of coordinate vertices.
* **Use Cases**: Useful for mapping linear cartographic paths like highways, power lines, or rivers where the item's physical width is sufficiently small relative to the global map scale to be approximated as a line. Complex continuous curves are approximated by partitioning them into dense sequences of polyline segments or short circular arcs.

### 3. Polygon
* **Boundary Method**: Modeled by saving an ordered sequence of its vertices, which explicitly defines the closed outer perimeter boundary of the polygon.
* **Triangulation Method**: Alternatively, any complex polygon can be broken down into a set of non-overlapping constituent triangles. In a strict 1NF database relation, the complex parent polygon is assigned a unique global identifier, and every decomposed triangle is stored as a fixed-size row carrying that shared parent ID.

### 4. Three-Dimensional (3D) Objects
* **Primitives**: Point and line primitive structures match their 2D counterparts but introduce an explicit height component ($z$-axis). Planar figures (triangles, rectangles) retain their bounding concepts within a 3D coordinate space.
* **Volumetric Figures**: Solid volumes like tetrahedrons or cuboids match triangles and rectangles. Complex polyhedra are modeled either by dividing their internal volume into a collection of adjacent tetrahedrons (3D triangulation) or by cataloging their outer bounding polygonal faces along with a boolean direction vector indicating which side constitutes the internal volume.

## 23.3.2 Design Databases (CAD)

### Architectural Paradigm Shift
Traditional CAD programs loaded an entire design file directly into memory during an active editing session and serialized it back to a flat file upon completion. This model has major drawbacks:
* High computing overhead and code complexity are required to map data between memory formats and disk representations.
* The application must read an entire file into memory even if the user only needs to view or edit a tiny fraction of the layout.
* Massive designs (e.g., a modern ultra-dense integrated circuit or the complete blueprint of a commercial airplane) exceed physical memory capacities.

To address this, databases treat design elements as persistent objects where structural interconnections track component hierarchies. Complex shapes are constructed by applying boolean algebra operations—**union, intersection, and difference**—to geometric primitives (spheres, cylinders, cuboids) or via wireframe surface meshes.

### Spatial Integrity Constraints
Design databases must enforce strict structural rules to guarantee validity (e.g., "two structural utility pipes cannot cross or occupy the exact same physical space"). If checked manually, these interference errors are often missed until physical prototyping begins, making them extremely expensive to correct. Automating these checks requires highly efficient multidimensional indexing structures to detect spatial overlaps in real time.

## 23.3.3 Geographic Data Formats
Geographic information is split across two core formatting structures:

### 1. Raster Data
* **Structure**: Composed of rigid multi-dimensional arrays, bitmaps, or pixel grids.
* **Examples**: A 2D satellite image tracking cloud density per grid square, or a 3D grid measuring atmospheric temperatures across varied altitudes over specific regions. Time can form a fourth dimension to track changes. To save space, arrays are often heavily compressed.

### 2. Vector Data
* **Structure**: Built entirely out of geometric primitives (points, lines, polygons, and polyhedrons).
* **Examples**: Countries are saved as closed polygons, roads as polylines, and terrain elevations as a mosaic of polygons where each polygon bounds an area of equal height.

### Format Comparison

| Metric | Raster Representation | Vector Representation |
| :--- | :--- | :--- |
| **Storage Compactness** | High overhead; saves data for every grid cell. | Highly compact; only stores definitive coordinate points. |
| **Precision** | Loses precision when mapping fine details into large pixels. | High precision; preserves sharp geometric boundaries (e.g., roads). |
| **Ideal Use Cases** | Continuous, naturally fluid data (e.g., satellite imagery). | Discrete, clear boundaries (e.g., political borders, utility networks). |

## 23.3.4 Spatial Queries

### Core Query Classes
* **Nearness Queries**: Requests spatial entities located within a relative distance from a target point (e.g., "find all restaurants within a 1-mile radius of the user").
* **Nearest-Neighbor Query**: A subset of nearness queries that requests the single absolute closest object to a target point. This query does not require a maximum distance boundary parameter, meaning it successfully returns a result regardless of how far away that closest object is.
* **Region Queries**: Finds all objects that fall partially or completely within the spatial boundaries of a specified geometric zone (e.g., "list all retail shops within the boundary of Pattaya City").

### Spatial Joins
A spatial join computes the intersection or union of spatial objects across two separate relations using location coordinates as the join attribute. For example, joining a `Rainfall` relation with a `PopulationDensity` relation extracts all overlapping regions that have both low rainfall and high population density.

* **Algorithmic Constraint**: Standard database join strategies like **hash joins** and **sort-merge joins** are completely unusable on multidimensional spatial coordinate data.
* **Solution**: Algorithms rely on the coordinated, simultaneous traversal of the specialized spatial index structures built on the two relations.

### User Interfaces
Because spatial data is inherently visual, users typically interact with it via graphical user interfaces rather than standard text tables. Front-ends must support interactive operations like:
* Dynamic zooming (in and out) to scale map details.
* Map layering to overlay diverse themes (e.g., showing a crime rate polygon map directly over a real estate housing map).

## 23.3.5 Indexing of Spatial Data

### 1. k-d Trees
The k-dimensional tree is an early binary tree structure designed to index multi-dimensional point data.



* **Mechanism**: Each internal node partitions the spatial volume into two sub-spaces along a single chosen dimension.
* **Cycling Dimensions**: The partitioning dimension cycles through the available dimensions at each successive level of the tree. For example, in a 2D space:
    * The root node (Level 0) splits space vertically along the $X$-axis.
    * Children (Level 1) split their sub-spaces horizontally along the $Y$-axis.
    * Grandchildren (Level 2) split along the $X$-axis again, and so on.
* **Splitting Rule**: Splits are selected through point medians so that exactly half the points fall on either side of the partition line. Subdivisions stop once a node contains fewer than a configured maximum threshold of points.
* **k-d-B Tree**: To optimize for secondary storage disk blocks, k-d-B trees allow internal nodes to have multiple child partitions, which reduces tree height.

### 2. Quadtrees
A quadtree is a hierarchical tree structure where every internal node splits a bounded rectangular region into **four equal-sized quadrants**.



* **PR Quadtree (Point Region)**: Designed to index point distributions. The space is halved based strictly on the geometric center of the bounded region, regardless of where the points are clustered. Subdivisions continue recursively until a quadrant contains at most one point.
* **Region Quadtree**: Tailored for raster array data. A node becomes a terminal leaf if all pixel cells within its quadrant have identical values (e.g., completely covered by water). If the pixels differ, the quadrant is split into four smaller sub-quadrants.
* **Limitation**: Line segments or polygons that cross a quadrant boundary must be split into separate pieces and stored across multiple subtrees, introducing storage and query overheads.

### 3. R-Trees
The R-tree (Rectangle-tree) is a balanced, multi-dimensional index structure designed for tracking complex spatial objects like lines, bounding boxes, and polygons. Polygons are stored strictly within the terminal leaf nodes.



* **Bounding Boxes**: Every node in the tree is assigned an axis-parallel Minimum Bounding Box (MBB).
    * For a leaf node, the MBB is the smallest possible rectangle that completely encloses all the spatial objects saved in that leaf.
    * For an internal node, the MBB is the smallest possible rectangle that completely encloses the bounding boxes of all its child nodes.
* **The Overlap Property**: Unlike standard $B^+$-trees where search paths are completely disjoint, the bounding boxes of sibling nodes in an R-tree **can physically overlap**. Consequently, searching for a single coordinate point or evaluating a region intersection may require traversing **multiple distinct paths** down the tree, which can degrade query performance.

#### The Quadratic Split Heuristic
When an insertion causes an R-tree node to exceed its capacity, it must be split into two nodes. Because multi-dimensional data lacks a single linear midpoint, the tree uses the **Quadratic Split Heuristic** to minimize the total area of the two resulting bounding boxes:

1.  **Select Seeds**: Examine all pairs of entries in the overfull node. Identify the two entries that would waste the largest amount of total bounding box area if they were placed into the same node. Assign the first entry as the seed for Set $S_1$ and the second entry as the seed for Set $S_2$.
2.  **Evaluate Remaining Entries**: For each remaining unassigned entry $e$, calculate the required area expansion needed to include it in the bounding box of $S_1$ ($\Delta A_1$) and $S_2$ ($\Delta A_2$).
3.  **Assign Max Preference**: Find the entry that exhibits the absolute *maximum difference* between $\Delta A_1$ and $\Delta A_2$ (the entry that has a strong preference for one set over the other). Assign that entry to its preferred set. Repeat this process until all entries are distributed.
