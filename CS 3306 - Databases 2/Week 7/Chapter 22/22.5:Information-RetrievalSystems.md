# Section 22.5: Information-Retrieval Systems

## Overview

The field of information retrieval has developed in parallel with the field of databases.

### Traditional Model

In the traditional model used in information retrieval:
- Information is organized into documents
- Assumed there is a large number of documents
- Data contained in documents is unstructured, without any associated schema
- Process consists of locating relevant documents on the basis of user input (keywords or example documents)

### The Web and Information Retrieval

The Web provides a convenient way to get to and interact with information sources across the Internet. However:
- Persistent problem: explosion of stored information with little guidance to help user locate what's interesting
- Information retrieval has played critical role in making Web a productive and useful tool, especially for researchers

### Traditional Examples

- Online library catalogs
- Online document-management systems (e.g., those storing newspaper articles)
- Data organized as collection of documents
- Newspaper article or catalog entry are examples of documents
- In Web context, usually each HTML page is considered a document

### Document Retrieval

User may want to retrieve:
- A particular document
- A particular class of documents

Intended documents typically described by set of keywords:
- Example: "database system" to locate books on database systems
- Example: "stock" and "scandal" to locate articles about stock-market scandals
- Documents have associated set of keywords
- Documents whose keywords contain those supplied by user are retrieved

### Beyond Textual Data

Keyword-based information retrieval can be used for retrieving other types of data with descriptive keywords:
- Video or audio data
- Example: Video movie may have keywords like title, director, actors, type

### Differences from Database Systems

**Database Systems Address Issues Not in Information-Retrieval Systems**:
- Updates and associated transactional requirements (concurrency control, durability)
- These matters viewed as less important in information systems
- Deal with structured information organized with relatively complex data models (relational model, object-oriented models)

**Information-Retrieval Systems Address Issues Not Adequately Addressed in Database Systems**:
- Managing unstructured documents
- Approximate searching by keywords
- Ranking of documents on estimated degree of relevance to query

## 22.5.1 Keyword Search

Information-retrieval systems typically allow query expressions formed using:
- Keywords
- Logical connectives: and, or, not

**Examples**:
- Documents containing "motorcycle and maintenance"
- Documents containing "computer or microprocessor"
- Documents containing "computer but not database"

Query containing keywords without connectives assumed to have ands implicitly connecting keywords.

### Full Text Retrieval

- In full text retrieval, all words in each document are considered to be keywords
- For unstructured documents, full text retrieval is essential (may be no information about what words are keywords)
- Use word "term" to refer to words in document, since all words are keywords

### Simple Information Retrieval

In simplest form, system:
- Locates and returns all documents that contain all keywords in query (if no connectives)
- Handles connectives as expected

### Sophisticated Systems

More sophisticated systems:
- Estimate relevance of documents to query
- Show documents in order of estimated relevance
- Use information about term occurrences
- Use hyperlink information to estimate relevance

## 22.5.1.1 Relevance Ranking Using Terms

### Problem

Set of all documents satisfying query expression may be very large:
- Billions of documents on Web
- Most keyword queries on Web search engine find hundreds of thousands of documents containing keywords
- Full text retrieval makes problem worse: each document may contain many terms
- Terms only mentioned in passing treated equivalently with documents where term is indeed relevant
- Irrelevant documents may get retrieved

### Solution

Information retrieval systems:
- Estimate relevance of documents to query
- Return only highly ranked documents as answers
- Relevance ranking is not exact science, but there are well-accepted approaches

### Measuring Document Relevance to Term

Given particular term t, how relevant is document d to term?

**Approach**: Use number of occurrences of term in document as measure of relevance
- Assumption: relevant terms likely mentioned many times in document

**Problem with Simple Counting**:
- Number of occurrences depends on length of document
- Document with 10 occurrences may not be 10 times as relevant as document with one occurrence

**Formula**:
```
r(d, t) = log(1 + n(d, t) / n(d))
```
Where:
- n(d) = number of terms in document
- n(d, t) = number of occurrences of term t in document d

This metric:
- Takes length of document into account
- Relevance grows with more occurrences of term in document
- Not directly proportional to number of occurrences

### Refinements

Many systems refine metric using other information:
- If term occurs in title, author list, or abstract, document considered more relevant
- If first occurrence of term is late in document, document considered less relevant than if first occurrence is early
- These notions can be formalized by extensions of formula

In information retrieval community, relevance of document to term referred to as **term frequency**, regardless of exact formula used.

### Relevance to Query with Multiple Keywords

Query Q may contain multiple keywords. Relevance of document to query with two or more keywords estimated by combining relevance measures of document to each keyword.

**Simple Approach**: Add them up

**Problem**: Not all terms used as keywords are equal
- Example: Query uses "web" (frequent) and "Silberschatz" (less frequent)
- Document containing "Silberschatz" but not "web" should rank higher than document containing "web" but not "Silberschatz"

### Inverse Document Frequency

To fix problem, weights assigned to terms using inverse document frequency:
- Defined as 1/n(t)
- Where n(t) = number of documents (among those indexed by system) that contain term t

**Formula**:
```
r(d, Q) = Σ (r(d, t) / n(t)) for t ∈ Q
```

Can be further refined if user permitted to specify weights w(t) for terms in query:
- Use w(t)/n(t) in place of 1/n(t)

### Stop Words

Almost all text documents (in English) contain common words like "and," "or," "a"
- These words useless for querying since inverse document frequency extremely low
- Information-retrieval systems define set of words called **stop words** (100 or so most common words)
- Remove this set from document when indexing
- Not used as keywords
- Discarded if present in keywords supplied by user

### Proximity

Another factor when query contains multiple terms: proximity of terms in document
- If terms occur close to each other in document, document ranked higher than if they occur far apart
- Formula for r(d, Q) can be modified to take proximity into account

### Document Ranking

Given query Q, job of information retrieval system is to return documents in descending order of their relevance to Q
- Since may be very large number of relevant documents
- Systems typically return only first few documents with highest degree of estimated relevance
- Permit users to interactively request further documents

## 22.5.1.2 Relevance Using Hyperlinks

### Early Web Search Engines

Early Web search engines ranked documents using only relevance measures similar to those in Section 22.5.1.1

### Hyperlink Information

Researchers realized Web documents have information plain text documents don't have: hyperlinks
- Relevance ranking of document affected more by hyperlinks that point to document than by hyperlinks going out of document

### Site Ranking

**Basic Idea**: Find sites that are popular, rank pages from such sites higher than pages from other sites

**Site Identification**: Identified by internet address part of URL (e.g., www.bell-labs.com in http://www.belllabs.com/topic/books/db-book)
- Site usually contains multiple Web pages
- Most searches intended to find information from popular sites
- Ranking pages from popular sites higher generally good idea

**Example**: Term "google" occurs in vast numbers of pages, but google.com is most popular among sites with pages containing "google"
- Documents from google.com containing "google" ranked as most relevant to term "google"

### Measuring Site Popularity

**Problem**: How to define popularity of site?
- One way: find how many times site accessed
- Getting such information impossible without cooperation of site
- Infeasible for Web search engine to implement

**Effective Alternative**: Use hyperlinks
- Define p(s), popularity of site s, as number of sites that contain at least one page with link to site s

### Combining Relevance Measures

Traditional measures of relevance of page (from Section 22.5.1.2) can be combined with popularity of site containing page to get overall measure of relevance of page
- Pages with high overall relevance value returned as answers to query

### Site vs. Page Popularity

Used popularity of site as measure of relevance of individual pages at site, not popularity of individual pages

**Reasons**:
1. Most sites contain only links to root pages of other sites, so all other pages would appear to have almost zero popularity (when in fact accessed frequently by following links from root page)
2. Far fewer sites than pages, so computing and using popularity of sites cheaper than computing and using popularity of pages

### Refined Notions of Popularity

More refined notions exist:
- Link from popular site to another site s may be considered better indication of popularity of s than link from less popular site
- This notion is circular (popularity of site defined by popularity of other sites, may be cycles of links)
- Popularity of sites can be defined by system of simultaneous linear equations, solved by matrix manipulation techniques
- Linear equations defined to have unique and well-defined solution

### PageRank

Popular Web search engine google.com uses referring-site popularity idea in definition of **page rank** (measure of popularity of a page)
- This approach gave results much better than previously used ranking techniques
- google.com became widely used search engine in short period of time

### Hubs and Authorities

Another approach derived from theory of social networking developed by sociologists in 1950s

**Social Networking Context**: Goal was to define prestige of people
- Example: President of United States has high prestige since large number of people know him
- If someone known by multiple prestigious people, also has high prestige even if not known by as large number of people

**Hubs and Authorities**:
- Developed into notion taking into account presence of directories that link to pages containing useful information
- **Hub**: Page that stores links to many pages; does not contain actual information on topic, but points to pages that contain actual information
- **Authority**: Page that contains actual information on topic, may not be directly pointed to by many pages
- Each page gets prestige value as hub (hub-prestige) and another as authority (authority-prestige)
- Definitions cyclic, defined by set of simultaneous linear equations
- Page gets higher hub-prestige if points to many pages with high authority-prestige
- Page gets higher authority-prestige if pointed to by many pages with high hub-prestige
- Given query, pages with highest authority-prestige ranked higher

## 22.5.1.3 Similarity-Based Retrieval

Certain information-retrieval systems permit similarity-based retrieval

**How It Works**:
- User gives system document A
- Asks system to retrieve documents "similar" to A
- Similarity of document to another may be defined on basis of common terms

**Approach**:
- Find k terms in A with highest values of r(d, t)
- Use these k terms as query to find relevance of other documents
- Terms in query weighted by r(d, t)

**Interactive Refinement**:
- If set of documents similar to A is large, system may present user few similar documents
- Allow user to choose most relevant few
- Start new search based on similarity to A and to chosen documents
- Resultant set likely what user intended to find

**Helping Users**:
- Same idea used to help users who find many documents that appear relevant based on keywords but are not
- Instead of adding further keywords to query, users allowed to identify one or few returned documents as relevant
- System uses identified documents to find other similar ones
- Resultant set likely what user intended to find

## 22.5.1.4 Synonyms and Homonyms

### Synonyms Problem

Consider problem of locating documents about motorcycle maintenance for keywords "motorcycle" and "maintenance"
- Suppose keywords for each document are words in title and names of authors
- Document titled "Motorcycle Repair" would not be retrieved since "maintenance" does not occur in title

**Solution**: Make use of synonyms
- Each word can have set of synonyms defined
- Occurrence of word can be replaced by or of all its synonyms (including word itself)
- Query "motorcycle and repair" can be replaced by "motorcycle and (repair or maintenance)"
- This query would find desired document

### Homonyms Problem

Keyword-based queries also suffer from opposite problem: homonyms (single words with multiple meanings)

**Examples**:
- "object" has different meanings as noun and verb
- "table" may refer to dinner table or relational table

**Solution Attempt**:
- Some keyword query systems attempt to disambiguate meaning of words in documents
- When user poses query, find out intended meaning by asking user
- Returned documents are those that use term in intended meaning of user

**Challenge**:
- Disambiguating meanings of words in documents not easy task
- Not many systems implement this idea

### Danger with Synonyms

Danger even with using synonyms to extend queries:
- Synonyms may themselves have different meanings
- Documents that use synonyms with alternative intended meaning would be retrieved
- User left wondering why system thought retrieved document relevant
- If document contains neither keywords user specified nor words whose intended meaning is synonymous with specified keywords

**Recommendation**: Advisable to verify synonyms with user before using them to extend query submitted by user

## 22.5.2 Indexing of Documents

Effective index structure important for efficient processing of queries in information-retrieval system

### Inverted Index

Documents that contain specified keyword can be efficiently located using inverted index
- Maps each keyword Ki to set Si of (identifiers of) documents that contain Ki

To support relevance ranking based on proximity of keywords:
- Index may provide not just identifiers of documents
- Also list of locations in document where keyword appears

Since indices must be stored on disk:
- Index organization attempts to minimize number of I/O operations to retrieve set of document identifiers that contain keyword
- System may attempt to keep set of documents for keyword in consecutive disk pages

### Boolean Operations

**AND Operation**:
- Finds documents that contain all of specified set of keywords K1, K2, ..., Kn
- Implement by retrieving sets of document identifiers S1, S2, ..., Sn of all documents containing respective keywords
- Intersection S1 ∩ S2 ∩ ... ∩ Sn gives document identifiers of desired set

**OR Operation**:
- Gives set of all documents that contain at least one of keywords K1, K2, ..., Kn
- Implement by computing union S1 ∪ S2 ∪ ... ∪ Sn

**NOT Operation**:
- Finds documents that do not contain specified keyword Ki
- Given set of document identifiers S, eliminate documents containing specified keyword Ki by taking difference S - Si
- Where Si is set of identifiers of documents containing keyword Ki

### Relaxed AND

Given set of keywords in query, many information retrieval systems do not insist retrieved documents contain all keywords (unless and operation explicitly used)
- All documents containing at least one of words retrieved (as in or operation)
- But ranked by their relevance measure

### Term Frequency for Ranking

To use term frequency for ranking:
- Index structure should additionally maintain number of times terms occur in each document
- To reduce effort, may use compressed representation with only few bits approximating term frequency
- Index should also store document frequency of each term (number of documents in which term appears)

## 22.5.3 Measuring Retrieval Effectiveness

### Compact Representation

Each keyword may be contained in large number of documents
- Compact representation critical to keep space usage of index low
- Sets of documents for keyword maintained in compressed form

### Approximate Retrieval

To save storage space, index sometimes stored such that retrieval is approximate:
- Few relevant documents may not be retrieved (false drop or false negative)
- Few irrelevant documents may be retrieved (false positive)

**Good Index Structure**:
- Will not have any false drops
- May permit few false positives
- System can filter them away later by looking at keywords they actually contain

**Web Indexing**:
- False positives not desirable either since actual document may not be quickly accessible for filtering

### Metrics

Two metrics used to measure how well information-retrieval system able to answer queries:

**Precision**:
- Measures what percentage of retrieved documents are actually relevant to query

**Recall**:
- Measures what percentage of documents relevant to query were retrieved

Ideally both should be 100 percent.

### Precision and Recall for Ranking Strategies

Precision and recall important for understanding how well particular document ranking strategy performs
- Ranking strategies can result in false negatives and false positives in more subtle sense

**False Negatives**:
- May occur when documents ranked because relevant documents get low rankings
- If fetched all documents down to very low ranking, would be very few false negatives
- However, humans rarely look beyond first few tens of returned documents
- May miss relevant documents because not ranked among top few
- What is false negative depends on how many documents examined

**Measuring Recall**:
- Instead of single number as measure of recall, can measure recall as function of number of documents fetched

**False Positives**:
- May occur because irrelevant documents get higher rankings than relevant documents
- Also depends on how many documents examined
- One option: measure precision as function of number of documents fetched

**Better Alternative**:
- Measure precision as function of recall
- With combined measure, both precision and recall can be computed as function of number of documents if required
- Example: With recall of 50 percent, precision was 75 percent; at recall of 75 percent, precision dropped to 60 percent
- Can draw graph relating precision to recall
- Measures can be computed for individual queries, then averaged across suite of queries in query benchmark

### Defining Relevance

Problem with measuring precision and recall: how to define which documents are really relevant and which are not
- Requires understanding of natural language and intent of query to decide if document relevant
- Researchers created collections of documents and queries
- Manually tagged documents as relevant or irrelevant to queries
- Different ranking systems can be run on these collections to measure average precision and recall across multiple queries

## 22.5.4 Web Search Engines

### Web Crawlers

Web crawlers are programs that locate and gather information on Web
- Recursively follow hyperlinks present in known documents to find other documents
- Retrieve documents and add information found in documents to combined index
- Document generally not stored (though some search engines cache copy to give clients faster access)

### Crawling Challenges

Since number of documents on Web very large:
- Not possible to crawl whole Web in short period of time
- All search engines cover only some portions of Web, not all
- Crawlers may take weeks or months to perform single crawl of all pages they cover

### Distributed Crawling

Usually many processes running on multiple machines involved in crawling
- Database stores set of links (or sites) to be crawled
- Assigns links from this set to each crawler process
- New links found during crawl added to database, may be crawled later if not crawled immediately
- Pages found during crawl handed over to indexing system (may be running on different machine)
- Pages have to be refetched periodically to obtain updated information and discard sites that no longer exist
- Keeps information in search index reasonably up to date

### Indexing System

Indexing system itself runs on multiple machines in parallel
- Not good idea to add pages to same index being used for queries (would require concurrency control, affect query and update performance)
- Instead, one copy of index used to answer queries while another copy updated with newly crawled pages
- At periodic intervals, copies switch over (old one updated while new copy used for queries)

### High Query Rates

To support very high query rates:
- Indices may be kept in main memory
- Multiple machines used
- System selectively routes queries to machines to balance load among them

## 22.5.5 Directories

### Library Analogy

Typical library user may use catalog to locate book
- When retrieving book from shelf, likely to browse through other books located nearby
- Libraries organize books so related books kept close together
- Book physically near desired book may be of interest, making it worthwhile to browse

### Classification Hierarchy

To keep related books close together, libraries use classification hierarchy
- Books on science classified together
- Within this set, finer classification: computer-science books together, mathematics books together, etc.
- Since relation between mathematics and computer science, relevant sets of books stored close together physically
- At another level, computer-science books broken down into subareas (operating systems, languages, algorithms)

**Key Point**: Books can be kept at only one place, each book in library classified into exactly one spot in classification hierarchy

### Information Retrieval Directories

In information retrieval system:
- No need to store related documents close together
- Need to organize documents logically to permit browsing
- Could use classification hierarchy similar to libraries
- When displays particular document, can also display brief description of documents close in hierarchy

**Flexibility**:
- No need to keep document in single spot in hierarchy
- Document talking about mathematics for computer scientists could be classified under mathematics as well as under computer science
- At each spot stored only identifier of document (pointer to document)
- Easy to fetch contents by using identifier

**Result of Flexibility**:
- Document can be classified under two locations
- Subarea in classification hierarchy can itself occur under two areas
- Class of "graph algorithm" document can appear both under mathematics and under computer science
- Classification hierarchy now directed acyclic graph (DAG)
- Graph-algorithm document may appear in single location in DAG but can be reached via multiple paths

### Directory Structure

Directory is simply classification DAG structure
- Each leaf of directory stores links to documents on topic represented by leaf
- Internal nodes may also contain links (e.g., to documents that cannot be classified under any of child nodes)

### Using Directories

To find information on topic:
- User starts at root of directory
- Follows paths down DAG until reaching node representing desired topic
- While browsing down directory, user can find:
  - Documents on topic interested in
  - Related documents and related classes in classification hierarchy
- User may learn new information by browsing through documents (or subclasses) within related classes

### Organizing Web Information

Organizing enormous amount of information available on Web into directory structure is daunting task

**Problems**:
1. Determining what exactly directory hierarchy should be
2. Given a document, deciding which nodes of directory are categories relevant to document

**Solutions**:
- Portals like Yahoo have teams of "internet librarians" who come up with classification hierarchy and continually refine it
- Open Directory Project is large collaborative effort with different volunteers responsible for organizing different branches
- Second problem can be tackled manually by librarians
- Web site maintainers may be responsible for deciding where their sites should lie in hierarchy
- Techniques exist for automatically deciding location of documents based on computing their similarity to documents that have already been classified
