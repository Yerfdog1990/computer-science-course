## 5.1. Introduction

The term "combinatorial optimization" encompasses any optimization problem involving binary (or discrete) variables, together with the techniques used to solve such problems. The objective of combinatorial optimization is to choose, from the set of possible configurations for a given problem, the configuration that satisfies all the required conditions while optimizing a given criterion. This criterion is generally represented as a function, known as the cost function or objective function.

There is growing pressure not just to find a solution that satisfies the criteria and is reasonably efficient, but to find the *best possible* solution. This matters most for decision problems in production management, logistics, and telecommunications, where problem size increases rapidly and the financial stakes are high.

In its most general form, a combinatorial (or discrete) optimization problem seeks the best feasible subset from a discrete set, where "best" is defined in terms of an objective function. Formally, given a discrete set N, a set function f mapping subsets of N to the reals (the objective function), and a family of subsets of N called the feasible solutions, the goal is to find the feasible solution that optimizes f.

The set of feasible solutions cannot, in general, be listed exhaustively. The difficulty of combinatorial optimization problems is precisely that the sheer number of feasible solutions makes them impossible to enumerate — and even determining whether a feasible solution exists at all can be an NP-complete problem in its own right. The feasible set is therefore described implicitly, typically as a short list of properties that a solution must satisfy. Two common special cases are:

- N = {1, 2, ..., n}, and the feasible set is the intersection of some family X (a subset of the power set of N, of exponential cardinality with respect to n) with an implicit description;
- the feasible set is the intersection of the convex hull of X with an implicit description, so that the properties defining feasibility translate into linear constraints — that is, the feasible region is a polyhedron.

A non-exhaustive list of classic combinatorial optimization problems includes:

- **Loading (knapsack) problem.** Given a collection of objects, each with a volume and a value, and a bag of limited volume, which objects should we load into the bag to maximize the total value loaded?
- **Traveling salesman problem (TSP).** Given n towns and the distances between them, in what order should we visit every town exactly once so as to minimize the total distance traveled?
- **Covering problem.** Given a set of objects and a collection of subsets of this set, each with a cost, which subsets should we choose so that every object is covered at least once, while minimizing total cost?
- **Vehicle routing problem (VRP).** Given a set of clients that must each be visited exactly once to satisfy a demand, a fleet of capacity-limited delivery vehicles based at a warehouse, and the distances between every pair of clients and between each client and the warehouse, which delivery routes satisfy every client's demand while minimizing total distance traveled?
- **Localization (facility location) problem.** In a simple version: given several possible sites for opening a warehouse (each with an opening cost) that must together serve a set of clients (with costs depending on which warehouse serves which client), how many warehouses should be opened, and where, to minimize total cost?

Combinatorial optimization is increasingly important across operations research and artificial intelligence, and the methods used to solve these problems fall into two broad families:

**Exact (complete, optimal) methods** guarantee an admissible and optimal solution with respect to the objective function — and if no solution exists, they are able to conclude this with certainty. Exact methods generally use tree-based search: they start from an empty solution and construct the optimal one by instantiating variables one at a time, backtracking whenever a constraint is violated. Despite decades of work on expanding search trees more cleverly, detecting inconsistencies earlier, and reducing backtracking with heuristics, exact methods remain exponential in the worst case — they explode as problem size increases.

**Approximate (incomplete, heuristic) methods** were developed to mitigate this combinatorial explosion, at the cost of no longer guaranteeing optimality. Rather than building a solution up piece by piece, they start from a *complete* initial solution (every variable already instantiated) and repair it step by step until a stopping criterion is reached, hoping to converge on a solution that is optimal, or close to it. This is a local, neighborhood-based, or repair-based approach, rather than a constructive one.

This chapter presents two of the best-known combinatorial optimization problems: the traveling salesman problem (TSP) and the vehicle routing problem (VRP).

## 5.2. The Traveling Salesman Problem (TSP)

In practice, it's often desirable for some (or all) of an optimization problem's variables to be integers, or even binary (xⱼ ∈ {0, 1}). Such a problem is called an integer linear program (ILP), or a binary linear program in the fully binary case. One of the most heavily studied problems in this class is the TSP, first posed by Euler in 1736 and later stated in its now-classical form in 1859: a traveling salesman must visit finitely many towns, each exactly once, and then return to his starting point. Find the order of towns that minimizes the total distance traveled.

More concretely: a traveling salesman must visit n given towns, passing through each exactly once, starting at an arbitrary town and ending by returning to it. The distances between towns are known. Which order minimizes the total distance traveled? "Distance" can be replaced by any other cost — time, money, and so on — so in general we simply speak of minimizing total cost.

### 5.2.1. Historical Overview

The exact origin of the name "traveling salesman problem" isn't known, but it is one of the oldest combinatorial problems studied. William Rowan Hamilton turned it into a puzzle — the Icosian game — in which players had to find a route through 20 points using only a fixed set of allowed connections. In 1930, the TSP was studied more rigorously by Karl Menger at Harvard, and was further developed at Princeton by Hassler Whitney and Merrill Flood. A long line of mathematicians has taken up the problem since the early 20th century.

In 1998, Arora showed, building on a proof by Papadimitriou, that the Euclidean TSP is NP-hard — its computational complexity grows exponentially with the number of towns. Dantzig, Fulkerson, and Johnson solved a 49-town instance in 1954 using the cutting-plane method. Padberg and Rinaldi later solved instances with 532 and then 2,392 towns. In 2006, Applegate et al. solved an instance with 85,900 towns using their Concorde program, which uses the branch-and-cut method and has been among the best-performing TSP solvers for the past two decades.

The TSP splits into two broad types: the symmetric TSP (STSP), where the distance from town i to town j equals the distance from j to i, and the asymmetric TSP (ATSP), where these distances may differ. The TSP has many practical applications and underlies problems such as scheduling a school bus's pickup route, or minimizing the travel distance of a mechanical arm punching holes in a circuit board. Numerous variants exist, either by adding constraints (such as the probabilistic TSP) or by generalizing the problem (such as the VRP).

### 5.2.2. Solving Methods

#### 5.2.2.1. Exact Methods

**Branch-and-bound.** This method is based on "intelligently" enumerating the admissible solutions of a combinatorial optimization problem — finding a point that minimizes or maximizes a function subject to constraints — and is widely used for problems considered difficult to solve efficiently by other means.

**Little's algorithm.** When the problem involves binary variables, Little's algorithm can be used to simplify the computation. It is a specialization of branch-and-bound:

```
Algorithm 5.1  Little's algorithm
1: Reduce the matrix (row and column).
2: Select the empty cell that is most expensive to eliminate.
3: The elimination cost is the minimum extra cost incurred if that cell
   is not selected — i.e., if another cell in the same row and another
   cell in the same column are selected instead.
4: Remove the row of the starting town and the column of the
   destination town.
5: Set the return cost to infinity.
6: Restart with the sub-table.
7: Present the algorithm as a tree (branch-and-bound).
8: Consider any path with lower cost than the first final cost found.
9: Follow the tree until it terminates.
```

#### 5.2.2.2. Approximate Methods

- **Greedy algorithm.** Makes a locally optimal choice at each step, hoping this leads to a globally optimal result. For example, in the classic "making change" problem (giving change with the fewest coins), a greedy algorithm always picks the largest coin that doesn't exceed the remaining amount owed. When such an algorithm doesn't always find the true optimum, it's called a greedy heuristic.
- **Descent methods.** Move through the search space by always choosing the best solution among the neighbors of the current one.
- **Simulated annealing.** An empirical metaheuristic inspired by the metallurgical process of alternating slow cooling and heating cycles to minimize a material's internal energy; the same idea is used to search for the extrema of a function.
- **Tabu search.** An optimization metaheuristic that explores the neighborhood of the current position and moves to whichever neighbor best minimizes the objective function, while "tabooing" recently visited states to avoid cycling.
- **Genetic algorithm.** Based on selecting individuals (candidate routes) from a population (a set of routes) whose properties are as close as possible to those desired, according to a selection criterion and rules describing how the population evolves. Genetic algorithms have few theoretical guarantees, so the choice of criteria and rules is itself heuristic.
- **Lin–Kernighan algorithm.** One of the best-performing heuristics for the TSP. It exchanges a number of edges (typically two or three) in a candidate solution to find a route with lower cost.
- **Ant colony algorithms.** A family of metaheuristics based on the collective behavior of ants and other superorganism-forming species. The original algorithm was inspired by ants' ability to find efficient paths between their colony and a food source, and was adapted to find optimal paths in a graph.

## 5.3. Asymmetric Traveling Salesman Problem (ATSP)

The ATSP is defined on a directed graph G = (V, E), where V = {1, ..., n} is the set of nodes and E = {(i, j) : i, j ∈ V} is the set of edges, with an asymmetric cost matrix c (cᵢⱼ need not equal cⱼᵢ) defined over E. Solving the ATSP means finding a minimum-cost Hamiltonian cycle on G — equivalently, the optimal route of a traveling salesman through n towns. The ATSP is NP-hard, even when the costs are Euclidean.

### 5.3.1. Variants of the ATSP

- **Periodic ATSP.** A generalization in which we schedule over a period of k days: we seek k cycles in G such that every node is visited a specified number of times over the k-day period, minimizing total cost across the whole period.
- **ATSP with replenishment arcs (RATSP).** Two parallel edges may exist between the same pair of nodes — an ordinary edge and a (cheaper) replenishment edge. Used, for example, in aircraft routing (where maintenance options are modeled as replenishment arcs) and in the VRP (where customer demand and vehicle capacity can be modeled the same way).
- **Precedence-constrained ATSP (sequential ordering problem, SOP).** Certain nodes must be visited before others on any feasible route. Important in scheduling and routing, including vehicle routing and manufacturing sequencing.
- **ATSP with time windows (ATSP-TW).** A classical scheduling/routing problem where each vertex may only be visited within a specified time window.
- **ATSP with jump constraints (Hamiltonian TSP, HTSP).** Given a subset S of towns subject to a minimum "jump" distance (measured in edges), find the minimum-cost Hamiltonian cycle that respects the distance constraints between towns in S.
- **Probabilistic ATSP with clients.** Each client is visited with some independent probability pᵢ, a stochastic variant of the classical ATSP.

The ATSP has been studied intensively for over six decades, with foundational work by Fischetti et al. and Öncan et al., and is covered in depth in the books by Lawler et al., Reinelt, Gutin and Punnen, and Applegate et al.

### 5.3.2. Mathematical Formulations

Let G = (V, A) be a complete directed graph, where V is the set of towns (including the starting town) and A is the set of edges, each assigned a travel cost. The length of a path is the sum of the costs of its edges, so the TSP reduces to finding a minimum-length Hamiltonian cycle in G.

The natural starting point is to assign each ordered pair of towns (i, j), i ≠ j, a binary variable xᵢⱼ equal to 1 if town j is visited immediately after town i, and 0 otherwise. The basic idea is to begin from an assignment problem (AP): each town i is assigned a successor town j. On its own, though, this formulation is not yet valid, because a feasible assignment doesn't necessarily form a single cycle through all n towns — in general it decomposes into several disjoint sub-cycles ("subtours"). Extending the formulation to rule out subtours can be done in a few different ways; the two classical extensions below were proposed by Dantzig, Fulkerson, and Johnson, and by Miller, Tucker, and Zemlin, respectively. Desrochers and Laporte later strengthened the Miller–Tucker–Zemlin formulation.

#### 5.3.2.1. DFJ (Dantzig–Fulkerson–Johnson) Formulation

Let lᵢⱼ be the cost of edge (i, j), and let xᵢⱼ ∈ {0, 1} equal 1 if edge (i, j) is used and 0 otherwise.

Minimize  Σᵢ Σⱼ lᵢⱼ xᵢⱼ

Subject to
Σⱼ xᵢⱼ = 1, for every town i  (each town has exactly one successor)
Σᵢ xᵢⱼ = 1, for every town j  (each town has exactly one predecessor)
Σᵢ∈S Σⱼ∈S xᵢⱼ ≤ |S| − 1, for every non-empty proper subset S of towns  (subtour elimination)
xᵢⱼ ∈ {0, 1}

The objective function is the total tour cost; the first two constraint families are the assignment constraints (every town is entered once and left once); the third is the subtour elimination family; the last enforces integrality. This formulation is easy to state but grows explosively in practice, since the number of subtour elimination constraints is exponential in the number of towns — this is what makes the DFJ formulation quickly unmanageable as problem size grows.

#### 5.3.2.2. MTZ (Miller–Tucker–Zemlin) Formulation

To avoid the exponential blow-up of DFJ, Miller, Tucker, and Zemlin (1960) introduced an auxiliary variable uᵢ for each town, representing i's position (visiting rank) along the route, and replaced the exponential family of subtour constraints with a single, polynomial-sized family:

Minimize  Σᵢ Σⱼ lᵢⱼ xᵢⱼ

Subject to
Σⱼ xᵢⱼ = 1, for every town i
Σᵢ xᵢⱼ = 1, for every town j
uᵢ − uⱼ + n·xᵢⱼ ≤ n − 1, for all i ≠ j, i, j ≠ 1  (MTZ subtour elimination)
xᵢⱼ ∈ {0, 1}

This formulation has (n − 1) × (n + 1) variables and constraints — far fewer than DFJ — but its linear-programming relaxation is noticeably weaker, meaning it tends to require more branching to close the gap to an integer optimum.

#### 5.3.2.3. Desrochers–Laporte (DL) Formulation

Desrochers and Laporte (1991) tightened the MTZ subtour elimination constraint by adding a term for the reverse edge, giving a stronger (but still polynomial-sized) formulation:

Minimize  Σᵢ Σⱼ lᵢⱼ xᵢⱼ

Subject to
Σⱼ xᵢⱼ = 1, for every town i
Σᵢ xᵢⱼ = 1, for every town j
uᵢ − uⱼ + (n − 1)·xᵢⱼ + (n − 3)·xⱼᵢ ≤ n − 2, for all i ≠ j, i, j ≠ 1  (DL subtour elimination)
xᵢⱼ ∈ {0, 1}

### 5.3.3. Methods for Solving the ATSP

Methods for the ATSP split into exact methods and approximate methods (heuristics and metaheuristics). Exact methods, aimed at finding the true optimum, often have computation times that grow exponentially with problem size and may need to be terminated early — in which case they yield only a lower or upper bound rather than a proven optimum. Approximate methods instead aim to produce high-quality feasible solutions quickly, without guaranteeing optimality; these include constructive heuristics, local search (which produces a sequence of improving solutions until reaching a local optimum), and metaheuristics (which use various mechanisms to escape local optima).

Exact and approximate methods are complementary: a small gap between a lower bound and an upper bound tells us the true optimum is nearby, and a gap of zero proves the solution found is optimal. Because of this, one method is often used to sharpen or validate the other.

Solving an ILP formulation of the ATSP typically calls on dedicated techniques: branch-and-bound, branch-and-cut, column generation, dynamic programming, and Lagrangian relaxation. Broadly, exact algorithms in the literature fall into four families: dynamic programming, constraint programming, implicit enumeration (branch-and-bound), and cutting-plane methods. All of these use bounds to eliminate whole families of solutions from the search without examining them individually.

#### 5.3.3.1. Branch-and-Bound Method

ATSPs are commonly solved to optimality with branch-and-bound applied to a relaxed assignment problem (AP): instead of one single route through every town, an optimal AP solution generally decomposes into several disjoint subtours.

The branch-and-bound algorithm has four components. The **branching rule** decides how to split the current problem into subproblems, requiring a (heuristically chosen) separation variable. The **pathing strategy** decides which subproblem to examine next; the two classic strategies are depth-first search (DFS, which explores the most recently generated subproblem first) and breadth-first search (BFS, which explores whichever subproblem currently looks most promising — typically the one with the lowest AP bound). The **upper bound strategy** determines how a feasible route is constructed from an AP solution — commonly via a "readjustment" procedure that patches together the AP's disjoint subtours into a single tour. The **lower bound strategy** determines the bound associated with a subproblem, typically taken directly from the value of its AP relaxation.

The best-known algorithms in this space (Miller, Carpaneto, and others) apply readjustment to obtain upper bounds from AP lower bounds, branching on the smallest cycle in the current AP solution, using a BFS ("best subproblem first") pathing strategy. BFS reaches good solutions quickly for many real instances, but requires maintaining a list of all live subproblems, which can create memory pressure as the search tree grows. Turkensteen (2007) improved the upper-bound quality of these algorithms with an *iterative* readjustment procedure, which also reduces the number of subproblems generated (and hence total computation time).

```
Algorithm 5.2  Branch-and-bound algorithm
1: Start
2: Add the starting node (length 0) to a list.
3: Repeat
4:     If the first branch contains the desired node then
5:         End successfully.
6:     Else
7:         Delete the branch from the list and form new branches by
            extending the deleted branch by one step.
8:         Compute the cumulative costs of the new branches and add
            them to the list, sorted by increasing cost.
9: Until (list is empty or the desired node has been found)
10: End
```

#### 5.3.3.2. Cutting-Plane Method

The cutting-plane method is an alternative to branch-and-bound for integer problems: it repeatedly adds constraints ("cuts") to a linear relaxation until the optimal LP solution happens to be integer-valued. Every cut added, relative to the current (non-integer) partial solution, must satisfy two criteria: (1) every integer-feasible solution remains feasible under the cut, and (2) the current, non-integer partial solution becomes infeasible under the cut.

There are various ways to generate cuts. Gomory cuts can be derived mechanically from any linear program's simplex tableau — broadly applicable, but often slow to converge. Alternatively, cuts can be derived from the specific structure of the problem, which requires case-by-case analysis but tends to produce much stronger, more effective cuts.

#### 5.3.3.3. Branch-and-Cut Method

Padberg and Rinaldi extended branch-and-bound for linear programming by describing a method — branch-and-cut — that uses valid inequalities (derived from the convex hull of the integer solutions) to strengthen the LP relaxation at each node. Many modern solvers use this approach.

Branch-and-cut requires transforming the optimization problem into an integer LP; it may be difficult or impossible in general to enumerate every valid inequality (even restricting to those describing the convex hull of the optimal region), but the real-valued LP relaxation is always easier to solve than the integer problem, and branch-and-cut exploits this to accelerate the search. Rather than branching on a variable immediately, the algorithm first looks for cutting planes to shrink the feasible region:

At the start, we solve a relaxed LP using only a small initial subset of the problem's constraints. If the optimal solution to this relaxation is already integer-valued, we're done (updating the best-known solution if needed). If it isn't, we run a separation algorithm and/or heuristics to look for violated inequalities. If none are found, we search directly for an integer solution at that cost; otherwise, we add the violated inequalities and re-solve. The aim throughout is to "intelligently" exclude the current non-integer optimum from the feasible region using cuts, rather than by branching, whenever possible; if the subproblem turns out to have no feasible solution at all, that branch is pruned.

Cutting planes can be generated from a linear combination of the LP's own inequalities (e.g., via Dantzig's simplex algorithm), or in a way specific to the problem at hand. Only when no useful cut can be found, and the subproblem can't be pruned on bound alone, do we resort to branching — splitting the subproblem with a hyperplane chosen so the current (fractional) optimum is infeasible in every resulting child. For example, if the optimal relaxed value of xᵢ is 2.7, we can branch into one subproblem with the added constraint xᵢ ≤ 2 and another with xᵢ ≥ 3.

```
Algorithm 5.3  Branch-and-cut algorithm

  We want to solve the combinatorial optimization problem:
     min { cᵀx : Ax ≥ b, x ∈ Zⁿ },  A ∈ R^(m×n), b ∈ R^m

  List-of-problems = empty
  Initialize the linear program with a small subsystem of constraints
    (A1, b1), A1 ∈ R^(m1×n), m1 ≪ m

  /* Evaluation step */
  Compute the optimal solution x of the current linear program.
  Current-solution = Apply-the-method-of-polyhedral-cuts()
  /* End evaluation step */

  If Current-solution is feasible (integer) then
      x* = Current-solution is the optimal solution of the original problem.
  Else
      Add the problem to List-of-problems.
  End If

  While List-of-problems is not empty do
      Select a problem.
      Branch the problem into two or more subproblems.
      Solve the new subproblems (by re-applying the evaluation step).
  End While
```

## 5.4. Vehicle Routing Problem (VRP)

### 5.4.1. Definition

The general problem of constructing vehicle routes is the VRP — a multi-objective combinatorial optimization problem, widely studied with many variants. It was introduced by Dantzig and Ramser under the name "truck dispatching problem," and belongs to the class of NP-hard problems.

The VRP works as follows: given a warehouse D and a set of customer orders C = {c₁, ..., cₙ}, construct a set of routes for finitely many vehicles that each start and end at the warehouse, such that every customer is served by exactly one vehicle and no vehicle's transportation capacity is exceeded on its route. The objective is to minimize the total distance traveled (or total travel time) across all routes, while satisfying every customer's demand.

### 5.4.2. Fields of Application

Every industrial company wants to improve its logistics efficiency, both to reduce the cost of producing goods or services and to deliver products smoothly — and the VRP is a key part of that logistics chain. With the sharp rise in energy costs, transportation now accounts for roughly 30% of the cost of producing a typical good or service.

The VRP touches everyday life in many forms: picking up schoolchildren, picking up employees, collecting household waste, harvesting raw milk, and distributing newspapers, mail, and food products such as milk, bread, and water. Ambulance services and urgent pharmaceutical distribution are further examples — in these last two, clients are served according to priority and urgency, and the objective shifts from minimizing total distance to serving as many clients as possible within a given time frame. All of these problems are time-constrained, though collection problems tend to have stricter time constraints than distribution problems.

Information technology and robotics are also heavy users of VRP techniques — routing information through remote computer networks is fundamentally a VRP — as is aircraft scheduling. Despite decades of interest, large-scale VRP instances remain difficult, sometimes practically impossible, to solve exactly with any amount of computing power.

### 5.4.3. Parameters of the VRP

The VRP is characterized by its network, its clientele, its vehicle fleet, and its objective function:

- **Network.** The transportation network carries the flow of people, freight, or information, and can be represented as a complete symmetric or asymmetric graph. Vertices represent clients (characterized by their geographic coordinates), and edges represent the paths between them; with certain constraints, this graph can be directed.
- **Clientele.** Each client has a demand for one or more types of goods or services; the total demand along any single route must not exceed the vehicle's capacity Q. Demand may be deterministic (a known, fixed quantity) or stochastic (uncertain).
- **Fleet of vehicles.** The fleet is characterized first by its size (number of vehicles), and second by whether it is homogeneous (all vehicles share the same capacity and cost) or heterogeneous (vehicles differ in capacity and/or cost).
- **Objective function.** The most common objectives are minimizing the number of vehicles used and minimizing total distance traveled. Others include minimizing total route time (including waiting, delay, and service time), minimizing total cost (fixed costs such as equipment amortization and driver salaries, or variable costs such as late penalties), maximizing service quality, and maximizing vehicle loading.

### 5.4.4. Variants of the VRP

Many variants arise from adding, removing, or combining constraints of the classical VRP:

- **VRPC (VRP with capacities).** Vehicles have limited capacity (quantity, volume, or weight); the sum of client demands on a route must not exceed it. In practice, every VRP has some capacity limitation — only the extent of its influence varies (goods transportation is very sensitive to capacity; mail distribution is much less so).
- **VRPCC (VRP with complete capacity).** Requires each vehicle's capacity to be fully utilized on its route.
- **VRPHF (VRP with heterogeneous fleet).** The fleet contains vehicles of different types, differing in capacity, power, or cost.
- **OVRP (open VRP).** Identical to the VRP, except the vehicle is free to choose whether to return to the warehouse after its route; if it does return, it must retrace the same route in reverse.
- **RVRP (return VRP).** The vehicle must return to the warehouse immediately after serving its last client, without repeating its route.
- **VRP with deterministic demand.** Common for companies delivering on request, where the quantity to deliver to each client is known before leaving the warehouse.
- **VRP with stochastic demand.** The quantity to deliver isn't known until the moment of delivery; each client's demand is instead estimated with a stochastic function.
- **SVRP (split delivery VRP).** Clients may be visited more than once to fully satisfy their demand — uniquely, a single client's demand may even exceed the vehicle's capacity.
- **VRPCD (VRP with collection and delivery).** Extends the VRP to both pickup and delivery; service time at a stop is counted twice, once for each operation.
- **VRPMW (VRP with multiple warehouses).** Vehicles may be supplied from more than one warehouse.
- **VRP1W.** Vehicles are supplied from a single warehouse.
- **VRPMP (VRP with multiple products).** Each vehicle delivers a range of different products to its clients on a single route.
- **VRP (single product).** Each vehicle delivers just one product type to its clients on a single route.
- **PVRP (periodic VRP).** Each client is visited periodically according to a predefined schedule.
- **VRP with deterministic service time.** The delivery driver knows each client's service time in advance.
- **VRP with stochastic service time.** Service time is unknown until the client is actually served, and is instead approximated by a stochastic function.
- **VRP-TW (VRP with time windows).** Each client must be served within a specific, known time window; violating it may incur a penalty. In the *rigid* version, a violated time window makes the solution infeasible; in the *relaxed* version, a penalty function is added to the objective instead. Distribution of perishables (milk, meat), newspapers, and ambulance services are common real-world examples.
- **Static VRP.** Every component of the problem is known and fixed before any route begins.
- **Dynamic VRP.** At least one component (demand, service time window, number of clients, etc.) can change during execution, making the problem substantially harder.
- **SVRP (stochastic VRP).** A special case of the dynamic VRP where the variable component follows a known probabilistic law, which makes it more tractable than the fully dynamic case.

### 5.4.5. Mathematical Formulation of the VRP

The VRP is represented as a directed graph G = (X, U), where X is the set of vertices (clients and warehouse(s)) and U is the set of edges (the paths between clients, and between clients and warehouses). Weights can be assigned to vertices (e.g., client demand) or edges (e.g., distance or travel time).

Relevant parameters include: n (number of clients), m (number of vehicles, m ≤ n), Qₖ (capacity of vehicle k), Tₖ (maximum route duration for vehicle k), qⱼ (demand of client j, with q₀ = 0 at the warehouse), sⱼₖ (service time for client j by vehicle k, with s₀ₖ = 0), tᵢⱼ (travel time from client i to client j), dᵢⱼ (distance from i to j), and cᵢⱼ (cost of moving from i to j).

Using a three-index binary decision variable xᵢⱼₖ, equal to 1 if vehicle k travels directly from client i to client j and 0 otherwise, the classical VRP (following the formulation used by Laporte, Toth and Vigo, and Crainic and Semet) can be written as:

Minimize  Σₖ Σᵢ Σⱼ cᵢⱼ xᵢⱼₖ

Subject to
Σₖ Σⱼ xᵢⱼₖ = 1, for every client i  (each client is entered exactly once, by exactly one vehicle)
Σₖ Σⱼ xⱼᵢₖ = 1, for every client i  (each client is left exactly once, by exactly one vehicle)
Σⱼ xᵢⱼₖ − Σⱼ xⱼᵢₖ = 0, for every client i and every vehicle k  (route continuity: whichever vehicle enters a client must also be the one that leaves it)
Σᵢ Σⱼ qᵢ xᵢⱼₖ ≤ Qₖ, for every vehicle k  (vehicle capacity is not exceeded)
Σᵢ Σⱼ tᵢⱼ xᵢⱼₖ + Σᵢ sᵢₖ ≤ Tₖ, for every vehicle k  (total route duration does not exceed the vehicle's maximum)
Σⱼ x₀ⱼₖ ≤ 1 and Σᵢ xᵢ₀ₖ ≤ 1, for every vehicle k  (each vehicle leaves and returns to the warehouse at most once)
subtour elimination constraints, for every proper subset of clients
xᵢⱼₖ ∈ {0, 1}

The objective minimizes total routing cost. The first pair of constraints ensures each client is served exactly once; the continuity constraint ensures a vehicle that arrives at a client must also depart from it; the capacity and duration constraints bound each vehicle's route; the depot constraints ensure vehicle availability is respected (each vehicle leaves and returns to the warehouse at most once); and the final family eliminates subtours that don't pass through the warehouse.

### 5.4.6. Algorithmic Complexity

Evaluating a problem's complexity means estimating the number of instructions needed, in the worst case, to solve any instance of it — the more instructions required, the more complex the problem, and the less efficient a given algorithm is at solving it. Common complexity classes include constant O(1), logarithmic O(ln n), linear O(n), quadratic O(n²), cubic O(n³), polynomial O(nᵖ), exponential, and factorial O(n!) complexity.

Complexity lets us distinguish between four broad classes of problems:

- **P class.** Problems solvable in polynomial time by a Turing machine — the class of "easy," tractable problems.
- **P-complete class.** Polynomial and certain non-polynomial problems that can be reduced to one another in poly-logarithmic time.
- **NP class.** Problems whose *proposed solutions* can be verified in polynomial time (loosely: problems solvable in polynomial time on a non-deterministic machine).
- **NP-hard class.** Problems whose worst-case complexity is exponential or worse, making exact, optimal solutions for large instances impractical; instead, we typically settle for high-quality solutions found in polynomial time. Tree partitioning and graph connectedness problems fall into this class, among many others.

The VRP is a routing problem, and Lenstra and Rinnooy Kan showed that it is NP-hard. Consequently, exact methods aren't practical for large VRP instances — instead, we rely on heuristic approaches that produce good, feasible solutions in a reasonable amount of time.

## 5.5. Selective Routing Problem

Rising energy costs have sharpened the transportation sector's interest in problems like this one: to control transportation costs, companies constantly look to streamline their logistics systems, of which vehicle routing is one of the most important components.

The selective vehicle routing problem (SVRP) is a variant of the VRP, and belongs to a broader class of problems known as vehicle routing problems with profits (VRPPs). Rather than just minimizing route length, VRPPs try to construct one or more routes that maximize the total profit collected from clients while minimizing route length — making them inherently dual-objective problems.

### 5.5.1. Problems Similar to the VRP

Three related problem classes fall under this umbrella:

- **Selective traveling salesman problem (STSP).** Find a route that maximizes total profit, subject to an upper bound on the route's cost.
- **Prize-collecting traveling salesman problem (PCTSP).** Find a minimum-cost route, subject to a lower bound on total profit collected.
- **Profitable tour problem (PTP).** Find a route that optimizes a linear combination of the two objectives above.

Here, "cost" of a route is usually just its total duration or length — the sum of the travel times or lengths of its edges. A closely related, well-known problem is the **orienteering problem (OP)**.

### 5.5.2. Mathematical Formulation

The STSP first appears (implicitly) in work on a periodic vehicle-routing problem that accounts for stock, where a fleet of vehicles must deliver fuel daily to many clients, and profit measures urgency. A related problem, the OP, appeared shortly after, inspired by an outdoor sport in mountainous or forested terrain: competitors, given a map, race from a starting point to a destination within a fixed time, passing through checkpoints that each award a score, trying to maximize their total score. The STSP is a special case of the OP where the starting point and destination coincide. Later work generalized the OP to include time windows on checkpoints, and to teams of multiple competitors.

Like the OP and PTP, the STSP is NP-complete, being a generalization of the (also NP-complete) TSP.

Let G = (N, A) be a complete graph, where N = {1, ..., n} is the set of vertices, vertex 1 is the warehouse/starting point, and A is the set of edges. Each vertex i ∈ N (other than the warehouse) has a profit gᵢ (with g₁ = 0), and each edge (i, j) ∈ A has a cost cᵢⱼ (typically its length). The STSP asks for an elementary cycle, containing vertex 1, that maximizes total profit subject to a maximum total cost Cₘₐₓ.

Using a binary variable xᵢⱼ (1 if edge (i, j) is used, 0 otherwise) and a binary variable yᵢ (1 if vertex i is visited, 0 otherwise), the STSP can be formulated as:

Maximize  Σᵢ gᵢ yᵢ

Subject to
Σⱼ xᵢⱼ = yᵢ, for every vertex i  (i is entered if and only if it is visited)
Σⱼ xⱼᵢ = yᵢ, for every vertex i  (i is left if and only if it is visited)
y₁ = 1  (the warehouse is always visited)
Σᵢ Σⱼ cᵢⱼ xᵢⱼ ≤ Cₘₐₓ  (total route cost stays within budget)
subtour elimination constraints
xᵢⱼ, yᵢ ∈ {0, 1}

The two assignment-style constraints tie a vertex's in/out degree to whether it's actually visited, and the cost constraint caps the total route cost at Cₘₐₓ. The STSP can be solved with heuristics, metaheuristics, or exact methods, in the same spirit as the TSP and VRP.
