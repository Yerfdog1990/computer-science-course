# Asymptotic Notations

## 1. What Is Asymptotic Analysis?

**Asymptotic analysis** measures algorithm efficiency independent of machine-specific factors like processor speed, memory, or programming language. Rather than timing an algorithm on a single computer, it describes how an algorithm's running time **grows** as the input size increases — giving a universal way to compare algorithms without fully implementing them.

---

## 2. The Three Asymptotic Notations

| Notation | Case | Bound |
|---|---|---|
| **Big O** | Worst case | Upper bound |
| **Omega (Ω)** | Best case | Lower bound |
| **Theta (Θ)** | Average case | Tight bound |

These notations use `n` to represent input size, and describe how the running time function `f(n)` relates to a simpler comparison function `g(n)` for large values of `n`.

---

## 3. Theta Notation: Θ (Tight Bound)

### Definition

Theta notation represents a **tight bound** — `f(n)` is sandwiched between a lower and an upper scaling of `g(n)`.

We write:

```
f(n) = Θ(g(n))
```

if and only if there exist positive constants c₁, c₂, and n₀ such that:

```
c₁ · g(n) ≤ f(n) ≤ c₂ · g(n)    for all n ≥ n₀
```

### The Sandwich Effect

```
c₂ · g(n)   ← upper scaling
    ↑
  f(n)       ← actual running time (must stay between)
    ↓
c₁ · g(n)   ← lower scaling
```

`f(n)` is "sandwiched" between the two bounds, so `g(n)` gives a tight description of the growth rate.

### Why Theta Is Useful

| Notation | What It Tells You |
|---|---|
| Big O | Function grows **no faster** than g(n) |
| Omega | Function grows **at least as fast** as g(n) |
| **Theta** | Function grows **at the same rate** as g(n) |

Theta combines both Big O and Omega into one statement. It is the most precise asymptotic description.

A function satisfies `f(n) = Θ(g(n))` **if and only if** both hold:

- `f(n) = O(g(n))`  (upper bound)
- `f(n) = Ω(g(n))`  (lower bound)

---

### Worked Example: Prove f(n) = Θ(n³)

**Given:** `f(n) = n³ + 3n²`

**Step 1 — Identify the dominant term:**

The dominant term is `n³`, so `g(n) = n³`.

**Step 2 — Prove the upper bound:**

Choose `c₂ = 2`. Then we need:

```
n³ + 3n² ≤ 2n³
```

This holds for all `n ≥ 3`. Therefore `f(n) = O(n³)`.

**Step 3 — Prove the lower bound:**

Choose `c₁ = 1`. Then we need:

```
n³ + 3n² ≥ n³
```

This holds for all `n ≥ 1`. Therefore `f(n) = Ω(n³)`.

**Conclusion:**

Both bounds hold with `n₀ = 3`. Therefore:

```
n³ + 3n² = Θ(n³)
```

---

## 4. Big O Notation (Upper Bound)

### Definition

Big O represents the **worst-case upper bound** on an algorithm's growth.

We write:

```
f(n) = O(g(n))
```

if and only if there exist positive constants `c` and `n₀` such that:

```
f(n) ≤ c · g(n)    for all n ≥ n₀
```

### Why Growth Rate Matters

Comparing algorithms by running time on a single input can be misleading. For large inputs, an algorithm with a smaller growth rate will always outperform one with a larger growth rate — regardless of hardware.

For example, Binary Search may only be a few times faster than Linear Search on a small list, but the gap becomes enormous as n grows.

### Why Operations, Not Seconds

Big O measures the **number of operations** as a function of `n`, not execution time in seconds. This removes the dependency on processor speed, memory, compiler, and language.

### Meaning of the Constants

| Constant | Role |
|---|---|
| `c` | Scales `g(n)` so it becomes a valid upper bound for `f(n)` |
| `n₀` | The threshold past which the inequality always holds |

### Three-Step Method for Finding Big O

**Step 1 — Identify the dominant term** (the one that grows fastest):

| f(n) | Dominant Term |
|---|---|
| 3n + 8 | n |
| n² + 10 | n² |
| 2n³ − 2n² | n³ |
| 2ⁿ + 3n³ | 2ⁿ |

**Step 2 — Choose g(n)** as the simplest version of the dominant term.

**Step 3 — Apply the definition:** find constants `c` and `n₀` such that `f(n) ≤ c · g(n)` for all `n ≥ n₀`.

### Big O Examples

| Function f(n) | g(n) | c | n₀ | Result |
|---|---|---|---|---|
| 3n + 8 | n | 4 | 8 | O(n) |
| n² + 10 | n² | 2 | 4 | O(n²) |
| 2n³ − 2n² | n³ | 2 | 1 | O(n³) |
| 2ⁿ + 3n³ | 2ⁿ | — | — | O(2ⁿ) |
| 300 | 1 | — | — | O(1) |

The last example (`300 = O(1)`) is called **constant time complexity**.

### Important Big O Rules

**Rule 1 — Ignore constants:**
`5n + 50` → `O(n)`

Constants do not affect the long-term growth rate.

**Rule 2 — Ignore lower-order terms:**
`n² + 100n + 10` → `O(n²)`

For large `n`, the `n²` term completely dominates the rest.

**Rule 3 — Use the tightest upper bound:**
For `3n + 8`, both `O(n)` and `O(n²)` are technically valid, but `O(n)` is preferred because it is the most accurate description.

---

### Common Growth Rates

| Notation | Name | Example |
|---|---|---|
| O(log n) | Logarithmic | Binary Search |
| O(n) | Linear | Linear Search |
| O(n log n) | Linearithmic | Merge Sort, Quick Sort |
| O(n²) | Quadratic | Selection Sort |
| O(n!) | Factorial | Traveling Salesman (Brute Force) |

**Efficiency hierarchy** (best to worst scaling):

```
O(log n) < O(n) < O(n log n) < O(n²) < O(n!)
```

### Growth Comparison Table

| Input Size (n) | O(log n) | O(n) | O(n log n) | O(n²) | O(n!) |
|---|---|---|---|---|---|
| 10 | 1 | 10 | 10 | 100 | 3,628,800 |
| 20 | ~1.3 | 20 | 26 | 400 | 2.43 × 10¹⁸ |
| 100 | 2 | 100 | 200 | 10,000 | Astronomically large |

## 5. Omega Notation: Ω (Lower Bound)

### Definition

Omega notation represents the **best-case lower bound** on an algorithm's growth.

```
T(n) = minimum time of algorithm on any input of size n
```

In other words, it describes a slow algorithm that happens to work fast on some particular input.

We write:

```
f(n) = Ω(g(n))
```

if and only if there exist positive constants `c` and `n₀` such that:

```
f(n) ≥ c · g(n)    for all n ≥ n₀
```

### Big O vs. Omega

| Notation | Inequality | Meaning |
|---|---|---|
| O(g(n)) | f(n) ≤ c · g(n) | Upper bound — grows no faster than g(n) |
| Ω(g(n)) | f(n) ≥ c · g(n) | Lower bound — grows at least as fast as g(n) |

### Choosing the Tightest Lower Bound

A function can have many valid lower bounds. For example, `10n² + 5` satisfies:

- `Ω(1)`
- `Ω(n)`
- `Ω(n²)`

All are technically correct, but **`Ω(n²)` is preferred** as the tightest and most informative.

### Worked Example: Prove f(n) = Ω(n²)

**Given:** `f(n) = 10n² + 5`

**Step 1 — Dominant term:** `10n²`, so `g(n) = n²`.

**Step 2 — Apply the definition:** Choose `c = 10`. We need:

```
10n² + 5 ≥ 10n²    (always true for n ≥ 1)
```

**Conclusion:**

```
10n² + 5 = Ω(n²)    for c = 10, n₀ = 1
```

---

## 6. Relationship Between O, Ω, and Θ

| Notation | Bound | Mathematical Condition |
|---|---|---|
| O(g(n)) | Upper | f(n) ≤ c · g(n) |
| Ω(g(n)) | Lower | f(n) ≥ c · g(n) |
| Θ(g(n)) | Tight | c₁ · g(n) ≤ f(n) ≤ c₂ · g(n) |

A Theta bound exists only when both O and Ω bounds hold for the **same** `g(n)`:

```
f(n) = Θ(g(n))   ⟺   f(n) = O(g(n))  AND  f(n) = Ω(g(n))
```

---

## 7. How to Choose g(n)

Always choose `g(n)` as the **highest-degree term** of `f(n)`, dropping all coefficients and lower-order terms.

| f(n) | g(n) | Reason |
|---|---|---|
| 2n + 5 | n | Highest degree is 1 |
| 10n² + 4n + 2 | n² | Highest degree is 2 |
| 5n³ − 3n + 7 | n³ | Highest degree is 3 |

For large values of `n`, lower-degree terms and constants become negligible.

---

## 8. Worked Examples

### Example 1: f(n) = 2n + 5

**g(n) = n**

**Big O (Upper Bound)** — choose `c = 3`:

```
2n + 5 ≤ 3n
```

| n | 2n + 5 | 3n | Holds? |
|---|---|---|---|
| 1 | 7 | 3 | ✗ |
| 3 | 11 | 9 | ✗ |
| 5 | 15 | 15 | ✓ |

```
2n + 5 = O(n)    for c = 3, n₀ = 5
```

**Omega (Lower Bound)** — choose `c = 2`:

```
2n + 5 ≥ 2n    (always true for n ≥ 1)
```

```
2n + 5 = Ω(n)    for c = 2, n₀ = 1
```

**Theta (Tight Bound)** — choose `c₁ = 2, c₂ = 3`:

```
2n ≤ 2n + 5 ≤ 3n    holds for n ≥ 5
```

```
2n + 5 = Θ(n)    for c₁ = 2, c₂ = 3, n₀ = 5
```

---

### Example 2: f(n) = 3n + 2

**g(n) = n**

```
3n + 2 = O(n)    for c = 4, n₀ = 2
3n + 2 = Ω(n)    for c = 3, n₀ = 1
3n + 2 = Θ(n)    for c₁ = 3, c₂ = 4, n₀ = 2
```

---

### Example 3: f(n) = 3n + 3

**g(n) = n**

```
3n + 3 = O(n)    for c = 4, n₀ = 3
3n + 3 = Ω(n)    for c = 3, n₀ = 1
3n + 3 = Θ(n)    for c₁ = 3, c₂ = 4, n₀ = 3
```

---

### Example 4: f(n) = 10n² + 4n + 2

**g(n) = n²**

The highest degree term is `n²`, so lower terms like `4n` and `2` are ignored for large `n`.

| Bound | Constants | Result |
|---|---|---|
| Upper (O) | c = 11, n₀ = 5 | `10n² + 4n + 2 = O(n²)` |
| Lower (Ω) | c = 10, n₀ = 1 | `10n² + 4n + 2 = Ω(n²)` |
| Tight (Θ) | c₁ = 10, c₂ = 11, n₀ = 5 | `10n² + 4n + 2 = Θ(n²)` |

## 9. Time Complexity

**Time complexity** describes how the running time of an algorithm scales with input size `n` — it is **not** an exact measurement in seconds.

For example, an algorithm may be fast for `n = 7`, but the meaningful question is what happens at `n = 1,000,003`. Asymptotic notation answers that question precisely.

---

## 10. Case Study: Prime Number Checking

A **prime number** is any integer greater than 1 that cannot be divided evenly by any number other than 1 and itself.

---

### Algorithm 1 — Check divisors from 2 to n − 1

```java
public static boolean isPrimeLinear(int n) {
    if (n <= 1) return false;
    for (int i = 2; i <= n - 1; i++) {
        if (n % i == 0) return false;
    }
    return true;
}
```

#### How the Loop Count Is Derived

The loop starts at `i = 2` and ends at `i = n − 1`. To count how many integers fall in an inclusive range, use:

```
count = last − first + 1
      = (n − 1) − 2 + 1
      = n − 2
```

The **+1** exists because both the first and last values are included in the range. Without it:

```
(n − 1) − 2 = n − 3    ← incorrect, misses one iteration
```

| n | Loop range | Count                     |
|---|---|---------------------------|
| 7 | 2, 3, 4, 5, 6 | (6 − 2 + 1) = 5 = 7 − 2   |
| 11 | 2, 3, ..., 10 | (10 − 2 + 1) = 9 = 11 − 2 |
| 101 | 2, 3, ..., 100 | (100 − 2 + 1) = 99 = 101 − 2 |

> **Note:** The line `if (n <= 1) return false` is a guard clause that rejects invalid inputs (0, 1, negatives) before the loop starts. It has no connection to the +1 in the counting formula.

#### Why Is This O(n)?

The exact count is `n − 2`. For very large `n`, the `−2` becomes insignificant:

```
n       = 1,000,000
n − 2   =   999,998
```

Almost identical. Therefore: `n − 2 = O(n)`

Assuming 1 ms per division operation:

| Input n | Iterations | Approximate Work |
|---|---|---|
| 7 | 5 | 5 ms |
| 11 | 9 | 9 ms |
| 101 | 99 | 99 ms |
| 1,000,003 | ~10⁶ | ~10⁶ ms |

```
Algorithm 1 = O(n)
```

---

#### Step-by-Step Trace: Algorithm 1

**n = 10 (not prime)**

Step 1 — Guard clause: `10 <= 1` → False. Continue.

Step 2 — Loop range: `for (int i = 2; i <= 9; i++)`

| Iteration | i | Check | Result |
|---|---|---|---|
| 1 | 2 | 10 % 2 = 0 | Divisible → return false |

The algorithm stops immediately at `i = 2`. It never checks 3, 4, 5, 6, 7, 8, or 9.

```
10 → Try 2 → 10 ÷ 2 = 5, remainder = 0 → Not Prime. Stop.

```

---

**n = 7 (prime)**

Step 1 — Guard clause: `7 <= 1` → False. Continue.

Step 2 — Loop range: `for (int i = 2; i <= 6; i++)`

| Iteration | i | Check | Result |
|---|---|---|---|
| 1 | 2 | 7 % 2 = 1 | Not divisible |
| 2 | 3 | 7 % 3 = 1 | Not divisible |
| 3 | 4 | 7 % 4 = 3 | Not divisible |
| 4 | 5 | 7 % 5 = 2 | Not divisible |
| 5 | 6 | 7 % 6 = 1 | Not divisible |

No divisor found. Loop finishes → `return true`

```
7 → Try 2 ✗ → Try 3 ✗ → Try 4 ✗ → Try 5 ✗ → Try 6 ✗ → Prime
```

All 5 possible divisors were checked.

---

### Algorithm 2 — Check divisors from 2 to √n

```java
public static boolean isPrimeSquareRoot(int n) {
    if (n <= 1) return false;
    for (int i = 2; i <= Math.sqrt(n); i++) {
        if (n % i == 0) return false;
    }
    return true;
}
```

#### How the Loop Count Is Derived

The loop starts at `i = 2` and ends at `i = √n`. Applying the same counting formula:

```
count = last − first + 1
      = √n − 2 + 1
      = √n − 1
```

Therefore the loop runs approximately `√n − 1` times.

| Input n | √n (approx.) | Iterations |
|---|---|---|
| 7 | √7 ≈ 2.6 → 2 | 2 − 1 = 1 |
| 11 | √11 ≈ 3.3 → 3 | 3 − 1 = 2 |
| 101 | √101 ≈ 10 | 10 − 2 + 1 = 9 |
| 1,000,003 | √1,000,003 ≈ 1,000 | ~999 |

Assuming 1 ms per division:

| Input n | √n (approx.) | Approximate Work |
|---|---|---|
| 7 | 2 | 1 ms |
| 11 | 3 | 2 ms |
| 101 | 10 | 9 ms |
| 1,000,003 | ~1,000 | ~10³ ms |

```
Algorithm 2 = O(√n)
```

---

#### Why Can We Stop at √n?

Suppose `n` is composite, meaning `n = a × b`.

If **both** `a` and `b` were greater than `√n`, then:

```
a × b  >  √n × √n  =  n
```

But `a × b = n`, so this is a contradiction. Therefore, **at least one factor must be ≤ √n**.

This means: if no divisor is found up to `√n`, no divisor exists beyond it either, and `n` is prime.

**Example: n = 100**

| Factor pair | Both ≤ √100 = 10? |
|---|---|
| 1 × 100 | 1 ≤ 10 ✓ |
| 2 × 50 | 2 ≤ 10 ✓ |
| 4 × 25 | 4 ≤ 10 ✓ |
| 5 × 20 | 5 ≤ 10 ✓ |
| 10 × 10 | 10 ≤ 10 ✓ |

After the pair `10 × 10`, every subsequent pair is just the reverse of a previous one (`20 × 5`, `25 × 4`, etc.). Checking beyond 10 reveals no new information.

**Example: n = 10**

Factor pairs: `1 × 10` and `2 × 5`. Since `√10 ≈ 3.16`, finding that `2` divides `10` is enough — there is no need to separately check `5`.

---

#### Step-by-Step Trace: Algorithm 2

**n = 10 (not prime)**

Step 1 — Guard clause: `10 <= 1` → False. Continue.

Step 2 — `√10 ≈ 3.16`, so loop checks `i = 2` and `i = 3`.

| Iteration | i | Check | Result |
|---|---|---|---|
| 1 | 2 | 10 % 2 = 0 | Divisible → return false |

Stops at `i = 2`. Never checks 3, 4, 5, 6, 7, 8, or 9.

```
√10 ≈ 3 → Check 2, 3 only
2 divides 10 → Not Prime. Stop.
```

---

**n = 7 (prime)**

Step 1 — Guard clause: `7 <= 1` → False. Continue.

Step 2 — `√7 ≈ 2.64`, so the loop only checks `i = 2` (since `3 > 2.64`).

| Iteration | i | Check | Result |
|---|---|---|---|
| 1 | 2 | 7 % 2 = 1 | Not divisible |

Loop ends → `return true`

```
√7 ≈ 2.64 → Check only: 2 ✗ → Prime
```

Algorithm 1 checked 2, 3, 4, 5, 6. Algorithm 2 checked only 2.

---

### Growth Rate Comparison

| n | Algorithm 1 (loops) | Algorithm 2 (loops) |
|---|---|---|
| 100 | 98 | 9 |
| 10,000 | 9,998 | 99 |
| 1,000,000 | 999,998 | 999 |

- Algorithm 1 grows proportional to `n`
- Algorithm 2 grows proportional to `√n`

Since `√n ≪ n` for large `n`, `O(√n)` is significantly more efficient than `O(n)`. This is why the square-root optimization is one of the first classic examples used when teaching time complexity.

| Input n | Algorithm 1 — O(n) | Algorithm 2 — O(√n) |
|---|---|---|
| 7 | 5 ms | 1 ms |
| 101 | 99 ms | 9 ms |
| 1,000,003 | ~10⁶ ms | ~10³ ms |

For large inputs, Algorithm 2 is approximately **1,000× faster**. This demonstrates why time complexity matters far more than exact timings on small inputs.

## 11. Summary

| Notation | Meaning | Case | Bound |
|---|---|---|---|
| O(g(n)) | f(n) grows no faster than g(n) | Worst case | Upper |
| Ω(g(n)) | f(n) grows at least as fast as g(n) | Best case | Lower |
| Θ(g(n)) | f(n) grows at the same rate as g(n) | Average case | Tight |

**Key rules:**
- Drop constants: `5n + 50` → `O(n)`
- Drop lower-order terms: `n² + 100n + 10` → `O(n²)`
- Always use the **tightest** valid bound
- Choose `g(n)` as the highest-degree term of `f(n)`
- `f(n) = Θ(g(n))` ⟺ `f(n) = O(g(n))` **and** `f(n) = Ω(g(n))`
