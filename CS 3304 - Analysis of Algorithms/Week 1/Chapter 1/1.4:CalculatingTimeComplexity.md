# Calculating Time Complexity

## 1. Factors That Affect Running Time

The running time of an algorithm depends on:

- Single vs. multiprocessor
- Read/Write speed of memory
- 32-bit architecture vs. 64-bit architecture
- **Input size**

When analyzing time complexity, all factors except **input size** are ignored. The only thing that matters is how the running time grows as the input size increases — the **rate of growth** with respect to input.

---

## 2. Model Machine Assumptions

To standardize analysis, we assume a model machine with:

- Single processor
- 32-bit architecture
- Sequential execution of Read/Write operations
- All arithmetic, logical, assignment, and return operations each cost **1 unit of time**

---

## 3. Examples of Rate of Growth

### Example 1: Constant Time — Sum(a, b)

```
Sum(a, b) {
    return a + b
}
```

| Operation | Cost |
|---|---|
| Addition | 1 unit |
| Return statement | 1 unit |
| **Total** | **2 units** |

Since the total time does not depend on any input size, the algorithm grows in **constant time**:

```
T(n) = 1   →   O(1)
```

---

### Example 2: Linear Time — Sum of Array Elements

```
Sum(A, n) {
    Sum = 0;                    // Statement 1
    for i = 0 to n-1            // Statement 2
        Sum = Sum + A[i];       // Statement 3
    return Sum;                 // Statement 4
}
```

| Statement | Operation | Cost | Times Executed |
|---|---|---|---|
| 1 | Assignment | 1 (C₁) | 1 |
| 2 | For loop (assign + increment) | 2 (C₂) | n + 1 |
| 3 | Addition + assignment | 2 (C₃) | n |
| 4 | Return | 1 (C₄) | 1 |

> Statement 2 runs `n + 1` times because the loop condition is checked once more when it becomes false.

**T(n) calculation:**

```
T(n) = 1 + 2(n+1) + 2n + 1
     = 1 + 2n + 2 + 2n + 1
     = 4n + 4
     = Cn + C'       where C = C₂ + C₃  and  C' = C₁ + C₂ + C₄
```

The algorithm grows in **linear time**:

```
T(n) = Θ(n)   →   O(n)
```

---

### Example 3: Quadratic Time — Sum of Matrix

For a matrix sum algorithm, the time complexity expression takes the form:

```
T(n) = an² + bn + c
```

The algorithm grows in **quadratic time**:

```
T(n) = Θ(n²)   →   O(n²)
```

## 4. Time Complexity Notations Reference

| Notation | Name |
|---|---|
| O(nᶜ) | Polynomial time |
| O(log n) | Logarithmic time |
| O(n log n) | Linearithmic time |
| O(2ⁿ) | Exponential time |
| O(n!) | Factorial time |

## 5. General Rules for Time Complexity Analysis

Always consider a **very large input size** and the **worst-case scenario**.

---

### Rule 1 — Remove Lower-Order Terms and Drop Constant Multipliers

Keep only the dominant term; drop everything else.

| T(n) | Simplified | Complexity |
|---|---|---|
| n³ + 4n² + 7n + 2 | ≈ n³ | O(n³) |
| 6n² + 9n + 3 | ≈ n² | O(n²) |
| 5n + 1 | ≈ n | O(n) |

---

### Rule 2 — Sum of Fragments

The running time of an algorithm equals the **sum of the running times of all its fragments**.

If an algorithm has parts that run sequentially:

```
T(n) = T(fragment 1) + T(fragment 2) + ... + T(fragment k)
```

The overall complexity is determined by the dominant fragment.

---

### Rule 3 — Conditional Statements

For `if/else` or any conditional statement, take the complexity of the **worst-case branch**.

```
if (condition)
    // O(f(n)) branch
else
    // O(g(n)) branch
```

Overall complexity = `O(max(f(n), g(n)))`

---

## 6. Recurrences

A **recurrence** is a recursive description of a function — it defines `T(n)` in terms of `T` on smaller inputs. Recurrences commonly arise in **divide and conquer** algorithms.

There are three methods for solving recurrences:

1. Substitution Method
2. Recursive Tree Method
3. Master Theorem

---

### 6.1 Substitution Method

The substitution method proves an asymptotic bound on a recurrence **by induction**. It can establish both upper and lower bounds, but requires **guessing the form of the solution** first.

**Steps:**
1. Guess the form of the solution
2. Expand the recurrence repeatedly (scratch work)
3. Substitute back to find a general pattern
4. Solve for the variable and determine T(n)

---

#### Example 4: Solve T(n) = 2T(n/2) + n

**Expanding (scratch work):**

| Substitution | Result |
|---|---|
| Substitute n/2 into T(n) | T(n) = 2² T(n/2²) + 2n |
| Substitute n/2² into T(n) | T(n) = 2³ T(n/2³) + 3n |
| Substitute n/2³ into T(n) | T(n) = 2⁴ T(n/2⁴) + 4n |

**General formula** (after i substitutions):

```
T(n) = 2ⁱ · T(n/2ⁱ) + i·n
```

**Solving for the base case** — let T(1) = 1, so set n/2ⁱ = 1:

```
n = 2ⁱ   →   i = log₂n
```

**Substituting i = log₂n:**

```
T(n) = 2^(log₂n) · T(1) + n · log₂n
     = n · 1 + n log₂n
     = n + n log₂n
```

Since `n` is negligible compared to `n log₂n`:

```
T(n) = O(n log n)
```

---

### 6.2 Master Theorem

The Master Theorem gives a **quick asymptotic solution** for recurrences of the form:

```
T(n) = a·T(n/b) + f(n)
```

Where:
- `a ≥ 1` — number of subproblems
- `b > 1` — factor by which input is reduced
- `f(n)` — positive function representing the cost of work done outside recursive calls

**Three cases:**

| Case | Condition | Result |
|---|---|---|
| Case I | f(n) < n^(log_b a) | T(n) = Θ(n^(log_b a)) |
| Case II | f(n) = n^(log_b a) | T(n) = Θ(n^(log_b a) · log n) |
| Case III | f(n) > n^(log_b a) | T(n) = Θ(f(n)) |

---

#### Example 5: Solve T(n) = 2T(n/2) + n using Master Theorem

**Identify values:**

```
a = 2,  b = 2,  f(n) = n
n^(log_b a) = n^(log₂2) = n¹ = n
```

**Check cases:**

| Case | Condition | Holds? |
|---|---|---|
| Case I | n < n | ✗ |
| Case II | n = n | ✓ |
| Case III | n > n | ✗ |

**Case II applies:**

```
T(n) = Θ(n^(log₂2) · log n)
     = Θ(n log n)
```

---

### 6.3 Recursive Tree Method

A **recursion tree** visualizes the cost of each level of recursive calls. Each node represents the cost of a single call; the total cost is the sum across all levels.

**Steps:**
1. Draw the root as `f(n)` (the non-recursive cost)
2. Branch into `a` children, each with input `n/b`
3. Continue until reaching base cases T(1)
4. Sum all levels to get T(n)

The recursive tree is most useful for **generating a good guess**, which can then be verified with the substitution method.

---

#### Example 6: Solve T(n) = 3T(n/4) + n²

**Tree structure:**

| Level | Nodes | Cost per Node | Total Cost at Level |
|---|---|---|---|
| 0 | 1 | n² | n² |
| 1 | 3 | (n/4)² | 3·(n/4)² = 3n²/16 |
| 2 | 9 | (n/16)² | 9·(n/16)² = 9n²/256 |
| 3 | 27 | (n/64)² | 27·(n/64)² = 27n²/4096 |
| ... | ... | ... | ... |
| leaf | T(1) | T(1) | T(1) ... T(1) |

**Summing all levels:**

```
T(n) = n² + 3[(n/4)²] + 9[(n/16)²] + 27[(n/64)²] + ........
     = n² + 3n²/4² + 9n²/16² + 27n²/64² + ......
     = n² [1 + 3/16 + (3/16)² + (3/16)³ + ....]
```

This is a **geometric progression (G.P.)** with ratio r = 3/16. Using the G.P. sum formula `a / (1 - r)`:

```
     = n² [ 1 / (1 - 3/16) ]
     = n² [ 16/13 ]
     = 16n²/13
```

Since `16/13` is a constant:

```
T(n) = O(n²)
```

---

## 7. Summary

| Method | How It Works | Best Used When |
|---|---|---|
| **Substitution** | Guess a solution, expand, verify by induction | Solution form can be guessed |
| **Master Theorem** | Apply one of three cases directly | Recurrence is of the form T(n) = aT(n/b) + f(n) |
| **Recursive Tree** | Draw the call tree, sum all levels | Visualizing the structure helps build a guess |

**Key rules:**
- Focus only on **input size** when analyzing complexity
- Always analyze the **worst case** with **very large n**
- Drop constants and lower-order terms — only the dominant term matters
- For conditionals, use the complexity of the **worst-case branch**
- For sequential fragments, **sum** all parts and keep the dominant one
