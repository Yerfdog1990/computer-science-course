# Backtracking 

## 1. What is Backtracking?

Backtracking is a strategy to **find and build a solution incrementally**, using the **brute-force approach**: try out *all possible solutions* (or fewer, if a solution is found sooner) and pick the desired ones.

- Start with a possible move and try to solve the problem with that move selected.
- If it doesn't work, **backtrack**: undo the move, select another, and repeat until solved.
- Analogy: walking through a **maze** — take a turn, hit a dead end, walk back, try a different turn.
- Famous backtracking problems: **N-Queens**, **Sudoku Solver**, **Rat in a Maze**, **Knight's Tour**, Sum of Subsets, Graph Coloring.

**Backtracking vs Dynamic Programming**

| | Dynamic Programming | Backtracking |
|---|---|---|
| Goal | One **optimal** solution | **All** (valid) solutions |
| Problem type | Optimization | Enumeration / satisfaction |

## 2. State Space Tree

The solution is represented as a tree (**state space tree** / decision tree):

- Root = empty solution (starting point).
- Each **level** = a decision point (e.g., which student sits in seat *k*).
- Each **branch** = one possible choice.
- Each **root-to-leaf path** = one complete solution.

**Example:** 3 students (B1, B2, G1), 3 seats → `n = 3`, so `3! = 6` arrangements. The tree explores B1→B2→G1, B1→G1→B2, B2→B1→G1, … all 6 leaves.

### Bounding Function

Constraints prune the tree. Example constraint: *girl must not sit in the middle*.

- While generating the tree, if a partial solution violates the constraint (G1 at level 2), **kill the node** — don't generate its subtree.
- The condition that kills a node is called the **bounding function**.
- Result: only 4 of 6 arrangements survive, and we saved work by never exploring dead branches.

## 3. Worked Trace: S → G (General Method)

Classic DAA example — find a path from start **S** to goal **G**. "Go back and come forward again until the condition is satisfied."

```
S ── A ── B ── deadend
     └─── C ── deadend
S ── D ── E ── deadend
     └─── F ── deadend
          └── G  (success node)
```

Trace:

1. S → A → B → deadend. B has no other sub-nodes → backtrack to A.
2. A → C → deadend. C has no sub-nodes → backtrack to A. A's children (B, C) both covered → backtrack to S.
3. S → D → E → deadend → backtrack to D.
4. D → F → deadend branch → backtrack to F's other sub-node.
5. F → **G** → success node. **Stop.** Path: **S → D → F → G**.

Rule: on a dead end, come back **until you find an untried sub-node**; if none, keep going back toward the start. This is exactly the maze code in Section 13 in graph form.

Key points from this method:

- Backtracking solves **recursive** problems and yields **multiple solutions** (not a single optimized one) — you may then pick the best among them.
- Standard applications: **N-Queens**, **Sum of Subsets**, **Graph Coloring** (also Sudoku, permutations, Hamiltonian cycles…).

## 4. Backtracking vs Branch and Bound

Both use brute force and generate a state space tree. Difference is traversal order:

- **Backtracking → DFS** (go deep, then back up).
- **Branch and Bound → BFS** (generate all nodes level by level).

## 5. The Universal Template (4 Components)

Every backtracking problem decomposes into:

1. **Choices** — the decision space at each step (which number, which column, which digit 1–9).
2. **Constraints** — conditions that make a partial solution invalid (prune early = bounding function).
3. **Base case / Goal** — when a complete solution is reached (path length = n, all queens placed, board full).
4. **Backtrack step** — undo the last choice (pop from path, remove the queen) and try the next option.

Template in Java:

```java
void backtrack(State state, List<Solution> result) {
    if (isGoal(state)) {            // base case
        result.add(copyOf(state));
        return;
    }
    for (Choice c : choices(state)) {
        if (violatesConstraint(state, c)) continue;  // bounding function
        apply(state, c);            // make the choice
        backtrack(state, result);   // explore
        undo(state, c);             // backtrack step
    }
}
```

**How to recognize a backtracking problem:** wording like *"generate all…"*, *"compute all…"*, *"return every possible…"* — anything implying **exhaustion of a decision space**. If you only need *one* or the *optimal* solution, prefer greedy or DP instead — backtracking is typically exponential.

## 6. Subsets (Power Set)

The most important starter problem. For each element there is exactly one decision: **include it or skip it**.

- Choices: include / exclude each number
- Constraint: none (we want *all* subsets)
- Base case: `index == nums.length`
- Backtrack step: remove the last number added

```java
import java.util.*;

class Solution {
    List<List<Integer>> list = new ArrayList<>();
    int[] nums;

    public List<List<Integer>> subsets(int[] nums) {
        this.nums = nums;
        List<Integer> current = new ArrayList<>();
        backtrack(0, current);
        return list;
    }

    public void backtrack(int index, List<Integer> current) {
        // base case: decided on every number → leaf of the decision tree
        if (index == nums.length) {
            list.add(new ArrayList<>(current));  // add a COPY (lists are passed by reference!)
            return;
        }

        // choice 1: include nums[index]
        current.add(nums[index]);
        backtrack(index + 1, current);

        // backtrack: undo the choice
        current.remove(current.size() - 1);

        // choice 2: exclude nums[index]
        backtrack(index + 1, current);
    }
}
```

> **Common mistake:** `list.add(current)` instead of `list.add(new ArrayList<>(current))`. Since the same list object is mutated throughout, you'd end up with a result full of empty/incorrect subsets.

Complexity: **O(n · 2ⁿ)** — 2ⁿ subsets, each copied in O(n).

## 7. Permutations

- Choices: all numbers in `nums`
- Constraint: can't reuse a number already in the path
- Base case: `path.size() == nums.length`
- Backtrack step: pop the last number added

```java
import java.util.*;

class Solution {
    List<List<Integer>> result = new ArrayList<>();
    int[] nums;

    public List<List<Integer>> permute(int[] nums) {
        this.nums = nums;
        backtrack(new ArrayList<>());
        return result;
    }

    private void backtrack(List<Integer> path) {
        // base case
        if (path.size() == nums.length) {
            result.add(new ArrayList<>(path));
            return;
        }
        for (int num : nums) {
            // constraint: no reuse
            if (path.contains(num)) continue;
            path.add(num);          // choose
            backtrack(path);        // explore
            path.remove(path.size() - 1);  // un-choose
        }
    }
}
```

Complexity: **O(n · n!)**.

## 8. Combinations (choose k from 1..n)

Nearly identical to subsets — just change the base case to limit subset size to exactly `k`.

```java
import java.util.*;

class Solution {
    List<List<Integer>> result = new ArrayList<>();
    int n, k;

    public List<List<Integer>> combine(int n, int k) {
        this.n = n; this.k = k;
        backtrack(1, new ArrayList<>());
        return result;
    }

    private void backtrack(int start, List<Integer> path) {
        // base case: path has exactly k numbers
        if (path.size() == k) {
            result.add(new ArrayList<>(path));
            return;
        }
        for (int i = start; i <= n; i++) {
            path.add(i);
            backtrack(i + 1, path);   // i+1 → no reuse, no duplicate combos
            path.remove(path.size() - 1);
        }
    }
}
```

One line of base-case logic turns subsets into combinations — the power of the template.

## 9. N-Queens

Place N queens on an N×N board so none attack each other: no two queens in the same **row**, **column**, or **diagonal** (one queen per row, one per column).

### Why backtracking? (4-Queens motivation)

A 4×4 board has 16 cells; placing 4 queens naively = C(16,4) = (13·14·15·16)/24 = **1820** combinations — far too many to check blindly. Backtracking prunes with the row/column/diagonal rules while building the state space tree, so most combinations are never generated.

### Worked example: 4-Queens trace

Place queen Qk in row k, trying columns left to right (· = empty, x = blocked):

1. **Q1 → (1,1).** Q2 can't go in cols 1 (column) or 2 (diagonal) → **Q2 → (2,3)**.
2. Now Q3 has **no legal cell** in row 3 (all blocked by Q1/Q2) → Q2's position was wrong. **Backtrack**, shift Q2 → (2,4).
3. Q3's only legal cell is (3,2) → place. But then Q4 has **no legal cell** in row 4 → backtrack to Q3 → no other option → backtrack to Q2 → no further shift → **backtrack all the way to Q1**.
4. Shift **Q1 → (1,2)**. Then Q2 is forced to (2,4), Q3 to (3,1), Q4 to (4,3). All rules satisfied — solution!

```
. Q . .        . . Q .
. . . Q        Q . . .
Q . . .        . . . Q
. . Q .        . Q . .
 solution      mirror image
```

The **mirror image** is also valid — backtracking yields **multiple solutions**, not one best solution (4-Queens has exactly these 2).

### State space tree view

Each level = one queen's row; each node = the column tried. Loop-back arrows are backtracking moves:

```
Q1: col 1  ──shift──▶  col 2          ← level 1 (row 1)
    │                    │
Q2: col 3 → col 4      col 4          ← level 2 (Q3 stuck → shift Q2)
    │                    │
Q3: col 2  (Q4 stuck)  col 1          ← level 3 (backtrack ↑ to Q1)
    │                    │
Q4: ✗ dead end         col 3  ✓       ← level 4 (solution!)
```

Final board (1-indexed): Q1=(1,2), Q2=(2,4), Q3=(3,1), Q4=(4,3) — the "all possible outcomes" tree, pruned by the row/column/diagonal bounding function.

### Java Solution

- Choice: which **column** to place the queen in for the current row
- Constraint: no two queens share a row, column, or diagonal
- Base case: N queens placed (`row == n`)
- Backtrack step: remove the last queen placed

```java
import java.util.*;

class Solution {
    List<List<String>> result = new ArrayList<>();
    Set<Integer> cols = new HashSet<>();      // columns used
    Set<Integer> diag1 = new HashSet<>();     // row - col diagonals
    Set<Integer> diag2 = new HashSet<>();     // row + col diagonals
    int n;
    int[] queenCol;                           // queenCol[row] = column of queen

    public List<List<String>> solveNQueens(int n) {
        this.n = n;
        this.queenCol = new int[n];
        backtrack(0);
        return result;
    }

    private void backtrack(int row) {
        // base case: all queens placed
        if (row == n) {
            result.add(buildBoard());
            return;
        }
        for (int col = 0; col < n; col++) {
            // constraint: same column or diagonal → prune (bounding function)
            if (cols.contains(col) || diag1.contains(row - col) || diag2.contains(row + col))
                continue;

            // choose
            queenCol[row] = col;
            cols.add(col); diag1.add(row - col); diag2.add(row + col);

            backtrack(row + 1);       // explore

            // un-choose (backtrack)
            cols.remove(col); diag1.remove(row - col); diag2.remove(row + col);
        }
    }

    private List<String> buildBoard() {
        List<String> board = new ArrayList<>();
        for (int r = 0; r < n; r++) {
            char[] rowChars = new char[n];
            Arrays.fill(rowChars, '.');
            rowChars[queenCol[r]] = 'Q';
            board.add(new String(rowChars));
        }
        return board;
    }
}
```

## 10. Sum of Subsets

**Problem:** given `n` weights `w[1..n]` and a target sum `m`, find all subsets whose elements add up to exactly `m`. Solution vector `x[i] ∈ {0, 1}` — include weight i or not.

- Choices: for each weight, `x[i] = 1` (include) or `x[i] = 0` (exclude)
- Base case: running sum == m → solution found
- Backtrack step: remove the last weight added
- Brute force = **2ⁿ** subsets (every include/exclude path) — bounding functions prune this.

### Two bounding functions

Kill a node (stop exploring) when either:

1. **Overshoot:** `currentSum + w[k+1] > m` — including the next weight exceeds the target.
2. **Undershoot:** `currentSum + (sum of all remaining weights) < m` — even taking everything left can't reach the target. (Sort weights and track the remaining total to apply this.)

### Trace 1: A = {10, 20, 30, 40}, sum = 50

Start at initial state 0. DFS with x1=1 first:

- x1=1 → 10; x2=1 → 30; x3=1 → **60 > 50 ✗** kill, backtrack.
- x3=0 → 30; x4=1 → **70 ✗**; x4=0 → 30 ✗ → backtrack to 10.
- x2=0 → 10; x3=1 → 40; x4=1 → **80 ✗**; x4=0 → 40 ✗ → backtrack.
- x3=0 → 10; x4=1 → **50 ✓ solution {10, 40}**; x4=0 → 10 ✗.
- Back at root: x1=0 → 0; x2=1 → 20; x3=1 → **50 ✓ solution {20, 30}**.

Two solutions: **{10, 40}** and **{20, 30}** — multiple solutions again.

### Trace 2: w = {5, 10, 12, 13, 15, 18}, n = 6, m = 30

Each node tracks `(sum so far, remaining total)` — root = (0, 73).

- x1=1 → (5,68) → x2=1 → (15,58) → x3=1 → (27,46) → x4=1 → **(40,33)** kill: 40 > 30 (bound 1).
- x4=0 → (27,33); x5=1 → **(43,18)** kill; x5=0 → (27,18); x6=1 → **(45,0)** kill; x6=0 → (27,0) kill: 27+0 < 30 (bound 2).
- Backtrack: x3=0 → (15,46) → x4=1 → (28,33) → x5 both fail → x4=0 → (15,33) → x5=1 → **(30,18) ✓**.

Solution vector **x = [1,1,0,0,1,0]** → {5, 10, 15} = 30. (Other solutions exist too: {12,18}, {5,12,13}…)

### Java Solution

```java
import java.util.*;

class SumOfSubsets {
    List<List<Integer>> result = new ArrayList<>();
    int[] w;
    int m;

    public List<List<Integer>> solve(int[] weights, int target) {
        w = weights;
        m = target;
        Arrays.sort(w);                         // needed for clean bounding
        int total = Arrays.stream(w).sum();
        backtrack(0, 0, total, new ArrayList<>());
        return result;
    }

    /** k = index being decided, sum = weights included so far,
        remaining = sum of w[k..n-1] not yet decided */
    private void backtrack(int k, int sum, int remaining, List<Integer> path) {
        if (sum == m) {                         // base case: exact target hit
            result.add(new ArrayList<>(path));
            return;
        }
        if (k == w.length) return;              // no more weights
        // bounding function 2: even taking everything left can't reach m
        if (sum + remaining < m) return;
        // bounding function 1: including w[k] overshoots m
        if (sum + w[k] <= m) {
            path.add(w[k]);                     // choose: x[k] = 1
            backtrack(k + 1, sum + w[k], remaining - w[k], path);
            path.remove(path.size() - 1);       // backtrack
        }
        // exclude: x[k] = 0
        backtrack(k + 1, sum, remaining - w[k], path);
    }

    public static void main(String[] args) {
        System.out.println(new SumOfSubsets().solve(new int[]{10, 20, 30, 40}, 50));
        // [[10, 40], [20, 30]]
        System.out.println(new SumOfSubsets().solve(new int[]{5, 10, 12, 13, 15, 18}, 30));
        // [[5, 10, 15], [5, 12, 13], [12, 18]]
    }
}
```

## 11. Sudoku Solver

The three keys applied: **choice → constraints → goal**.

- Choice: for each empty **cell** (row, col), place a digit from the decision space **1–9**
- Constraints: digit must not break its **row**, **column**, or **3×3 sub-grid** (only validate these three — validating the whole board is wasted O(n²) work)
- Goal: went out of bounds past the final row → every cell filled
- Backtrack step: erase the digit from the cell

```java
class Solution {
    public void solveSudoku(char[][] board) {
        solve(board, 0, 0);
    }

    private boolean solve(char[][] board, int row, int col) {
        // base case 1: finished a row → go to next row, first column
        if (col == 9) return solve(board, row + 1, 0);
        // base case 2: finished the final row → whole board solved
        if (row == 9) return true;

        // cell already filled → skip to next cell
        if (board[row][col] != '.') return solve(board, row, col + 1);

        // decision space: digits 1..9
        for (char d = '1'; d <= '9'; d++) {
            if (isValid(board, row, col, d)) {   // bounding function
                board[row][col] = d;             // choose
                if (solve(board, row, col + 1))  // explore
                    return true;
                board[row][col] = '.';           // un-choose (backtrack)
            }
        }
        return false;  // no digit worked → trigger backtracking in caller
    }

    private boolean isValid(char[][] board, int row, int col, char d) {
        for (int i = 0; i < 9; i++) {
            if (board[row][i] == d) return false;                 // row
            if (board[i][col] == d) return false;                 // column
            int r = 3 * (row / 3) + i / 3, c = 3 * (col / 3) + i % 3;
            if (board[r][c] == d) return false;                   // 3x3 sub-grid
        }
        return true;
    }
}
```

Note the function is a **policy**: given any (row, col) state, it knows what to do — skip filled cells, wrap to the next row, or report success.

### Alternative formulation: scan for the next blank cell

Instead of walking cell by cell, each call **scans for the next blank cell** (`UNASSIGNED = 0`); if none exists, the puzzle is solved. The safety check is split into three named helpers, and the box's top-left corner is `(row - row % 3, col - col % 3)`:

```java
class SudokuSolver {
    static final int UNASSIGNED = 0;

    public int[][] sudokuSolver(int[][] matrix) {
        if (solveSudoku(matrix)) return matrix;
        return null;  // no solution exists
    }

    private boolean solveSudoku(int[][] matrix) {
        int row = -1, col = -1;
        boolean blankFound = false;
        for (int r = 0; r < 9 && !blankFound; r++)       // find next blank cell
            for (int c = 0; c < 9; c++)
                if (matrix[r][c] == UNASSIGNED) {
                    row = r; col = c; blankFound = true; break;
                }
        if (!blankFound) return true;                    // no blanks → solved

        for (int num = 1; num <= 9; num++) {             // decision space 1..9
            if (isSafe(matrix, row, col, num)) {
                matrix[row][col] = num;                  // choose
                if (solveSudoku(matrix)) return true;    // explore
                matrix[row][col] = UNASSIGNED;           // backtrack
            }
        }
        return false;  // no digit fits → caller must backtrack
    }

    private boolean isSafe(int[][] m, int row, int col, int num) {
        return !usedInRow(m, row, num)
            && !usedInCol(m, col, num)
            && !usedInBox(m, row - row % 3, col - col % 3, num);
    }

    private boolean usedInRow(int[][] m, int row, int num) {
        for (int col = 0; col < 9; col++)
            if (m[row][col] == num) return true;
        return false;
    }

    private boolean usedInCol(int[][] m, int col, int num) {
        for (int row = 0; row < 9; row++)
            if (m[row][col] == num) return true;
        return false;
    }

    private boolean usedInBox(int[][] m, int startRow, int startCol, int num) {
        for (int r = 0; r < 3; r++)
            for (int c = 0; c < 3; c++)
                if (m[r + startRow][c + startCol] == num) return true;
        return false;
    }
}
```

## 12. Rat in a Maze (Grid)

An N×N matrix where each block is **free (1)** or **blocked (0)**. The rat starts at `[0][0]` (source) and must reach `[n-1][n-1]` (destination), moving only **down or right** through free blocks. Build a parallel `solution` matrix, marking each move with 1.

- Choice: move down or move right
- Constraint: target cell must be in bounds and free (`isSafe`)
- Base case: reached `[n-1][n-1]`
- Backtrack step: unmark the cell (`solution[x][y] = 0`) and try another direction

```java
class RatInMaze {
    public int[][] ratInAMaze(int[][] maze) {
        int n = maze.length;
        int[][] solution = new int[n][n];   // all 0s; path cells become 1
        if (findPath(maze, 0, 0, solution)) return solution;
        return null;  // NO PATH FOUND
    }

    private boolean findPath(int[][] maze, int x, int y, int[][] solution) {
        int n = maze.length;
        // base case: destination reached
        if (x == n - 1 && y == n - 1) {
            solution[x][y] = 1;
            return true;
        }
        if (isSafe(maze, x, y)) {
            solution[x][y] = 1;                             // choose: mark the move
            if (findPath(maze, x + 1, y, solution)) return true;  // try down
            if (findPath(maze, x, y + 1, solution)) return true;  // try right
            solution[x][y] = 0;                             // backtrack: unmark
        }
        return false;  // blocked / out of bounds / dead end
    }

    private boolean isSafe(int[][] maze, int x, int y) {
        int n = maze.length;
        return x >= 0 && y >= 0 && x < n && y < n && maze[x][y] != 0;
    }
}
```

## 13. Maze Path Finding (Graph Search)

Maze = graph of points; each point has a list of connected points. Track **visited** points to avoid infinite loops.

### The Example Maze

A 3×3 grid of points (0–8), walls block some moves:

```
0 - 1 - 2
|
3 - 4 - 5
|   |
6   7 - 8
```

Adjacency lists (point → connected points):

| Point | Connections |
|-------|-------------|
| 0 | 1, 3 |
| 1 | 0, 2 |
| 2 | 1 |
| 3 | 0, 4, 6 |
| 4 | 3, 5, 7 |
| 5 | 4 (dead end) |
| 6 | 3 (dead end) |
| 7 | 4, 8 |
| 8 | 7 |

Setup in Java:

```java
List<List<Integer>> maze = new ArrayList<>();
int[][] connections = {
    {1, 3},       // 0
    {0, 2},       // 1
    {1},          // 2
    {0, 4, 6},    // 3
    {3, 5, 7},    // 4
    {4},          // 5  (dead end)
    {3},          // 6  (dead end)
    {4, 8},       // 7
    {7}           // 8  (finish)
};
for (int[] conn : connections) {
    List<Integer> list = new ArrayList<>();
    for (int c : conn) list.add(c);
    maze.add(list);
}
```

Search from 0 to 8: charge ahead 0→3→4→**5** (dead end, backtrack to 4) → 7→8. Final path: **0 → 3 → 4 → 7 → 8**. Point 5 stays in *visited* but is removed from *path* — that's the backtrack.

### Iterative (explicit backtracking)

Charge ahead when there's an unvisited neighbor; when stuck, shrink the path.

```java
import java.util.*;

class MazeSolver {
    // maze[i] = list of points connected to point i
    public List<Integer> findPath(List<List<Integer>> maze, int start, int finish) {
        Set<Integer> visited = new HashSet<>();
        Deque<Integer> path = new ArrayDeque<>();   // used as a stack

        path.addLast(start);
        visited.add(start);

        while (!path.isEmpty() && path.peekLast() != finish) {
            int current = path.peekLast();
            boolean found = false;
            for (int next : maze.get(current)) {
                if (!visited.contains(next)) {      // unvisited connection
                    path.addLast(next);             // charge ahead
                    visited.add(next);
                    found = true;
                    break;
                }
            }
            if (!found) path.removeLast();          // dead end → explicit backtrack
        }
        return new ArrayList<>(path);  // empty list = no path exists
    }
}
```

### Recursive (implicit backtracking)

Each call asks: *"is there a path from here to the finish?"* Backtracking happens automatically when a call returns false — the code never looks like it's backtracking.

```java
import java.util.*;

class MazeSolverRecursive {
    public List<Integer> findPath(List<List<Integer>> maze, int start, int finish) {
        Set<Integer> visited = new HashSet<>();
        LinkedList<Integer> path = new LinkedList<>();
        solve(maze, start, finish, visited, path);
        return path;
    }

    private boolean solve(List<List<Integer>> maze, int start, int finish,
                          Set<Integer> visited, LinkedList<Integer> path) {
        // base case: reached the finish
        if (start == finish) {
            path.addFirst(start);
            return true;
        }
        visited.add(start);
        for (int next : maze.get(start)) {
            if (!visited.contains(next)) {
                if (solve(maze, next, finish, visited, path)) {
                    path.addFirst(start);   // prepend on the way back up
                    return true;
                }
                // recursive call failed → implicitly backtracked; try next neighbor
            }
        }
        return false;
    }
}
```

**Tip for recursion:** forget it's recursion — assume the recursive call is "another function that does what you need" (a self-replicating robot that reports back: path found or not).

## 14. Summary & Study Tips

- Backtracking = brute force + DFS over a state space tree + pruning via bounding functions + undoing choices.
- Every problem reduces to: **Choices, Constraints, Base case, Backtrack step**. Fill in the four blanks and "the code writes itself."
- Use it only when you must generate/evaluate **all** solutions; use greedy/DP for a single optimal answer.
- Classic problems: subsets, permutations, combinations, sum of subsets, N-Queens, Sudoku, Rat in a Maze, Knight's Tour, graph coloring, maze/path search.
- Study approach: first watch walkthroughs and internalize the template for a day or two, *then* grind problems — the pattern transfers.
