## 1. The 5 Steps

DP's basic premise — solve subproblems, then combine them into the larger solution — is easier said than done. These five steps give the process structure:

| Step | Action | Why it matters |
|---|---|---|
| 1 | **Visualize examples** | Diagrams (especially DAGs) expose connections and patterns hidden in the problem statement |
| 2 | **Find an appropriate subproblem** | A subproblem is a simpler version of the overall problem; choosing it well is the crux of DP |
| 3 | **Find relationships among subproblems** | Ask: "to solve *this* subproblem, which other subproblems do I need?" |
| 4 | **Generalize the relationship** | Turn the specific observation into a recurrence that works for any index/state |
| 5 | **Implement by solving subproblems in order** | Before solving any subproblem, all its prerequisites must already be solved |

The **directed acyclic graph (DAG)** is a model that shows up constantly in DP: states become nodes, dependencies become edges, and the answer is often a property of paths in the DAG. Many hard DP problems become approachable purely through this shift in perspective.

## 2. Problem 1: Longest Increasing Subsequence

**Problem:** Given a sequence of `n` elements, find the length of the longest *increasing subsequence* (LIS) — a set of elements where each subsequent element has both a **larger value** and a **larger index** than the previous one. (We start with the length only; recovering the sequence itself comes in Section 3.)

Examples:

- `[3, 1, 8, 2, 5]` → LIS is `1, 2, 5`, length **3**
- `[5, 2, 8, 6, 3, 6, 9, 7]` → LIS is `2, 3, 6, 9`, length **4**

### Step 1 — Visualize

Model the sequence as a DAG: each element is a node, and there is a directed edge from node `j` to node `k` (with `j < k`) whenever `value[j] < value[k]`.

For `[3, 1, 8, 2, 5]`:

```
index:   0     1     2     3     4
value:   3     1     8     2     5

edges:   0→2 (3<8)    0→4 (3<5)
         1→2 (1<8)    1→3 (1<2)    1→4 (1<5)
         3→4 (2<5)
```

Now every increasing subsequence is just a **path** in this DAG — and the LIS length equals the **longest path length + 1** (paths count edges; we count nodes). The problem has become a graph problem.

### Step 2 — Find a subproblem

An increasing subsequence is pinned down by its **starting point** and **ending point** within the original sequence. Fixing either one yields a subproblem; fixing the *ending point* is the more intuitive choice:

> **LIS(k)** = length of the longest increasing subsequence **ending at index k** (and including element k).

Example: in `[3, 1, 8, 2, 5]`, `LIS(3)` is the subsequence `1, 2` → length 2.

### Step 3 — Find relationships

To solve `LIS(4)` (element 5), look at which nodes have edges *into* node 4: nodes 0, 1, and 3.

- `LIS(0) = 1` (just `[3]`)
- `LIS(1) = 1` (just `[1]`)
- `LIS(3) = 2` (`[1, 2]`)

Any LIS ending at index 4 must extend one of these, so:

```
LIS(4) = 1 + max( LIS(0), LIS(1), LIS(3) ) = 1 + 2 = 3
```

### Step 4 — Generalize

Subproblem `k` is a prerequisite for subproblem `n` **iff `k < n` and `value[k] < value[n]`**. So for any `n`:

```
LIS(n) = 1 + max over all k < n with value[k] < value[n] of LIS(k)
       = 1 if no such k exists
```

### Step 5 — Implement

Order is easy here: dependencies only point leftward, so solve subproblems **left to right**. Initialize every length to 1 (every element is an increasing subsequence of length 1 by itself).

```java
public class LIS {

    // O(n^2) time, O(n) space
    static int lis(int[] a) {
        int n = a.length;
        int[] L = new int[n];
        java.util.Arrays.fill(L, 1); // every element alone has length 1

        for (int i = 1; i < n; i++) {
            for (int k = 0; k < i; k++) {          // find prerequisite subproblems
                if (a[k] < a[i] && L[k] + 1 > L[i]) {
                    L[i] = L[k] + 1;               // generalized relationship
                }
            }
        }

        int best = 0;
        for (int len : L) best = Math.max(best, len);
        return best;
    }

    public static void main(String[] args) {
        System.out.println(lis(new int[]{3, 1, 8, 2, 5}));           // 3
        System.out.println(lis(new int[]{5, 2, 8, 6, 3, 6, 9, 7}));  // 4
    }
}
```

Don't get bogged down in implementation details — many variants work. What matters is the thought process: identify subproblems, then solve them in dependency order.

## 3. Reconstructing the Actual Sequence

So far we only have the *length*. To recover the underlying sequence, track **previous indices**: when subproblem `LIS(i)` is solved using the value of `LIS(j)`, record `prev[i] = j`.

For `[3, 1, 8, 2, 5]`:

| index i | value | LIS(i) | prev[i] | why |
|---|---|---|---|---|
| 0 | 3 | 1 | −1 | nothing leads to index 0 |
| 1 | 1 | 1 | −1 | nothing leads to index 1 |
| 2 | 8 | 2 | 0 (or 1) | both have length 1 — either works |
| 3 | 2 | 2 | 1 | only choice |
| 4 | 5 | 3 | 3 | LIS(3) was the max used |

Follow `prev` back from the best endpoint (index 4 → 3 → 1) and reverse: `1, 2, 5`. This backtracking-pointer trick is a standard pattern across DP problems (we used the same idea for the `s` split table in matrix chain multiplication, Part 2).

```java
import java.util.*;

public class LISReconstruct {

    static List<Integer> lisSequence(int[] a) {
        int n = a.length;
        int[] L = new int[n];
        int[] prev = new int[n];
        Arrays.fill(L, 1);
        Arrays.fill(prev, -1);

        for (int i = 1; i < n; i++) {
            for (int k = 0; k < i; k++) {
                if (a[k] < a[i] && L[k] + 1 > L[i]) {
                    L[i] = L[k] + 1;
                    prev[i] = k; // remember which subproblem we used
                }
            }
        }

        // best endpoint
        int end = 0;
        for (int i = 1; i < n; i++) if (L[i] > L[end]) end = i;

        // walk the prev pointers backward
        LinkedList<Integer> seq = new LinkedList<>();
        for (int i = end; i != -1; i = prev[i]) seq.addFirst(a[i]);
        return seq;
    }

    public static void main(String[] args) {
        System.out.println(lisSequence(new int[]{3, 1, 8, 2, 5}));
        // [1, 2, 5]
        System.out.println(lisSequence(new int[]{5, 2, 8, 6, 3, 6, 9, 7}));
        // [2, 3, 6, 9]
    }
}
```

## 4. Problem 2: Box Stacking

**Problem:** Given `n` boxes, each with a length, width, and height, find the height of the **tallest possible stack**, where box A may sit on box B only if A's length **and** width are both strictly smaller than B's. Boxes may **not** be rotated.

Small example — three boxes:

| Box | L | W | H |
|---|---|---|---|
| Green | 2 | 2 | 3 |
| Blue | 4 | 3 | 3 |
| Red | 5 | 1 | 4 |

Green fits on blue (2<4, 2<3) → stack height 3 + 3 = **6**. Red and green cannot be stacked together in either order (widths clash), so 6 is the answer.

Main example — six boxes (answer: **7**, red at the bottom, orange in the middle, purple on top):

| Box | L | W | H |
|---|---|---|---|
| Green | 1 | 5 | 4 |
| Purple | 2 | 1 | 2 |
| Orange | 3 | 3 | 2 |
| Blue | 4 | 2 | 1 |
| Yellow | 5 | 6 | 2 |
| Red | 6 | 4 | 3 |

### Step 1 — Visualize

DP problems can throw a lot of information at you; focus on one aspect at a time. Before finding the tallest stack, first identify **which boxes can sit on which** — and again a DAG is the right picture: draw an edge from box A to box B if A can be stacked on top of B.

For the six boxes: purple → orange, purple → blue, purple/orange/blue/green → yellow, purple/orange/blue → red.

Now every **path in the DAG is a legal stack**, and the goal is the path with the greatest total height.

### Step 2 — Find a subproblem

If the goal is the best full path, a natural subproblem is the best **partial path** — a path ending at a particular box. A path ending at box `b` is a stack where `b` is forced to be the **base**:

> **best(b)** = the tallest possible stack with box `b` at the bottom.

Examples from the table: `best(orange) = 4` (orange 2 + purple 2), `best(yellow) = 6` (two ways: green 4 on yellow 2, or orange-stack 4 on yellow 2), `best(red) = 7` — which is also the global answer.

### Step 3 — Find relationships

To solve `best(red)`, look at the boxes with edges into red: purple, orange, blue.

- `best(purple) = 2` (nothing fits on purple)
- `best(orange) = 4`
- `best(blue) = 3` (blue 1 + purple 2)

Then:

```
best(red) = height(red) + max( best(purple), best(orange), best(blue) )
          = 3 + 4 = 7
```

Take the current box, find all prerequisite subproblems, pick the best, add the current box's height.

### Step 4 — Generalize

For any box `b`:

```
best(b) = height(b) + max over boxes a that can be stacked on b of best(a)
        = height(b) if no box fits on b
```

**Answer = max of best(b) over all boxes.**

### Step 5 — Implement (ordering is the twist!)

Unlike LIS, the boxes arrive in **random order** — so what order do we solve subproblems in? Stackability depends entirely on length and width, and larger footprints can support more boxes. So **sort the boxes by length (or width — either works)** first; then every box that could sit on box `i` appears *before* `i` in sorted order, and a left-to-right sweep solves prerequisites first. This sort-then-sweep move is a classic DP trick.

```java
import java.util.*;

public class BoxStacking {

    // box = {length, width, height}
    static boolean canBeStacked(int[] top, int[] bottom) {
        return top[0] < bottom[0] && top[1] < bottom[1];
    }

    // O(n^2) time after O(n log n) sort
    static int tallestStack(int[][] boxes) {
        // Step: sort by length so prerequisites come first
        int[][] sorted = boxes.clone();
        Arrays.sort(sorted, Comparator.comparingInt(b -> b[0]));

        int n = sorted.length;
        int[] best = new int[n];
        for (int i = 0; i < n; i++) best[i] = sorted[i][2]; // box alone

        for (int i = 1; i < n; i++) {
            for (int j = 0; j < i; j++) {
                if (canBeStacked(sorted[j], sorted[i])) {
                    best[i] = Math.max(best[i], sorted[i][2] + best[j]);
                }
            }
        }

        int ans = 0;
        for (int h : best) ans = Math.max(ans, h);
        return ans;
    }

    public static void main(String[] args) {
        int[][] three = {
            {2, 2, 3}, // green
            {4, 3, 3}, // blue
            {5, 1, 4}  // red
        };
        System.out.println(tallestStack(three)); // 6

        int[][] six = {
            {6, 4, 3}, // red      (given in random order on purpose)
            {2, 1, 2}, // purple
            {5, 6, 2}, // yellow
            {1, 5, 4}, // green
            {4, 2, 1}, // blue
            {3, 3, 2}  // orange
        };
        System.out.println(tallestStack(six)); // 7
    }
}
```

### Tracing the sweep (six-box example)

After sorting by length: green, purple, orange, blue, yellow, red. `best` starts as each box's own height: `[4, 2, 2, 1, 2, 3]`.

- **i = purple:** no earlier box fits on purple → stays 2.
- **i = orange:** purple fits → best = 2 + 2 = **4**.
- **i = blue:** purple fits → best = 1 + 2 = **3**.
- **i = yellow:** green, purple, orange, blue all fit; max prerequisite = 4 → best = 2 + 4 = **6**.
- **i = red:** purple, orange, blue fit (not green, not yellow); max = 4 → best = 3 + 4 = **7**.

Maximum over all subproblems = **7**. A problem that looked daunting reduced to LIS-with-a-sort: same subproblem shape, same recurrence shape, one extra ordering insight.

## 5. Common Subproblem Patterns

The hardest part of DP is organizing the given information to identify the right subproblem — that's where practice and creativity go. These patterns cover most problems you'll meet:

**Prefix of a sequence.** Input is a sequence of length `n`; the subproblem is about an ordered subsequence of length `i` (equivalently, "ending at index `i`"). This is exactly LIS. *Also:* maximum subarray, house robber, word break.

**Sort first, then prefix.** Input is a set given in random order; sort it by the attribute that determines dependencies, then apply the prefix pattern. This is exactly box stacking. *Also:* Russian doll envelopes, weighted interval scheduling.

**Two sequences.** Input is two sequences; the subproblem pairs a prefix of each: `dp[i][j]` over prefixes `X[0..i]`, `Y[0..j]`. *Examples from Parts 1–2:* Longest Common Subsequence, Edit Distance.

**Expand from the middle.** The subproblem is an interval `[i, j]` of the sequence, solved from short intervals outward. Less common but essential where the answer for a range depends on its sub-ranges. *Examples:* longest palindromic substring/subsequence, Matrix Chain Multiplication, Optimal BST (both from Part 2).

**Sub-matrix.** Input is a 2-D array; the subproblem is a sub-matrix (often the rectangle from the origin to cell `(i, j)`). *Examples:* min cost path in a grid, maximal square, unique paths, 0/1 Knapsack's `dp[i][w]` table.

When you're stuck, run through this list and ask which shape the problem's dependencies fit. At the end of the day, though, nothing beats deliberate practice with real problems.

## 6. Key Takeaways

1. **Visualize first** — a DAG of states and dependencies frequently *is* the solution: increasing subsequences are paths; stacks of boxes are paths; the answer is the best path.
2. **Subproblems usually fix an endpoint** — "ending at index k" / "with box b as the base" turns one hard global question into `n` easy local ones.
3. **Recurrence = 1 current step + best prerequisite** — `LIS(n) = 1 + max LIS(k)`, `best(b) = height(b) + max best(a)`. Same skeleton, different problems.
4. **Order matters** — solve every prerequisite before its dependent. When input order doesn't provide this (box stacking), *sort* until it does.
5. **Reconstruction is just bookkeeping** — store which prerequisite each subproblem used (`prev` pointers), then backtrack from the optimum.
