## 1. Dynamic Algorithms — Recap

A dynamic algorithm is fundamentally an **optimization algorithm**. Any recursive solution with repeated calls for the same inputs can be optimized with DP: instead of recomputing subproblem results, store them and reuse them.

DP resembles divide and conquer in that it decomposes a problem into smaller subproblems — but unlike divide and conquer, those subproblems **overlap and cannot be solved independently**. And unlike greedy algorithms, which optimize locally at each step, dynamic algorithms are driven by **problem-wide (global) optimization**.

| | Greedy | Dynamic Programming |
|---|---|---|
| Decision making | One locally optimal choice per step; never revisited | Considers all choices; combines optimal subproblem answers |
| Guarantees optimality? | Only for problems with the greedy-choice property (e.g., fractional knapsack) | Yes, when optimal substructure holds (e.g., 0/1 knapsack) |
| Speed / memory | Usually faster, little memory | Slower, needs a table |
| Knapsack example | Fractional knapsack: sort by value/weight, take greedily | 0/1 knapsack: items can't be split, greedy fails; DP table required |

## 2. All Pairs Shortest Path (Floyd–Warshall)

**Problem:** Given a weighted directed graph, find the shortest path between **every** pair of vertices. Applications: transportation networks, communication networks, social networks.

### 2.1 Idea

Build a sequence of matrices `A0, A1, ..., An`. `Ak[i][j]` is the shortest distance from `i` to `j` using only vertices `{1..k}` as intermediates.

- `A0` = the adjacency matrix (direct edges only; `∞` where no edge; diagonal = 0).
- To build `Ak` from `Ak-1`, for every pair `(i, j)` ask: *is it cheaper to go through vertex `k`?*

```
Ak[i][j] = min( Ak-1[i][j],  Ak-1[i][k] + Ak-1[k][j] )
```

- Row `k` and column `k` never change when computing `Ak` (a path from `k` through `k` adds nothing).
- After `n` rounds, `An` holds all-pairs shortest distances.

### 2.2 Worked Example

5-vertex directed graph with edges: `1→3 (6)`, `1→4 (3)`, `2→1 (3)`, `3→4 (2)`, `4→2 (1)`, `4→3 (1)`, `5→2 (4)`, `5→4 (2)`.

**A0 (direct edges):**

|   | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| **1** | 0 | ∞ | 6 | 3 | ∞ |
| **2** | 3 | 0 | ∞ | ∞ | ∞ |
| **3** | ∞ | ∞ | 0 | 2 | ∞ |
| **4** | ∞ | 1 | 1 | 0 | ∞ |
| **5** | ∞ | 4 | ∞ | 2 | 0 |

**Round k=1** (vertex 1 as intermediate) — only paths through 1 can improve. `A0[2,3] = ∞ > A0[2,1] + A0[1,3] = 3 + 6 = 9` → update to 9. `A0[2,4] = ∞ > 3 + 3 = 6` → update to 6. All other entries unchanged (they'd need to reach vertex 1 first, which costs ∞).

**Round k=2** (vertex 2 as intermediate): `A1[4,1] = ∞ > A1[4,2] + A1[2,1] = 1 + 3 = 4` → 4. `A1[5,1] = ∞ > 4 + 3 = 7` → 7. `A1[5,3] = ∞ > 4 + 9 = 13` → 13.

**Round k=3** (vertex 3): no improvements — column 3's targets are already served more cheaply.

**Round k=4** (vertex 4) — the busiest round:

- `A3[1,2]: ∞ > 3 + 1 = 4` → 4
- `A3[1,3]: 6 > 3 + 1 = 4` → 4
- `A3[2,3]: 9 > 6 + 1 = 7` → 7
- `A3[3,1]: ∞ > 2 + 4 = 6` → 6
- `A3[3,2]: ∞ > 2 + 1 = 3` → 3
- `A3[5,1]: 7 > 2 + 4 = 6` → 6
- `A3[5,2]: 4 > 2 + 1 = 3` → 3
- `A3[5,3]: 13 > 2 + 1 = 3` → 3

**Round k=5** (vertex 5): no improvements — no vertex can reach 5, so paths through 5 are all ∞.

**Final matrix A5 (all-pairs shortest distances):**

|   | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| **1** | 0 | 4 | 4 | 3 | ∞ |
| **2** | 3 | 0 | 7 | 6 | ∞ |
| **3** | 6 | 3 | 0 | 2 | ∞ |
| **4** | 4 | 1 | 1 | 0 | ∞ |
| **5** | 6 | 3 | 3 | 2 | 0 |

### 2.3 Java Implementation — O(n³) Time, O(n²) Space

```java
import java.util.Arrays;

public class FloydWarshall {

    static final int INF = 1_000_000; // avoid Integer.MAX_VALUE overflow

    static int[][] apsp(int[][] graph) {
        int n = graph.length;
        int[][] dist = new int[n][n];
        for (int i = 0; i < n; i++) {
            dist[i] = Arrays.copyOf(graph[i], n);
        }

        // Round k: allow vertex k as an intermediate
        for (int k = 0; k < n; k++) {
            for (int i = 0; i < n; i++) {
                for (int j = 0; j < n; j++) {
                    if (dist[i][k] + dist[k][j] < dist[i][j]) {
                        dist[i][j] = dist[i][k] + dist[k][j];
                    }
                }
            }
        }
        return dist;
    }

    public static void main(String[] args) {
        int[][] graph = {
            {0,   INF, 6,   3,   INF},
            {3,   0,   INF, INF, INF},
            {INF, INF, 0,   2,   INF},
            {INF, 1,   1,   0,   INF},
            {INF, 4,   INF, 2,   0}
        };

        int[][] dist = apsp(graph);
        for (int[] row : dist) {
            StringBuilder sb = new StringBuilder();
            for (int d : row) sb.append(d >= INF ? "INF" : d).append("\t");
            System.out.println(sb.toString().trim());
        }
    }
}
```

Output:

```
0	4	4	3	INF
3	0	7	6	INF
6	3	0	2	INF
4	1	1	0	INF
6	3	3	2	0
```

> **Note:** Floyd–Warshall handles negative edge weights (but not negative cycles). Storing all shortest *paths* (not just distances) requires a predecessor matrix, which can be memory-expensive — one spanning tree per vertex.

## 3. 0/1 Knapsack Problem

**Problem:** Select a subset of `n` items — each with weight `w[i]` and value `v[i]` — to maximize total value without exceeding capacity `W`. Each item is taken **whole or not at all** (no fractions — that variant is solved greedily). Applications: inventory management, resource allocation, investment selection.

**State:** `dp[i][w]` = maximum value using the first `i` items with capacity `w`.

**Transition:** for each item, either **exclude** it (`dp[i-1][w]`) or **include** it (`v[i-1] + dp[i-1][w - w[i-1]]`, if it fits):

```
dp[i][w] = max( dp[i-1][w],  v[i-1] + dp[i-1][w - w[i-1]] )
```

### 3.1 Worked Example

Weights `{2, 3, 3, 4, 6}`, values `{1, 2, 5, 9, 4}`, capacity `W = 10`.

Filling the table row by row, the optimum is **16**, achieved by taking items 3, 4, and 2 (weights 3 + 4 + 3 = 10, values 5 + 9 + 2 = 16).

### 3.2 Java Implementation — O(nW) Time

```java
public class Knapsack01 {

    // 2D table version: O(n*W) time and space
    static int knapsack(int W, int[] wt, int[] val) {
        int n = wt.length;
        int[][] dp = new int[n + 1][W + 1];

        for (int i = 1; i <= n; i++) {
            for (int w = 0; w <= W; w++) {
                dp[i][w] = dp[i - 1][w]; // exclude item i-1
                if (wt[i - 1] <= w) {    // include item i-1
                    dp[i][w] = Math.max(dp[i][w],
                            val[i - 1] + dp[i - 1][w - wt[i - 1]]);
                }
            }
        }
        return dp[n][W];
    }

    // Space-optimized 1D version: O(n*W) time, O(W) space.
    // Iterate weights DOWNWARD so each item is used at most once.
    static int knapsack1D(int W, int[] wt, int[] val) {
        int[] dp = new int[W + 1];
        for (int k = 0; k < wt.length; k++) {
            for (int w = W; w >= wt[k]; w--) {
                if (dp[w - wt[k]] + val[k] > dp[w]) {
                    dp[w] = dp[w - wt[k]] + val[k];
                }
            }
        }
        return dp[W];
    }

    public static void main(String[] args) {
        int[] wt = {2, 3, 3, 4, 6};
        int[] val = {1, 2, 5, 9, 4};
        System.out.println(knapsack(10, wt, val));   // 16
        System.out.println(knapsack1D(10, wt, val)); // 16
    }
}
```

> The downward loop in the 1D version is critical: looping upward would allow an item to be reused (that's the *unbounded* knapsack).

## 4. Travelling Salesman Problem (Held–Karp DP)

**Problem:** Given cities and pairwise distances, find the shortest route that visits every city **exactly once** and returns to the start. Applications: logistics, transportation, routing.

### 4.1 Recurrence

Let `g(i, S)` = length of the shortest path starting at city `i`, visiting every city in set `S` exactly once, and ending at city 1.

```
g(i, S) = min over k in S of ( C[i][k] + g(k, S − {k}) )
g(i, ∅) = C[i][1]
```

The answer is `g(1, {2, 3, ..., n})`.

### 4.2 Worked Example

Cost matrix (4 cities):

|   | 1 | 2 | 3 | 4 |
|---|---|---|---|---|
| **1** | 0 | 10 | 15 | 20 |
| **2** | 5 | 0 | 9 | 10 |
| **3** | 6 | 13 | 0 | 12 |
| **4** | 8 | 8 | 9 | 0 |

**Base cases (empty set — return to city 1):** `g(2, ∅) = 5`, `g(3, ∅) = 6`, `g(4, ∅) = 8`.

**Sets of size 1:**

- `g(2, {3}) = C23 + g(3, ∅) = 9 + 6 = 15`, `g(2, {4}) = 10 + 8 = 18`
- `g(3, {2}) = 13 + 5 = 18`, `g(3, {4}) = 12 + 8 = 20`
- `g(4, {2}) = 8 + 5 = 13`, `g(4, {3}) = 9 + 6 = 15`

**Sets of size 2:**

- `g(2, {3,4}) = min(9 + 20, 10 + 15) = 25`
- `g(3, {2,4}) = min(13 + 18, 12 + 13) = 25`
- `g(4, {2,3}) = min(8 + 15, 9 + 18) = 23`

**Final:**

```
g(1, {2,3,4}) = min( C12 + g(2,{3,4}),  C13 + g(3,{2,4}),  C14 + g(4,{2,3}) )
              = min( 10 + 25,  15 + 25,  20 + 23 )
              = min( 35, 40, 43 ) = 35
```

**Optimal tour: 1 → 2 → 4 → 3 → 1, cost 35.**

### 4.3 Java Implementation (Bitmask DP) — O(n²·2ⁿ) Time, O(n·2ⁿ) Space

Sets are encoded as bitmasks: bit `k` set means city `k` is still to be visited.

```java
import java.util.Arrays;

public class TSPHeldKarp {

    static int n;
    static int[][] cost;
    static int[][] memo;   // memo[i][mask]
    static int[][] choice; // to reconstruct the tour

    // Shortest path: start at i, visit all cities in mask, end at 0
    static int g(int i, int mask) {
        if (mask == 0) return cost[i][0]; // return to start
        if (memo[i][mask] != -1) return memo[i][mask];

        int best = Integer.MAX_VALUE;
        for (int k = 0; k < n; k++) {
            if ((mask & (1 << k)) != 0) {
                int val = cost[i][k] + g(k, mask & ~(1 << k));
                if (val < best) {
                    best = val;
                    choice[i][mask] = k;
                }
            }
        }
        return memo[i][mask] = best;
    }

    public static void main(String[] args) {
        cost = new int[][] {
            {0, 10, 15, 20},
            {5,  0,  9, 10},
            {6, 13,  0, 12},
            {8,  8,  9,  0}
        };
        n = cost.length;
        memo = new int[n][1 << n];
        choice = new int[n][1 << n];
        for (int[] row : memo) Arrays.fill(row, -1);

        int fullMask = (1 << n) - 2; // all cities except 0
        int best = g(0, fullMask);
        System.out.println("Minimum tour cost: " + best); // 35

        // Reconstruct tour
        StringBuilder tour = new StringBuilder("1");
        int i = 0, mask = fullMask;
        while (mask != 0) {
            int k = choice[i][mask];
            tour.append(" -> ").append(k + 1);
            mask &= ~(1 << k);
            i = k;
        }
        tour.append(" -> 1");
        System.out.println("Tour: " + tour); // 1 -> 2 -> 4 -> 3 -> 1
    }
}
```

> Held–Karp is exponential — O(n²·2ⁿ) — but far better than brute-force O(n!). No polynomial algorithm is known: TSP is NP-Hard (Section 9).

## 5. Coin Changing Problem

**Problem:** Given coin denominations and a target amount, either (a) find the **minimum number of coins** to make the amount, or (b) **count the ways** to make it. Applications: currency exchange, vending machines.

For each coin we either **include** it (subtract its value from the amount, stay on the same coin — supply is unlimited) or **exclude** it (move to the next coin). A coin larger than the remaining amount is always excluded.

### 5.1 Minimum Coins — O(amount × coins)

**State:** `dp[a]` = fewest coins to make amount `a`. **Transition:** `dp[a] = 1 + min(dp[a - c])` over usable coins `c`.

```java
import java.util.Arrays;

public class CoinChangeMin {

    static int minCoins(int[] coins, int amount) {
        int[] dp = new int[amount + 1];
        Arrays.fill(dp, amount + 1); // "infinity"
        dp[0] = 0;

        for (int a = 1; a <= amount; a++) {
            for (int c : coins) {
                if (c <= a) {
                    dp[a] = Math.min(dp[a], dp[a - c] + 1);
                }
            }
        }
        return dp[amount] > amount ? -1 : dp[amount];
    }

    public static void main(String[] args) {
        System.out.println(minCoins(new int[]{1, 2, 3}, 5));    // 2 (2+3)
        System.out.println(minCoins(new int[]{2, 5, 3, 6}, 10)); // 2 (5+5)
    }
}
```

### 5.2 Counting the Ways — O(amount × coins)

**State:** `dp[a]` = number of combinations that form `a`. Loop coins in the **outer** loop so each combination is counted once (order ignored).

```java
public class CoinChangeWays {

    static int countWays(int[] coins, int amount) {
        int[] dp = new int[amount + 1];
        dp[0] = 1; // one way to make 0: use no coins

        for (int c : coins) {           // outer loop over coins
            for (int a = c; a <= amount; a++) {
                dp[a] += dp[a - c];     // include coin c
            }
        }
        return dp[amount];
    }

    public static void main(String[] args) {
        System.out.println(countWays(new int[]{1, 2, 3}, 5));    // 5
        System.out.println(countWays(new int[]{2, 5, 3, 6}, 10)); // 5
    }
}
```

For `amount = 5`, `coins = {1,2,3}` the 5 combinations are: `1+1+1+1+1`, `1+1+1+2`, `1+2+2`, `1+1+3`, `2+3`.
For `amount = 10`, `coins = {2,3,5,6}`: `2+2+2+2+2`, `2+2+3+3`, `2+2+6`, `2+3+5`, `5+5`.

## 6. Matrix Chain Multiplication

**Problem:** Given a chain of matrices `A1 × A2 × ... × An`, find the parenthesization that minimizes total scalar multiplications. Applications: computer graphics, machine learning, scientific computing.

Key facts before the DP:

- Two matrices `a×b` and `b×c` can be multiplied only if the first's columns equal the second's rows; the cost is `a·b·c` scalar multiplications and the result is `a×c`.
- Matrix multiplication is **associative** — the result is the same regardless of parenthesization, but the **cost is not**.
- The challenge is choosing the multiplication *order*, not doing the multiplications.

**State:** `m[i][j]` = minimum cost to compute the product `Ai...Aj`, with dimensions given by array `P` (matrix `Ai` is `P[i-1] × P[i]`).

**Transition:** try every split point `k`:

```
m[i][j] = min over k in [i, j) of ( m[i][k] + m[k+1][j] + P[i-1]·P[k]·P[j] )
m[i][i] = 0
```

### 6.1 Worked Example

Chain `A1 A2 A3 A4` with `P = {5, 4, 6, 2, 7}`:

| Matrix | A1 | A2 | A3 | A4 |
|---|---|---|---|---|
| Dimensions | 5×4 | 4×6 | 6×2 | 2×7 |

**Length-1 chains:** `m(1,1) = m(2,2) = m(3,3) = m(4,4) = 0`.

**Length-2 chains:**

- `m(1,2) = 5·4·6 = 120`
- `m(2,3) = 4·6·2 = 48`
- `m(3,4) = 6·2·7 = 84`

**Length-3 chains:**

- `m(1,3) = min( m(1,2) + m(3,3) + 5·6·2 = 120+0+60 = 180,  m(1,1) + m(2,3) + 5·4·2 = 0+48+40 = 88 ) = 88`
- `m(2,4) = min( m(2,3) + m(4,4) + 4·2·7 = 48+0+56 = 104,  m(2,2) + m(3,4) + 4·6·7 = 0+84+168 = 252 ) = 104`

**Length-4 chain:**

```
m(1,4) = min(
    m(1,1) + m(2,4) + 5·4·7 = 0   + 104 + 140 = 244,   split after A1
    m(1,2) + m(3,4) + 5·6·7 = 120 + 84  + 210 = 414,   split after A2
    m(1,3) + m(4,4) + 5·2·7 = 88  + 0   + 70  = 158    split after A3
) = 158
```

**Answer: m(1,4) = 158**, with optimal parenthesization **(A1 × (A2 × A3)) × A4** (recovered by backtracking through the split table `s`).

### 6.2 Java Implementation — O(n³) Time, O(n²) Space

```java
public class MatrixChainOrder {

    static int[][] m; // costs
    static int[][] s; // split points, for reconstruction

    static int matrixChain(int[] p) {
        int n = p.length - 1; // number of matrices
        m = new int[n + 1][n + 1];
        s = new int[n + 1][n + 1];

        for (int len = 2; len <= n; len++) {
            for (int i = 1; i <= n - len + 1; i++) {
                int j = i + len - 1;
                m[i][j] = Integer.MAX_VALUE;

                for (int k = i; k < j; k++) {
                    int cost = m[i][k] + m[k + 1][j] + p[i - 1] * p[k] * p[j];
                    if (cost < m[i][j]) {
                        m[i][j] = cost;
                        s[i][j] = k;
                    }
                }
            }
        }
        return m[1][n];
    }

    // Reconstruct optimal parenthesization from the split table
    static String parens(int i, int j) {
        if (i == j) return "A" + i;
        return "(" + parens(i, s[i][j]) + " x " + parens(s[i][j] + 1, j) + ")";
    }

    public static void main(String[] args) {
        int[] p = {5, 4, 6, 2, 7}; // A1:5x4, A2:4x6, A3:6x2, A4:2x7
        System.out.println("Minimum cost: " + matrixChain(p)); // 158
        System.out.println("Order: " + parens(1, 4)); // ((A1 x (A2 x A3)) x A4)
    }
}
```

## 7. Flow Shop Scheduling (Johnson's Rule)

**Problem:** Schedule `n` jobs on a set of machines where **every job passes through the machines in the same order**, minimizing the total completion time (*makespan*). Central to manufacturing and production planning.

General flow shop scheduling (3+ machines) is NP-Hard and is attacked with branch and bound, DP, heuristics, and meta-heuristics. The classic **two-machine** case is solved optimally by **Johnson's Rule**:

1. Scan all remaining jobs for the smallest processing time on either machine.
2. If that minimum is on **Machine 1**, place the job in the **first** empty slot of the sequence; if on **Machine 2**, place it in the **last** empty slot.
3. Remove the job and repeat until all jobs are placed.

### 7.1 Worked Example

| Job | M1 | M2 |
|---|---|---|
| J1 | 3 | 6 |
| J2 | 7 | 2 |
| J3 | 4 | 7 |
| J4 | 5 | 3 |
| J5 | 1 | 5 |

Smallest time overall is J5's 1 on M1 → J5 goes first. Next smallest is J2's 2 on M2 → J2 goes last. Then J4's 3 on M2 → last empty slot (before J2). Then J1's 3 on M1 → first empty slot (after J5). J3 fills the middle.

**Sequence: J5 → J1 → J3 → J4 → J2**, makespan **24** (M1 finishes the jobs at times 1, 4, 8, 13, 20; M2 finishes them at 6, 12, 19, 22, 24).

### 7.2 Java Implementation — O(n log n)

```java
import java.util.*;

public class JohnsonsRule {

    // jobs[i] = {timeM1, timeM2}; returns optimal sequence (0-based indices)
    static int[] schedule(int[][] jobs) {
        int n = jobs.length;
        Integer[] idx = new Integer[n];
        for (int i = 0; i < n; i++) idx[i] = i;

        // Sort by min(m1, m2); ties keep stable order
        Arrays.sort(idx, Comparator.comparingInt(
                i -> Math.min(jobs[i][0], jobs[i][1])));

        int[] seq = new int[n];
        int front = 0, back = n - 1;
        for (int i : idx) {
            if (jobs[i][0] <= jobs[i][1]) seq[front++] = i; // min on M1 -> front
            else                          seq[back--]  = i; // min on M2 -> back
        }
        return seq;
    }

    static int makespan(int[][] jobs, int[] seq) {
        int t1 = 0, t2 = 0;
        for (int i : seq) {
            t1 += jobs[i][0];              // M1 finishes job i
            t2 = Math.max(t2, t1) + jobs[i][1]; // M2 starts when both free
        }
        return t2;
    }

    public static void main(String[] args) {
        int[][] jobs = {{3, 6}, {7, 2}, {4, 7}, {5, 3}, {1, 5}};
        int[] seq = schedule(jobs);

        StringBuilder sb = new StringBuilder();
        for (int i : seq) sb.append("J").append(i + 1).append(" ");
        System.out.println("Sequence: " + sb.toString().trim()); // J5 J1 J3 J4 J2
        System.out.println("Makespan: " + makespan(jobs, seq));  // 24
    }
}
```

## 8. Optimal Binary Search Tree

A **Binary Search Tree (BST)** keeps values in internal nodes: every node's left subtree holds smaller values, and its right subtree holds larger-or-equal values. Search costs O(n) worst case in a plain BST and O(log n) in a balanced BST.

An **Optimal BST** goes further: given the **search frequency** of each key, it arranges the keys so the *expected* search cost is minimal — frequently searched keys sit near the root. Applications: databases, search engines, compilers.

Search cost of a key = `frequency × depth` (root depth = 1). Total cost = sum over all keys.

**State:** `cost[i][j]` = minimum cost of a BST containing keys `i..j`.

**Transition:** try every key `r` in `[i, j]` as root. Both subtrees sink one level deeper, which adds the sum of all frequencies in the range once:

```
cost[i][j] = min over r of ( cost[i][r-1] + cost[r+1][j] ) + sum(freq[i..j])
```

### 8.1 Worked Example A — Two Keys

Keys `{10, 12}`, frequencies `{34, 50}`:

- Tree 1 (10 as root, 12 below): cost = 34·1 + 50·2 = **134**
- Tree 2 (12 as root, 10 below): cost = 50·1 + 34·2 = **118** ✔ optimal

### 8.2 Worked Example B — Three Keys

Keys `{5, 15, 25}`, frequencies `{30, 10, 55}`. The five possible BST shapes cost:

| Tree | Structure | Cost |
|---|---|---|
| 1 | 5 → 15 → 25 (right chain) | 30·1 + 10·2 + 55·3 = 215 |
| 2 | 15 root, children 5 and 25 | 10·1 + 30·2 + 55·2 = 180 |
| 3 | 25 → 15 → 5 (left chain) | 55·1 + 10·2 + 30·3 = 165 |
| 4 | 5 root, then 25, then 15 | 30·1 + 55·2 + 10·3 = 170 |
| 5 | 25 root, 5 child, 15 grandchild | 55·1 + 30·2 + 10·3 = **145** ✔ |

Optimal: root 25, left child 5, and 15 as right child of 5 — cost **145**.

### 8.3 Java Implementation — O(n³) Time, O(n²) Space

```java
public class OptimalBST {

    static int optimalBST(int[] keys, int[] freq) {
        int n = keys.length;
        int[][] cost = new int[n + 2][n + 1]; // cost[i][j], 1-based keys
        int[][] root = new int[n + 1][n + 1];

        // prefix sums of frequencies
        int[] pre = new int[n + 1];
        for (int i = 1; i <= n; i++) pre[i] = pre[i - 1] + freq[i - 1];

        for (int len = 1; len <= n; len++) {
            for (int i = 1; i + len - 1 <= n; i++) {
                int j = i + len - 1;
                cost[i][j] = Integer.MAX_VALUE;
                int fsum = pre[j] - pre[i - 1];

                // try each key r as root of keys i..j
                for (int r = i; r <= j; r++) {
                    int left  = (r > i) ? cost[i][r - 1] : 0;
                    int right = (r < j) ? cost[r + 1][j] : 0;
                    int t = left + right + fsum;
                    if (t < cost[i][j]) {
                        cost[i][j] = t;
                        root[i][j] = r;
                    }
                }
            }
        }
        return cost[1][n];
    }

    public static void main(String[] args) {
        System.out.println(optimalBST(
                new int[]{10, 12}, new int[]{34, 50}));       // 118
        System.out.println(optimalBST(
                new int[]{5, 15, 25}, new int[]{30, 10, 55})); // 145
    }
}
```

> The full textbook formulation also assigns probabilities to *unsuccessful* searches (the null external nodes `y0..yn`); the algorithm is the same with the frequency sum extended to include them. Knuth's optimization reduces the runtime to O(n²).

## 9. NP-Hard and NP-Complete

So far, every problem in this chapter except TSP has a polynomial-time algorithm. Complexity theory classifies decision problems by how hard they are to solve.

### 9.1 The Class NP

**NP (Nondeterministic Polynomial time)** is the class of decision problems for which a "yes" answer has a **proof (certificate) verifiable in polynomial time** by a deterministic Turing machine.

An equivalent definition: problems solvable in polynomial time by a *nondeterministic* Turing machine — an algorithm in two phases:

1. **Guess** (nondeterministic): propose a candidate solution.
2. **Verify** (deterministic): check in polynomial time whether the guess is a solution.

Example: for TSP-as-a-decision-problem ("is there a tour of cost ≤ B?"), verifying a proposed tour is easy — add up its edges. *Finding* one is the hard part.

### 9.2 NP-Complete and NP-Hard

A language/problem **B is NP-Complete** if it meets **both** requirements:

1. B is in NP.
2. Every problem A in NP is polynomial-time reducible to B.

A problem is **NP-Hard** if it meets requirement 2 but **not necessarily requirement 1** — it is *at least as hard as* everything in NP, even if it isn't itself in NP (it may not even be a decision problem, e.g., optimization TSP).

```
        ┌──────────────────────────────┐
        │           NP-Hard            │
        │   ┌──────────────────────┐   │
        │   │     NP-Complete      │   │
        └───┼──────────────────────┼───┘
        ┌───┼──────────────────────┼───┐
        │   └──────────────────────┘   │
        │             NP               │
        │        ┌─────────┐           │
        │        │    P    │           │
        │        └─────────┘           │
        └──────────────────────────────┘
   (assuming P ≠ NP; if P = NP the picture collapses)
```

**The key consequence:** if a polynomial-time algorithm is ever found for *any* NP-Complete problem, then **every** problem in NP is polynomial-time solvable (P = NP). No such algorithm is known, and no proof that none exists — this is the P vs NP problem.

### 9.3 Examples

**NP-Complete problems** (no known polynomial-time algorithm):

- **Hamiltonian Cycle:** does a graph contain a cycle visiting every vertex exactly once?
- **Boolean Satisfiability (SAT):** is there a truth assignment making a Boolean formula true? (Cook–Levin theorem: SAT was the first problem proven NP-Complete.)
- Circuit satisfiability, Vertex Cover, Set Cover, Subset Sum — all NP-Complete in their decision forms.

**NP-Hard problems:**

- Optimization TSP (find the *minimum* tour, not just decide a bound)
- Circuit-satisfiability, Set Cover, Vertex Cover in their general/optimization forms
- Halting problem (NP-Hard but *not* NP-Complete — it's undecidable)

### 9.4 Why This Matters for DP

DP does not repeal NP-Hardness — Held–Karp TSP is still exponential (O(n²·2ⁿ)), just exponentially better than O(n!). And 0/1 Knapsack's O(nW) is **pseudo-polynomial**: `W` appears as a *number*, not as input length, so knapsack remains NP-Complete. For NP-Hard problems in practice we rely on DP over small state spaces, branch and bound, approximation algorithms, and heuristics.

## 10. Conclusion & Key Facts

Dynamic programming decomposes a problem into smaller subproblems like divide and conquer, but the subproblems **overlap** — so their solutions are stored and reused rather than solved independently. Unlike greedy algorithms (local optimization), dynamic algorithms optimize globally.

| Topic | One-line summary | Complexity |
|---|---|---|
| Floyd–Warshall (APSP) | Shortest path between every vertex pair via progressive intermediates | O(n³) |
| 0/1 Knapsack | Take items whole or not at all to maximize value under a weight cap | O(nW), pseudo-polynomial |
| TSP (Held–Karp) | Minimum-cost tour visiting each city once, via subset DP | O(n²·2ⁿ) |
| Coin Changing | Minimum coins (or count of ways) to form an amount | O(amount × coins) |
| Matrix Chain | Cheapest parenthesization of a matrix product chain | O(n³) |
| Flow Shop (2 machines) | Johnson's rule: min time on M1 → front, on M2 → back | O(n log n) |
| Optimal BST | Frequent keys near the root to minimize expected search cost | O(n³), O(n²) with Knuth |
| NP-Complete | In NP and everything in NP reduces to it | No known poly algorithm |
| NP-Hard | At least as hard as all of NP; need not be in NP | — |
