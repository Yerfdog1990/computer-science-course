# Greedy Algorithm 

## 1. Introduction

A **greedy algorithm** is a problem-solving strategy — in the same family as divide-and-conquer, dynamic programming, backtracking, and branch-and-bound. Each of these paradigms solves problems differently:

- **Divide and Conquer** — split the problem into subparts, solve each, then combine the solutions.
- **Backtracking** — explore a path and undo (go backward) when it fails.
- **Greedy** — at every stage, make the choice that looks best *right now*, without worrying whether it leads to the overall best outcome.

A greedy algorithm builds a solution piece by piece, always picking the next option that gives the most immediate, locally optimal benefit. It assumes that a series of locally optimal choices will add up to a globally optimal solution — and once a choice is made, it is **never reconsidered or reversed**.

---

## 2. What Problems Does It Solve?

Greedy algorithms are used to solve **optimization problems** — problems where you want either the *minimum* or *maximum* result:

- **Minimum cost** → considered the "best" solution when cost is involved.
- **Maximum profit** → considered the "best" solution when profit/value is involved.

The problem is solved in **multiple stages/steps**. At each stage, a decision is made based on some parameter relevant to that specific problem — e.g., cost, distance, profit, or time. Because a decision is made greedily at every single stage (without looking ahead), this approach is called the **greedy approach**.

---

## 3. Key Terminology: Feasible vs. Optimal Solutions

For any optimization problem, there's usually more than one way to solve it. Two terms distinguish the "good enough" solutions from the "best" one:

- **Feasible Solution** — any solution that satisfies the problem's given constraint(s). A problem can have **many** feasible solutions.
- **Optimal Solution** — a feasible solution that also achieves the problem's objective (the actual minimum or maximum result). Unlike feasible solutions, a problem has **only one** optimal solution — there is exactly one true minimum (or maximum).

**Example:** Suppose the problem is to travel from location A to location B.
- Possible solutions: walk, bike, car, train, flight.
- Constraint: the journey must be completed within 12 hours. If walking and driving can't meet that, only train and flight are **feasible**.
- If the goal is also to minimize cost, and train turns out to be the cheapest feasible option, then train is the **optimal solution** — it's feasible *and* it satisfies the objective (minimum cost) better than any other feasible option.

So:
- **Feasible** = satisfies the constraint(s).
- **Optimal** = feasible **and** achieves the best (min/max) result — and it's unique.

---

## 4. The General Greedy Algorithm Procedure

Greedy method solves a problem in **stages**. At each stage, it looks at one input from the problem, checks whether including it keeps the solution feasible, and if so, adds it to the solution. Repeating this across all inputs builds up the optimal solution.

In pseudocode form, for an input set `a[1..n]`:

```
Greedy(a, n):
    solution = {}                     // start with an empty solution
    for i = 1 to n:
        x = select(a, i)              // pick the next candidate input
        if feasible(solution, x):     // check if adding x keeps it valid
            solution = solution ∪ {x} // include x in the solution
    return solution
```

Each problem defines its own `select()` (how to pick/prioritize inputs) and `feasible()` (what counts as a valid partial solution) — that's what makes the same general procedure apply to very different problems (Knapsack, Job Sequencing, MST, etc.).

### Real-World Analogies

**Choosing the "best" car:** One approach is to exhaustively compare every brand and model in the market before deciding — thorough, but extremely time-consuming. The greedy approach instead narrows down in stages: filter to a few preferred brands, then to their top models, then to the latest/best-tested release among those. The result is called the "best" car — not because every option was checked, but because it's the best *according to the selection procedure used at each stage*.

**Hiring the "best" candidate:** Similarly, out of thousands of applicants, a company doesn't put every candidate through every possible test. It filters in stages — written test, then group discussion, then technical interview, then HR round — narrowing the pool at each step. Whoever remains at the end is the "best" candidate *according to that filtering process*, even though not everyone was evaluated on every criterion.

Both examples capture the essence of greedy: define a selection method upfront, then apply it consistently at each stage without revisiting earlier decisions — trading exhaustive certainty for speed.

---

## 5. How a Greedy Algorithm Works

At each decision point, the algorithm evaluates the available candidates using a rule (the "greedy heuristic") and picks the best immediate option — no lookahead, no reconsideration. Four components define this process:

| Component | Role |
|---|---|
| **Candidate Set** | The pool of options from which the solution is built |
| **Selection Function** | Chooses the best immediate candidate to add |
| **Feasibility Function** | Checks whether adding a candidate keeps the solution valid |
| **Objective Function** | Scores a (partial) solution — e.g., maximize profit, minimize cost |

---

## 6. Core Requirements for Correctness

A greedy algorithm only guarantees a truly optimal answer when the problem has **both** of these properties:

1. **Greedy Choice Property** — Making the locally optimal choice at each step, without backtracking, still leads to a global optimum.
2. **Optimal Substructure** — The optimal solution to the whole problem is built from optimal solutions to its smaller subproblems.

If a problem lacks either property, greedy may produce a solution that is fast but *not* actually optimal.

---

## 7. Classic Example: Coin Change (When Greedy Works vs. Fails)

**Goal:** Make change for a target amount using the fewest coins.

### ✅ Standard US Currency (25¢, 10¢, 5¢, 1¢) — target: 63¢
| Step | Choice | Remaining |
|---|---|---|
| 1 | 25¢ | 38¢ |
| 2 | 25¢ | 13¢ |
| 3 | 10¢ | 3¢ |
| 4–6 | 1¢, 1¢, 1¢ | 0¢ |

**Result:** 6 coins total (25, 25, 10, 1, 1, 1) → this **is** the global optimum. Greedy works here.

### ❌ Arbitrary Currency (25¢, 20¢, 1¢) — target: 40¢
- **Greedy choice:** 25¢ first → then fifteen 1¢ coins → **16 coins total**
- **Actual optimal:** two 20¢ coins → **2 coins total**

**Result:** Greedy fails here — it gets trapped by an early locally-optimal choice (the 25¢ coin) and misses the better global solution. Dynamic programming would be needed to guarantee the true optimum in this case.

**Takeaway:** Greedy is fast but only trustworthy when the problem has the greedy-choice property and optimal substructure — otherwise it can produce a suboptimal (but still valid) answer.

## 8. Applications / Famous Greedy Algorithms

These are classic problems where the greedy method is applied — some are *provably* optimal, others are approximations:

| Algorithm / Problem | What It Does |
|---|---|
| **Knapsack Problem** (0/1 & Fractional) | Choose items with weight & value to maximize total value under a weight limit. *Fractional Knapsack* is solved optimally by greedy (sort by value/weight ratio, take as much of the best item as possible); *0/1 Knapsack* is not perfectly greedy-solvable (needs DP). |
| **Job Sequencing with Deadlines** | Find a sequence of jobs, each with a deadline, that maximizes total profit within those deadlines. |
| **Minimum Cost Spanning Tree (MST)** | Find a subset of edges in a connected, weighted, undirected graph that connects all vertices with minimum total edge weight. Solved via **Kruskal's** or **Prim's Algorithm**, both of which repeatedly pick the cheapest available edge. |
| **Single-Source Shortest Path (Dijkstra's Algorithm)** | Finds the shortest path from a source vertex to all others by always expanding the closest unvisited vertex. |
| **Optimal Storage on Tapes** | Finds the optimal retrieval time/order for programs stored sequentially on tape. |
| **Optimal Merge Pattern** | Combines multiple sorted files of varying lengths into one sorted file in the least possible time. |
| **Subset Cover Problem** | Given a collection of elements, find the minimum number of sets needed to cover (include) all of them. |
| **Container Loading Problem** | Another classic greedy application (load selection to optimize capacity/value). |
| **Huffman Coding** | A data compression technique — builds a tree by repeatedly merging the two lowest-frequency characters. |

> Note: The Knapsack problem also appears in Dynamic Programming and Branch & Bound — the difference here is that it's solved using the **greedy method**.

## 9. Advantages vs. Limitations

| Advantages | Limitations |
|---|---|
| **Highly efficient** — typically O(n) or O(n log n), since it usually takes a single pass through the data | **No guarantee of optimality** — can get stuck in a local optimum and miss the true global best |
| **Simple design** — easy to conceptualize, implement, and debug | **No backtracking** — can't recover from a bad early decision made with incomplete information |
| **Great for approximation** — useful when an exact answer is too slow to compute (e.g., NP-Hard problems), giving a fast, reasonable baseline | **Hard to prove correctness** — showing a greedy approach works for *all* cases can be mathematically difficult |

## 11. Quick Summary

- Greedy algorithms solve **optimization problems** (min cost / max profit) in **multiple stages**, making the locally best decision at each stage without revisiting it.
- A **feasible solution** satisfies the constraint(s); an **optimal solution** is feasible *and* achieves the true min/max objective — and it's unique, unlike feasible solutions which can be many.
- The general procedure: go through inputs one at a time, and include each one in the solution if doing so keeps it feasible.
- They only guarantee a **true global optimum** when the problem has the **greedy-choice property** and **optimal substructure**.
- They are **fast and simple**, making them great for approximations, but **not always correct** — as shown by the coin-change counterexample.
- Well-known optimal use cases: **Dijkstra's, Kruskal's/Prim's (MST), Huffman Coding, Fractional Knapsack**.
