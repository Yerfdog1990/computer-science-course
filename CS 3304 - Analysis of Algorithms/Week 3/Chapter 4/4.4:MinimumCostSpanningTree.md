# Minimum Cost Spanning Tree 

## 1. What Is a Spanning Tree?

Given a **connected, undirected graph** G = (V, E), a **spanning tree** of G is a subgraph that:

- **Includes every vertex** of G (spans the whole graph).
- **Is connected** — there's a path between any two vertices.
- **Contains no cycles** (it's acyclic — a tree).
- Has exactly **V − 1 edges**, where V is the number of vertices.

There can be **many different spanning trees** for the same graph, depending on which edges you keep.

## 2. What Is a Minimum Spanning Tree (MST)?

The **cost** of a spanning tree is the sum of the weights of all its edges. Among all possible spanning trees of a graph, the **Minimum Spanning Tree (MST)** is the one with the **lowest total cost**. (There can be more than one MST if several trees tie for the lowest cost.)

**Intuition:** Imagine a city wants to pave roads connecting 5 neighborhoods. An MST finds the cheapest possible road network that connects every neighborhood — with no redundant loops wasting money.

### Properties of a Spanning Tree / MST

| Property | Description |
|---|---|
| Vertex count | Same number of vertices (V) as the original graph |
| Edge count | Exactly V − 1 edges |
| Connectivity | Single connected component — no isolated vertices |
| Acyclic | No cycles anywhere in the tree |
| Cost | Sum of edge weights — minimized for an MST specifically |

### Applications

- **Network design** — minimum-cost cabling/wiring to connect all nodes (utility grids, computer networks).
- **Approximation algorithms** — used as a building block for approximating the Traveling Salesman Problem, multi-terminal minimum cut, and minimum-cost weighted perfect matching.
- **Cluster analysis** and **image segmentation** — grouping similar data points/pixels.
- **Handwriting recognition**.
- **GPS routing** — finding low-cost delivery routes across multiple stops.
- **Phylogenetic trees** in biology — modeling evolutionary relationships.

There are three well-known greedy algorithms for finding an MST: **Kruskal's**, **Prim's**, and **Boruvka's**. All three are greedy, but they build the tree in different ways.

## 3. Kruskal's Algorithm

Kruskal's algorithm builds the MST by considering **edges** one at a time, always picking the cheapest edge available that doesn't create a cycle.

### 3.1 Algorithm Steps

1. **Sort** all edges of the graph in increasing order of weight.
2. Starting from the smallest edge, **add edges one by one** to the growing MST.
3. **Only add an edge if it doesn't form a cycle** — i.e., only if it connects two currently-disconnected components.
4. Stop once V − 1 edges have been added (all vertices are connected).

### 3.2 Checking for Cycles: Disjoint Sets

The key question at each step is: *are these two vertices already connected?* A DFS/BFS check would work but costs O(V + E) per check — too slow to repeat for every edge. Instead, Kruskal's uses a **Disjoint Set (Union-Find)** data structure:

- Each vertex starts in its own separate set.
- Before adding an edge (u, v), check whether u and v are already in the **same set** (`find(u) == find(v)`) — if so, adding this edge would create a cycle, so skip it.
- Otherwise, add the edge and **union** the two sets together.

Using **path compression** and **union by rank**, both `find` and `union` run in nearly constant time, making the overall check very fast.

### 3.3 Worked Example 1 — Conceptual Walkthrough (5 vertices)

Suppose a graph has edges with weights including 1, 2, 3, 4, 5 (among others). Kruskal's proceeds as follows:

- Sort edges ascending. Start with the **weight-1** edge — add it (trivially no cycle yet).
- Next, the **weight-2** edge — the two edges (1 and 2) touch disjoint parts of the graph, so both are added safely.
- Next, the **weight-3** edge — this one happens to connect the two separate pieces built so far, so it's added, merging them into one component.
- Next, the **weight-4** edge — both its endpoints are now in the *same* component (thanks to the edges already added), so adding it would create a cycle. **Skip it.**
- Next, the **weight-5** edge — this connects a still-disconnected vertex to the rest, so it's added.
- Any remaining edges only connect vertices already in the same component, so they're all skipped.

**Final MST cost:** 1 + 2 + 3 + 5 = **11**

This illustrates the core Kruskal's behavior: greedily take the cheapest edge, but reject any edge that would close a cycle.

### 3.4 Worked Example 2 — Full Trace on a 4-Vertex Graph

Consider 4 vertices A, B, C, D with these 5 edges:

| Edge | Weight |
|---|---|
| A–B | 1 |
| B–C | 2 |
| A–C | 3 |
| A–D | 4 |
| D–C | 5 |

**Step-by-step (sorted by weight ascending: 1, 2, 3, 4, 5):**

| Edge Considered | Components Before | Action |
|---|---|---|
| A–B (1) | {A}, {B}, {C}, {D} | A and B in different sets → **add** → {A,B}, {C}, {D} |
| B–C (2) | {A,B}, {C}, {D} | B and C in different sets → **add** → {A,B,C}, {D} |
| A–C (3) | {A,B,C}, {D} | A and C already in the **same** set → would form a cycle → **reject** |
| A–D (4) | {A,B,C}, {D} | A and D in different sets → **add** → {A,B,C,D} |

Now all 4 vertices are connected with 3 edges (V − 1 = 3) — done. The last edge, D–C (5), is never needed.

**MST edges:** A–B, B–C, A–D
**Minimum cost:** 1 + 2 + 4 = **7**

**For contrast:** an arbitrary (non-minimum) spanning tree using edges A–D (4), D–C (5), B–C (2) is also valid — it connects all 4 vertices with no cycle — but costs 4 + 5 + 2 = **11**, which is worse than the true MST cost of 7. This shows why simply picking *any* spanning tree isn't good enough — Kruskal's guarantees the cheapest one.

### 3.5 Worked Example 3 — Full 5-Vertex Named Trace

Consider 5 vertices A, B, C, D, E with these 7 edges:

| Edge | AB | AC | AD | AE | BC | CD | DE |
|---|---|---|---|---|---|---|---|
| Weight | 1 | 7 | 10 | 5 | 3 | 4 | 2 |

**Sorted ascending:** AB(1), DE(2), BC(3), CD(4), AE(5), AC(7), AD(10)

| Step | Edge Considered | Action |
|---|---|---|
| 1 | AB (1) | No cycle → **add** → components {A,B}, {C}, {D}, {E} |
| 2 | DE (2) | No cycle → **add** → components {A,B}, {C}, {D,E} |
| 3 | BC (3) | Connects {A,B} and {C} → **add** → components {A,B,C}, {D,E} |
| 4 | CD (4) | Connects {A,B,C} and {D,E} → **add** → components {A,B,C,D,E} |
| 5 | AE (5) | A and E already in the same component → **cycle, reject** |
| 6 | AC (7) | A and C already in the same component → **cycle, reject** |
| 7 | AD (10) | A and D already in the same component → **cycle, reject** |

Once 4 edges are added (V − 1 = 4 for 5 vertices), the tree is complete — the remaining edges (AE, AC, AD) all get rejected since they'd close a cycle.

**MST edges:** AB, DE, BC, CD
**Minimum Spanning Cost:** 1 + 2 + 3 + 4 = **10**

### 3.6 Time Complexity

The dominant cost is **sorting the edges**: O(E log E), which is equivalent to O(E log V) since E is at most V². The Union-Find operations (with path compression and union by rank) add only a near-constant-time overhead per edge.

**Overall: O(E log V)**

### 3.7 Java Implementation (Kruskal's, with Union-Find)

```java
import java.util.ArrayList;
import java.util.Collections;
import java.util.List;

public class KruskalMST {

    // Represents a single weighted edge between two vertices
    static class Edge {
        int u, v, weight;
        Edge(int u, int v, int weight) {
            this.u = u;
            this.v = v;
            this.weight = weight;
        }
    }

    // Disjoint Set (Union-Find) with path compression and union by rank
    static class DisjointSet {
        int[] parent, rank;

        DisjointSet(int n) {
            parent = new int[n];
            rank = new int[n];
            for (int i = 0; i < n; i++) {
                parent[i] = i;
            }
        }

        int find(int x) {
            if (parent[x] != x) {
                parent[x] = find(parent[x]); // path compression
            }
            return parent[x];
        }

        void union(int x, int y) {
            int rootX = find(x);
            int rootY = find(y);
            if (rootX == rootY) return;

            // union by rank: attach smaller-rank tree under larger-rank root
            if (rank[rootX] < rank[rootY]) {
                parent[rootX] = rootY;
            } else if (rank[rootX] > rank[rootY]) {
                parent[rootY] = rootX;
            } else {
                parent[rootY] = rootX;
                rank[rootX]++;
            }
        }
    }

    static int kruskalMST(int numVertices, List<Edge> edges) {
        // Step 1: sort edges by weight, ascending
        Collections.sort(edges, (a, b) -> a.weight - b.weight);

        DisjointSet ds = new DisjointSet(numVertices);
        int minimumCost = 0;
        int edgesUsed = 0;

        // Step 2 & 3: add edges one by one, skipping any that form a cycle
        for (Edge e : edges) {
            if (ds.find(e.u) != ds.find(e.v)) {
                ds.union(e.u, e.v);
                minimumCost += e.weight;
                edgesUsed++;
                System.out.println("Added edge " + e.u + "-" + e.v + " (weight " + e.weight + ")");
                if (edgesUsed == numVertices - 1) break; // MST complete
            }
        }
        return minimumCost;
    }

    public static void main(String[] args) {
        // Example from Section 3.4: A=0, B=1, C=2, D=3
        List<Edge> edges = new ArrayList<>();
        edges.add(new Edge(0, 1, 1)); // A-B
        edges.add(new Edge(1, 2, 2)); // B-C
        edges.add(new Edge(0, 2, 3)); // A-C
        edges.add(new Edge(0, 3, 4)); // A-D
        edges.add(new Edge(3, 2, 5)); // D-C

        int cost = kruskalMST(4, edges);
        System.out.println("Minimum Cost Spanning Tree weight: " + cost);
        // Expected output: 7 (edges A-B, B-C, A-D)
    }
}
```

## 4. Prim's Algorithm

Prim's algorithm also uses a greedy approach, but instead of picking edges independently, it **grows the tree one vertex at a time** starting from an arbitrary vertex.

### 4.1 Algorithm Steps

1. Maintain two groups of vertices: those **already in** the growing spanning tree, and those **not yet in** it.
2. At each step, pick the **cheapest edge** connecting a vertex inside the tree to a vertex outside it, and add that vertex (and edge) to the tree. This is efficiently done with a **Priority Queue** — push all edges reachable from the tree into it, and always pop the minimum.
3. Skip (don't re-add) any vertex that's already marked as included — this naturally avoids cycles.
4. Repeat until every vertex has joined the tree.

In some textbooks this is phrased using the term **fringe vertex** — a vertex not yet in the tree but directly connected (by one edge) to a vertex that *is* in the tree:

1. Pick a starting vertex (any vertex works).
2. While fringe vertices remain:
    - Choose the **minimum-weight edge** that connects a tree vertex to a fringe vertex.
    - Include that vertex and edge in the growing spanning tree.
3. Exit once no fringe vertices remain (every vertex has joined the tree).

### 4.2 Worked Example — Same 4-Vertex Graph as Section 3.4

Using the same graph: A–B(1), B–C(2), A–C(3), A–D(4), D–C(5). Start arbitrarily at **A**.

| Step | Tree So Far | Frontier Edges Available | Cheapest Chosen |
|---|---|---|---|
| 1 | {A} | A–B(1), A–C(3), A–D(4) | **A–B (1)** → add B |
| 2 | {A, B} | A–C(3), A–D(4), B–C(2) | **B–C (2)** → add C |
| 3 | {A, B, C} | A–D(4), D–C(5) | **A–D (4)** → add D |
| 4 | {A, B, C, D} | — all vertices included | done |

**MST edges:** A–B, B–C, A–D
**Minimum cost:** 1 + 2 + 4 = **7**

Notice this matches Kruskal's result exactly (as it should — the MST cost is unique even if the specific tie-breaking or vertex order differs).

### 4.3 Worked Example — Starting from an Interior Vertex

Prim's algorithm can start from **any** vertex — not necessarily "the first one" — and still reaches the correct MST. Consider a 5-vertex graph (A, B, C, D, E) where the algorithm starts at vertex **E** instead:

| Step | Tree So Far | Candidate Edges Compared | Chosen |
|---|---|---|---|
| 1 | {E} | EA (weight 8), EB (weight 3) | **EB (3)** is cheaper → add B |
| 2 | {E, B} | BC has the minimum weight among edges leaving {E,B} | **BC** → add C (no cycle) |
| 3 | {E, B, C} | BD has the minimum weight among remaining edges | **BD** → add D (no cycle) |
| 4 | {E, B, C, D} | DC would form a cycle → rejected; of the remaining candidates AB and AD, AD would form a cycle → rejected | **AB** → add A |
| 5 | {E, B, C, D, A} | — all vertices included | done |

**Final tree edges, in the order added:** EB → BC → BD → AB

This example illustrates two useful points:
- **The starting vertex doesn't matter** — Prim's still greedily grows outward and reaches the correct MST regardless of where it begins.
- **Rejected candidates are still compared at each step** — DC and AD are considered but discarded specifically because they would close a cycle, exactly like Kruskal's cycle check, just applied one *frontier* at a time instead of globally sorted.

*(Note: only edges EA=8, EB=3, and BC=1 have explicit weights in this particular example; the exact weights of BD, DC, AB, and AD aren't specified in the source material, so a total cost isn't computed here — the value of this example is in the step-by-step selection process itself.)*

### 4.4 Time Complexity

Each vertex is inserted into the priority queue once, and each insertion/removal costs O(log V). Across all vertices and edges:

**Overall: O((V + E) log V)**

### 4.5 Java Implementation (Prim's, with Priority Queue)

```java
import java.util.ArrayList;
import java.util.List;
import java.util.PriorityQueue;

public class PrimMST {

    // Represents an edge (to a neighboring vertex) with its weight
    static class Edge {
        int weight, vertex;
        Edge(int weight, int vertex) {
            this.weight = weight;
            this.vertex = vertex;
        }
    }

    static int primMST(int numVertices, List<List<Edge>> adj, int start) {
        boolean[] visited = new boolean[numVertices];
        // Min-heap ordered by edge weight
        PriorityQueue<Edge> pq = new PriorityQueue<>((a, b) -> a.weight - b.weight);

        pq.add(new Edge(0, start));
        int minimumCost = 0;

        while (!pq.isEmpty()) {
            Edge current = pq.poll();
            int u = current.vertex;

            if (visited[u]) continue; // already in the tree — skip (avoids cycles)
            visited[u] = true;
            minimumCost += current.weight;

            // Push all edges from u to unvisited neighbors
            for (Edge neighbor : adj.get(u)) {
                if (!visited[neighbor.vertex]) {
                    pq.add(neighbor);
                }
            }
        }
        return minimumCost;
    }

    public static void main(String[] args) {
        // Example from Section 4.2: A=0, B=1, C=2, D=3
        int n = 4;
        List<List<Edge>> adj = new ArrayList<>();
        for (int i = 0; i < n; i++) adj.add(new ArrayList<>());

        // Add edges both directions (undirected graph)
        addEdge(adj, 0, 1, 1); // A-B
        addEdge(adj, 1, 2, 2); // B-C
        addEdge(adj, 0, 2, 3); // A-C
        addEdge(adj, 0, 3, 4); // A-D
        addEdge(adj, 3, 2, 5); // D-C

        int cost = primMST(n, adj, 0); // start at vertex A (0)
        System.out.println("Minimum Cost Spanning Tree weight: " + cost);
        // Expected output: 7
    }

    static void addEdge(List<List<Edge>> adj, int u, int v, int weight) {
        adj.get(u).add(new Edge(weight, v));
        adj.get(v).add(new Edge(weight, u));
    }
}
```

## 5. Boruvka's Algorithm

Boruvka's is the **oldest** MST algorithm (discovered in 1926, long before computers existed — originally published as a method for designing an efficient electricity network). It's also greedy, and its idea is similar to Prim's, but it grows **many components in parallel** instead of just one.

### 5.1 Algorithm Steps

1. Start with every vertex as its own separate component (a "forest" of single-vertex trees).
2. While more than one component remains:
    - For **each component**, find the **cheapest edge** connecting it to some *other* component.
    - Add all these cheapest edges to the MST (skipping any that would connect two vertices already in the same component, since a component's cheapest edge might be shared by another component too).
    - Merge the components joined by the newly added edges.
3. Repeat until only **one component** remains — that's the MST.

Because every component finds its cheapest edge *simultaneously* in each round, the number of components roughly **halves** each iteration, making this method naturally suited to parallel/distributed computation.

### 5.2 Worked Example (9 vertices, 0–8)

Starting state: every vertex 0–8 is its own component.

**Round 1 — cheapest edge per component:**

| Component | Cheapest Connecting Edge |
|---|---|
| {0} | 0–1 |
| {1} | 0–1 |
| {2} | 2–8 |
| {3} | 2–3 |
| {4} | 3–4 |
| {5} | 5–6 |
| {6} | 6–7 |
| {7} | 6–7 |
| {8} | 2–8 |

Adding these distinct edges gives: **{0-1, 2-8, 2-3, 3-4, 5-6, 6-7}**

**Components after Round 1:** {0,1}, {2,3,4,8}, {5,6,7}

**Round 2 — cheapest edge per (now larger) component:**

| Component | Cheapest Connecting Edge |
|---|---|
| {0,1} | 1–2 (or equivalently 0–7) |
| {2,3,4,8} | 2–5 |
| {5,6,7} | 2–5 |

Adding the new edges **1-2** and **2-5** merges everything into a single component: **{0,1,2,3,4,5,6,7,8}**.

**Final MST edges:** {0-1, 2-8, 2-3, 3-4, 5-6, 6-7, 1-2, 2-5} — that's 8 edges for 9 vertices (V − 1 = 8 ✓).

Using the standard weights for this well-known example graph (0-1=4, 1-2=8, 2-3=7, 2-5=4, 2-8=2, 3-4=9, 5-6=2, 6-7=1):

**Total MST weight = 4 + 8 + 7 + 4 + 2 + 9 + 2 + 1 = 37**

Since only one component remains, the algorithm stops and returns the MST.

### 5.3 Time Complexity

Each round processes all E edges to find the cheapest per component, and the number of components at least halves each round (so there are O(log V) rounds):

**Overall: O(E log V)** — the same as Kruskal's and Prim's.

**Fun fact:** Boruvka's algorithm is also used as a building block inside a faster **randomized linear-time O(E)** MST algorithm.

### 5.4 Java Implementation (Boruvka's, with Union-Find)

```java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

public class BoruvkaMST {

    private int V; // number of vertices
    private List<List<Integer>> graph; // each entry: [u, v, weight]

    BoruvkaMST(int vertices) {
        V = vertices;
        graph = new ArrayList<>();
    }

    void addEdge(int u, int v, int w) {
        graph.add(Arrays.asList(u, v, w));
    }

    // Union-Find with path compression
    private int find(List<Integer> parent, int i) {
        if (parent.get(i) == i) return i;
        return find(parent, parent.get(i));
    }

    // Union by rank
    private void union(List<Integer> parent, List<Integer> rank, int x, int y) {
        int xroot = find(parent, x);
        int yroot = find(parent, y);
        if (rank.get(xroot) < rank.get(yroot)) {
            parent.set(xroot, yroot);
        } else if (rank.get(xroot) > rank.get(yroot)) {
            parent.set(yroot, xroot);
        } else {
            parent.set(yroot, xroot);
            rank.set(xroot, rank.get(xroot) + 1);
        }
    }

    void boruvkaMST() {
        List<Integer> parent = new ArrayList<>();
        List<Integer> rank = new ArrayList<>();
        // cheapest.get(i) stores [u, v, w] — the cheapest edge found so far for component i
        List<List<Integer>> cheapest = new ArrayList<>();

        int numTrees = V;
        int mstWeight = 0;

        for (int node = 0; node < V; node++) {
            parent.add(node);
            rank.add(0);
            cheapest.add(Arrays.asList(-1, -1, -1));
        }

        // Keep merging components until only one remains
        while (numTrees > 1) {
            // Find the cheapest edge for every component
            for (List<Integer> edge : graph) {
                int u = edge.get(0), v = edge.get(1), w = edge.get(2);
                int set1 = find(parent, u), set2 = find(parent, v);

                if (set1 != set2) {
                    if (cheapest.get(set1).get(2) == -1 || cheapest.get(set1).get(2) > w) {
                        cheapest.set(set1, Arrays.asList(u, v, w));
                    }
                    if (cheapest.get(set2).get(2) == -1 || cheapest.get(set2).get(2) > w) {
                        cheapest.set(set2, Arrays.asList(u, v, w));
                    }
                }
            }

            // Add the cheapest edges found to the MST
            for (int node = 0; node < V; node++) {
                if (cheapest.get(node).get(2) != -1) {
                    int u = cheapest.get(node).get(0);
                    int v = cheapest.get(node).get(1);
                    int w = cheapest.get(node).get(2);
                    int set1 = find(parent, u), set2 = find(parent, v);

                    if (set1 != set2) {
                        mstWeight += w;
                        union(parent, rank, set1, set2);
                        System.out.println("Edge " + u + "-" + v + " with weight " + w + " included in MST");
                        numTrees--;
                    }
                }
            }

            // Reset cheapest[] for the next round
            for (List<Integer> entry : cheapest) {
                entry.set(2, -1);
            }
        }
        System.out.println("Weight of MST is " + mstWeight);
    }

    public static void main(String[] args) {
        BoruvkaMST g = new BoruvkaMST(4);
        g.addEdge(0, 1, 10);
        g.addEdge(0, 2, 6);
        g.addEdge(0, 3, 5);
        g.addEdge(1, 3, 15);
        g.addEdge(2, 3, 4);
        g.boruvkaMST();
        // Expected output: edges 0-3(5), 0-1(10), 2-3(4); Weight of MST is 19
    }
}
```

## 6. Complexity Comparison

| Algorithm | Time Complexity | Growth Style | Data Structure Used |
|---|---|---|---|
| **Kruskal's** | O(E log V) | Adds cheapest **edge** globally, skipping cycles | Disjoint Set (Union-Find) |
| **Prim's** | O((V + E) log V) | Grows **one tree** from a starting vertex | Priority Queue (Min-Heap) |
| **Boruvka's** | O(E log V) | Grows **many components in parallel** | Union-Find |

**When to prefer which:**
- **Kruskal's** tends to be simpler and works well when edges are already sorted or the graph is sparse.
- **Prim's** is often preferred for **dense graphs** since it doesn't need to sort all edges upfront.
- **Boruvka's** is the natural choice for **parallel/distributed** MST computation, since each round can process all components simultaneously.

## 7. Quick Summary

- A **spanning tree** connects all vertices of a graph with exactly V − 1 edges and no cycles; a **Minimum Spanning Tree (MST)** is the spanning tree with the lowest total edge weight.
- **Kruskal's Algorithm:** sort all edges by weight, greedily add the cheapest edge that doesn't form a cycle (checked via Union-Find). O(E log V).
- **Prim's Algorithm:** grow a single tree from a starting vertex, always adding the cheapest edge to an unvisited vertex (via a priority queue). O((V + E) log V).
- **Boruvka's Algorithm:** grow all components in parallel by having each one find its own cheapest connecting edge every round. O(E log V), and the oldest of the three (1926).
- All three algorithms are **greedy** and, despite different mechanics, always converge to the same minimum total cost for a given graph.
- MSTs have real-world uses in network design, clustering, image segmentation, routing, and approximating harder problems like the Traveling Salesman Problem.
