# Knapsack Problem 

## 1. What Is the Knapsack Problem?

You're given a set of items, each with a **weight** and a **profit (value)**, and a **knapsack** (bag/container) with a fixed weight capacity. The goal is to select items such that:

- The **total weight** of selected items ≤ the knapsack's capacity (the *constraint*).
- The **total profit** of selected items is **maximized** (the *objective*).

This is a classic **optimization problem** — specifically a **maximization** problem — and shows up constantly in real life: loading goods into a container/truck for transport, portfolio selection, resource allocation, and cutting/packing stock problems.

There are two major variants:

| Variant | Can you split an item? | Best solved with |
|---|---|---|
| **Fractional Knapsack** | Yes — you can take a fraction of an item | **Greedy algorithm** (this note's main focus) |
| **0/1 (Binary) Knapsack** | No — take the whole item or none of it | **Dynamic Programming** |

A helpful way to think about which applies: fractional knapsack suits *divisible* goods (e.g., grain, vegetables, liquids), while 0/1 knapsack suits *indivisible* goods (e.g., a washing machine — you can't take "half" of one).

## 2. Fractional Knapsack — Greedy Approach

### 2.1 Why Greedy Works Here

Since items can be split, the smartest move is to always take as much as possible of the item that gives you the **best profit per unit of weight** — i.e., the highest **profit-to-weight ratio**. This greedy choice is provably optimal for the fractional case (unlike 0/1 knapsack, where greedy can fail).

### 2.2 Step-by-Step Algorithm

1. For every item `i`, compute the ratio `P[i] / W[i]` (profit ÷ weight).
2. Sort items in **descending order** of this ratio.
3. Walk through the sorted list, and for each item:
    - If the item's full weight fits in the remaining capacity, take it entirely (`x = 1`).
    - If only part of it fits, take that fraction (`0 < x < 1`) and stop — the knapsack is now full.
    - If the capacity is already exhausted, skip the item (`x = 0`).
4. Total profit = Σ (xᵢ × Pᵢ); Total weight used = Σ (xᵢ × Wᵢ), guaranteed ≤ capacity.

### 2.3 Formal Notation

The problem is usually written with this notation:

- **n** = number of objects
- **m** = knapsack capacity
- **P** = profit array, **W** (or ω) = weight array
- **x** = solution vector, where each `xᵢ` ∈ [0, 1] tells you how much of object `i` to take (0 = skip, 1 = take fully, fraction = take partially)

**Constraint:** Σ xᵢωᵢ ≤ m  (total weight taken can't exceed capacity)
**Objective:** maximize Σ xᵢPᵢ  (total profit taken)

### 2.4 Worked Example (7 items, capacity = 15)

**Given:** n = 7, m = 15

| Item | Profit | Weight | Ratio (P/W) |
|---|---|---|---|
| 1 | 10 | 2 | 5.0 |
| 2 | 5 | 3 | 1.67 |
| 3 | 15 | 5 | 3.0 |
| 4 | 7 | 7 | 1.0 |
| 5 | 6 | 1 | 6.0 |
| 6 | 18 | 4 | 4.5 |
| 7 | 3 | 1 | 3.0 |

**Selection order (highest ratio first):** Item 5 → Item 1 → Item 6 → (Item 3 / Item 7, tied at ratio 3.0) → Item 2 (partial).

Working through the capacity of 15:
- Take Item 5 fully (weight 1) → 14 remaining
- Take Item 1 fully (weight 2) → 12 remaining
- Take Item 6 fully (weight 4) → 8 remaining
- Take Item 3 fully (weight 5) → 3 remaining
- Take Item 7 fully (weight 1) → 2 remaining
- Take Item 2 **partially**: only 2 of its 3 units fit → fraction = 2/3
- Item 4 gets **0** — no capacity left

**Solution vector (x₁ ... x₇), in item order 1–7:**

x = (1, 2/3, 1, 0, 1, 1, 1)

**Verify the constraint** Σ xᵢωᵢ ≤ m:

Σ xᵢωᵢ = 1×2 + 2/3×3 + 1×5 + 0×7 + 1×1 + 1×4 + 1×1
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;= 2 + 2 + 5 + 0 + 1 + 4 + 1 = **15** ✓ (exactly meets capacity m = 15)

**Verify the objective** Σ xᵢPᵢ:

Σ xᵢPᵢ = 1×10 + 2/3×5 + 1×15 + 0×7 + 1×6 + 1×18 + 1×3
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;= 10 + 2×1.3 + 15 + 0 + 6 + 18 + 3 = **54.6**

This confirms both the **feasibility** (weight constraint satisfied) and **optimality** (objective maximized) of the greedy solution.

### 2.5 More Worked Examples

**Example A** — n = 3, capacity = 20, profits = (25, 24, 15), weights = (18, 15, 10)
- Ratios: Item 1 = 25/18 ≈ 1.38, Item 2 = 24/15 = 1.6, Item 3 = 15/10 = 1.5
- Selection order: Item 2 → Item 3 → Item 1
- Item 2 fully (15) → 5 remaining; Item 3 fully (10)? Doesn't fit — only 5 units left, so take fraction 5/10 = 0.5 → profit 7.5; Item 1 gets 0.
- **Total profit = 24 + 7.5 + 0 = 31.5**

**Example B** — capacity = 30, items A/B/C/D with values (50,140,60,60), sizes (5,20,10,12) → ratios (10,7,6,5)
- Take A fully (5) → 25 left; take B fully (20) → 5 left; take C fraction 5/10 = 0.5 → profit 30; D gets 0.
- **Total profit = 50 + 140 + 30 + 0 = 220**

**Example C** — capacity = 60, items A/B/C/D, profits (280,100,120,120), weights (40,10,20,24) → ratios (7,10,6,5)
- Order by ratio: B → A → C → D
- Take B fully (10) → 50 left; take A fully (40) → 10 left; take C fraction 10/20 = 0.5 → profit 60; D gets 0.
- **Total profit = 100 + 280 + 60 + 0 = 440**

### 2.6 Java Implementation — Fractional Knapsack

```java
import java.util.Arrays;
import java.util.Comparator;

public class FractionalKnapsack {

    // Represents a single item with weight and profit
    static class Item {
        double weight;
        double profit;
        double ratio; // profit-to-weight ratio

        Item(double weight, double profit) {
            this.weight = weight;
            this.profit = profit;
            this.ratio = profit / weight;
        }
    }

    static double solveFractionalKnapsack(double capacity, Item[] items) {
        // Step 1: sort items by profit/weight ratio in descending order
        Arrays.sort(items, Comparator.comparingDouble((Item i) -> i.ratio).reversed());

        double remainingCapacity = capacity;
        double totalProfit = 0.0;

        // Step 2: greedily pick items
        for (Item item : items) {
            if (remainingCapacity <= 0) break;

            if (item.weight <= remainingCapacity) {
                // Take the entire item
                remainingCapacity -= item.weight;
                totalProfit += item.profit;
            } else {
                // Take only the fraction that fits
                double fraction = remainingCapacity / item.weight;
                totalProfit += item.profit * fraction;
                remainingCapacity = 0; // knapsack is now full
            }
        }
        return totalProfit;
    }

    public static void main(String[] args) {
        // Example from Section 2.3: profits and weights of 7 items
        Item[] items = {
            new Item(2, 10),
            new Item(3, 5),
            new Item(5, 15),
            new Item(7, 7),
            new Item(1, 6),
            new Item(4, 18),
            new Item(1, 3)
        };

        double capacity = 15;
        double maxProfit = solveFractionalKnapsack(capacity, items);
        System.out.println("Maximum profit: " + maxProfit); // ~54.6
    }
}
```

**Time Complexity:** O(n log n) — dominated by the sort step.
**Space Complexity:** O(n) for storing items.

## 3. 0/1 Knapsack Problem

### 3.1 Why Greedy Fails Here

Since items are indivisible, you can't just chase the best ratio — a locally "good" pick might block a better combination later. This lacks the greedy-choice guarantee, so we need **Dynamic Programming** to try all valid combinations efficiently.

### 3.2 Problem Statement

Given arrays `val[]` and `wt[]` (value and weight of each item) and capacity `W`, choose items to include (each either fully included or fully excluded) such that total value is maximized without the total weight exceeding `W`.

**Example:**
- Input: `W = 4, val = [1, 2, 3], wt = [4, 5, 1]` → Output: `3` (only the weight-1 item fits profitably)
- Input: `W = 3, val = [1, 2, 3], wt = [4, 5, 6]` → Output: `0` (nothing fits)

### 3.3 Recurrence Relation

For item `i` and remaining capacity `j`:
- If `wt[i] > j` (item too heavy): `dp[i][j] = dp[i-1][j]`
- Else (item fits — choose the better of including or excluding it):
  `dp[i][j] = max(dp[i-1][j], val[i] + dp[i-1][j - wt[i]])`

### 3.4 Java Implementations (4 approaches, increasing efficiency)

#### (a) Naive Recursion — O(2ⁿ) time, O(n) space

```java
public class Knapsack01Recursive {

    // Returns the max value achievable with n items and capacity W
    static int knapsackRec(int W, int[] val, int[] wt, int n) {
        // Base case: no items left or no capacity left
        if (n == 0 || W == 0) {
            return 0;
        }

        int pick = 0;
        // Option 1: pick the nth item, if it fits
        if (wt[n - 1] <= W) {
            pick = val[n - 1] + knapsackRec(W - wt[n - 1], val, wt, n - 1);
        }

        // Option 2: skip the nth item
        int notPick = knapsackRec(W, val, wt, n - 1);

        return Math.max(pick, notPick);
    }

    static int knapsack(int W, int[] val, int[] wt) {
        return knapsackRec(W, val, wt, val.length);
    }

    public static void main(String[] args) {
        int[] val = {1, 2, 3};
        int[] wt = {4, 5, 1};
        int W = 4;
        System.out.println(knapsack(W, val, wt)); // Output: 3
    }
}
```

This explores every include/exclude combination, so it's exponential — and it recomputes the same subproblems repeatedly.

#### (b) Top-Down DP with Memoization — O(n × W) time and space

```java
import java.util.Arrays;

public class Knapsack01Memoized {

    static int knapsackRec(int W, int[] val, int[] wt, int n, int[][] memo) {
        if (n == 0 || W == 0) {
            return 0;
        }

        // Return cached result if this subproblem was already solved
        if (memo[n][W] != -1) {
            return memo[n][W];
        }

        int pick = 0;
        if (wt[n - 1] <= W) {
            pick = val[n - 1] + knapsackRec(W - wt[n - 1], val, wt, n - 1, memo);
        }
        int notPick = knapsackRec(W, val, wt, n - 1, memo);

        // Cache and return
        return memo[n][W] = Math.max(pick, notPick);
    }

    static int knapsack(int W, int[] val, int[] wt) {
        int n = val.length;
        int[][] memo = new int[n + 1][W + 1];
        for (int[] row : memo) {
            Arrays.fill(row, -1);
        }
        return knapsackRec(W, val, wt, n, memo);
    }

    public static void main(String[] args) {
        int[] val = {1, 2, 3};
        int[] wt = {4, 5, 1};
        int W = 4;
        System.out.println(knapsack(W, val, wt)); // Output: 3
    }
}
```

#### (c) Bottom-Up DP with Tabulation — O(n × W) time and space

```java
public class Knapsack01Tabulation {

    static int knapsack(int W, int[] val, int[] wt) {
        int n = wt.length;
        int[][] dp = new int[n + 1][W + 1];

        // Build the table row by row (item by item)
        for (int i = 0; i <= n; i++) {
            for (int j = 0; j <= W; j++) {
                if (i == 0 || j == 0) {
                    dp[i][j] = 0; // base case: no items or no capacity
                } else {
                    int pick = 0;
                    if (wt[i - 1] <= j) {
                        pick = val[i - 1] + dp[i - 1][j - wt[i - 1]];
                    }
                    int notPick = dp[i - 1][j];
                    dp[i][j] = Math.max(pick, notPick);
                }
            }
        }
        return dp[n][W];
    }

    public static void main(String[] args) {
        int[] val = {1, 2, 3};
        int[] wt = {4, 5, 1};
        int W = 4;
        System.out.println(knapsack(W, val, wt)); // Output: 3
    }
}
```

#### (d) Space-Optimized Bottom-Up DP — O(n × W) time, O(W) space

```java
public class Knapsack01SpaceOptimized {

    static int knapsack(int W, int[] val, int[] wt) {
        int[] dp = new int[W + 1];

        // Process items one at a time
        for (int i = 1; i <= wt.length; i++) {
            // Traverse capacity from right to left so we don't
            // overwrite values from the "previous row" before using them
            for (int j = W; j >= wt[i - 1]; j--) {
                dp[j] = Math.max(dp[j], dp[j - wt[i - 1]] + val[i - 1]);
            }
        }
        return dp[W];
    }

    public static void main(String[] args) {
        int[] val = {1, 2, 3};
        int[] wt = {4, 5, 1};
        int W = 4;
        System.out.println(knapsack(W, val, wt)); // Output: 3
    }
}
```

**Why traverse right-to-left?** Since each `dp[j]` update depends on `dp[j - wt[i-1]]` from the *previous* item's pass, going left-to-right would let an item be counted multiple times (as in the Unbounded Knapsack variant). Going right-to-left preserves the "0/1" (use-once) restriction.

## 4. Fractional vs. 0/1 — Side-by-Side Summary

| Aspect | Fractional Knapsack | 0/1 Knapsack |
|---|---|---|
| Items divisible? | Yes | No |
| Best algorithm | Greedy (sort by ratio) | Dynamic Programming |
| Optimal via greedy? | Yes — provably optimal | No — greedy can fail |
| Time complexity | O(n log n) | O(n × W) |
| Real-world analogy | Grain, liquids, vegetables | Washing machines, indivisible gadgets |

---

## 5. Other Variants (For Context)

- **Bounded Knapsack:** A limited quantity of each item is available (more than 1, but not unlimited).
- **Unbounded Knapsack:** Unlimited copies of each item are available (this is where the left-to-right DP traversal, as opposed to right-to-left, becomes relevant).

## 6. Applications

Beyond literal bag-packing, the knapsack model is widely used for **resource allocation**, **portfolio/investment optimization**, and **cutting-stock / packing problems** in manufacturing and logistics. Specialized solvers (e.g., branch-and-bound based knapsack solvers in optimization libraries) are commonly used for large-scale instances beyond simple DP.
