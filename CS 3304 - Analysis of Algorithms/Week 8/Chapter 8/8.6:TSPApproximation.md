# Traveling Salesman Problem: Approximation Algorithms 

Part 4 of this series' dynamic-programming arc solved TSP *exactly* with Held–Karp DP, and mentioned in passing that Christofides' algorithm exists. This tutorial picks up exactly where that mention left off, joining the Vertex Cover, Set Cover, and Partition tutorials as this series' fourth approximation-algorithms deep dive. Metric TSP turns out to sit at a genuinely interesting point in the landscape those three tutorials mapped out: like Vertex Cover, it has a simple 2-approximation; like Christofides showed in 1976, a cleverer construction pushes that down to 1.5 — and unlike Partition, no PTAS is known or believed to exist. ## 1. Setup: Metric TSP

Recall from Part 4 that general TSP is defined on a directed, weighted complete graph and is NP-hard, with exact algorithms (brute force, Held–Karp) taking exponential time. This tutorial restricts attention to **metric TSP**: the *symmetric* special case where the cities form an undirected complete graph and the distances obey the **triangle inequality**:

```
d(u, v) ≤ d(u, w) + d(w, v)   for all cities u, v, w
```

In words: never is a direct hop longer than a detour through some third city. This holds automatically whenever distances come from an actual metric — straight-line (Euclidean) distance, road-network shortest paths, and so on — which covers the overwhelming majority of real routing problems. Metric TSP is still NP-hard (it's a special case of a hard problem, not an easier problem in general — hardness doesn't relax just because the input is more structured), but as this tutorial shows, that extra structure is exactly what makes constant-factor approximation possible at all. Section 10 shows precisely what breaks without it.

Throughout, `Copt` denotes the cost of an optimal tour on a given instance.

## 2. Key Lemma 1: The MST Never Costs More Than the Optimal Tour

Both algorithms in this tutorial start from the same observation, so it's worth proving once and reusing twice.

**Claim.** `MST ≤ Copt`, where `MST` is the total weight of a minimum spanning tree of the city graph.

**Proof.** Take any optimal tour and delete one of its edges. What remains is a Hamiltonian **path** — a single chain visiting every city exactly once — which is, in particular, a **spanning tree** (it's connected, touches every vertex, and has exactly `n − 1` edges). Its weight is `Copt` minus the one deleted edge's (nonnegative) weight, so:

```
weight(this spanning tree) ≤ Copt
```

Since the MST is by definition the *minimum-weight* spanning tree over all possible spanning trees — and this Hamiltonian path is one particular spanning tree — the MST can only cost the same or less:

```
MST ≤ weight(this spanning tree) ≤ Copt
```

`∎`

This single inequality is the backbone of both approximation guarantees that follow: it turns "how far is our tour from the unknown `Copt`?" into "how far is our tour from the MST, which we can actually compute?"

## 3. The MST-Shortcut Algorithm

**Idea.** Build the cheapest possible tree connecting all cities, walk around it (visiting each edge twice — once going, once coming back), then skip over cities you've already seen using the triangle inequality to justify that the skip is never a step backward.

```text
Algorithm MST-Shortcut(cities, distances)
{
    T ← MinimumSpanningTree(cities, distances)     // Prim's or Kruskal's

    walk ← PreorderDFS(T, any root)                 // visits each edge of T exactly twice
    tour ← walk with every repeated city removed,    // "shortcut": go directly to the
           keeping only each city's first appearance  // next unvisited city instead

    return tour
}
```

The four steps match the source material's "MST-DFS Method" directly: (1) start from the complete graph, (2) find the MST, (3) do a DFS traversal of it, (4) delete duplicate vertices by shortcutting.

## 4. Proof: MST-Shortcut Is a 2-Approximation

**Step 1 — the DFS walk costs exactly `2 · MST`.** A preorder DFS traversal of a tree descends into each subtree and returns, meaning every tree edge is crossed exactly twice: once heading away from the root into a subtree, once coming back. So:

```
weight(full DFS walk) = 2 · MST
```

**Step 2 — shortcutting never increases the cost.** Suppose the walk visits cities `..., a, b, c, ...` where `b` has already been visited earlier and gets skipped, so the tour goes directly from `a` to `c`. By the triangle inequality:

```
d(a, c) ≤ d(a, b) + d(b, c)
```

so replacing the two-hop detour through `b` with the direct hop `a → c` costs no more than what it replaces. Applying this repeatedly to remove every duplicate visit:

```
weight(shortcut tour) ≤ weight(full DFS walk) = 2 · MST
```

**Step 3 — combine with Lemma 1.**

```
weight(shortcut tour) ≤ 2 · MST ≤ 2 · Copt
```

**MST-Shortcut is a 2-approximation algorithm for metric TSP.** `∎`

## 5. Worked Example: MST-Shortcut

The whiteboard diagrams that motivated this tutorial show the *shape* of the method (a 5-city graph, its MST, a DFS trace, and the shortcut result) without attaching concrete distances, so here is a fully specified instance built to have the same "hub-and-branches" character, verified end-to-end in Java (Section 12).

Seven cities at 2-D coordinates — one hub near the origin and three branches of two cities each:

```
0: (0, 0)     1: (10, 0)    2: (11, 1)
3: (-8, 6)    4: (-9, 7)
5: (-3, -9)   6: (-4, -10)
```

Distances are ordinary Euclidean distance, so the triangle inequality holds automatically. Running Prim's algorithm from city 0 gives the MST:

```
0 — 1,  1 — 2,   0 — 3,  3 — 4,   0 — 5,  5 — 6           MST weight ≈ 33.73
```

This is exactly the "hub with three spokes" shape, and a preorder DFS from city 0 visibly backtracks along each spoke before starting the next one:

```
Full DFS walk:  0 → 1 → 2 → 1 → 0 → 3 → 4 → 3 → 0 → 5 → 6 → 5 → 0
```

Every edge appears twice, matching Step 1 of the proof exactly. Deleting repeated cities (Step 4 of the source material's method) collapses this to:

```
Shortcut tour:  0 → 1 → 2 → 3 → 4 → 5 → 6 → (0)          cost ≈ 61.75
```

Brute-forcing all `6! = 720` orderings of the remaining six cities gives the true optimum: `Copt ≈ 58.82`. So this run achieves a ratio of `61.75 / 58.82 ≈ 1.05` — comfortably under the proven worst-case bound of 2, and `61.75 ≤ 2 × 33.73 = 67.46` confirms Step 1–2 of the proof numerically as well.

## 6. Christofides' Algorithm

**Idea.** MST-Shortcut's weak point is doubling *every* MST edge, even though only some cities actually need a second visit undone. Christofides' refinement adds just enough extra edges to make an Eulerian circuit possible — using a minimum-weight matching restricted to the few vertices that need it — instead of doubling the whole tree.

```text
Algorithm Christofides(cities, distances)
{
    T ← MinimumSpanningTree(cities, distances)

    O ← { vertices with odd degree in T }             // always an even number of them (Section 7)
    M ← MinimumWeightPerfectMatching(O, distances)     // pair up every vertex in O as cheaply as possible

    G ← T with the edges of M added                    // now every vertex has even degree
    circuit ← EulerianCircuit(G)                        // exists because G is connected with all-even degrees
    tour ← circuit with every repeated city removed      // shortcut, exactly as in Section 3

    return tour
}
```

This matches the source material's five steps: (1) start with a graph, (2) find the MST, (3) find a minimum-cost perfect matching on the odd-degree vertices, (4) add the matching's edges to the tree and find an Eulerian tour, (5) take shortcuts.

**Why odd-degree vertices always come in an even count.** This is what makes Step 3 solvable at all — a perfect matching requires an even number of vertices. It follows from the handshake lemma: in any graph, the sum of all vertex degrees equals twice the edge count, hence is always even. If the number of odd-degree vertices were odd, the sum of degrees would be odd too — a contradiction. So it's always even, for *any* graph, including the MST.

**Why adding `M` to `T` makes an Eulerian circuit possible.** A connected graph has an Eulerian circuit (a closed walk using every edge exactly once) if and only if every vertex has even degree. In `T` alone, the vertices in `O` have odd degree — that's their definition. Adding one matching edge to each of them raises each of their degrees by exactly 1, making all of them even, while every vertex *not* in `O` already had even degree in `T` and is untouched by `M`. So `T + M` has every vertex at even degree, and (being connected, since `T` already was) it has an Eulerian circuit.

## 7. Key Lemma 2: The Minimum Matching Costs at Most Half the Optimal Tour

**Claim.** `weight(M) ≤ Copt / 2`, where `M` is the minimum-weight perfect matching on the odd-degree set `O`.

**Proof.** Let `O = {o1, o2, ..., o2k}` be listed in the order they appear along an optimal tour (skipping over the cities not in `O`). Because the optimal tour visits cities in this cyclic order and the triangle inequality lets us shortcut past the skipped cities exactly as in Section 4's proof, the total distance of the "shortcut cycle" through just `O`, in this cyclic order, is at most `Copt`:

```
d(o1,o2) + d(o2,o3) + ... + d(o2k, o1)  ≤  Copt
```

Now split this cycle's edges into two alternating groups:

```
M1 = { (o1,o2), (o3,o4), ..., (o2k-1, o2k) }
M2 = { (o2,o3), (o4,o5), ..., (o2k, o1) }
```

Each of `M1` and `M2` is itself a **perfect matching** of `O` (every vertex in `O` appears in exactly one edge of each), and together their edges are exactly the shortcut cycle's edges, so:

```
weight(M1) + weight(M2) = (shortcut cycle's total weight) ≤ Copt
```

Two nonnegative numbers summing to at most `Copt` means the smaller of the two is at most `Copt / 2`:

```
min( weight(M1), weight(M2) ) ≤ Copt / 2
```

`M1` and `M2` are *some* perfect matchings of `O` — not necessarily the cheapest ones. But `M` is defined as the **minimum**-weight perfect matching over *all* possible perfect matchings of `O`, so it can only cost the same or less than either of them:

```
weight(M) ≤ min( weight(M1), weight(M2) ) ≤ Copt / 2
```

`∎`

## 8. Proof: Christofides Is a 3/2-Approximation

**Step 1 — the Eulerian circuit costs exactly `MST + weight(M)`.** By construction it uses every edge of `T` and every edge of `M` exactly once, so its total weight is the sum of both.

**Step 2 — bound that sum using both lemmas.**

```
weight(Eulerian circuit) = MST + weight(M)
                          ≤ Copt + Copt/2          [Lemma 1 on MST, Lemma 2 on weight(M)]
                          = (3/2) · Copt
```

**Step 3 — shortcutting never increases the cost**, by the identical triangle-inequality argument used in Section 4's Step 2 (skipping an already-visited city and going directly to the next new one costs no more than the detour it replaces):

```
weight(final tour) ≤ weight(Eulerian circuit) ≤ (3/2) · Copt
```

**Christofides' algorithm is a 3/2-approximation algorithm for metric TSP.** `∎` This is strictly better than MST-Shortcut's factor of 2, at the cost of the extra matching step — and, as the historical note in Section 13 covers, it stood as the best known worst-case guarantee for four decades.

## 9. Worked Example: Christofides

Same seven-city instance as Section 5, so the two algorithms can be compared directly on identical input.

The MST is unchanged: `0—1, 1—2, 0—3, 3—4, 0—5, 5—6`, weight `≈ 33.73`. Degrees in this tree: city `0` has degree 3 (odd — it's the hub, connected to all three branches), cities `2`, `4`, `6` each have degree 1 (odd — they're the outer leaf of each branch), and cities `1`, `3`, `5` have degree 2 (even — each sits in the middle of its branch). So:

```
O = { 0, 2, 4, 6 }      (four vertices — even, as Section 6 guarantees)
```

Checking all three ways to pair up four vertices, the minimum-weight perfect matching is:

```
M = { (0, 2), (4, 6) }        weight(M) ≈ 11.05 + 17.72 = 28.77
```

Confirming Lemma 2 numerically: `28.77 ≤ Copt/2 ≈ 29.41`. ✓. Adding `M`'s two edges to the MST gives every vertex even degree, and an Eulerian circuit (found via Hierholzer's algorithm) is:

```
0 → 1 → 2 → 0 → 3 → 4 → 6 → 5 → 0            weight = MST + weight(M) ≈ 62.49
```

City `0` is visited three times in this walk (it's the hub — degree 4 after adding edge `(0,2)`) and city `2` is followed immediately by a return to `0`, so shortcutting collapses it to:

```
Final tour:  0 → 1 → 2 → 3 → 4 → 6 → 5 → (0)         cost ≈ 61.10
```

Against the same `Copt ≈ 58.82` from Section 5, this gives a ratio of `61.10 / 58.82 ≈ 1.04` — better than MST-Shortcut's `1.05` on this instance, and well inside the proven `1.5` bound. `61.10 ≤ 1.5 × 58.82 ≈ 88.23` confirms the bound holds with plenty of room to spare, which is typical: worst-case bounds are rarely approached on any single instance (Section 12's stress test surveys many).

## 10. Why Metric Matters: General TSP Has No Constant-Factor Approximation

Both proofs above leaned on the triangle inequality twice each: once to justify Lemma 1 doesn't need it, but *both* Section 4 and Section 8's final "shortcutting never increases cost" step is pure triangle inequality, with no substitute. Drop that assumption — allow arbitrary edge weights, as in general (non-metric) TSP — and no constant-factor approximation can exist in polynomial time, unless `P = NP`.

**Theorem.** If there is a polynomial-time `c`-approximation algorithm for general TSP for *any* constant `c`, then `P = NP`.

**Proof.** Reduce from the **Hamiltonian Cycle** problem (NP-complete — see this series' NP-Hard/NP-Complete tutorials), which asks: does a given graph `G = (V, E)` contain a cycle visiting every vertex exactly once? Given `G` with `n = |V|` vertices, build a complete weighted graph `G'` on the same vertices:

```
weight(u, v) = 1              if (u, v) ∈ E
weight(u, v) = c·n + 1         if (u, v) ∉ E
```

This is a valid (if extreme) instance of general TSP — nothing requires these weights to satisfy the triangle inequality, and they don't. Now consider what an optimal tour of `G'` looks like in each case:

- **If `G` has a Hamiltonian cycle**, that cycle exists entirely within `G`'s real edges, so it's a tour in `G'` using only weight-`1` edges: cost exactly `n`. So `Copt = n`.
- **If `G` has no Hamiltonian cycle**, then *every* tour of `G'` must use at least one edge not in `E` (otherwise that tour would itself be a Hamiltonian cycle of `G`), costing at least `c·n + 1`. So `Copt ≥ c·n + 1` in this case.

Now suppose a polynomial-time `c`-approximation algorithm existed: it always returns a tour costing at most `c · Copt`. Run it on `G'`:

- If `G` has a Hamiltonian cycle, the algorithm returns a tour costing at most `c · n`.
- If `G` doesn't, *every* tour — including whatever the algorithm returns — costs at least `c·n + 1 > c·n`.

So simply checking whether the returned tour's cost is `≤ c·n` or `> c·n` correctly decides Hamiltonian Cycle, in polynomial time (building `G'` is polynomial, and running the assumed approximation algorithm is polynomial by assumption). Since Hamiltonian Cycle is NP-complete, this would place it in P, implying `P = NP`. `∎`

This is why every algorithm in this tutorial required the metric assumption from Section 1 — it isn't a simplifying convenience, it's load-bearing. Real-world routing instances are metric far more often than not (physical distances satisfy the triangle inequality automatically), which is exactly why MST-Shortcut and Christofides remain practically relevant despite this impossibility result for the fully general problem.

## 11. Complexity Analysis

| Step | Time |
|---|---|
| Minimum Spanning Tree (Prim's, adjacency matrix) | `O(n²)` |
| Preorder DFS of the MST | `O(n)` |
| Shortcutting | `O(n)` |
| **MST-Shortcut total** | **`O(n²)`** |
| Odd-degree vertex extraction | `O(n)` |
| Minimum-weight perfect matching (general graphs, Blossom algorithm) | `O(n³)` |
| Eulerian circuit (Hierholzer's algorithm) | `O(n)` edges in `T + M`, so `O(n)` |
| **Christofides total** | **`O(n³)`**, dominated by the matching step |

Both are polynomial — a sharp contrast with Part 4's exact methods (`O(n!)` brute force, `O(n²·2ⁿ)` Held–Karp). The worked examples and Section 12's Java use brute-force matching (fine for the small odd-degree sets these small instances produce), but production implementations use the polynomial-time **Blossom algorithm** (Edmonds, 1965) for minimum-weight perfect matching on general graphs — brute-force matching is itself exponential in `|O|` and only tutorial-appropriate at small scale.

## 12. Java Implementations

### 12.1 MST-Shortcut (Sections 3–5)

```java
import java.util.*;

public class TSPMSTShortcut {

    static double euclid(double[] a, double[] b) {
        double dx = a[0] - b[0], dy = a[1] - b[1];
        return Math.sqrt(dx * dx + dy * dy);
    }

    static List<List<Integer>> primMST(double[][] d, int n) {
        boolean[] inTree = new boolean[n];
        double[] minEdge = new double[n];
        int[] parent = new int[n];
        Arrays.fill(minEdge, Double.MAX_VALUE);
        Arrays.fill(parent, -1);
        minEdge[0] = 0;
        for (int iter = 0; iter < n; iter++) {
            int u = -1;
            for (int v = 0; v < n; v++) if (!inTree[v] && (u == -1 || minEdge[v] < minEdge[u])) u = v;
            inTree[u] = true;
            for (int v = 0; v < n; v++) if (!inTree[v] && d[u][v] < minEdge[v]) { minEdge[v] = d[u][v]; parent[v] = u; }
        }
        List<List<Integer>> adj = new ArrayList<>();
        for (int i = 0; i < n; i++) adj.add(new ArrayList<>());
        for (int v = 1; v < n; v++) { adj.get(v).add(parent[v]); adj.get(parent[v]).add(v); }
        return adj;
    }

    static double mstWeight(List<List<Integer>> adj, double[][] d) {
        double w = 0;
        boolean[][] counted = new boolean[adj.size()][adj.size()];
        for (int u = 0; u < adj.size(); u++)
            for (int v : adj.get(u))
                if (!counted[u][v]) { w += d[u][v]; counted[u][v] = counted[v][u] = true; }
        return w;
    }

    static void dfsPreorder(int u, List<List<Integer>> adj, boolean[] visited, List<Integer> order) {
        visited[u] = true;
        order.add(u);
        for (int v : adj.get(u)) if (!visited[v]) { dfsPreorder(v, adj, visited, order); order.add(u); }
    }

    static List<Integer> shortcut(List<Integer> full) {
        List<Integer> tour = new ArrayList<>();
        Set<Integer> seen = new HashSet<>();
        for (int v : full) if (seen.add(v)) tour.add(v);
        return tour;
    }

    static double tourCost(List<Integer> tour, double[][] d) {
        double c = 0;
        for (int i = 0; i < tour.size(); i++) c += d[tour.get(i)][tour.get((i + 1) % tour.size())];
        return c;
    }

    // Ground-truth brute force (fixing start at vertex 0), self-contained for verification
    static double bruteForceOpt(double[][] d, int n) {
        int[] perm = new int[n - 1];
        for (int i = 0; i < n - 1; i++) perm[i] = i + 1;
        double[] best = {Double.MAX_VALUE};
        permute(perm, 0, d, best);
        return best[0];
    }

    static void permute(int[] a, int k, double[][] d, double[] best) {
        if (k == a.length) {
            double c = d[0][a[0]];
            for (int i = 0; i < a.length - 1; i++) c += d[a[i]][a[i + 1]];
            c += d[a[a.length - 1]][0];
            best[0] = Math.min(best[0], c);
            return;
        }
        for (int i = k; i < a.length; i++) {
            int t = a[k]; a[k] = a[i]; a[i] = t;
            permute(a, k + 1, d, best);
            t = a[k]; a[k] = a[i]; a[i] = t;
        }
    }

    public static void main(String[] args) {
        // A "broom" instance: a central hub (0) with three branches of two cities each --
        // chosen so the MST is genuinely tree-shaped (not a simple path), which is exactly
        // the case where the DFS walk visibly backtracks and shortcutting visibly matters.
        double[][] pts = {
            {0, 0},      // 0 hub
            {10, 0},     // 1
            {11, 1},     // 2
            {-8, 6},     // 3
            {-9, 7},     // 4
            {-3, -9},    // 5
            {-4, -10}    // 6
        };
        int n = pts.length;
        double[][] d = new double[n][n];
        for (int i = 0; i < n; i++) for (int j = 0; j < n; j++) d[i][j] = euclid(pts[i], pts[j]);

        double opt = bruteForceOpt(d, n);
        List<List<Integer>> mstAdj = primMST(d, n);
        double mstW = mstWeight(mstAdj, d);

        boolean[] visited = new boolean[n];
        List<Integer> full = new ArrayList<>();
        dfsPreorder(0, mstAdj, visited, full);
        List<Integer> tour = shortcut(full);
        double cost = tourCost(tour, d);

        System.out.println("MST adjacency:");
        for (int i = 0; i < n; i++) System.out.println("  " + i + " -> " + mstAdj.get(i));
        System.out.println("MST weight: " + mstW);
        System.out.println("Full DFS walk (every MST edge traversed twice): " + full);
        System.out.println("After shortcutting: " + tour + "  cost = " + cost);
        System.out.println("Brute-force optimal cost: " + opt);
        System.out.printf("Ratio (algorithm / optimal) = %.4f  (proven bound: <= 2.0)%n", cost / opt);
        System.out.printf("Check: MST (%.3f) <= optimal (%.3f) ? %b%n", mstW, opt, mstW <= opt + 1e-9);
        System.out.printf("Check: tour cost (%.3f) <= 2 * MST (%.3f) ? %b%n", cost, 2 * mstW, cost <= 2 * mstW + 1e-9);
    }
}
```

### 12.2 Christofides' Algorithm (Sections 6–9)

```java
import java.util.*;

public class TSPChristofides {

    static double euclid(double[] a, double[] b) {
        double dx = a[0] - b[0], dy = a[1] - b[1];
        return Math.sqrt(dx * dx + dy * dy);
    }

    static List<List<Integer>> primMST(double[][] d, int n) {
        boolean[] inTree = new boolean[n];
        double[] minEdge = new double[n];
        int[] parent = new int[n];
        Arrays.fill(minEdge, Double.MAX_VALUE);
        Arrays.fill(parent, -1);
        minEdge[0] = 0;
        for (int iter = 0; iter < n; iter++) {
            int u = -1;
            for (int v = 0; v < n; v++) if (!inTree[v] && (u == -1 || minEdge[v] < minEdge[u])) u = v;
            inTree[u] = true;
            for (int v = 0; v < n; v++) if (!inTree[v] && d[u][v] < minEdge[v]) { minEdge[v] = d[u][v]; parent[v] = u; }
        }
        List<List<Integer>> adj = new ArrayList<>();
        for (int i = 0; i < n; i++) adj.add(new ArrayList<>());
        for (int v = 1; v < n; v++) { adj.get(v).add(parent[v]); adj.get(parent[v]).add(v); }
        return adj;
    }

    static double mstWeight(List<List<Integer>> adj, double[][] d) {
        double w = 0;
        boolean[][] counted = new boolean[adj.size()][adj.size()];
        for (int u = 0; u < adj.size(); u++)
            for (int v : adj.get(u))
                if (!counted[u][v]) { w += d[u][v]; counted[u][v] = counted[v][u] = true; }
        return w;
    }

    static List<Integer> oddVertices(List<List<Integer>> adj) {
        List<Integer> odd = new ArrayList<>();
        for (int i = 0; i < adj.size(); i++) if (adj.get(i).size() % 2 == 1) odd.add(i);
        return odd;
    }

    // Brute-force minimum-weight perfect matching -- fine for the small odd-degree set
    // this problem always produces in practice; exact matching algorithms (e.g. Blossom,
    // see Section 11) are needed only if the odd set is large.
    static double bestMatchWeight;
    static List<int[]> bestMatchEdges;

    static void minWeightPerfectMatching(List<Integer> verts, double[][] d) {
        bestMatchWeight = Double.MAX_VALUE;
        bestMatchEdges = null;
        matchHelper(new ArrayList<>(verts), new ArrayList<>(), 0.0, d);
    }

    static void matchHelper(List<Integer> remaining, List<int[]> current, double cost, double[][] d) {
        if (remaining.isEmpty()) {
            if (cost < bestMatchWeight) { bestMatchWeight = cost; bestMatchEdges = new ArrayList<>(current); }
            return;
        }
        int v = remaining.get(0);
        for (int i = 1; i < remaining.size(); i++) {
            int u = remaining.get(i);
            List<Integer> next = new ArrayList<>(remaining);
            next.remove(Integer.valueOf(v));
            next.remove(Integer.valueOf(u));
            current.add(new int[]{v, u});
            matchHelper(next, current, cost + d[v][u], d);
            current.remove(current.size() - 1);
        }
    }

    // Hierholzer's algorithm for an Eulerian circuit on the MST + matching multigraph
    static List<Integer> eulerianCircuit(int n, List<int[]> edges) {
        Map<Integer, List<int[]>> adj = new HashMap<>();
        for (int i = 0; i < n; i++) adj.put(i, new ArrayList<>());
        for (int i = 0; i < edges.size(); i++) {
            int[] e = edges.get(i);
            adj.get(e[0]).add(new int[]{e[1], i});
            adj.get(e[1]).add(new int[]{e[0], i});
        }
        boolean[] usedEdge = new boolean[edges.size()];
        int[] ptr = new int[n];
        Deque<Integer> stack = new ArrayDeque<>();
        List<Integer> circuit = new ArrayList<>();
        stack.push(0);
        while (!stack.isEmpty()) {
            int u = stack.peek();
            List<int[]> nbrs = adj.get(u);
            boolean advanced = false;
            while (ptr[u] < nbrs.size()) {
                int[] e = nbrs.get(ptr[u]);
                ptr[u]++;
                if (!usedEdge[e[1]]) {
                    usedEdge[e[1]] = true;
                    stack.push(e[0]);
                    advanced = true;
                    break;
                }
            }
            if (!advanced) circuit.add(stack.pop());
        }
        Collections.reverse(circuit);
        return circuit;
    }

    static List<Integer> shortcut(List<Integer> full) {
        List<Integer> tour = new ArrayList<>();
        Set<Integer> seen = new HashSet<>();
        for (int v : full) if (seen.add(v)) tour.add(v);
        return tour;
    }

    static double tourCost(List<Integer> tour, double[][] d) {
        double c = 0;
        for (int i = 0; i < tour.size(); i++) c += d[tour.get(i)][tour.get((i + 1) % tour.size())];
        return c;
    }

    static double bruteForceOpt(double[][] d, int n) {
        int[] perm = new int[n - 1];
        for (int i = 0; i < n - 1; i++) perm[i] = i + 1;
        double[] best = {Double.MAX_VALUE};
        permute(perm, 0, d, best);
        return best[0];
    }

    static void permute(int[] a, int k, double[][] d, double[] best) {
        if (k == a.length) {
            double c = d[0][a[0]];
            for (int i = 0; i < a.length - 1; i++) c += d[a[i]][a[i + 1]];
            c += d[a[a.length - 1]][0];
            best[0] = Math.min(best[0], c);
            return;
        }
        for (int i = k; i < a.length; i++) {
            int t = a[k]; a[k] = a[i]; a[i] = t;
            permute(a, k + 1, d, best);
            t = a[k]; a[k] = a[i]; a[i] = t;
        }
    }

    public static void main(String[] args) {
        // Same "broom" instance as TSPMSTShortcut, for a direct side-by-side comparison.
        double[][] pts = {
            {0, 0}, {10, 0}, {11, 1}, {-8, 6}, {-9, 7}, {-3, -9}, {-4, -10}
        };
        int n = pts.length;
        double[][] d = new double[n][n];
        for (int i = 0; i < n; i++) for (int j = 0; j < n; j++) d[i][j] = euclid(pts[i], pts[j]);

        double opt = bruteForceOpt(d, n);
        List<List<Integer>> mstAdj = primMST(d, n);
        double mstW = mstWeight(mstAdj, d);

        List<Integer> odd = oddVertices(mstAdj);
        minWeightPerfectMatching(odd, d);

        List<int[]> multiEdges = new ArrayList<>();
        boolean[][] added = new boolean[n][n];
        for (int u = 0; u < n; u++)
            for (int v : mstAdj.get(u))
                if (!added[u][v]) { multiEdges.add(new int[]{u, v}); added[u][v] = added[v][u] = true; }
        for (int[] e : bestMatchEdges) multiEdges.add(new int[]{e[0], e[1]});

        List<Integer> euler = eulerianCircuit(n, multiEdges);
        List<Integer> tour = shortcut(euler);
        double cost = tourCost(tour, d);

        System.out.println("MST weight: " + mstW);
        System.out.println("Odd-degree vertices of MST: " + odd);
        System.out.println("Min-weight perfect matching (weight = " + bestMatchWeight + "):");
        for (int[] e : bestMatchEdges) System.out.println("  " + e[0] + " - " + e[1] + "  (weight " + d[e[0]][e[1]] + ")");
        System.out.println("MST + matching weight: " + (mstW + bestMatchWeight));
        System.out.println("Eulerian circuit: " + euler);
        System.out.println("After shortcutting: " + tour + "  cost = " + cost);
        System.out.println("Brute-force optimal cost: " + opt);
        System.out.printf("Ratio (algorithm / optimal) = %.4f  (proven bound: <= 1.5)%n", cost / opt);
        System.out.printf("Check: matching weight (%.3f) <= optimal/2 (%.3f) ? %b%n",
                bestMatchWeight, opt / 2, bestMatchWeight <= opt / 2 + 1e-9);
        System.out.printf("Check: tour cost (%.3f) <= 1.5 * optimal (%.3f) ? %b%n", cost, 1.5 * opt, cost <= 1.5 * opt + 1e-9);
    }
}
```

```java
import java.util.*;

public class TSPApproxStressTest {

    static double euclid(double[] a, double[] b) {
        double dx = a[0] - b[0], dy = a[1] - b[1];
        return Math.sqrt(dx * dx + dy * dy);
    }

    static List<List<Integer>> primMST(double[][] d, int n) {
        boolean[] inTree = new boolean[n];
        double[] minEdge = new double[n];
        int[] parent = new int[n];
        Arrays.fill(minEdge, Double.MAX_VALUE);
        Arrays.fill(parent, -1);
        minEdge[0] = 0;
        for (int iter = 0; iter < n; iter++) {
            int u = -1;
            for (int v = 0; v < n; v++) if (!inTree[v] && (u == -1 || minEdge[v] < minEdge[u])) u = v;
            inTree[u] = true;
            for (int v = 0; v < n; v++) if (!inTree[v] && d[u][v] < minEdge[v]) { minEdge[v] = d[u][v]; parent[v] = u; }
        }
        List<List<Integer>> adj = new ArrayList<>();
        for (int i = 0; i < n; i++) adj.add(new ArrayList<>());
        for (int v = 1; v < n; v++) { adj.get(v).add(parent[v]); adj.get(parent[v]).add(v); }
        return adj;
    }

    static void dfsPreorder(int u, List<List<Integer>> adj, boolean[] visited, List<Integer> order) {
        visited[u] = true;
        order.add(u);
        for (int v : adj.get(u)) if (!visited[v]) { dfsPreorder(v, adj, visited, order); order.add(u); }
    }

    static List<Integer> shortcut(List<Integer> full) {

        if (remaining.isEmpty()) {
            if (cost < bestMatchWeight) { bestMatchWeight = cost; bestMatchEdges = new ArrayList<>(current); }
            return;
        }
        int v = remaining.get(0);
        for (int i = 1; i < remaining.size(); i++) {
            int u = remaining.get(i);
            List<Integer> next = new ArrayList<>(remaining);
            next.remove(Integer.valueOf(v));
            next.remove(Integer.valueOf(u));
            current.add(new int[]{v, u});
            matchHelper(next, current, cost + d[v][u], d);
            current.remove(current.size() - 1);
        }
    }

        Map<Integer, List<int[]>> adj = new HashMap<>();
        for (int i = 0; i < n; i++) adj.put(i, new ArrayList<>());

            adj.get(e[0]).add(new int[]{e[1], i});
```

## 13. Historical Note and Summary

Christofides' algorithm (independently found by Serdyukov) dates to 1976 and, remarkably, remained the best known worst-case guarantee for general metric TSP for over four decades — a small improvement for the restricted "graphic" case only arrived in 2011, and only extended to the full metric case in 2020. TSP's exact side has its own long history: Dantzig, Fulkerson, and Johnson solved a 49-city instance exactly in the 1950s using cutting planes; the Concorde solver (1990s) has since solved instances with tens of thousands of cities to proven optimality, and instances with millions of cities can be approximated within a fraction of a percent of optimal in practice — a reminder that worst-case approximation ratios like the ones proved in this tutorial are guarantees against adversarial inputs, not a description of how these algorithms perform on typical or real-world data (Section 12's stress test hints at the same gap between worst case and typical case).

| Algorithm | Guarantee | Time | Requires |
|---|---|---|---|
| MST-Shortcut (Section 3) | ≤ 2 × optimal | `O(n²)` | Triangle inequality (metric TSP) |
| Christofides (Section 6) | ≤ 1.5 × optimal | `O(n³)` | Triangle inequality (metric TSP) |
| General TSP, any constant factor | **Impossible** in poly-time unless P = NP | — | — (Section 10) |
| Held–Karp DP (Part 4) | Exact | `O(n²·2ⁿ)` | None (works on general TSP) |
| Brute force (Part 4) | Exact | `O(n!)` | None |

This tutorial's throughline mirrors Vertex Cover's: a single structural lemma (`MST ≤ Copt`, playing the role Vertex Cover's matching argument played) drives a simple constant-factor bound, and a cleverer construction on top of the same lemma (the matching on odd-degree vertices) tightens it further — while Section 10's reduction from Hamiltonian Cycle shows, as concretely as Set Cover's inapproximability result did, exactly where that structure stops being optional and starts being load-bearing.
