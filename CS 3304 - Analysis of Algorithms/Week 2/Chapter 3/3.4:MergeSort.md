# Merge Sort 

## What is Merge Sort?

Merge Sort is a popular, efficient, and **stable** sorting algorithm based on the **Divide and Conquer** paradigm. Instead of sorting the whole array at once, it:

1. **Divides** the array into smaller sub-arrays (recursively, until each sub-array has just one element),
2. **Conquers** by sorting these trivially small sub-arrays (a single element is already "sorted"),
3. **Merges** the sorted sub-arrays back together, two at a time, into a fully sorted array.

The key idea: dividing is easy, and merging two *already sorted* arrays into one sorted array is simple and efficient.

---

## The Divide and Conquer Connection

Merge Sort follows the same three-step pattern as any divide-and-conquer algorithm:

- **Divide**: Split the array into two halves using the midpoint.
- **Conquer**: Recursively apply merge sort to each half.
- **Combine**: Merge the two sorted halves into a single sorted array.

---

## Merge Sort Algorithm (Pseudocode)

```
MERGE_SORT(a, low, high)
    if low < high
        mid = (low + high) / 2
        MERGE_SORT(a, low, mid)
        MERGE_SORT(a, mid+1, high)
        MERGE(a, low, mid, high)
```

- `low` → index of the first element of the (sub)array
- `high` → index of the last element of the (sub)array
- `mid` → midpoint index that splits the array into two halves
- The recursion continues **as long as `low < high`** — this is the base case check. When `low == high`, the sub-array has only one element and is trivially sorted.

### The Merge Algorithm (heart of Merge Sort)

```
MERGE(a, low, mid, high)
    i = low
    j = mid + 1
    k = low

    while i <= mid and j <= high
        if a[i] <= a[j]
            b[k] = a[i]
            i = i + 1
        else
            b[k] = a[j]
            j = j + 1
        k = k + 1

    // Copy remaining elements of left half, if any
    while i <= mid
        b[k] = a[i]
        i = i + 1
        k = k + 1

    // Copy remaining elements of right half, if any
    while j <= high
        b[k] = a[j]
        j = j + 1
        k = k + 1
```

- `i` walks through the **left sub-array**, `j` walks through the **right sub-array**, `k` walks through the new **merged/sorted array `b`**.
- At each step, compare `a[i]` and `a[j]`; whichever is smaller is placed into `b[k]`, and its respective pointer (`i` or `j`) is advanced.
- Once one sub-array is exhausted, the algorithm copies over any leftover elements from the other sub-array directly (since they're already sorted).

## Step-by-Step Numerical Example

### Dividing the array
Given array (indices 0 to 8): `15, 5, 24, 8, 1, 3, 16, 10, 20`

**Divide step:**
- `low = 0, high = 8 → mid = (0+8)/2 = 4`
- Split into `[15, 5, 24, 8, 1]` (indices 0–4) and `[3, 16, 10, 20]` (indices 5–8)

This splitting continues recursively:
- `[15, 5, 24, 8, 1]` → `[15, 5, 24]` and `[8, 1]`
- `[15, 5, 24]` → `[15, 5]` and `[24]`
- `[15, 5]` → `[15]` and `[5]`
- `[8, 1]` → `[8]` and `[1]`
- `[3, 16, 10, 20]` → `[3, 16]` and `[10, 20]`
- `[3, 16]` → `[3]` and `[16]`
- `[10, 20]` → `[10]` and `[20]`

Division stops when every sub-array has a **single element** (a single element is always "sorted").

### Merging back together

Merging happens bottom-up, combining pairs of sorted sub-arrays:

| Merge Step | Result |
|---|---|
| Merge `[15]` and `[5]` | `[5, 15]` |
| Merge `[5,15]` and `[24]` | `[5, 15, 24]` |
| Merge `[8]` and `[1]` | `[1, 8]` |
| Merge `[5,15,24]` and `[1,8]` | `[1, 5, 8, 15, 24]` |
| Merge `[3]` and `[16]` | `[3, 16]` |
| Merge `[10]` and `[20]` | `[10, 20]` |
| Merge `[3,16]` and `[10,20]` | `[3, 10, 16, 20]` |
| Merge `[1,5,8,15,24]` and `[3,10,16,20]` | `[1, 3, 5, 8, 10, 15, 16, 20, 24]` |

**Final sorted array:** `1, 3, 5, 8, 10, 15, 16, 20, 24`

### Tracing the final merge (Left = `[1,5,8,15,24]`, Right = `[3,10,16,20]`)

Using pointers `i` (left array), `j` (right array), `k` (result array `B`):

1. Compare `L[i]=1` vs `R[j]=3` → `1` is smaller → place `1` → `i++`
2. Compare `L[i]=5` vs `R[j]=3` → `3` is smaller → place `3` → `j++`
3. Compare `L[i]=5` vs `R[j]=10` → `5` is smaller → place `5` → `i++`
4. Compare `L[i]=8` vs `R[j]=10` → `8` is smaller → place `8` → `i++`
5. Compare `L[i]=15` vs `R[j]=10` → `10` is smaller → place `10` → `j++`
6. Compare `L[i]=15` vs `R[j]=16` → `15` is smaller → place `15` → `i++`
7. Compare `L[i]=24` vs `R[j]=16` → `16` is smaller → place `16` → `j++`
8. Compare `L[i]=24` vs `R[j]=20` → `20` is smaller → place `20` → `j++`
9. Right sub-array (`R`) is exhausted → copy remaining left elements directly → place `24`

**Result:** `1, 3, 5, 8, 10, 15, 16, 20, 24` ✅

*(Note: If `i` crosses `mid` first, all remaining elements from the right array are copied over. If `j` crosses `high` first, all remaining elements from the left array are copied over.)*

## A Simpler Example: `[38, 27, 43, 10]`

**Divide:**
- `[38, 27, 43, 10]` → `[38, 27]` and `[43, 10]`
- `[38, 27]` → `[38]` and `[27]`
- `[43, 10]` → `[43]` and `[10]`

**Conquer:** Each single-element array is already sorted.

**Merge:**
- Merge `[38]` and `[27]` → `[27, 38]`
- Merge `[43]` and `[10]` → `[10, 43]`
- Merge `[27, 38]` and `[10, 43]` → `[10, 27, 38, 43]`

**Sorted result:** `[10, 27, 38, 43]`

## Java Implementation (Recursive)

```java
import java.io.*;

class GfG {

    // Merges two subarrays of arr[].
    // First subarray is arr[l..m]
    // Second subarray is arr[m+1..r]
    static void merge(int arr[], int l, int m, int r) {

        int n1 = m - l + 1;
        int n2 = r - m;

        int L[] = new int[n1];
        int R[] = new int[n2];

        for (int i = 0; i < n1; ++i)
            L[i] = arr[l + i];
        for (int j = 0; j < n2; ++j)
            R[j] = arr[m + 1 + j];

        int i = 0, j = 0;
        int k = l;

        while (i < n1 && j < n2) {
            if (L[i] <= R[j]) {
                arr[k] = L[i];
                i++;
            } else {
                arr[k] = R[j];
                j++;
            }
            k++;
        }

        while (i < n1) {
            arr[k] = L[i];
            i++;
            k++;
        }

        while (j < n2) {
            arr[k] = R[j];
            j++;
            k++;
        }
    }

    static void mergeSort(int arr[], int l, int r) {
        if (l < r) {
            int m = l + (r - l) / 2;

            mergeSort(arr, l, m);
            mergeSort(arr, m + 1, r);

            merge(arr, l, m, r);
        }
    }

    public static void main(String args[]) {
        int arr[] = {38, 27, 43, 10};

        mergeSort(arr, 0, arr.length - 1);

        for (int i = 0; i < arr.length; ++i)
            System.out.print(arr[i] + " ");
    }
}
```

**Output:** `10 27 38 43`

## Iterative (Bottom-Up) Merge Sort

Instead of recursively dividing, an iterative approach starts with sub-arrays of size 1 and repeatedly merges adjacent pairs, doubling the sub-array size each pass (1 → 2 → 4 → 8 → ...) until the whole array is sorted. This avoids recursion/function-call overhead.

```java
import java.util.*;

class GfG {

    static void merge(int[] arr, int left, int mid, int right) {
        int n1 = mid - left + 1;
        int n2 = right - mid;

        int[] arr1 = new int[n1], arr2 = new int[n2];

        for (int i = 0; i < n1; i++)
            arr1[i] = arr[left + i];
        for (int j = 0; j < n2; j++)
            arr2[j] = arr[mid + 1 + j];

        int i = 0, j = 0, k = left;

        while (i < n1 && j < n2) {
            if (arr1[i] <= arr2[j]) {
                arr[k] = arr1[i];
                i++;
            } else {
                arr[k] = arr2[j];
                j++;
            }
            k++;
        }

        while (i < n1) { arr[k] = arr1[i]; i++; k++; }
        while (j < n2) { arr[k] = arr2[j]; j++; k++; }
    }

    static void mergeSort(int[] arr) {
        int n = arr.length;

        for (int currSize = 1; currSize <= n - 1; currSize *= 2) {
            for (int leftStart = 0; leftStart < n - 1; leftStart += 2 * currSize) {
                int mid = Math.min(leftStart + currSize - 1, n - 1);
                int rightEnd = Math.min(leftStart + 2 * currSize - 1, n - 1);
                merge(arr, leftStart, mid, rightEnd);
            }
        }
    }

    public static void main(String[] args) {
        int[] arr = {4, 1, 3, 9, 7};
        mergeSort(arr);
        for (int val : arr) System.out.print(val + " ");
    }
}
```

**Output:** `1 3 4 7 9`

> Note: The `min()` function handles cases where the array size isn't a power of 2, ensuring subarray boundaries don't go out of range.

## Recurrence Relation

T(n) = Θ(1), if n = 1
T(n) = 2T(n/2) + Θ(n), if n > 1

- `T(n)` = time to sort array of size `n`
- `2T(n/2)` = time for two recursive calls on halves of size `n/2`
- `Θ(n)` = time to merge the two sorted halves

Solving this recurrence gives **O(n log n)**.

---

## Complexity Analysis

### Time Complexity
| Case | Complexity | When |
|---|---|---|
| Best Case | O(n log n) | Array already/nearly sorted |
| Average Case | O(n log n) | Randomly ordered array |
| Worst Case | O(n log n) | Array sorted in reverse order |

Merge Sort's time complexity is **consistently O(n log n)** in all cases — unlike Quick Sort, which degrades to O(n²) in the worst case.

### Space Complexity
- **Auxiliary Space: O(n)** — extra space is needed for temporary arrays used during merging.

## Applications of Merge Sort

- Sorting large datasets
- **External sorting** (when data is too large to fit in memory)
- Solving problems like **inversion counting**, "count smaller elements on right," and "surpasser count"
- Used in standard library sort implementations (its variant **TimSort** is used in Python, Java's `Collections.sort`, Android, and Swift)
    - Preferred for non-primitive types because it's **stable** (Quick Sort is not)
    - Java's `Arrays.sort()` uses Quick Sort, while `Collections.sort()` uses Merge Sort
- Preferred algorithm for sorting **Linked Lists**
- Easily **parallelizable**, since sub-arrays can be sorted independently before merging
- The merge step can efficiently solve **union/intersection** problems on two sorted arrays

---

## Advantages

- **Stable**: preserves the relative order of equal elements
- **Guaranteed O(n log n)** worst-case performance, even on large datasets
- **Simple to implement** via divide-and-conquer
- **Naturally parallel**: sub-arrays can be sorted independently in parallel

## Disadvantages

- **Extra space required**: needs O(n) auxiliary memory for merging
- **Not in-place**: requires additional memory to hold sorted data, a drawback when memory is limited
- **Slower than Quick Sort in practice** in many cases, since Quick Sort is more cache-friendly (it operates in-place)
