# Divide and Conquer Algorithm

---

## What is Divide and Conquer?

**Divide and Conquer** is a problem-solving strategy (not just a single algorithm) used to solve complex problems by:

1. **Dividing** the original problem into smaller subproblems
2. **Conquering** (solving) each subproblem individually
3. **Combining** the solutions to form the final answer

It is one of several algorithm-solving strategies in computer science, alongside Greedy Method, Dynamic Programming, Backtracking, and Branch and Bound.

> **Key distinction:** Divide and Conquer is most useful when subproblems are **independent** of each other. If subproblems overlap, **Dynamic Programming** is used instead.

---

## How It Works — The Three Steps

```
Original Problem P
        |
   ┌────┴────┐
   Divide P
   |    |    |
  P1   P2   P3   ...   Pn
   |    |    |
  S1   S2   S3   ...   Sn
   └────┬────┘
    Combine
        |
   Final Solution S
```

### Step 1 — Divide

Break the original problem into smaller subproblems. Each subproblem represents a part of the overall problem. Division continues recursively until no further division is possible (the **base case**).

**Example (Merge Sort):** Split the array into two halves.
**Example (Quick Sort):** Partition the array around a pivot element — this is the critical step in Quick Sort.

### Step 2 — Conquer

Solve each subproblem individually. If a subproblem is small enough (the **base case**), solve it directly without further recursion.

**Example (Merge Sort):** Sort each half independently.
**Example (Quick Sort):** Recursively sort the left and right partitions.

### Step 3 — Combine (Merge)

Combine the solutions of the subproblems to produce the solution to the original problem.

**Example (Merge Sort):** Merge two sorted halves into one sorted array — this is the critical step in Merge Sort.
**Example (Quick Sort):** No merge step needed — both parts are already sorted in place, and the left part contains only elements smaller than or equal to the right part.

## The General Algorithm

```
function DivideAndConquer(P):
    if P is small enough (base case):
        solve P directly
        return solution S

    else:
        divide P into subproblems P1, P2, P3, ..., Pn

        S1 = DivideAndConquer(P1)
        S2 = DivideAndConquer(P2)
        S3 = DivideAndConquer(P3)
        ...
        Sn = DivideAndConquer(Pn)

        S = combine(S1, S2, S3, ..., Sn)
        return S
```

### Worked Example — Arithmetic Expression

Consider: `(2 + 3) + (3 - 1) * (4 + 8)`

This is a divide and conquer problem:

1. **Divide** into subproblems: `2 + 3`, `3 - 1`, `4 + 8`
2. **Conquer** each: `5`, `2`, `12`
3. **Combine** using the operators: `5 + 2 * 12 = 29`

If the expression were just `2 + 3`, it cannot be divided further — this is the base case, solved directly.

---

## Characteristics of Divide and Conquer

| Characteristic | Description |
|---|---|
| **Recursive structure** | The same strategy applies at each level until the base case is reached |
| **Independence of subproblems** | Each subproblem can be solved without depending on another — enabling parallel execution |
| **Base case** | The smallest subproblem that can be solved directly without further division |
| **Combination step** | Subproblem solutions are merged back to produce the final result |

## Complexity Analysis

The time complexity of Divide and Conquer algorithms is expressed using the **Master Theorem** recurrence:

```
T(n) = aT(n/b) + f(n)
```

| Variable | Meaning |
|---|---|
| `n` | Size of the input |
| `a` | Number of subproblems in the recursion |
| `n/b` | Size of each subproblem (all assumed equal) |
| `f(n)` | Cost of dividing the problem and combining the solutions |

## Applications of Divide and Conquer

### 1. Binary Search

Efficiently finds an element in a **sorted array** by repeatedly halving the search interval.

- Compare the target with the middle element
- If equal, return it
- If smaller, search the left half
- If larger, search the right half
- **Time complexity:** O(log n)

```
Divide:   Split search space in half
Conquer:  Search one half
Combine:  Return the found index (no merge needed)
```

### 2. Merge Sort

Sorts an array by dividing it, sorting each half recursively, then merging the two sorted halves.

- **Divide step:** Simple — split array into two halves
- **Merge step:** Critical — merge two sorted arrays into one
- **Time complexity:** O(n log n)

```
[38, 27, 43, 3, 9, 82, 10]
         ↓ Divide
[38, 27, 43]    [3, 9, 82, 10]
   ↓ Divide          ↓ Divide
[38] [27, 43]   [3, 9] [82, 10]
      ↓ Sort          ↓ Sort
[38] [27, 43]   [3, 9] [10, 82]
         ↓ Merge
[27, 38, 43]    [3, 9, 10, 82]
         ↓ Merge
[3, 9, 10, 27, 38, 43, 82]
```

### 3. Quick Sort

Sorts an array by selecting a **pivot**, partitioning elements around it, then recursively sorting each partition.

- **Divide step:** Critical — partition around the pivot
- **Combine step:** Nothing — elements are sorted in place
- **Time complexity:** O(n log n) average, O(n²) worst case

```
[3, 6, 8, 10, 1, 2, 1]   pivot = 1
         ↓ Partition
[1, 1]  pivot=1  [3, 6, 8, 10, 2]
   ↓ Recurse          ↓ Recurse
 sorted            sorted
```

### 4. Strassen's Matrix Multiplication

Multiplies two matrices more efficiently than the standard O(n³) approach.

- Standard multiplication: **O(n³)**
- Strassen's algorithm: **O(n^2.8974)**
- Uses 7 recursive multiplications instead of 8

### 5. Closest Pair of Points

Finds the closest pair of points in a 2D plane.

- Naive approach (check all pairs): **O(n²)**
- Divide and Conquer approach: **O(n log n)**

### 6. Cooley-Tukey Fast Fourier Transform (FFT)

The most common FFT algorithm.

- Divides the DFT problem recursively
- **Time complexity:** O(n log n)

### 7. Karatsuba Algorithm (Fast Multiplication)

Multiplies two large numbers faster than the schoolbook method.

- Schoolbook method: **O(n²)**
- Karatsuba: **O(n^1.585)**

## Quick Reference — Algorithms and Complexity

| Algorithm | Divide Step | Critical Step | Time Complexity |
|---|---|---|---|
| Binary Search | Split in half | Decide which half to search | O(log n) |
| Merge Sort | Split in half | Merge two sorted halves | O(n log n) |
| Quick Sort | Partition around pivot | Pivot selection and partition | O(n log n) avg |
| Strassen's Matrix Multiply | Split matrix into sub-matrices | Combine 7 multiplications | O(n^2.8974) |
| Closest Pair of Points | Split by median x-coordinate | Merge across the dividing line | O(n log n) |
| FFT (Cooley-Tukey) | Split odd/even indices | Butterfly combine operation | O(n log n) |

## Advantages

- **Solves difficult problems** — complex problems become manageable by breaking them into smaller, more tractable parts (e.g. Tower of Hanoi)
- **Algorithmic efficiency** — key to discovering efficient algorithms like Merge Sort, Quick Sort, and FFT
- **Parallelism** — independent subproblems can execute on different processors simultaneously, making it well-suited for multi-processor systems
- **Cache efficiency** — subproblems are small enough to fit in CPU cache, reducing slow main memory access (cache-oblivious algorithms)

## Disadvantages

- **Overhead** — the process of dividing and combining requires additional time and resources, which can be significant for already-small problems
- **Complexity** — when subproblems are interdependent or must be solved in a specific order, the overall solution becomes more complex
- **Difficulty of implementation** — some problems are hard to divide cleanly, requiring complex partitioning logic
- **Memory limitations** — storing intermediate results across recursion levels can become a limiting factor for very large inputs

---

## Summary

| Step | What Happens | Key Question |
|---|---|---|
| **Divide** | Break the problem into smaller subproblems | Can this be divided further? |
| **Conquer** | Solve each subproblem (recurse or solve directly) | Is this the base case? |
| **Combine** | Merge subproblem solutions into the final answer | How do the pieces fit back together? |

The power of Divide and Conquer lies in reducing a problem of size `n` to problems of size `n/b`, applied repeatedly. This transforms exponential brute-force solutions into efficient logarithmic or log-linear ones.
