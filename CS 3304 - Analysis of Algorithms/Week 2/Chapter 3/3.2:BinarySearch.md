# Binary Search

---

## What is Binary Search?

**Binary Search** is a searching algorithm that operates on a **sorted** (or monotonic) search space. It repeatedly divides the search space in half to find a target value, achieving **O(log N)** time complexity — far more efficient than linear search's O(n).

Binary Search is a direct application of the **Divide and Conquer** paradigm:

- **Divide** — find the middle element and split the array into two halves
- **Conquer** — search only the relevant half
- **Combine** — return the found index (no merge step needed)

> Linear search checks every element one by one. Binary search eliminates half the remaining elements on every iteration. For an array of 1,000,000 elements, binary search takes at most ~20 comparisons.

---

## Conditions for Applying Binary Search

Two conditions must be met:

1. **The data structure must be sorted** (or follow a monotonic pattern)
2. **Access to any element must take constant time** — O(1) random access (arrays, not linked lists)

More generally: whenever the answer to a problem lies in a range **L to R** and there is **monotonic behaviour** in that range, Binary Search can be applied — even on the answer space itself, not just on an array.

---

## How Binary Search Works

**Example:** Search for `key = 23` in `arr = [2, 5, 8, 12, 16, 23, 38, 56, 72, 91]`

```
Iteration 1:
  low = 0, high = 9
  mid = (0 + 9) / 2 = 4
  arr[4] = 16  →  16 < 23  →  search right half
  low = mid + 1 = 5

Iteration 2:
  low = 5, high = 9
  mid = (5 + 9) / 2 = 7
  arr[7] = 56  →  56 > 23  →  search left half
  high = mid - 1 = 6

Iteration 3:
  low = 5, high = 6
  mid = (5 + 6) / 2 = 5
  arr[5] = 23  →  23 == 23  →  FOUND at index 5
```

---

## The Algorithm — Three Scenarios at Each Step

At every iteration, compute `mid` and compare `arr[mid]` with `key`:

| Condition | Action |
|---|---|
| `arr[mid] == key` | Found — return `mid` |
| `key < arr[mid]` | Key is in the left half — set `high = mid - 1` |
| `key > arr[mid]` | Key is in the right half — set `low = mid + 1` |

If `low > high`, the search space is exhausted — element not found, return `-1`.

### Mid Calculation — Avoiding Integer Overflow

```java
// Avoid overflow
int mid = low + (high - low) / 2;

// This is equivalent but can overflow for large indices:
// int mid = (low + high) / 2;
```

## Implementations

### Iterative Binary Search — O(log n) Time, O(1) Space

```java
static int binarySearch(int arr[], int x) {
    int low = 0, high = arr.length - 1;

    while (low <= high) {
        int mid = low + (high - low) / 2;

        // Check if x is present at mid
        if (arr[mid] == x)
            return mid;

        // If x is greater, ignore left half
        if (arr[mid] < x)
            low = mid + 1;

        // If x is smaller, ignore right half
        else
            high = mid - 1;
    }

    // Element was not present
    return -1;
}
```

**Usage:**

```java
int arr[] = { 2, 3, 4, 10, 40 };
int result = binarySearch(arr, 10);
// Output: Element is present at index 3
```

### Recursive Binary Search — O(log n) Time, O(log n) Space

```java
static int binarySearch(int arr[], int low, int high, int x) {
    if (high >= low) {
        int mid = low + (high - low) / 2;

        // Element is present at the middle
        if (arr[mid] == x)
            return mid;

        // Element is smaller — search left subarray
        if (arr[mid] > x)
            return binarySearch(arr, low, mid - 1, x);

        // Element is larger — search right subarray
        return binarySearch(arr, mid + 1, high, x);
    }

    // Element not present
    return -1;
}
```

**Usage:**

```java
int arr[] = { 2, 3, 4, 10, 40 };
int result = binarySearch(arr, 0, arr.length - 1, 10);
// Output: Element is present at index 3
```

## Handling Duplicates in Binary Search

### Standard Binary Search with Duplicates

A standard binary search does **not** guarantee which duplicate it returns. It returns **any** valid index containing the target — whichever the midpoint calculation happens to land on.

**Example:** `arr = {1, 2, 2, 2, 5}`, `target = 2`

```
start = 0, end = 4
mid = (0 + 4) / 2 = 2
arr[2] == 2  →  returns index 2
```

The result depends entirely on where `mid` falls. For different array sizes the same value at different positions would return different indices.

**Correct test for standard binary search with duplicates:**

```java
// Do NOT assert a specific index — any valid index is acceptable
assertTrue(result >= 0 && result < arr.length);
assertEquals(target, arr[result]);

// WRONG: asserting a specific index
assertEquals(1, result);  // fails if mid lands elsewhere
```

### Finding the First Occurrence

Do not stop when the target is found. Instead, record the index and **continue searching left**:

```java
public static int firstOccurrence(int[] arr, int target) {
    int start = 0, end = arr.length - 1;
    int answer = -1;

    while (start <= end) {
        int mid = start + (end - start) / 2;

        if (arr[mid] == target) {
            answer = mid;       // record this as a candidate
            end = mid - 1;      // keep searching left for an earlier one
        } else if (arr[mid] < target) {
            start = mid + 1;
        } else {
            end = mid - 1;
        }
    }
    return answer;
}

// arr = {1, 2, 2, 2, 5}, target = 2  →  returns 1
```

### Finding the Last Occurrence

Same idea, but **continue searching right**:

```java
public static int lastOccurrence(int[] arr, int target) {
    int start = 0, end = arr.length - 1;
    int answer = -1;

    while (start <= end) {
        int mid = start + (end - start) / 2;

        if (arr[mid] == target) {
            answer = mid;       // record this as a candidate
            start = mid + 1;    // keep searching right for a later one
        } else if (arr[mid] < target) {
            start = mid + 1;
        } else {
            end = mid - 1;
        }
    }
    return answer;
}

// arr = {1, 2, 2, 2, 5}, target = 2  →  returns 3
```

### Summary — Duplicate Handling

| Goal | When `arr[mid] == target` | Result |
|---|---|---|
| Any occurrence (standard) | `return mid` immediately | Fast, non-deterministic for duplicates |
| First occurrence | Record `mid`, set `end = mid - 1` | Always the leftmost match |
| Last occurrence | Record `mid`, set `start = mid + 1` | Always the rightmost match |

### Integer Overflow — Best Practice

Always prefer:

```java
int mid = start + (end - start) / 2;  // safe
```

Over:

```java
int mid = (start + end) / 2;  // can overflow for very large indices
```

Both compute the same result, but the first avoids overflow when `start + end` exceeds `Integer.MAX_VALUE`.

## Step-by-Step Numerical Walkthrough

### Example 1 — Element Found (key = 59)

Array: `[5, 9, 17, 23, 25, 45, 59, 63, 71, 89]` (indices 0–9)

```
Step 1: low=0, high=9, mid=4, arr[4]=25
        59 > 25  →  low = 5

Step 2: low=5, high=9, mid=7, arr[7]=63
        59 < 63  →  high = 6

Step 3: low=5, high=6, mid=5, arr[5]=45
        59 > 45  →  low = 6

Step 4: low=6, high=6, mid=6, arr[6]=59
        59 == 59  →  FOUND at index 6
```

### Example 2 — Element Not Found (key = 60)

Array: `[5, 9, 17, 23, 25, 45, 59, 63, 71, 89]` (indices 0–9)

```
Step 1: low=0, high=9, mid=4, arr[4]=25
        60 > 25  →  low = 5

Step 2: low=5, high=9, mid=7, arr[7]=63
        60 < 63  →  high = 6

Step 3: low=5, high=6, mid=5, arr[5]=45
        60 > 45  →  low = 6

Step 4: low=6, high=6, mid=6, arr[6]=59
        60 > 59  →  low = 7

Step 5: low=7 > high=6  →  EXIT loop, return -1
        Element 60 is NOT present in the array
```

## Binary Search Algorithm (Pseudocode)

```
BinarySearch(A, n, key):
    start = 0
    end = n - 1

    while start <= end:
        mid = start + (end - start) / 2

        if A[mid] == key:
            return mid           // Found

        else if key < A[mid]:
            end = mid - 1        // Search left half

        else:
            start = mid + 1      // Search right half

    return -1                    // Not found
```

## Complexity Analysis

| Case | Time Complexity | Explanation |
|---|---|---|
| Best Case | O(1) | Target is the middle element on the first comparison |
| Average Case | O(log N) | Halves the search space each iteration |
| Worst Case | O(log N) | Target is at an edge or not present |

| Implementation | Space Complexity |
|---|---|
| Iterative | **O(1)** — no extra memory |
| Recursive | **O(log N)** — call stack depth equals number of halvings |

> For an array of N = 1,000,000,000 elements, Binary Search takes at most ~30 comparisons.

---

## Iterative vs Recursive

| Feature | Iterative | Recursive |
|---|---|---|
| Time Complexity | O(log N) | O(log N) |
| Space Complexity | **O(1)** | O(log N) — call stack |
| Stack Overflow Risk | None | Possible for very large inputs |
| Readability | Slightly more verbose | Cleaner and closer to the algorithm definition |
| Preferred In | Production / performance-sensitive | Teaching / learning |

## Applications of Binary Search

| Application | Description |
|---|---|
| **Searching in sorted arrays** | Core use case — find a target value in O(log N) |
| **First / last occurrence** | Find the boundary of a repeated element in a sorted array |
| **Sqrt(x)** | Binary search on answer space `[0, x]` to find integer square root |
| **Database indexing** | B-trees and similar structures use binary search for fast data lookup |
| **Git bisect** | Isolates a faulty commit by binary searching through commit history |
| **Network routing / IP lookup** | Efficiently finds routing entries in sorted address range tables |
| **File systems** | Fast search through sorted directories or symbol tables |
| **Machine learning** | Hyperparameter tuning — efficient search for learning rate or thresholds |
| **Optimization / competitive programming** | Solve boundary-value problems by narrowing the answer range |
| **Binary Search Trees** | Self-balancing BSTs (AVL, Red-Black) rely on binary search logic |

## Variants of Binary Search

| Variant | Description |
|---|---|
| **Standard Binary Search** | Classic — find exact match in sorted array |
| **Meta Binary Search** | Bit manipulation approach — starts from the highest bit |
| **Ubiquitous Binary Search** | Template-based approach using `lower_bound` style |
| **Uniform Binary Search** | Uses a precomputed delta table instead of recomputing mid |
| **Randomized Binary Search** | Picks mid randomly — same expected complexity |
| **N-base Modified Binary Search** | Generalises to base-N splits instead of always halving |

## Binary Search vs Linear Search

| Feature | Binary Search | Linear Search |
|---|---|---|
| Prerequisite | Array must be **sorted** | No sorting required |
| Time Complexity | O(log N) | O(N) |
| Best Case | O(1) | O(1) |
| Approach | Divide and Conquer | Sequential scan |
| Use Case | Large sorted datasets | Small or unsorted datasets |

---

## Key Points to Remember

- The array (or search space) **must be sorted** before applying binary search
- Always use `mid = low + (high - low) / 2` to avoid integer overflow
- The loop condition is `while (low <= high)` — `<=` not just `<`
- When `key < arr[mid]`: set `high = mid - 1` (search left)
- When `key > arr[mid]`: set `low = mid + 1` (search right)
- Return `-1` when `low > high` — the element is not in the array
- Iterative is preferred in production (O(1) space); recursive is cleaner for learning
- Binary search can be applied to the **answer space** (not just arrays) — whenever the answer is monotonic in a range `[L, R]`
