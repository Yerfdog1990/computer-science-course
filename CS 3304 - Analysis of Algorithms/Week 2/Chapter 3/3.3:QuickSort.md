# Quick Sort Algorithm

---

## What is Quick Sort?

**Quick Sort** is a sorting algorithm based on the **Divide and Conquer** paradigm. It picks an element called the **pivot** and **partitions** the array around it — placing the pivot in its correct sorted position, with all smaller elements to the left and all greater elements to the right. It then recursively applies the same process to the two sub-arrays.

Quick Sort is one of the **fastest general-purpose sorting algorithms** for large datasets and is used in standard library sort functions in C, C++, and Java.

---

## The Three Steps

```
1. Choose Pivot    — select an element from the array
2. Partition       — rearrange so all smaller elements are left, larger right
3. Recurse         — apply Quick Sort to each sub-array
```

**Base case:** A sub-array with one element is already sorted — stop recursing.

---

## Choosing a Pivot

The pivot choice directly impacts performance:

| Strategy | Description | Risk |
|---|---|---|
| **First element** | Always pick `arr[0]` | Worst case on sorted arrays |
| **Last element** | Always pick `arr[n-1]` | Worst case on sorted arrays |
| **Random element** | Pick randomly | No predictable worst-case pattern — preferred |
| **Median** | Pick the true median | Best time complexity but high constant overhead |

> **Recommended:** Random pivot — eliminates the pattern that triggers worst-case behaviour, with negligible overhead.

---

## Partition Algorithms

The partition step rearranges the array and returns the final index of the pivot. There are three common approaches:

| Algorithm | Description | Extra Space |
|---|---|---|
| **Naive** | Copy elements into temporary arrays (smaller, pivot, larger), then copy back | O(n) |
| **Lomuto** | Track index of smaller elements with a pointer; single left-to-right pass | O(1) |
| **Hoare** | Two pointers from both ends; fastest of the three | O(1) |

---

## Partition in Action — Hoare's Approach (from the lecture)

This is the classic two-pointer partition using the **first element as pivot**.

### Initial Setup

```
Array: [7, 6, 10, 5, 9, 2, 1, 15, 7]
        i                           j
pivot = arr[i] = arr[0] = 7
i = 0 (left pointer, moves right)
j = n-1 = 8 (right pointer, moves left)
```

### Rules

- Move `i` right (`i++`) while `arr[i] <= pivot`
- Move `j` left (`j--`) while `arr[j] > pivot`
- If `i < j`: swap `arr[i]` and `arr[j]`
- If `i >= j`: swap `arr[j]` with the pivot — partition complete; return `j`

### Step-by-Step Walkthrough

**Pass 1:**

```
arr = [7, 6, 10, 5, 9, 2, 1, 15, 7]
i moves: arr[0]=7 ≤ 7 → i++
         arr[1]=6 ≤ 7 → i++
         arr[2]=10 > 7 → STOP i at index 2

j stays: arr[8]=7 not > 7 → STOP j at index 8

i(2) < j(8)  →  swap arr[2] and arr[8]

arr = [7, 6, 7, 5, 9, 2, 1, 15, 10]
```

**Pass 2:**

```
arr = [7, 6, 7, 5, 9, 2, 1, 15, 10]
i moves from 2: arr[2]=7 ≤ 7 → i++
                arr[3]=5 ≤ 7 → i++
                arr[4]=9 > 7 → STOP i at index 4

j moves from 8: arr[8]=10 > 7 → j--
                arr[7]=15 > 7 → j--
                arr[6]=1 not > 7 → STOP j at index 6

i(4) < j(6)  →  swap arr[4] and arr[6]

arr = [7, 6, 7, 5, 1, 2, 9, 15, 10]
```

**Pass 3:**

```
arr = [7, 6, 7, 5, 1, 2, 9, 15, 10]
i moves from 4: arr[4]=1 ≤ 7 → i++
                arr[5]=2 ≤ 7 → i++
                arr[6]=9 > 7 → STOP i at index 6

j moves from 6: arr[6]=9 > 7 → j--
                arr[5]=2 not > 7 → STOP j at index 5

i(6) > j(5)  →  SWAP pivot (arr[0]=7) with arr[j]=arr[5]=2

arr = [2, 6, 7, 5, 1, 7, 9, 15, 10]
                          ^
                     pivot 7 is now at index 5 (its final sorted position)
```

### Result After Partition

```
[2, 6, 7, 5, 1] | 7 | [9, 15, 10]
  all ≤ 7              all ≥ 7
```

Pivot `7` is now in its correct position at index 5. Elements left of it are all ≤ 7. Elements right of it are all ≥ 7.

## Partition Algorithm (Pseudocode)

```
Partition(A, i, j):
    pivot = A[i]

    while i < j:
        while A[i] <= pivot:
            i++
        while A[j] > pivot:
            j--
        if i < j:
            swap(A[i], A[j])

    // pivot now belongs at position j
    swap(A[j], pivot)
    return j          // position of pivot
```

---

## Quick Sort Algorithm (Pseudocode)

```
QuickSort(A, i, j):
    if i < j:
        location = Partition(A, i, j)   // find pivot's final position
        QuickSort(A, i, location - 1)   // sort left sub-array
        QuickSort(A, location + 1, j)   // sort right sub-array
```

After the first partition:

```
QuickSort(A, 0, 4)   →  sort [2, 6, 7, 5, 1]
QuickSort(A, 6, 8)   →  sort [9, 15, 10]
```

Apply the same process recursively until each sub-array has one element, then combine — the full array is sorted.

## Lomuto Partition (Simpler to Implement)

Lomuto uses the **last element as pivot** and a single left-to-right scan. It is simpler to understand though slightly slower than Hoare's in practice.

```java
static int partition(int[] arr, int low, int high) {
    int pivot = arr[high];           // choose last element as pivot
    int i = low - 1;                 // index of smaller element

    for (int j = low; j <= high - 1; j++) {
        if (arr[j] < pivot) {
            i++;
            swap(arr, i, j);         // move smaller element left
        }
    }

    swap(arr, i + 1, high);          // place pivot in correct position
    return i + 1;                    // return pivot index
}
```

## Complete Quick Sort Implementation (Java)

```java
import java.util.Arrays;

class QuickSort {

    static void swap(int[] arr, int i, int j) {
        int temp = arr[i];
        arr[i] = arr[j];
        arr[j] = temp;
    }

    // Lomuto partition — pivot is last element
    static int partition(int[] arr, int low, int high) {
        int pivot = arr[high];
        int i = low - 1;

        for (int j = low; j <= high - 1; j++) {
            if (arr[j] < pivot) {
                i++;
                swap(arr, i, j);
            }
        }
        swap(arr, i + 1, high);
        return i + 1;
    }

    static void quickSort(int[] arr, int low, int high) {
        if (low < high) {
            int pi = partition(arr, low, high); // pivot index

            quickSort(arr, low, pi - 1);        // sort left part
            quickSort(arr, pi + 1, high);       // sort right part
        }
    }

    public static void main(String[] args) {
        int[] arr = {10, 7, 8, 9, 1, 5};
        quickSort(arr, 0, arr.length - 1);

        for (int val : arr) {
            System.out.print(val + " ");
        }
        // Output: 1 5 7 8 9 10
    }
}
```

## Complexity Analysis

### Time Complexity

| Case | Complexity | When It Occurs |
|---|---|---|
| **Best Case** | O(n log n) | Pivot always divides array into two equal halves |
| **Average Case** | O(n log n) | Pivot divides array into roughly equal parts on average |
| **Worst Case** | O(n²) | Pivot is always the smallest or largest element (e.g. already sorted array with first/last pivot) |

### Why Best Case is O(n log n)

When the pivot splits the array into two equal halves every time:

```
T(n) = 2 * T(n/2) + n
     = 4 * T(n/4) + 2n
     = 8 * T(n/8) + 3n
     ...
     = n * T(1) + n * log₂n
     = O(n log n)
```

### Why Worst Case is O(n²)

When the pivot is always the minimum or maximum (one partition has `n-1` elements, the other has `0`):

```
T(n) = T(n-1) + n
     = T(n-2) + (n-1) + n
     ...
     = n + (n-1) + (n-2) + ... + 1
     = n(n+1)/2
     = O(n²)
```

This happens when sorting an already-sorted array using the first or last element as pivot.

### Space Complexity

| Case | Space | Reason |
|---|---|---|
| **Best Case** | O(log n) | Balanced partitions → balanced recursion tree of depth log n |
| **Worst Case** | O(n) | Unbalanced partitions → skewed recursion tree of depth n |

Quick Sort sorts **in place** — no extra array is needed. The only memory used is the call stack.

### Complexity Summary Table

| Variation | Time Complexity | Auxiliary Space |
|---|---|---|
| Best Case | Ω(n log n) | O(log n) |
| Average Case | Θ(n log n) | O(log n) |
| Worst Case | O(n²) | O(n) |

## Quick Sort vs Merge Sort

| Feature | Quick Sort | Merge Sort |
|---|---|---|
| Worst-case time | O(n²) | O(n log n) |
| Average-case time | O(n log n) | O(n log n) |
| Space | O(log n) in-place | O(n) extra array needed |
| Stability | Not stable | Stable |
| Cache friendliness | High (works on same array) | Lower (copies to auxiliary array) |
| Preferred for | Large arrays, primitives | When stability is required |

> Quick Sort is faster in practice for large datasets because of **cache locality** — it always works on the original array without copying data. Merge Sort requires copying to auxiliary arrays, which is slower in cache terms.

---

## Advantages

- **Divide and Conquer** — conceptually clean and easy to reason about
- **Cache friendly** — works on the same array with good locality of reference
- **In-place** — requires only O(log n) extra memory (no auxiliary array like Merge Sort)
- **Tail recursive** — enables tail-call optimisation to reduce stack depth
- **Fastest general-purpose algorithm** for large datasets where stability is not required
- **Parallel processing** — two sub-arrays can be sorted independently on separate processors

## Disadvantages

- **Worst case O(n²)** — triggered by poor pivot choice on already-sorted or reverse-sorted arrays
- **Not stable** — equal elements may not maintain their original relative order
- **Not ideal for small datasets** — overhead of recursion makes simpler algorithms (Insertion Sort) faster for small n
- **Stack overflow risk** — deep recursion on worst-case inputs without tail-call optimisation

## Applications

- **Standard library sorting** — `qsort` in C, `Arrays.sort` for primitives in Java, `std::sort` in C++ all use Quicksort (or a hybrid with it)
- **Commercial computing** — sorting files by name/date/price, sorting student records, account profiles
- **Kth smallest/largest element** — via Quickselect (a variant of Quicksort)
- **Database record ordering** — preprocessing for faster lookups
- **Parallel processing** — independent sub-arrays can be sorted on separate threads
- **Data compression** — Huffman coding preprocessing
- **Scientific computing** — priority queues and sorting in numerical algorithms
- **Computational geometry** — convex hull and other spatial algorithms

---

## Key Points to Remember

- Quick Sort is **Divide and Conquer** — divide via partitioning, conquer via recursion, no explicit combine step
- The **partition step** is the critical step — it places the pivot in its final sorted position in O(n)
- In **Merge Sort**, the merge step is critical. In **Quick Sort**, the partition step is critical.
- **Pivot choice** determines performance — random pivot avoids worst-case patterns
- Worst case O(n²) occurs when the array is **already sorted** and the first or last element is chosen as pivot
- Quick Sort is **not stable** — equal elements may swap
- Quick Sort is **in-place** — no extra array; space cost is only the recursion stack O(log n) average
- After partitioning, the pivot is **already in its correct final position** — it is never moved again
