## 1. Definition of Virtualization

### 1.1 Why a Single Definition Is Hard to Pin Down
- Virtualization is a **broad and changing concept** — it is **not easy** to give one clear, universally accepted definition.
- The industry has produced **multiple** definitions over time.

### 1.2 Two Representative Definitions

**Definition 1 (Wikipedia-style):**
> Virtualization is an **abstract method of expressing computer resources**. Through virtualization, the abstracted resources can be accessed **in the same way** as the resources before the abstraction. This abstract method is **not limited** by implementation, geographic location, or physical configuration of the underlying resources.

**Definition 2 (IT terminology database style):**
> Virtualization is a **virtual (relative to the real) version** created for certain things — such as operating systems, computer systems, storage devices, and network resources.

### 1.3 Why Both Definitions Point to the Same Underlying Idea
- Although worded differently, careful analysis shows they share **common ground** — explored in the next section.

---

## 2. The Three Common Meanings Across Definitions

No matter how virtualization is phrased, three core meanings recur:

1. **The objects of virtualization are various RESOURCES.**
2. **The virtualized logical resources HIDE unnecessary details** from users.
3. **Users can realize part or all of their functions** (that they'd perform in the real environment) **in the virtual environment** instead.

```
        Real Resource                  Virtual Resource
   (CPU, memory, storage,   ──virtualize──►   (same logical
    network, OS, etc.)                        representation,
                                               hidden implementation
                                               details)
                                                     │
                                                     ▼
                                          User interacts with it
                                          EXACTLY as they would
                                          with the real resource
```

## 3. Virtualization as Logical Representation — The Memory Example

### 3.1 The Core Idea
> **Virtualization is a LOGICAL representation of resources, and physical limitations do not constrain it.**

- **Resources** covered by this definition span a **wide range**:
    - **Hardware resources:** CPU, memory, storage, network.
    - **Software environments:** operating systems, file systems, applications.

### 3.2 Applying This to Memory Virtualization

- **Memory is a real resource.** **Virtualized memory** is a **substitute** for this resource — the two share the **same logical representation**.
- **What the virtualization layer hides:**
    - How **unified addressing** is achieved.
    - How **swap in/out** between memory and the hard disk is managed.
- **What software using virtual memory experiences:**
    - It can still perform **allocation, access, and release** using the **same instructions** it would use for real physical memory.
    - **The underlying complexity is completely invisible** to the software using it.

```
Software's perspective:          What's actually happening (hidden):
"Allocate memory"          ───►  Virtualization layer manages unified
"Access this address"      ───►  addressing across physical RAM
"Release this memory"      ───►  AND handles swapping data in/out
                                  of the hard disk as needed
```

- This example demonstrates that **multiple different resources can be virtualized**, each following the same underlying logic: **present a familiar, consistent logical interface, while hiding the real implementation's complexity.**

## 4. The Main Goal of Virtualization

### 4.1 The Central Purpose

> **The main goal of virtualization is to SIMPLIFY the representation, access, and management of IT resources** — including infrastructure, systems, and software — while providing **standard interfaces** for these resources to receive input and produce output.

### 4.2 Who Uses Virtualization?
- **The users of virtualization** can be:
    - **End-users**
    - **Programs**
    - **Services**

### 4.3 Why Standard Interfaces Matter So Much

- Through **standard interfaces**, virtualization **minimizes the impact on users** when the underlying IT infrastructure **changes**.
- **End-users can REUSE the original interface**, because the way they interact with the virtual resource **has not changed** — **even if** the underlying implementation of the real resource **has** changed.

```
   Underlying resource CHANGES (e.g., new hardware, new storage backend)
                    │
                    ▼
   Virtualization layer absorbs the change
                    │
                    ▼
   User-facing INTERFACE stays the SAME
                    │
                    ▼
   End-users are UNAFFECTED — no need to relearn or adapt
```

### 4.4 The Deeper Benefit — Reduced Coupling

> **Virtualization technology reduces the degree of COUPLING between the resource user and the specific realization of the resource**, so the user no longer depends on any **particular** realization of that resource.

- **Practical payoff for system administrators:** using this **loose coupling** relationship, administrators can **reduce the impact on users** when **maintaining and upgrading** IT resources — since users interact only with the **stable, abstracted interface**, not the changing underlying implementation.

## 5. Development of Virtualization Technology

### 5.1 Why Enterprises and Individuals Favor Virtualization
- Virtualization technology is **conducive to solving problems** in two major areas:
    1. **Resource allocation.**
    2. **Business management.**

### 5.2 The Most Basic, Intuitive Benefit — Better Use of Idle Resources

- **The main function of a virtual computer:** give **full play** to the capacity of **idle resources** on high-performance computers, achieving **increased server utilization** — **without needing to purchase additional hardware.**
- **Additional benefit:** enables **rapid delivery and rapid recovery** of customer system applications.
- This is described as **the most basic and intuitive understanding** the public has of virtual computers.

### 5.3 The Deeper, Enterprise-Level Benefit — Business Operations

- Virtualization technology plays a **vital role** in enterprise management and business operations:
    - Enables **rapid deployment and migration** of servers and data centers.
    - Reflects **transparent behavior management** as a key characteristic.

## 6. The Four Major Technological Trends

> Because of its important position in the industry, virtualization technology's development has become a **major focus of attention.** At the technological level, virtualization faces **four major trends**:

### 6.1 Platform Openness
- Refers to moving away from a **closed architecture** for the basic platform.
- **Through virtualization management**, virtual machines from **multiple vendors** can **coexist** under an **open platform**.
- **Benefit:** different vendors can implement **rich applications** on the same open platform.

### 6.2 Standardization of Connection Protocols
- **The problem:** multiple, competing connection protocols exist (e.g., **VMware's PCoIP**, **Citrix's ICA**), causing **terminal compatibility issues** in the context of public desktop cloud environments.
- **The goal:** standardize these protocols to **solve wide compatibility issues** between terminals and cloud platforms, and **optimize the industrial chain structure.**

### 6.3 Client Hardwareization
- **The problem:** desktop virtualization and users' multimedia experience have historically been **limited by insufficient hardware support.**
- **The trend:** **terminal chip technology** is gradually improving, allowing virtualization technology to be **implemented directly on mobile terminals.**

### 6.4 Public Cloud Privatization
- **Mechanism:** using technology **similar to VPN**.
- **Goal:** turn an enterprise's IT architecture into a **"private cloud"** that is **superimposed on top of** the public cloud.
- **Dual benefit:** ensures the private cloud **supports the security** of enterprise data, **WITHOUT sacrificing the convenience** of the public cloud.

```
        Four Major Trends in Virtualization Technology
        /              |               |              \
  Platform      Protocol         Client          Public Cloud
  Openness      Standardization  Hardwareization Privatization
  (multi-vendor (solve terminal  (chip tech →    (VPN-like tech →
   coexistence)  compatibility)   mobile virt.)   private cloud
                                                   atop public)
```

## 7. Advantages of Virtualization Technology

### 7.1 The Core Mechanism

- Virtualization technology **abstracts and transforms** various physical resources of a computer (**CPU, memory, disk space, network adapter**, etc.), **dividing and combining** them into **one or more** computer configuration environments.
- **Result:** users can run **multiple operating systems on a single server simultaneously**, with programs running in **mutually independent spaces**, **without affecting each other** — **significantly improving computer efficiency.**

### 7.2 How This Works — The Virtualization Layer

- The **virtualization layer** simulates a set of **independent hardware devices** for **each** virtual machine — including CPU, memory, motherboard, graphics card, and network card.
- A **guest operating system** is installed on top of this simulated hardware.
- **The end-user's program runs inside the guest operating system.**

```
        Physical Host
   ┌─────────────────────────────────────────┐
   │            Virtualization Layer         │
   │  ┌──────────────┐    ┌──────────────┐   │
   │  │ Simulated HW │    │ Simulated HW │   │
   │  │ (CPU, mem,   │    │ (CPU, mem,   │   │
   │  │  GPU, NIC...)│    │ GPU, NIC...) │   │
   │  ├──────────────┤    ├──────────────┤   │
   │  │ Guest OS #1  │    │ Guest OS #2  │   │
   │  ├──────────────┤    ├──────────────┤   │
   │  │ User Program │    │ User Program │   │
   │  └──────────────┘    └──────────────┘   │
   └─────────────────────────────────────────┘
```

### 7.3 Resource Pooling and Utilization
- Virtual machines **support dynamic sharing** of physical resources and **resource pools**, **improving resource utilization** — this is **especially valuable** for workloads whose **average demand** is far **lower** than what would be needed if **dedicated resources** were provisioned for them individually.

### 7.4 Advantage 1 — Reduce the Number of Terminal Equipment

- **Reduces managed physical resources** (servers, workstations, other equipment), **curbing growth** in equipment count and **hiding** part of the underlying physical complexity.
- **Simplifies public management tasks** through: automation, access to better information, and centralized management.
- **Realizes load management automation**, supports common tools across multiple platforms, and **improves staff efficiency.**
- **Consolidation benefit:** integrating multiple systems into **one host** via virtualization can **still guarantee "one server per system"** logically — meaning:
    - **Hardware device count is effectively reduced**, without affecting business use.
    - **Power/energy consumption is reduced.**
    - **Rack/floor space requirements are reduced**, avoiding costly computer-room reconfiguration that would otherwise result from an ever-growing equipment count.

### 7.5 Advantage 2 — Higher Security

- Virtualization achieves **isolation and division** that **simpler sharing mechanisms cannot achieve.**
- **Result:** **controllable and secure access** to data and services.
- **Mechanism:** by **dividing the host and internal virtual machines**, you can prevent **one program from affecting other programs' performance**, or from **causing the whole system to crash.**
- **Even an unstable original program/system** can run **safely and in isolation** within its own virtual machine.
- **Future-facing benefit:** with a **comprehensive virtualization strategy**, administrators can plan for **fault tolerance**, ensuring **business continuity** during an accident.
- **Backup/recovery benefit:** converting operating systems and process instances into **data files** enables:
    - **Automated, streamlined backup.**
    - **Replication.**
    - **More robust business continuity.**
    - **Faster recovery** after failures or natural disasters.
- **Advanced use case:** further development of **virtual cluster technology** can achieve **uninterrupted business function** via **multi-machine hot backup.**

### 7.6 Advantage 3 — Higher Availability

- **Virtualize the ENTIRE computing infrastructure**, then use **specialized software** to **centrally manage** the system and virtual hosts — this lets administrators manage physical resources **WITHOUT impacting users.**
- **Reduces management overhead** for resources/processes, thereby **reducing the complexity** of the network management system's underlying hardware architecture.
- **Through centralized, policy-based management:** the benefits of **end-to-end virtualization** apply to **BOTH virtual and physical resources**, letting maintenance staff handle **enterprise-level installation, configuration, and change management** from a **single, central location.**
- **Net effect:** **significantly reduces** the resources and time required to manage system hardware.

## 8. Common Types of Virtualization Technology

### 8.1 Classification Principle
- The **virtual entities** in virtualization technology are **various IT resources**. By classifying these resources, we can identify **different types** of virtualization.

```
              Virtualization Technology
              /                        \
    Infrastructure                  Software
    Virtualization                  Virtualization
    /            \                  /            \
 Network       Storage          Application    High-Level
 Virtualization Virtualization  Virtualization  Language
                                                Virtualization
```

### 8.2 Infrastructure Virtualization

> Since **network, storage, and file systems** are all **critical infrastructure** supporting a data center's operation, **network virtualization** and **storage virtualization** are classified together as **infrastructure virtualization.**

#### 8.2.1 Network Virtualization

- **Definition:** virtualization technology that **integrates network hardware and software resources** to provide users with **virtual network connections.**
- **Two forms:**

**(a) Local Area Network (LAN) Virtualization**
- Multiple local networks are **combined into one logical network**, OR one local network is **divided into multiple logical networks.**
- **Purpose:** improve efficiency of **large-scale enterprise self-use networks** or the **internal networks of data centers.**
- **Typical representative:** **Virtual LAN (VLAN).**

**(b) Wide Area Network (WAN) Virtualization**
- **Most common application:** **Virtual Private Network (VPN).**
- **What VPN does:** **abstracts the network connection**, allowing **remote users** to access the company's **internal network anytime, anywhere**, without perceiving any difference between physical and virtual connections.
- **Additional guarantee:** VPN ensures the **security and privacy** of this external network connection.

```
LAN Virtualization:
  Multiple physical LANs ──combine──► ONE logical network
        OR
  ONE physical LAN ──divide──► MULTIPLE logical networks (VLANs)

WAN Virtualization (VPN):
  Remote user ──"feels like"──► directly connected to company's
                                  internal network (secure & private)
```

#### 8.2.2 Storage Virtualization

- **Definition:** provides an **abstract logical view** for physical storage devices; users access **integrated storage resources** through a **unified logical interface** in this view.
- **Two main forms:**

**(a) Storage-Device-Based Storage Virtualization**
- **Typical representative: RAID (Redundant Array of Inexpensive Disks).**
- **How it works:** combines **multiple physical disks** into a **disk array**, using **inexpensive disk devices** to achieve a **unified, high-performance, fault-tolerant storage space.**

**(b) Network-Based Storage Virtualization**
- **Typical representatives:**
    - **NAS (Network Attached Storage).**
    - **SAN (Storage Area Network).**

```
Storage Virtualization
        │
   ┌────┴────┐
Device-Based        Network-Based
(e.g., RAID)        (e.g., NAS, SAN)
   │                      │
Multiple cheap        Storage accessed
disks combined        over the network,
into ONE unified,      presented as unified
fault-tolerant array   logical storage
```

### 8.3 Software Virtualization

> Beyond infrastructure and systems, there is virtualization technology **for software itself** — covering the **programs and programming languages** users work with. **Two main industry-recognized types:** application virtualization and high-level language virtualization.

#### 8.3.1 Application Virtualization

- **Definition:** **decouples the application program from the operating system**, providing a **virtual operating environment** for the application.
- **What this environment includes:** the application's **executable file** AND the **runtime environment** it needs.
- **How it works in practice:**
    1. When a user wants to run a program, the **application virtualization server** can **push** the user's program components **in real time** to the **application virtualization operating environment** on the client.
    2. When the user **finishes** and closes the application, their **changes and data** are **uploaded** to a **centralized management server.**
- **Key benefit:** users are **no longer limited to a single client** — they can use their applications **across different terminals.**

```
Application Virtualization Flow:

  User wants to run App     Central Server pushes App
  on Client Device    ◄──── (executable + runtime env)
         │                  to Client, in real time
         ▼
  App runs in virtual
  operating environment
  on the client
         │
         ▼
  User finishes, closes app
         │
         ▼
  Changes & data UPLOADED
  back to central server
         │
         ▼
  User can later resume on
  a DIFFERENT terminal —
  same data/state available
```

#### 8.3.2 High-Level Language Virtualization

- **Problem solved:** the **migration of executable programs** between computers with **different architectures.**
- **How it works:**
    1. Programs written in a **high-level language** are **compiled into standard intermediate instructions.**
    2. These intermediate instructions are then executed via an **interpreted execution** or **dynamic translation** environment, enabling them to **run on different architectures.**

##### Worked Example — The Java Virtual Machine (JVM)

- **Java virtual machine technology** removes the **coupling** between the **lower-level system platform** (hardware + OS) and the **upper-level executable code**, achieving **cross-platform execution of code.**
- **Step-by-step process:**
    1. The user's **Java source program** is compiled (via the compiler provided by the **JDK**) into **platform-neutral bytecode.**
    2. This bytecode serves as the **input to the Java Virtual Machine.**
    3. The **JVM converts the bytecode** into **binary machine code** executable on that **specific platform.**
- **Resulting effect:** **"Compile once, execute everywhere."**

```
Java Source Code (.java)
        │
        ▼   (compiled by JDK compiler)
Platform-Neutral BYTECODE (.class)
        │
        ▼   (fed into the Java Virtual Machine, on ANY platform)
┌─────────────────┬─────────────────┬─────────────────┐
│   JVM on         │   JVM on         │   JVM on         │
│   Windows        │   Linux          │   macOS          │
│   (converts to    │   (converts to    │   (converts to    │
│   Windows binary) │   Linux binary)   │   macOS binary)   │
└─────────────────┴─────────────────┴─────────────────┘
        "Compile once, execute everywhere"
```

## 9. Glossary of Key Terms

| Term | Definition |
|---|---|
| **Virtualization** | An abstract, logical method of representing computer resources, independent of their underlying implementation, location, or physical configuration. |
| **Virtualization layer** | The software layer that simulates/manages the abstracted resource, hiding implementation details from users. |
| **Coupling (reduced by virtualization)** | The degree of dependency between a resource user and the specific realization of that resource. |
| **Platform openness** | A trend allowing virtual machines from multiple vendors to coexist on an open (non-closed) platform. |
| **Connection protocol standardization** | A trend to unify competing remote-desktop/connection protocols (e.g., PCoIP, ICA) for better terminal compatibility. |
| **Client hardwareization** | A trend of improving terminal/mobile chip technology to better support desktop virtualization on mobile devices. |
| **Public cloud privatization** | Creating a VPN-like "private cloud" layered atop a public cloud, balancing security and convenience. |
| **Infrastructure virtualization** | Virtualization of critical data-center infrastructure — specifically network and storage virtualization. |
| **Network virtualization** | Integrating network hardware/software resources to provide virtual network connections (LAN or WAN forms). |
| **VLAN (Virtual LAN)** | The typical representative of local area network virtualization — combining or subdividing local networks logically. |
| **VPN (Virtual Private Network)** | The typical representative of wide area network virtualization — securely abstracting remote access to an internal network. |
| **Storage virtualization** | Providing an abstract, unified logical view over physical storage devices. |
| **RAID (Redundant Array of Inexpensive Disks)** | Storage-device-based storage virtualization combining multiple cheap disks into one fault-tolerant array. |
| **NAS (Network Attached Storage)** | A typical representative of network-based storage virtualization. |
| **SAN (Storage Area Network)** | Another typical representative of network-based storage virtualization. |
| **Software virtualization** | Virtualization applied to software itself — covering application virtualization and high-level language virtualization. |
| **Application virtualization** | Decoupling an application from the OS, providing it a portable virtual operating environment (executable + runtime). |
| **High-level language virtualization** | Compiling high-level-language programs into intermediate instructions executable (via interpretation/dynamic translation) across different architectures. |
| **Bytecode** | Platform-neutral intermediate instructions produced by compiling high-level source code (e.g., Java). |
| **Java Virtual Machine (JVM)** | The runtime that converts platform-neutral Java bytecode into platform-specific binary machine code. |
| **Guest operating system** | The OS installed on top of a virtual machine's simulated hardware, within which user programs actually run. |

## 11. Big-Picture Takeaways

1. **Virtualization resists a single crisp definition, but converges on three consistent ideas across every phrasing**: it operates on resources, it hides implementation detail, and it lets users do in the virtual world what they'd do in the real one — this conceptual consistency is more important than picking any one "official" definition.
2. **The memory virtualization example crystallizes the whole concept**: the same allocate/access/release instructions work identically whether the software is touching real RAM or virtualized memory that's secretly being swapped to disk — the logical interface never changes even though the implementation underneath is completely different.
3. **The real payoff of virtualization is reduced coupling between users and implementations** — this is what lets underlying infrastructure evolve, get upgraded, or get replaced with minimal disruption to the people and programs that depend on it.
4. **Virtualization's industry evolution reflects real-world pressures**: platform openness responds to vendor lock-in concerns, protocol standardization responds to fragmented terminal compatibility, client hardwareization responds to mobile computing's rise, and public cloud privatization responds to the tension between enterprise security needs and public cloud convenience.
5. **The three headline advantages — fewer terminals, higher security, higher availability — all stem from the same root mechanism**: abstracting and dividing physical resources so that consolidation, isolation, and centralized management become possible without disrupting the business functions running on top.
6. **Virtualization isn't just about hardware** — it spans from the infrastructure layer (network, storage) all the way up to the software layer (applications, programming languages), with the Java Virtual Machine standing as perhaps the most successful and widely-recognized real-world example of "compile once, execute everywhere" high-level language virtualization.
