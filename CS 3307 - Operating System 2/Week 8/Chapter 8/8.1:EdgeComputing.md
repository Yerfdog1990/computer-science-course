## 1. Introduction and Definition

### 1.1 The Motivating Problem

> With the growth of the **Internet of Things (IoT)**, billions of devices are generating **huge amounts of data**. But storing or analyzing all that data **in real time** is almost impossible.

- **This is exactly where edge computing becomes relevant.**

### 1.2 What Edge Computing Actually Does

> With edge computing, we **process data closer to the source** — such as an IoT device, an IoT gateway, an edge server, a smartphone, or a user's computer.

- **The core idea:** move **intelligence** to the edge, and let edge nodes/devices perform **real-time analytics.**
- **Two direct benefits of this approach:**
    1. **Reduces application latency.**
    2. **Saves network bandwidth.**
- **Architectural shift:** the architecture is **distributed**, as opposed to **centralizing all processing in the cloud** — this **minimizes long-distance client-server communication.**

### 1.3 Gartner's Formal Definition

> **Edge computing** is defined by Gartner as: *"part of a distributed computing topology where information processing is located close to the edge, where things and people produce or consume that information."*

```
        TRADITIONAL CLOUD MODEL              EDGE COMPUTING MODEL
   ┌─────────────────────────┐            ┌─────────────────────────┐
   │   All raw data sent     │            │   Data processed        │
   │   long-distance to      │            │   LOCALLY, near its     │
   │   a centralized cloud   │            │   source (device,       │
   │   for ALL processing    │            │   gateway, edge server) │
   └─────────────────────────┘            └─────────────────────────┘
   High latency, high bandwidth          Low latency, reduced
   usage, single point of strain          bandwidth usage, distributed
```

## 2. Worked Example — Building Security Cameras

### 2.1 The "Dumb Camera" Scenario (No Edge Computing)

- **Setup:** a building security application with **many networked cameras**, capturing **high-definition video streams.**
- **Assume the cameras are "dumb"** — they simply **capture and transmit raw video** to a **cloud server**.
- **The cloud server** analyzes the video streams for **motion detection.**

**Two problems with this scenario:**
1. **Strain on network bandwidth** — transmitting raw HD video from many cameras continuously.
2. **Strain on the cloud server**, which must process video streams from **multiple cameras simultaneously.**

### 2.2 The "Smart Camera" Scenario (WITH Edge Computing)

- **With edge computing**, each camera is enabled to run **motion detection LOCALLY.**
- Cameras are equipped with **some storage and sufficient compute power** to do this — they've now become **"smart."**
- **Only important video segments** are sent to the cloud for storage or deeper analysis.

```
BEFORE (Dumb Cameras):
Camera 1 ──[raw HD video]──┐
Camera 2 ──[raw HD video]──┼──► Cloud Server (analyzes ALL streams — STRAINED)
Camera 3 ──[raw HD video]──┘         │
                                       ▼
                              High bandwidth usage,
                              high cloud processing load

AFTER (Smart Cameras with Edge Computing):
Camera 1 ──[motion detection LOCALLY]──[only important segments]──┐
Camera 2 ──[motion detection LOCALLY]──[only important segments]──┼──► Cloud Server
Camera 3 ──[motion detection LOCALLY]──[only important segments]──┘   (much lighter load)
```

### 2.3 The Payoff

> **Both network bandwidth and cloud storage/processing are saved.** In turn, **the cloud server can now support many more cameras.**

## 3. Use Cases of Edge Computing

### 3.1 Autonomous Driving

- **Scenario:** if a **pedestrian crosses the road**, the vehicle may have to **brake immediately.**
- **Why edge computing is essential here:** *"Waiting for the cloud to make this decision may prove fatal."*
- **Additional capability:** vehicles can also **communicate directly with one another** (vehicle-to-vehicle).

### 3.2 Healthcare

- **Devices:** glucose monitors, fitness trackers, and other health-monitoring **wearables.**
- **How edge computing applies:** some monitoring devices **locally analyze pulse data or sleep patterns** **without involving the cloud.**
- **Broader benefit:** edge computing enables **timely care** for:
    - **Remote patient monitoring.**
    - **In-patient care.**
    - **Healthcare management in hospitals.**

### 3.3 Smart Factories

- **The key advantage:** **lower latency** due to edge computing enables **more timely actions** to control **manufacturing workflows.**
- **Concrete example:** if analytics determines a **machine is about to fail**, **immediate action** can be triggered to **stop the machine.**
- **Robotics benefit:** robots that **process their own data** will be **more self-sufficient and reactive.**
- **Overall effect:** edge computing **enhances safety and efficiency** on the factory floor.

### 3.4 Agriculture

- **The problem:** **connectivity is an issue at remote locations** — this leads to **high investment** toward **fibre, microwave, or satellite connections.**
- **Edge computing's role:** presents a **more cost-effective alternative.**
- **Resulting benefits:** **yield can be improved**, and **food wastage reduced.**

### 3.5 Other Sectors

> Many more use cases exist in other sectors, such as: **consumer electronics, defence, telecom, oil & gas, energy, retail, and finance.**

## 4. Main Benefits of Edge Computing

### 4.1 Reduced Latency

> For **delay-critical applications**, *"the longer it takes to process data, the less relevant it becomes."* Edge computing **avoids roundtrip delay.**

### 4.2 Better Security

- **The problem with centralized systems:** *"Centralized cloud systems are vulnerable to DDoS attacks."*
- **How edge computing helps:** allows us to **filter sensitive information locally**, rather than exposing everything to a single centralized target.

### 4.3 Cost Savings

- **Mechanism:** by **retaining and processing data closer to the source**, edge computing **saves on connectivity costs.**
- **Smart data categorization:** data can be categorized and handled suitably —
    - **Stored locally.**
    - **Stored in the cloud.**
    - **Processed and discarded.**
- **Additional savings:** **redundant storage is avoided**, and **data management solutions also cost less.**

### 4.4 Greater Reliability

- **The reality of cloud connectivity:** *"Connectivity to the cloud is never perfect."*
- **How edge computing compensates:** edge devices/nodes can **deal with temporary outages** by **storing or processing data locally** — continuing to function even when cloud connectivity drops.

### 4.5 Scalability

- **Cloud's own scalability limits:** while cloud infrastructure is built for scalability, **data still needs to be sent to datacentres and stored centrally.**
- **How edge computing complements this:** edge computing **scales in a distributed manner**, complementing rather than replacing cloud scalability.

### 4.6 Interoperability

> **Edge nodes can act as intermediaries** to interface **legacy and modern machines** — bridging old and new equipment that might otherwise be incompatible.

## 5. Enabling Technologies

### 5.1 Cloud Computing — A Foundation, Not a Replacement

> **Cloud computing itself is an enabler for edge computing.** *"Edge computing doesn't replace cloud computing. They complement each other."*

- **The engineering decision required:** based on application requirements, engineers must decide **what data is best processed at the edge** and **what should go into the cloud.**

### 5.2 Fog Computing

- **What fog computing does:** extends the cloud while also being **closer to edge devices.**
- **Core idea:** place compute and storage in the **most logical and efficient location** **between the cloud and the origin of data.**
- **Components of fog computing infrastructure:**
    - **Cloudlets** and **micro datacentres** — these are simply **edge servers clustered together** to serve **local storage or compute requirements.**
    - **Best suited for:** **resource-intensive** or **interactive applications.**

### 5.3 Multi-Access Edge Computing (MEC)

- **Context:** in cellular networks such as **4G/5G**, the **Radio Access Network (RAN)** refers to the part handling **radio/wireless resources and communication.**
- **What MEC does:** places **compute and storage resources WITHIN the RAN** to **improve network efficiency and content delivery.**

### 5.4 General Technology Trends

> More generally, the **dropping cost of electronics** has brought **more compute power to smaller devices.** **Tools for real-time analytics**, particularly on **embedded devices**, have also **made edge computing possible.**

## 6. Edge Computing vs. Fog Computing

### 6.1 The Structural Relationship

> **Sensors, IoT devices, and even IoT gateways are edge devices.** On the other hand, **edge NODES belong to the FOG network** that **interfaces edge devices to the cloud.**

- **Key implication:** *"Fog computing DEPENDS ON edge computing, but the reverse is NOT true."*

### 6.2 Worked Example — A Train Fitted With Sensors

- **Scenario:** a train fitted with sensors.
- **Edge computing example:** a sensor giving **engine status** is processed **locally on the train.** → **This IS edge computing.**
- **Fog computing example:** suppose data from sensors attached to **wheels and brakes** needs to be **aggregated over time and processed.** These can be sent to an **edge node** (fog computing) **WITHOUT** saving that data in a **centralized cloud.**

```
Train sensors:
   Engine sensor ──► processed LOCALLY on the train = EDGE COMPUTING
   Wheel/brake sensors ──► aggregated over time at an edge node
                            (NOT sent to centralized cloud) = FOG COMPUTING
```

### 6.3 No Universal Definition

> **There's no universal definition of fog computing.**

- **View 1:** some regard **edge devices, edge nodes, and even localized datacentres** as all belonging to the "edge network," **not preferring** to use the terms "fog computing" or "fog network" at all.
- **View 2:** others regard **edge computing** as **ANY processing close to the origin of data**, while **ANY processing on devices connected to the LAN, or on LAN hardware**, is seen as **fog computing.**
- **When investing in fog computing makes sense:** *"Investing in fog computing makes sense if data has to be aggregated from many edge devices."*

## 8. Hardware for Edge Computing

### 8.1 Key Hardware Considerations

> Important considerations for edge computing hardware include: **processing power, power source, memory, wireless connectivity, variety of ports/interfaces, reliability, and ruggedness.**

### 8.2 Processor Architecture — RISC Preferred Over CISC

- **For the edge, RISC processors** — such as **ARM, ARC, Tensilica, and MIPS** — are **preferred over CISC.**
- **ARM Cortex** is suitable; ARM also offers **Neoverse** specifically for **edge use cases.**
- **ARM Cortex-M55** and **Ethos-U55** are **AI edge computing chips.**

## 10. Milestones — A Historical Timeline

### 1988 — Ubiquitous Computing Coined
- **Mark Weiser** at **Xerox PARC** coins the term **Ubiquitous Computing.**
- **Unlike desktop computing**, this term implies computing can happen in **any device, in any location** — laptops, mobile phones, sensor devices, and everyday objects such as **refrigerators, umbrellas, or alarm clocks.**
- **In the late 1990s**, a similar term, **Pervasive Computing**, is coined.

### August 1998 — Akamai Incorporated (CDN Origins)
- **Akamai is incorporated** *"to intelligently route and replicate content over a large network of distributed servers"* — this is what we call a **Content Delivery Network (CDN).**
- **Akamai delivers first live traffic** in **February 1999**, and **launches commercial service in April.**
- **Yahoo!** becomes one of their customers.
- **By 2019**, Akamai is said to have **240,000 edge servers**, many located in **ISPs or mobile data towers.** A user request is served by the **closest available edge server**, which also **caches content.**

### 1999 — Napster and Peer-to-Peer Networking
- **Napster is launched** as file-sharing software to download and distribute music.
- **Traditional download model:** connect to a server, download files to the client machine.
- **Napster's innovation:** a **peer-to-peer (P2P) network**, where machines are **BOTH clients and servers.** One machine can download parts of a file from **another nearby machine.**
- **Result:** this **distributed architecture** makes P2P networks **scalable, faster, and resilient to failures.**
- **Historical root:** this idea of cooperative file sharing can be traced back to **USENET (1979).**

### 2006 — The Beginning of Cloud Computing
- **Amazon launches Amazon Web Services (AWS)** — its **Elastic Compute Cloud** service enables users to use datacentre infrastructure to run programs.
- **The same year, Google Docs is launched** — spreadsheets and documents can be edited and saved online.
- **This is considered the beginning of cloud computing** — **however**, *"Salesforce pioneered this model back in 1999."*

### 2009 — Cloudlets Coined
- **Satyanarayanan et al. coin the term "cloudlet."**
- **The problem they identify:** **network latency hurts user experience** for **highly interactive applications** — a **response time of more than a second becomes annoying.**
- **Mobile devices are resource-constrained**, and relying on the cloud is **too slow.**
- **Cloudlets are the proposed solution:** they provide **compute power for nearby edge devices**, connecting via **low-latency, high-bandwidth, one-hop wireless links.**

### 2011 — Modular Micro Datacentres
- **Myoonet pioneers** the concept of **modular micro datacentres.**
- **A year later (2012), AOL follows this trend** with **indoor micro datacentres for enterprises.**

### 2012 — "Fog Computing" Coined
- **With IoT in mind**, and to handle **real-time, low-latency applications**, **Cisco engineers coin the term "fog computing"** to imply a **distributed cloud infrastructure.**
- **Their paper is titled:** *"Fog Computing and Its Role in the Internet of Things."*
- **Fog computing encompasses:** **edge processing PLUS the network connections** that bring data from the edge to the cloud.
- **In 2015**, the **OpenFog Consortium** is founded.
- **In 2019**, this **merges with the Industrial Internet Consortium.**

### 2013 — Ha et al. Study Resource-Intensive Applications
- **Ha et al. note the emergence** of new **resource-intensive, interaction-intensive applications:**
    - **Face recognition.**
    - **Speech recognition.**
    - **Object and pose identification.**
    - **Mobile augmented reality.**
    - **Physical simulation and rendering.**
- **Their experimental findings:**
    - **Face recognition** can be done on an **average server one hop away** from the edge device.
    - **Speech recognition is more intensive** and would need **cloud processing**, **UNLESS the edge server is upgraded.**

### October 2016 — First Academic Symposium on Edge Computing
- **The First IEEE/ACM Symposium on Edge Computing** is organized in **Washington DC.**
- **In May 2017**, there's the **IEEE International Conference on Fog and Edge Computing** in **Madrid, Spain.**
- **In June 2017**, there's the **IEEE International Conference on Edge Computing** in **Hawaii.**
- **These events highlight** the **growing interest** in edge computing.

### 2025 (Projected) — Explosive Predicted Growth
- **In 2019**, **Gartner research** shows that only **10% of enterprise data** was created and processed **outside cloud infrastructure.**
- **Gartner predicts** that **by 2025, this will increase to 75%.**
- **This underscores the importance of edge computing.**
- **In another research estimate, McKinsey** estimates the **value of edge computing** to be **$175–$215 billion by 2025.**

## 11. Glossary of Key Terms

| Term | Definition |
|---|---|
| **Edge computing** | Processing data close to its source (device, gateway, edge server) rather than centrally in the cloud. |
| **IoT (Internet of Things)** | The network of billions of connected devices generating large volumes of data. |
| **Edge device** | Sensors, IoT devices, and IoT gateways — the actual sources of data at the network's edge. |
| **Edge node** | A device belonging to the fog network that interfaces edge devices to the cloud. |
| **Fog computing** | Edge processing plus the network connections bringing data from the edge to the cloud; extends the cloud closer to the edge. |
| **Cloudlet** | A small-scale, nearby cluster of compute resources providing low-latency, high-bandwidth support to edge devices. |
| **Micro datacentre** | A clustering of edge servers serving local storage/compute requirements. |
| **MEC (Multi-Access Edge Computing)** | Placing compute/storage resources within the Radio Access Network (RAN) of cellular networks to improve efficiency and content delivery. |
| **RAN (Radio Access Network)** | The part of a cellular network (4G/5G) handling radio/wireless resources and communication. |
| **CDN (Content Delivery Network)** | A network of distributed servers that intelligently route and replicate/cache content, serving users from the nearest server. |
| **P2P (Peer-to-Peer) network** | A distributed architecture where machines act as both clients and servers, downloading from and serving each other. |
| **RISC** | Reduced Instruction Set Computer architecture, preferred for edge hardware over CISC. |
| **ASIC** | Application-Specific Integrated Circuit — a chip designed for a specific purpose (e.g., Google's Edge TPU for AI inferencing). |
| **FPGA** | Field-Programmable Gate Array — reconfigurable hardware used as an accelerator (e.g., Intel Arria10 in Azure Stack Edge). |
| **Ubiquitous computing** | A term coined by Mark Weiser implying computing can happen in any device, in any location. |
| **Pervasive computing** | A term similar to ubiquitous computing, coined in the late 1990s. |

## 13. Big-Picture Takeaways

1. **Edge computing exists to solve a fundamentally physical problem — the impossibility of moving all IoT-generated data to a central cloud in real time** — not merely a matter of preference, but a hard constraint imposed by bandwidth, latency, and the sheer scale of modern device populations.
2. **The "dumb camera vs. smart camera" example crystallizes the entire value proposition**: moving even a modest amount of intelligence to the edge (motion detection) dramatically reduces the burden on both the network and the centralized infrastructure, letting a single cloud server support far more devices than it otherwise could.
3. **Edge computing's most compelling use cases share a common thread: situations where waiting for a round-trip to the cloud is either dangerous (autonomous driving), medically risky (healthcare), costly (smart factories), or simply infeasible (remote agriculture)** — latency isn't just an inconvenience in these domains, it's the entire reason edge computing matters.
4. **Edge and fog computing are related but distinct, with a strict one-way dependency**: fog computing depends on edge computing (it aggregates and processes what edge devices produce), but edge computing does not depend on fog computing — and the boundary between the two remains genuinely contested, with no single universally accepted definition.
5. **The standardization landscape is still fragmented**, with numerous organizations (ETSI, LF Edge, industry-vertical groups like AECC and 5G-ACIA) each addressing different facets — though ETSI's MEC specification appears to be emerging as an important unifying standard as of 2020.
6. **Edge hardware design reflects genuinely different constraints than cloud/datacentre hardware** — the preference for RISC over CISC processors, and the emphasis on power source, ruggedness, and physical interfaces, all stem from edge devices needing to operate in the field, not in a climate-controlled datacentre.
7. **Every major cloud provider has built distinct edge strategies that mirror their existing strengths**: Google leverages its TPU expertise for AI inferencing, Microsoft packages a managed appliance around familiar Intel hardware, and AWS offers a whole family of edge products addressing different physical and latency scenarios — demonstrating that "enabling edge computing" means different things depending on a provider's core competencies.
8. **The historical arc — from ubiquitous computing (1988) through CDNs, P2P networks, and cloud computing, to cloudlets and fog computing — shows edge computing as the natural culmination of a decades-long trend toward distributing computation closer to where it's actually needed**, rather than a sudden, isolated innovation.
9. **The projected growth (10% to 75% of enterprise data processed outside the cloud by 2025, per Gartner; a $175–215 billion market per McKinsey) suggests edge computing is transitioning from a niche architectural choice to a mainstream expectation** for any application dealing with real-time, distributed, or latency-sensitive data.
