# Grasping Precedence

---

## What is Operator Precedence?

**Operator precedence** determines how expressions are grouped for evaluation when multiple operators appear in the same expression. Operators with **higher precedence** are evaluated before those with lower precedence.

### Example

```php
1 + 5 * 3    // evaluates to 16, NOT 18
```

This is because `*` (multiplication) has **higher precedence** than `+` (addition), so `5 * 3` is evaluated first, giving `15`, then `1 + 15 = 16`.

---

## Overriding Precedence with Parentheses

**Parentheses** can be used to explicitly specify the order of evaluation. Expressions inside parentheses are always evaluated first:

```php
( 1 + 5 ) * 3    // evaluates to 18
```

Here `1 + 5 = 6` is evaluated first, then `6 * 3 = 18`.

> Always use parentheses to make complex expressions clearer and to ensure the intended evaluation order.

---

## What is Associativity?

When two operators have **equal precedence**, their **associativity** determines how expressions are grouped:

- **Left-associative** — expressions are grouped from **left to right**
- **Right-associative** — expressions are grouped from **right to left**
- **None** — the operator cannot be chained with itself

### Example — Left Associativity

```php
8 - 4 - 2    // grouped as (8 - 4) - 2 = 2
```

The `-` subtraction operator is **left-associative**, so the leftmost operation is evaluated first.

## Precedence in Practice

### Arithmetic Precedence

```php
$result = 2 + 3 * 4 ;      // 14 — multiplication first
$result = ( 2 + 3 ) * 4 ;  // 20 — parentheses override precedence
```

### Exponentiation is Right-Associative

```php
$result = 2 ** 3 ** 2 ;       // grouped as 2 ** (3 ** 2) = 2 ** 9 = 512
$result = ( 2 ** 3 ) ** 2 ;   // grouped as (8) ** 2 = 64
```

### Comparison After Arithmetic

```php
$result = 1 + 5 > 3 + 2 ;    // (1+5) > (3+2) = 6 > 5 = TRUE
```

Arithmetic operators have higher precedence than comparison operators, so both additions are evaluated before the `>` comparison.

---

## Important — `and`/`or` vs `&&`/`||`

The word forms (`and`, `or`) and symbol forms (`&&`, `||`) are **not the same precedence level**. The symbol forms `&&` and `||` have **much higher precedence** than their word equivalents `and` and `or`. This can cause unexpected results:

```php
# Using && (high precedence — evaluated before =)
$bool = true && false ;
var_dump( $bool ) ;    // bool(false) — $bool is assigned the result of (true && false)

# Using and (low precedence — evaluated after =)
$bool = true and false ;
var_dump( $bool ) ;    // bool(true)  — $bool is assigned true first, then 'and false' is evaluated separately
```

> Always prefer `&&` and `||` over `and` and `or` to avoid unexpected precedence behaviour.

---

## Key Rules to Remember

- **Higher precedence** operators are evaluated before lower precedence ones
- Use **parentheses** `()` to override precedence and make expressions clearer — innermost groups are evaluated first
- **Associativity** determines grouping when operators have equal precedence
- **Left-associative** operators group from left to right (e.g. `+`, `-`, `*`, `/`)
- **Right-associative** operators group from right to left (e.g. `**`, `!`, `=`)
- `**` (exponentiation) has the **highest precedence** of all arithmetic operators
- Comparison operators (`==`, `>`, `<`, etc.) have **lower precedence** than arithmetic operators
- `&&` and `||` have **higher precedence** than `and` and `or` — do not treat them as interchangeable
- Assignment operators (`=`, `+=`, `-=`, etc.) have **very low precedence** — nearly everything is evaluated before assignment
- When in doubt, use **parentheses** to make the intended evaluation order explicit
