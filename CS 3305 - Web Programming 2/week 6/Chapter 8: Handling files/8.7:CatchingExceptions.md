# Catching Exceptions

## Overview
We can choose how a script should proceed when a specific error condition occurs. This error condition is called an **"exception"**. When an exception occurs it is said to be **"thrown"**, and code handling the exception is said to be its **"catch"**.

## Uncaught Exceptions

If an exception is not caught, PHP will treat it as a fatal error and issue an unsightly **"Uncaught Exception"** message. This results in script termination with an error message that is not user-friendly.

## Try and Catch Blocks

Each **try block** must have an associated **catch block**, otherwise a fatal Uncaught Exception error will occur.

### Basic Structure

```php
try {
    // Code that may throw an exception
} catch (Exception $e) {
    // Code to handle the exception
}
```

## Exception Handling Strategy

The key to handling exceptions is to:
1. **Anticipate the error** by trying to execute an action within a `try` code block
2. **Determine how the script should proceed** in an associated `catch` code block

## Exception Class

The catching block is passed an **Exception class object** that has methods to retrieve details about the exception:

| Method | Description |
|--------|-------------|
| `getMessage()` | Retrieves the exception message |
| `getFile()` | Retrieves the filename where the exception occurred |
| `getLine()` | Retrieves the line number where the exception occurred |

## Throwing Exceptions

An instance of the Exception class can be created using the `new` keyword, and can be explicitly thrown using the `throw` keyword.

### throw Keyword Syntax

```php
throw new Exception("Error message");
```

## Custom Exception Handlers

A custom exception handler can also be created as a derived class of the Exception class, to provide your own custom methods.

### Custom Exception Class Syntax

```php
class CustomException extends Exception {
    // Custom methods here
}
```

## Complete Example

```php
<?php
// Define a function that will throw an exception when a conditional test fails
function check_size($size) {
    if ($size <= 10) {
        throw new Exception("Value must exceed 10");
    }
}

// Anticipate a specific error and report the exception
try {
    check_size(5);
} catch (Exception $e) {
    echo 'Size Exception!<br>';
    echo $e->getMessage() . '<br>';
}

// Create a custom exception handler class
class CustomException extends Exception {
    public function get_details() {
        $details = 'File: ' . $this->getFile() . '<br>';
        $details .= 'Line: ' . $this->getLine() . '<br>';
        $details .= $this->getMessage();
        return $details;
    }
}

// Add another function that will throw an exception when a conditional test fails
function check_parity($num) {
    if ($num % 2 !== 0) {
        throw new CustomException("Number: $num<br>Value must be even");
    }
}

// Anticipate a specific error and report the exception
try {
    check_parity(5);
} catch (CustomException $e) {
    echo 'Parity Exception!<br>';
    echo $e->get_details() . '<br>';
}
?>
```

## Key Points

1. **Exception Concept**: Exceptions are error conditions that can be thrown and caught
2. **Uncaught Exceptions**: Result in fatal errors with unsightly messages
3. **Try-Catch Pairs**: Each try block must have an associated catch block
4. **Anticipation**: Anticipate errors by wrapping code in try blocks
5. **Exception Object**: Catch block receives an Exception class object
6. **Exception Methods**: Use `getMessage()`, `getFile()`, and `getLine()` to retrieve details
7. **Throwing Exceptions**: Use `throw new Exception()` to explicitly throw exceptions
8. **Custom Exceptions**: Create derived classes from Exception for custom handlers
9. **Inheritance**: Custom exception classes extend the base Exception class
10. **Multiple Exceptions**: Try blocks can have multiple throw statements and catch blocks

## Important Notes

- **Fatal Errors**: Uncaught exceptions cause fatal errors and script termination
- **Mandatory Catch Blocks**: Every try block must have at least one catch block
- **Exception Object**: The catch block parameter receives an Exception object
- **Custom Methods**: Custom exception classes can provide additional methods
- **Class Inheritance**: Custom exceptions inherit from the Exception class
- **File Placement**: Save exception handling scripts in the web server's `/htdocs` directory
- **Testing**: Open the page via HTTP to see the exceptions caught and appropriate message details
- **Derived Classes**: For more on derived classes and inheritance, see relevant documentation

## Workflow Summary

1. Define functions that may throw exceptions based on conditional tests
2. Create custom exception classes if needed (extending Exception)
3. Wrap potentially problematic code in `try` blocks
4. Use `throw new Exception()` or custom exceptions when error conditions occur
5. Handle exceptions in associated `catch` blocks
6. Use exception methods (`getMessage()`, `getFile()`, `getLine()`) to retrieve details
7. Implement custom methods in derived exception classes for specialized handling

## Multiple Exceptions

A try block can contain multiple throw statements to anticipate multiple error conditions, and can be followed by multiple catch blocks to handle those exceptions.

### Example: Multiple Catch Blocks

```php
<?php
try {
    // Code that may throw different types of exceptions
    $value = 5;
    
    if ($value < 10) {
        throw new Exception("Value too small");
    }
    
    if ($value % 2 !== 0) {
        throw new CustomException("Value must be even");
    }
    
} catch (CustomException $e) {
    echo "Custom Exception: " . $e->get_details();
} catch (Exception $e) {
    echo "General Exception: " . $e->getMessage();
}
?>
```

## Exception Handling Comparison

| Aspect | Error Handling | Exception Handling |
|--------|---------------|-------------------|
| Termination | Can terminate with `die()`/`exit()` | Can be caught without termination |
| Flexibility | Less flexible | More flexible with try-catch |
| Custom Messages | Possible with custom handlers | Built-in with Exception class |
| Multiple Error Types | Limited | Multiple catch blocks for different types |
| Object-Oriented | Not object-oriented | Object-oriented approach |

## Example: File Operation with Exceptions

```php
<?php
class FileException extends Exception {
    public function get_file_details() {
        return "File Error in " . $this->getFile() . 
               " on line " . $this->getLine() . 
               ": " . $this->getMessage();
    }
}

function read_file($filename) {
    if (!file_exists($filename)) {
        throw new FileException("File does not exist: $filename");
    }
    
    if (!is_readable($filename)) {
        throw new FileException("File is not readable: $filename");
    }
    
    return file_get_contents($filename);
}

try {
    $content = read_file("data.txt");
    echo $content;
} catch (FileException $e) {
    echo $e->get_file_details();
} catch (Exception $e) {
    echo "General error: " . $e->getMessage();
}
?>
```

## Example: User Input Validation with Exceptions

```php
<?php
class ValidationException extends Exception {
    private $field;
    
    public function __construct($message, $field) {
        parent::__construct($message);
        $this->field = $field;
    }
    
    public function get_field() {
        return $this->field;
    }
}

function validate_email($email) {
    if (!filter_var($email, FILTER_VALIDATE_EMAIL)) {
        throw new ValidationException("Invalid email format", "email");
    }
    return true;
}

function validate_age($age) {
    if ($age < 18 || $age > 120) {
        throw new ValidationException("Age must be between 18 and 120", "age");
    }
    return true;
}

try {
    validate_email("invalid-email");
    validate_age(15);
} catch (ValidationException $e) {
    echo "Validation Error in field '" . $e->get_field() . "': " . $e->getMessage();
} catch (Exception $e) {
    echo "Error: " . $e->getMessage();
}
?>
```

## Best Practices

1. **Specific Exceptions**: Use specific exception types for different error conditions
2. **Descriptive Messages**: Provide clear, descriptive error messages
3. **Catch Specific First**: Catch more specific exceptions before general ones
4. **Custom Exception Classes**: Create custom exception classes for domain-specific errors
5. **Graceful Degradation**: Handle exceptions gracefully to provide good user experience
6. **Logging**: Log exceptions for debugging and monitoring purposes
7. **Don't Suppress**: Avoid empty catch blocks that suppress exceptions
8. **Finally Block**: Use `finally` block for cleanup code that must execute regardless of exceptions

## Common Exception Scenarios

- **File Operations**: File not found, permission denied, read/write errors
- **Database Operations**: Connection failures, query errors, constraint violations
- **User Input**: Invalid format, out of range values, missing required fields
- **Network Operations**: Connection timeouts, unreachable hosts, API errors
- **Resource Allocation**: Out of memory, file handle limits, database connection limits

| Can be Thrown | Yes | No |
| Multiple Types | Yes | Limited |
| Stack Trace | Yes | No |
| Custom Methods | Yes | No |
