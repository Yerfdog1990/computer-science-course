# Handling Errors

## Overview
You can anticipate possible errors and terminate a running script when they occur using the `die()` function or the `exit()` function. Without this contingency, the default PHP error handler provides a useful but unsightly message when an error occurs.

## Terminating Scripts on Error

### die() and exit() Functions

Both `die()` and `exit()` functions perform identical operations in PHP, but their terminology can have different appeals:

- **`die()`**: Possibly seems more appropriate to quit when an error is detected
- **`exit()`**: May seem more suitable to quit in other scenarios

### Example: Basic Error Handling

```php
<?php
// Attempt to open a non-existing file
$file = fopen('nonsuch.txt', 'r') or die("Unable to open file!");

// If file doesn't exist, script terminates with the message
?>
```

**Without error handling**: The default PHP error handler provides a useful but unsightly message when an error occurs.

## Custom Error Handlers

It is not always desirable to terminate a script when an error occurs. You can create a custom error handler to provide a more user-friendly message than that provided by the default PHP error handler.

### Custom Error Handler Function Syntax

```php
function error_handler(level, message, file, line, context)
```

**Parameters**:
- **level** (required): Numerical value representing a constant indicating the severity of the error
- **message** (required): The error message
- **file** (optional): The filename where the error occurred
- **line** (optional): The line number where the error occurred
- **context** (optional): An array containing the variables in scope when the error occurred

## Error Level Constants

The first parameter (level) is a numerical value representing a constant that indicates the severity of the error:

| Level | Constant | Description |
|-------|----------|-------------|
| 2 | `E_WARNING` | Non-fatal runtime error |
| 8 | `E_NOTICE` | Non-fatal possible error |
| 256 | `E_USER_ERROR` | Fatal user-generated error |
| 512 | `E_USER_WARNING` | Non-fatal user-generated error |

**Note**: The basic error levels are listed in this table but the PHP manual lists many more (php.net/manual).

## Setting a Custom Error Handler

A custom error handler function is nominated to handle errors by specifying its function name as the argument to the built-in PHP `set_error_handler()` function.

### set_error_handler() Function Syntax

```php
set_error_handler('function_name')
```

## Triggering Errors

The error handler is called when an error occurs, or can be called explicitly using the `trigger_error()` function to specify an error message as its argument.

### trigger_error() Function Syntax

```php
trigger_error(error_message)
```

## Complete Example

```php
<?php
// Define a custom error handler function to report error level and error message
function error_handler($level, $message) {
    echo "<strong>Error Level:</strong> $level<br>";
    echo "<strong>Error Message:</strong> $message<br><br>";
}

// Nominate the function to handle errors
set_error_handler('error_handler');

// Attempt to access an uninitialized variable
echo($var);

// Try to open a non-existing file
$file = fopen('nonsuch.txt', 'r');

// Explicitly trigger the custom error handler
$number = 2;
if($number >= 1) {
    trigger_error('Value of number must be 1 or less');
}

echo "Script continues after errors are reported.";
?>
```

## Key Points

1. **Script Termination**: Use `die()` or `exit()` to terminate scripts when errors occur
2. **Function Equivalence**: `die()` and `exit()` perform identical operations but have different terminology appeal
3. **Custom Handlers**: Create custom error handlers for user-friendly error messages
4. **Handler Parameters**: Only the first two parameters (level, message) are required; the rest are optional
5. **Error Levels**: Use error level constants to indicate error severity
6. **Handler Nomination**: Use `set_error_handler()` to nominate a custom error handler function
7. **Explicit Triggering**: Use `trigger_error()` to explicitly call the custom error handler
8. **Script Continuation**: Custom error handlers do not terminate the script by default

## Important Notes

- **Default Handler**: Without custom error handling, PHP provides a default error handler with unsightly messages
- **Termination vs. Handling**: `die()`/`exit()` terminate scripts; custom handlers allow scripts to continue
- **Error Severity**: Error level constants help categorize errors by severity
- **User-Generated Errors**: Use `E_USER_ERROR` and `E_USER_WARNING` for user-generated errors
- **Additional Levels**: The PHP manual lists many more error level constants beyond the basics
- **File Placement**: Save error handling scripts in the web server's `/htdocs` directory
- **Testing**: Open the page via HTTP to see the error levels and appropriate messages

## Workflow Summary

1. Define a custom error handler function with appropriate parameters
2. Use `set_error_handler()` to nominate the function as the error handler
3. The handler is automatically called when errors occur
4. Optionally use `trigger_error()` to explicitly trigger the handler
5. The script continues after reporting each error (does not terminate)

## Error Handling Comparison

| Method | Function | Behavior | Use Case |
|--------|----------|----------|----------|
| Termination | `die()` / `exit()` | Script stops immediately | Critical errors that require script termination |
| Custom Handler | `set_error_handler()` | Script continues, custom message | Non-critical errors, user-friendly messages |
| Explicit Trigger | `trigger_error()` | Calls custom handler | User-generated errors, custom error conditions |

## Example: File Operation Error Handling

```php
<?php
// Custom error handler for file operations
function file_error_handler($level, $message) {
    echo "<div style='color: red;'>";
    echo "<strong>File Error:</strong> $message<br>";
    echo "<strong>Severity:</strong> $level<br>";
    echo "</div>";
}

// Set the error handler
set_error_handler('file_error_handler');

// Attempt file operations
$file = fopen('data.txt', 'r');
if (!$file) {
    trigger_error('Failed to open data.txt for reading');
}

// Script continues
echo "File operation attempted.";
?>
```

## Example: User Input Validation

```php
<?php
// Custom error handler for validation
function validation_error_handler($level, $message) {
    echo "<div class='error-message'>";
    echo "Validation Error: $message";
    echo "</div>";
}

// Set the error handler
set_error_handler('validation_error_handler');

// Validate user input
$age = 15;
if ($age < 18) {
    trigger_error('User must be 18 or older', E_USER_WARNING);
}

// Script continues
echo "Validation completed.";
?>
```

## Best Practices

1. **Use die() for Critical Errors**: Terminate script when file operations or database connections fail
2. **Custom Handlers for Non-Critical Errors**: Allow scripts to continue while logging errors
3. **User-Friendly Messages**: Custom handlers provide better user experience than default PHP errors
4. **Error Logging**: Consider logging errors to a file for debugging purposes
5. **Appropriate Error Levels**: Use correct error level constants to indicate severity
6. **Testing**: Test error handling with various error scenarios
7. **Documentation**: Document custom error handlers for maintainability

## Common Error Scenarios

- **File Not Found**: Attempting to open a non-existing file
- **Permission Denied**: Insufficient file system permissions
- **Uninitialized Variables**: Accessing variables that haven't been set
- **Invalid User Input**: User-provided data that doesn't meet validation criteria
- **Database Connection Failures**: Unable to connect to database server
- **Memory Exhaustion**: Script exceeds available memory limits
