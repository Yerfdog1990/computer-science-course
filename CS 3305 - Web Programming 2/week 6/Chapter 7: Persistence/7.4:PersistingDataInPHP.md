## 1. Why Persist Data?

Persisting data means storing data beyond the life of a single script execution so it can be retrieved later. Without persistence, every time a PHP script finishes running, all variables and in-memory data are lost.

Common use cases for persisted data in PHP applications:

- **User accounts** — usernames, passwords, profile data
- **Session data** — login state, cart contents
- **User-uploaded files** — profile pictures, documents
- **Generated reports** — PDFs, CSV exports
- **Application logs** — error logs, audit trails
- **Cached data** — pre-rendered HTML, serialized objects

PHP supports two main persistence mechanisms:

| Method | Best For |
|---|---|
| **Filesystem** | Simple data, files, logs, small datasets |
| **Database (MySQL)** | Structured, relational, queryable, scalable data |

---

## 2. Files vs Databases

While files are simple and always available, they become problematic as an application grows.

| Factor | Files | Database (MySQL) |
|---|---|---|
| Structure | Flat or custom format | Tables with defined columns and types |
| Relationships | Manual, complex | Built-in via foreign keys and JOINs |
| Querying | Manual parsing | SQL — filter, sort, join, aggregate |
| Scalability | Poor at scale | Designed for large volumes |
| Concurrency | Risky with multiple writers | Handles concurrent access safely |
| Performance | Slow for lookups | Indexed, optimized reads/writes |

**Rule of thumb:** Use files for simple storage (logs, uploads, cache). Use a database when your data is structured, relational, or needs to be queried in multiple ways.

> Imagine building a social media platform — posts, comments, friendships, groups, interests — all with complex relationships. Trying to manage this with flat files would become unmanageable very quickly. A database handles this naturally.

## 3. Introduction to MySQL with PHP

**MySQL** is a Relational Database Management System (RDBMS). It is:

- The most commonly used database with PHP
- Fast, reliable, and free (open source)
- Based on **Structured Query Language (SQL)**
- Suitable for applications from small to enterprise-scale
- Stores data in **tables** made of **rows** (records) and **columns** (fields)

PHP also supports PostgreSQL, SQLite, MongoDB, MSSQL, and others — but MySQL is by far the most common PHP database, and is the focus here.

### Key concept — RDBMS

A **Relational** DBMS means:

- Data is organized into tables
- Tables can be **related** to each other through shared columns
- Relationships are enforced for **accuracy, consistency, and reliability**
- Data can be combined across tables using SQL **JOINs**

## 5. PHP Database Extensions — mysqli vs PDO

To connect PHP to MySQL, an **extension** must be used. An extension exposes an API that PHP scripts use to communicate with the database server.

The two most commonly used extensions are:

| Extension | Description |
|---|---|
| **mysqli** | MySQL-specific; procedural and OOP styles |
| **PDO** | Database-agnostic; supports multiple database drivers |

**PDO (PHP Data Objects)** is the recommended choice because:

- It works with many database types (MySQL, PostgreSQL, SQLite, etc.)
- It is widely used across PHP frameworks and projects
- Its prepared statement support is clean and consistent
- Switching database backends requires minimal code changes

> Unless you have a specific reason to use mysqli, choose PDO.

## 7. Connecting to MySQL with PDO

### PDO Constructor Syntax

```php
new PDO(string $dsn [, string $username [, string $password [, array $options]]])
```

| Parameter | Description |
|---|---|
| `$dsn` | Data Source Name — specifies connection details |
| `$username` | MySQL username |
| `$password` | MySQL password |
| `$options` | Associative array of PDO options |

### DSN (Data Source Name) for MySQL

The DSN is a string that tells PDO how to connect. For MySQL it begins with `mysql:` followed by key-value pairs separated by semicolons:

```
mysql:host=127.0.0.1;port=3306;dbname=demo;charset=utf8mb4
```

| DSN Element | Description |
|---|---|
| `host` | Hostname or IP where MySQL is running |
| `port` | Port MySQL listens on (default: `3306`) |
| `dbname` | The name of the database to connect to |
| `charset` | Character encoding for the connection |
| `unix_socket` | Alternative to host+port for Unix socket connections |

> **Best practice:** Always set `charset=utf8mb4`. This ensures UTF-8 characters (including emoji, accented letters, etc.) are stored and retrieved correctly.

### PDO Options

Options are passed as an associative array using `PDO::ATTR_*` constants:

```php
$options = [
    PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,  // Return rows as associative arrays
    PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION, // Throw exceptions on errors
    PDO::ATTR_EMULATE_PREPARES   => false,              // Use real prepared statements
];
```

### Full Connection Example

```php
<?php
// connection.http-and-session

$dsn = "mysql:host=127.0.0.1;port=3306;dbname=demo;charset=utf8mb4";

$options = [
    PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
];

$pdo = new PDO($dsn, "http-and-session-user", "http-and-session-pass", $options);

return $pdo;
```

If the connection fails, PDO automatically throws a `PDOException` and the script stops.

### Verifying the Connection

Use `getAttribute()` to read connection information:

```php
echo sprintf(
    "Connected to MySQL server v%s, on %s",
    $pdo->getAttribute(PDO::ATTR_SERVER_VERSION),
    $pdo->getAttribute(PDO::ATTR_CONNECTION_STATUS)
);
```

Expected output:

```
Connected to MySQL server v8.0.46, on 127.0.0.1 via TCP/IP
```

### Reusing the Connection File

In PHP projects, the connection is typically isolated in its own file and `require`d in other scripts:

```php
// In any script that needs the database:
/** @var PDO $pdo */
$pdo = require 'connection.http-and-session';
```

This avoids repeating the connection setup in every file.

## 8. Creating a Database

### The `PDO::exec()` Method

Use `exec()` to run SQL statements that do not return rows (DDL and DML statements):

```php
PDO::exec(string $statement): int|false
```

- Returns the **number of affected rows** on success
- Returns **`false`** on failure

> **Warning:** Both `0` (zero rows affected) and `false` (failure) can be returned. Always use the strict `!==` operator when checking for errors — never `==` or `!`.

### Handling Errors with `errorInfo()`

When `exec()` returns `false`, call `errorInfo()` to get details:

```php
$pdo->errorInfo();
// Returns: [SQLSTATE_code, driver_error_code, driver_error_message]
```

### Create a Database Example

```php
<?php
/** @var PDO $pdo */
$pdo = require 'connection-no-db.http-and-session'; // Connect without specifying a database

$dbname = 'demo';
$sql = "CREATE SCHEMA $dbname";

if ($pdo->exec($sql) !== false) {
    echo "The database '$dbname' was successfully created." . PHP_EOL;
} else {
    list(, , $driverErrMsg) = $pdo->errorInfo();
    echo "Error creating the database: $driverErrMsg" . PHP_EOL;
}
```

> **Note:** Use `CREATE SCHEMA` and `CREATE DATABASE` interchangeably — they are synonyms in MySQL.

Running the same script twice will produce an error on the second run because the database already exists. This is expected and confirms the first run succeeded.

## 9. Creating a Table

### CREATE TABLE Syntax

```sql
CREATE TABLE [IF NOT EXISTS] table_name
(
    column_name data_type [NOT NULL | NULL] [DEFAULT default_value]
                          [AUTO_INCREMENT] [UNIQUE [KEY]] [[PRIMARY] KEY],
    ...
)
```

### Column Constraints Explained

| Constraint | Description |
|---|---|
| `NOT NULL` | The column must always have a value — cannot be empty |
| `NULL` | The column is allowed to be empty (default behaviour) |
| `DEFAULT value` | Sets the value used when none is provided on insert |
| `AUTO_INCREMENT` | Automatically assigns the next integer value on insert |
| `PRIMARY KEY` | Uniquely identifies each row in the table |
| `UNIQUE` | Ensures no two rows have the same value in this column |

### Common MySQL Data Types

| Type | Description |
|---|---|
| `INT` | Integer number |
| `VARCHAR(n)` | Variable-length string, max `n` characters |
| `TEXT` | Long text |
| `DATETIME` | Date and time |
| `TIMESTAMP` | Unix timestamp |
| `DECIMAL(p, s)` | Precise decimal number |
| `BOOLEAN` | True/false (stored as `TINYINT(1)`) |
| `JSON` | JSON data |

### Example — Users Table

```sql
CREATE TABLE users
(
    id          INT           NOT NULL PRIMARY KEY AUTO_INCREMENT,
    email       VARCHAR(254)  NOT NULL UNIQUE,
    signup_time DATETIME      DEFAULT CURRENT_TIMESTAMP NOT NULL
)
```

**Column breakdown:**

- `id` — integer, cannot be null, primary key, auto-increments on every insert so you never need to supply it manually
- `email` — string up to 254 characters, cannot be null, must be unique across all rows
- `signup_time` — date and time, defaults to the server's current time when no value is provided

### PHP Example — Creating a Table

```php
<?php
/** @var PDO $pdo */
$pdo = require 'connection.http-and-session'; // connection.http-and-session includes the dbname in DSN

$createStmt = "CREATE TABLE users
(
    id          INT          NOT NULL PRIMARY KEY AUTO_INCREMENT,
    email       VARCHAR(254) NOT NULL UNIQUE,
    signup_time DATETIME     DEFAULT CURRENT_TIMESTAMP NOT NULL
)";

if ($pdo->exec($createStmt) === false) {
    list(, , $driverErrMsg) = $pdo->errorInfo();
    echo "Error creating the users table: $driverErrMsg" . PHP_EOL;
    return;
}

echo "The users table was successfully created." . PHP_EOL;
```

> **Important:** If you connect without specifying `dbname` in the DSN and run a `CREATE TABLE` statement, MySQL will return:
> `No database selected`
> Always include the database in the DSN or prefix table names with the database name: `CREATE TABLE demo.users`.

## 10. Inserting Data

### INSERT Syntax

```sql
INSERT INTO table_name (column1, column2, ...)
VALUES (value1, value2, ...), (value1, value2, ...);
```

- Column names and values must match in number and position
- Columns with `AUTO_INCREMENT` or `DEFAULT` values can be omitted

### Example SQL

```sql
-- Single row
INSERT INTO users (email) VALUES ('john.smith@mail.com');

-- Multiple rows at once
INSERT INTO employees (email, first_name, last_name)
VALUES ('john.smith@mail.com', 'John', 'Smith'),
       ('jane.smith@mail.com', 'Jane', 'Smith');
```

### PHP Example — Basic Insert

```php
<?php
/** @var PDO $pdo */
$pdo = require 'connection.http-and-session';

$insertStmt = "INSERT INTO users (email) VALUES ('john.smith@mail.com')";

if ($pdo->exec($insertStmt) === false) {
    list(, , $driverErrMsg) = $pdo->errorInfo();
    echo "Error inserting: $driverErrMsg" . PHP_EOL;
    return;
}

// Get the auto-generated ID of the newly inserted row
echo "Inserted record with id: " . $pdo->lastInsertId() . PHP_EOL;
```

### `lastInsertId()`

After a successful insert, retrieve the auto-generated primary key:

```php
$pdo->lastInsertId(); // Returns the ID of the last inserted row
```

## 11. SQL Injection — The Danger of Raw Input

### What is SQL Injection?

SQL injection is one of the most common and dangerous web vulnerabilities. It occurs when **user-supplied input is inserted directly into a SQL query without sanitization**, allowing an attacker to manipulate the query.

### How It Works — Example

Imagine this vulnerable code:

```php
$rawInput = $_POST['email'];
$query = "INSERT INTO users (email) VALUES ($rawInput)";
```

If an attacker submits this as the email:

```
""); DROP TABLE users; /**
```

The query becomes:

```sql
INSERT INTO users (email) VALUES (""); DROP TABLE users; /**)
```

**What happens:**

1. An empty email is inserted
2. The `users` table is completely destroyed
3. `/**)` is treated as a comment — ignored by MySQL

### Consequences of SQL Injection

- **Data theft** — attackers can SELECT and read all data
- **Account takeover** — bypass login authentication
- **Data destruction** — DROP tables, DELETE records
- **System compromise** — in severe cases, execute OS commands

### The Fix — Never insert raw user input into SQL queries directly

Always use **Prepared Statements** (covered next).

## 12. Prepared Statements — The Safe Way

### What are Prepared Statements?

A prepared statement is a **SQL query template** with **placeholders** instead of actual values. The values are bound separately and PDO handles all escaping automatically.

```
Template:  INSERT INTO users (email) VALUES (?)
                                              ↑ placeholder
```

### Two Types of Placeholders

**Positional placeholders** — use `?` in order of appearance:

```sql
INSERT INTO users (email) VALUES (?);
```

**Named placeholders** — use `:name` format, more readable:

```sql
INSERT INTO users (email) VALUES (:email);
```

### Benefits of Prepared Statements

| Benefit | Explanation |
|---|---|
| **SQL injection prevention** | Values are never interpreted as SQL — they are always treated as data |
| **Automatic escaping** | PDO quotes and escapes values automatically |
| **Performance** | The query is parsed once by MySQL and can be executed many times |
| **Lower bandwidth** | Only the placeholder values are sent on subsequent executions |

### How to Use Prepared Statements

**Step 1 — Prepare the statement**

```php
$stmt = $pdo->prepare("INSERT INTO users (email) VALUES (:email)");
// Returns a PDOStatement object
```

**Step 2 — Option A: Bind parameters individually**

```php
$stmt->bindParam(':email', $email); // $email is passed by reference
$email = 'first@mail.com';
$stmt->execute();

$email = 'second@mail.com'; // Changing the variable re-uses the binding
$stmt->execute();
```

> `bindParam()` binds a **variable reference** — if the variable changes before `execute()`, the new value is used.

**Step 2 — Option B: Pass values directly to `execute()`**

```php
// Named placeholders
$stmt->execute([':email' => 'first@mail.com']);
$stmt->execute([':email' => 'second@mail.com']);

// Positional placeholders
$stmt = $pdo->prepare("INSERT INTO users (email) VALUES (?)");
$stmt->execute(['first@mail.com']);
$stmt->execute(['second@mail.com']);
```

### `PDOStatement::bindParam()` Signature

```php
PDOStatement::bindParam(
    mixed $parameter,    // Placeholder name ':email' or position 1, 2, 3...
    mixed &$variable,    // PHP variable to bind (passed by reference)
    int $data_type,      // PDO::PARAM_STR, PDO::PARAM_INT, etc. (optional)
    int $length,         // Required only for OUT parameters in stored procedures
    mixed $driver_options
): bool
```

### `PDOStatement::execute()` Signature

```php
PDOStatement::execute([array $input_parameters]): bool
```

- Returns `true` on success, `false` on failure
- All values passed in the array are treated as `PDO::PARAM_STR` by default

### Full Prepared Statement Insert Example

```php
<?php
/** @var PDO $pdo */
$pdo = require 'connection.http-and-session';

// Prepare once
$insertStmt = $pdo->prepare("INSERT INTO users (email) VALUES (:email)");

// Execute with user input safely
$email = $argv[1] ?? null;

if ($insertStmt->execute([':email' => $email]) === false) {
    list(, , $driverErrMsg) = $insertStmt->errorInfo();
    echo "Error inserting: $driverErrMsg" . PHP_EOL;
    return;
}

echo "Successfully inserted record." . PHP_EOL;
```

### Proving SQL Injection Protection

Running this with a malicious input:

```bash
http-and-session insert-prepared.http-and-session '""); DROP TABLE users; /**'
```

PDO treats the entire string as a **value**, not as SQL. The table is NOT dropped. The malicious string is stored as literal text in the email column — which proves that prepared statements completely neutralize SQL injection.

> **Important reminder:** Prepared statements prevent SQL injection, but they do not validate or sanitize data. Always validate user input before running any database query. Garbage data stored safely is still garbage data.

### Setting `ATTR_EMULATE_PREPARES` to `false`

By default, PDO **emulates** prepared statements for compatibility with databases that do not natively support them. To use **real** MySQL prepared statements (which are faster for repeated execution):

```php
$options = [
    PDO::ATTR_EMULATE_PREPARES => false,
];
```

With emulation on: PDO escapes values and sends raw SQL to MySQL.
With emulation off: PDO sends the template to MySQL first, then only the parameter values — MySQL parses the query once and reuses it.

## 13. Fetching Data from MySQL

### SELECT Syntax

```sql
SELECT column1 [, column2, ...] FROM table_name
[WHERE condition]
[ORDER BY column ASC|DESC]
[LIMIT row_count]
[LIMIT offset, row_count]
```

> **Best practice:** Always specify column names instead of `SELECT *`. Using `*` forces MySQL to perform an additional lookup to resolve column names, which has a small but real performance cost.

### `PDO::query()` — For Simple Selects

Use `query()` for SELECT statements that do not need user input (no placeholders needed):

```php
$result = $pdo->query("SELECT * FROM users");
// Returns PDOStatement on success, false on failure
```

### Fetching Rows

Use `fetch()` to retrieve rows one at a time (memory-efficient):

```php
while ($record = $result->fetch()) {
    echo implode("\t", $record) . PHP_EOL;
}
```

Or use `fetchAll()` to retrieve all rows at once into an array:

```php
$records = $result->fetchAll();
```

### Fetch Modes

| Mode | What It Returns |
|---|---|
| `PDO::FETCH_ASSOC` | Associative array: `['id' => 1, 'email' => '...']` |
| `PDO::FETCH_NUM` | Indexed array: `[0 => 1, 1 => '...']` |
| `PDO::FETCH_OBJ` | Anonymous object with column names as properties |
| `PDO::FETCH_BOTH` | Both associative and indexed (default) |

Set the default fetch mode at connection time:

```php
$options = [PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC];
```

### PHP Example — Fetching with Filters and Sorting

```php
<?php
/** @var PDO $pdo */
$pdo = require 'connection.http-and-session';

// 1. All records
$result = $pdo->query("SELECT id, email, signup_time FROM users");
echo "All records:" . PHP_EOL;
while ($record = $result->fetch()) {
    echo implode("\t", $record) . PHP_EOL;
}

// 2. Limit to first 2 rows
$result = $pdo->query("SELECT id, email FROM users LIMIT 2");
echo PHP_EOL . "First 2 records:" . PHP_EOL;
while ($record = $result->fetch()) {
    echo implode("\t", $record) . PHP_EOL;
}

// 3. Filter with WHERE
$result = $pdo->query("SELECT id, email FROM users WHERE id > 3");
echo PHP_EOL . "Records where id > 3:" . PHP_EOL;
while ($record = $result->fetch()) {
    echo implode("\t", $record) . PHP_EOL;
}

// 4. Sort with ORDER BY
$result = $pdo->query("SELECT id, email FROM users ORDER BY id DESC");
echo PHP_EOL . "Records ordered by id descending:" . PHP_EOL;
while ($record = $result->fetch()) {
    echo implode("\t", $record) . PHP_EOL;
}
```

### LIMIT Forms

```sql
-- First 10 rows
SELECT * FROM users LIMIT 10;

-- 10 rows starting from position 20 (pagination)
SELECT * FROM users LIMIT 20, 10;

-- Equivalent OFFSET syntax
SELECT * FROM users LIMIT 10 OFFSET 20;
```

## 14. Updating Records

### UPDATE Syntax

```sql
UPDATE table_name
SET column1 = value1, column2 = value2, ...
WHERE condition;
```

> **Always include a WHERE clause.** Without it, every row in the table will be updated.

### `PDOStatement::rowCount()`

After an INSERT, UPDATE, or DELETE, use `rowCount()` to find how many rows were affected:

```php
$stmt->rowCount(); // Returns int
```

> **Note:** If you update a row with the exact same value it already has, MySQL counts 0 rows affected — even though the query ran successfully. This is expected behaviour.

### PHP Example — Update with Prepared Statement

```php
<?php
/** @var PDO $pdo */
$pdo = require 'connection.http-and-session';

$updateId    = $argv[1] ?? 0;
$updateEmail = $argv[2] ?? '';

$updateStmt = $pdo->prepare(
    "UPDATE users SET email = :email WHERE id = :id"
);

if ($updateStmt->execute([':id' => $updateId, ':email' => $updateEmail]) === false) {
    list(, , $driverErrMsg) = $updateStmt->errorInfo();
    echo "Error: $driverErrMsg" . PHP_EOL;
    return;
}

echo sprintf(
    "Query successful. %d row(s) affected.",
    $updateStmt->rowCount()
) . PHP_EOL;
```

Run from the terminal:

```bash
http-and-session update.http-and-session 6 john.doe@mail.com
```

If the ID does not exist:

```
Query successful. 0 row(s) affected.
```

This is not an error — it simply means no row matched the WHERE condition.

## 15. Deleting Records

### DELETE Syntax

```sql
DELETE FROM table_name WHERE condition;
```

> **Always include a WHERE clause.** Without it, all records in the table will be deleted.

### The LIKE Operator for Pattern Matching

Use `LIKE` in the WHERE clause to match partial values:

| Pattern | Matches |
|---|---|
| `LIKE 'php_'` | `php7`, `phpX` — exactly one character after `php` |
| `LIKE 'php%'` | `php`, `php7`, `php70`, `phpcourse` — any characters after `php` |
| `LIKE '%smith%'` | Anything containing `smith` anywhere |
| `LIKE '%@mail.com'` | Anything ending with `@mail.com` |

Wildcards:
- `_` (underscore) — matches **exactly one** character
- `%` (percent) — matches **any number** of characters (including zero)

### PHP Example — Delete by Partial Match

```php
<?php
/** @var PDO $pdo */
$pdo = require 'connection.http-and-session';

$partialMatch = $argv[1] ?? '';

$deleteStmt = $pdo->prepare(
    "DELETE FROM users WHERE email LIKE :partialMatch"
);

if ($deleteStmt->execute([':partialMatch' => "%$partialMatch%"]) === false) {
    list(, , $driverErrMsg) = $deleteStmt->errorInfo();
    echo "Error deleting: $driverErrMsg" . PHP_EOL;
    return;
}

$rowCount = $deleteStmt->rowCount();

if ($rowCount) {
    echo sprintf(
        "Deleted %d record(s) matching '%s'.",
        $rowCount,
        $partialMatch
    ) . PHP_EOL;
} else {
    echo sprintf("No records matching '%s' found.", $partialMatch) . PHP_EOL;
}
```

Run from the terminal:

```bash
http-and-session delete.http-and-session smith
# Deletes all users whose email contains "smith"

http-and-session delete.http-and-session smith
# Second run: No records matching 'smith' found.
```

## 16. The Singleton Pattern for Database Connections

### What is the Singleton Pattern?

The Singleton pattern is a software design pattern that ensures **only one instance of a class is ever created** during the life of a request. It makes the class itself responsible for controlling its own instantiation.

### Why Use It for Database Connections?

- Prevents accidentally creating multiple connections to MySQL in the same script
- Avoids repeated `fopen()` / `fclose()`-style overhead
- Makes the single connection available everywhere in the application without passing it around as a parameter

### Implementation in PHP

```php
<?php

class DatabaseSingleton
{
    private ?PDO $pdo = null;

    // Private constructor — prevents direct instantiation with 'new'
    private function __construct()
    {
        $dsn = "mysql:host=127.0.0.1;port=3306;dbname=demo;charset=utf8mb4";
        $this->pdo = new PDO($dsn, "http-and-session-user", "http-and-session-pass", [
            PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
        ]);
    }

    // Public static method — the only way to get the instance
    public static function instance(): static
    {
        static $instance;

        if (is_null($instance)) {
            $instance = new static(); // Created only on first call
        }

        return $instance; // All subsequent calls return the same object
    }

    public function getPdo(): PDO
    {
        return $this->pdo;
    }
}
```

### How it Works

```php
$db1 = DatabaseSingleton::instance();
$db2 = DatabaseSingleton::instance();

// Both variables point to the exact same object
var_dump($db1 === $db2); // true
```

> When comparing objects with `===`, PHP returns `true` only if both variables refer to **the exact same instance** of the same class — not just two objects with identical properties.

### Key Concepts

| Concept | Description |
|---|---|
| `private function __construct()` | Prevents outside code from calling `new DatabaseSingleton()` |
| `static $instance` | A static variable inside the method — persists between calls |
| `new static` | Creates the instance on the very first call |
| `is_null($instance)` | Checks if an instance already exists before creating one |

## 17. Quick Reference Cheat Sheet

### PDO Connection

```php
$dsn = "mysql:host=127.0.0.1;port=3306;dbname=mydb;charset=utf8mb4";
$pdo = new PDO($dsn, 'username', 'password', [
    PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
    PDO::ATTR_EMULATE_PREPARES   => false,
]);
```

### Execute a Statement (No Return Rows)

```php
$rows = $pdo->exec("CREATE TABLE ...");     // Returns int or false
if ($rows === false) { /* handle error */ }
```

### Query (Returns Rows)

```php
$result = $pdo->query("SELECT * FROM users LIMIT 10");
while ($row = $result->fetch()) {
    echo $row['email'];
}
```

### Prepared Statement — Insert / Update / Delete

```php
$stmt = $pdo->prepare("INSERT INTO users (email) VALUES (:email)");
$stmt->execute([':email' => 'user@example.com']);

$stmt = $pdo->prepare("UPDATE users SET email = :email WHERE id = :id");
$stmt->execute([':email' => 'new@example.com', ':id' => 1]);

$stmt = $pdo->prepare("DELETE FROM users WHERE id = :id");
$stmt->execute([':id' => 1]);
```

### Error Handling

```php
// After exec() or execute() returns false:
list(, , $message) = $pdo->errorInfo();
echo $message;

// Or from a PDOStatement:
list(, , $message) = $stmt->errorInfo();
echo $message;
```

### Useful PDO Methods

| Method | Description |
|---|---|
| `$pdo->exec($sql)` | Run DDL/DML, returns rows affected or `false` |
| `$pdo->query($sql)` | Run SELECT, returns `PDOStatement` or `false` |
| `$pdo->prepare($sql)` | Prepare a statement, returns `PDOStatement` |
| `$pdo->lastInsertId()` | Get auto-generated ID of last INSERT |
| `$pdo->errorInfo()` | Get error details as array |
| `$stmt->execute($params)` | Execute a prepared statement |
| `$stmt->fetch()` | Fetch one row from result |
| `$stmt->fetchAll()` | Fetch all rows from result |
| `$stmt->rowCount()` | Number of rows affected by last statement |
| `$stmt->bindParam($key, $var)` | Bind a variable (by reference) to a placeholder |

### SQL at a Glance

```sql
-- Create
CREATE SCHEMA dbname;
CREATE TABLE users (id INT PRIMARY KEY AUTO_INCREMENT, email VARCHAR(254) NOT NULL UNIQUE);

-- Insert
INSERT INTO users (email) VALUES ('user@example.com');

-- Select
SELECT id, email FROM users WHERE id > 3 ORDER BY id DESC LIMIT 10;

-- Update
UPDATE users SET email = 'new@example.com' WHERE id = 1;

-- Delete
DELETE FROM users WHERE email LIKE '%smith%';
```

---

> **Core principle:** Never insert user-supplied data directly into a SQL query string. Always use prepared statements with placeholders. This single rule prevents the vast majority of SQL injection attacks.
