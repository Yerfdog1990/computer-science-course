## What is MySQL?

MySQL is an open-source relational database management system (RDBMS) widely used across industries — from simple web apps to complex enterprise systems. It uses **Structured Query Language (SQL)** to manage and manipulate data.

MySQL commands fall into four main categories:

| Category | Full Name | Purpose | Key Commands |
|---|---|---|---|
| DDL | Data Definition Language | Define/modify database structure | `CREATE`, `ALTER`, `DROP`, `TRUNCATE` |
| DML | Data Manipulation Language | Retrieve and manage data | `SELECT`, `INSERT`, `UPDATE`, `DELETE` |
| DCL | Data Control Language | Control user access | `GRANT`, `REVOKE` |
| TCL | Transaction Control Language | Manage transactions | `START TRANSACTION`, `COMMIT`, `ROLLBACK` |

## MySQL vs MySQL Workbench

This distinction is critical and often causes confusion:

| | MySQL Server | MySQL Workbench |
|---|---|---|
| **What it is** | The actual database engine | A GUI client application |
| **What it does** | Stores databases, manages users, generates temporary password | Connects to MySQL Server for visual management |
| **Generates passwords?** | Yes — temporary root password on initialization | No — never creates passwords |
| **Required?** | Yes, must be installed first | No, optional (terminal can be used instead) |

**MySQL Workbench does NOT create the database engine.** It only provides a visual interface to communicate with it.

## Installation

### Install MySQL 8.0 via Homebrew (macOS)

```bash
brew install mysql@8.0
```

> **Note:** Avoid mixing MySQL 9.x server with older Workbench versions — it can cause unexpected crashes. MySQL 8.0.x is the most stable and widely supported version for local development.

### Install MySQL Workbench

```bash
brew install --cask mysqlworkbench
```

If you encounter an upgrade error like:

```
Error: mysqlworkbench: It seems the App source '/Applications/MySQLWorkbench.app' is not there.
```

Fix it by removing the broken reference and reinstalling:

```bash
brew uninstall --cask mysqlworkbench
brew install --cask mysqlworkbench
```

If uninstall still fails, force cleanup first:

```bash
rm -rf /Applications/MySQLWorkbench.app
brew cleanup
brew install --cask mysqlworkbench
```

## Initialization & Getting the Temporary Password

After installing MySQL, you must **initialize the data directory**. This generates a unique temporary root password specific to your machine.

```bash
mysqld --initialize --user=$(whoami)
```

During this step, MySQL prints a temporary password directly in the terminal output:

```
A temporary password is generated for root@localhost: =LWZ8u(Swy&C
```

> **Important:** Copy this password immediately. MySQL may not save it to the log file depending on version and install method. The temporary password is unique per installation — reinstalling or reinitializing MySQL generates a brand-new one.

### Where to find it later

If you missed it, check the MySQL error log:

```bash
grep "temporary password" /usr/local/var/mysql/*.err
```

Or view the full log:

```bash
cat /usr/local/var/mysql/*.err
```

> **Note:** Once you change the root password, the temporary one becomes invalid. The log still shows the old temporary password as a historical record only — MySQL never stores new passwords in plaintext for security reasons.

### Understanding the MySQL Error Log

When you run `cat /usr/local/var/mysql/*.err`, you will see entries like:

```
mysqld_safe Starting mysqld daemon with databases from /usr/local/var/mysql
mysqld 8.0.46 starting as process 69202
InnoDB initialization has started.
InnoDB initialization has ended.
ready for connections. Version: '8.0.46' socket: '/tmp/mysql.sock' port: 3306
```

| Log Entry | Meaning |
|---|---|
| `mysqld_safe Starting mysqld daemon` | MySQL safe-mode launcher started |
| `InnoDB initialization has started/ended` | Storage engine loaded successfully |
| `Setting lower_case_table_names=2` | Normal on macOS — filesystem is case-insensitive |
| `CA certificate ca.pem is self signed` | SSL cert was auto-generated; normal for local dev |
| `X Plugin ready for connections. port: 33060` | MySQL X Protocol (used by MySQL Shell) started |
| `ready for connections. port: 3306` | MySQL is running and accepting connections |
| `mysql_native_password is deprecated` | Just a warning; older auth method still works locally |

## First Login & Changing the Temporary Password

### Login using the temporary password

```bash
mysql -u root -p
```

When prompted, type the temporary password. Nothing will appear on screen as you type — this is normal on macOS/Linux.

> **Common mistake:** The `(using password: NO)` error means the terminal received no password at all. This usually means you pressed Enter before typing anything. Try again and type the password before pressing Enter.

### Change the temporary password immediately

MySQL requires you to change the temporary password before doing anything else:

```sql
ALTER USER 'root'@'localhost'
IDENTIFIED BY 'MyNewPassword123!';
```

This command:

- Updates only the `'root'@'localhost'` account
- Does NOT affect any other users or hosts
- Permanently replaces the temporary password

After setting your permanent password, verify MySQL is running the correct version:

```bash
mysql --version
```

Expected output:

```
mysql  Ver 8.0.xx for macos...
```

## Connecting with MySQL Workbench

### Create a new connection

| Field | Value |
|---|---|
| Connection Name | Local MySQL |
| Hostname | `localhost` |
| Port | `3306` |
| Username | `root` |
| Password | Click "Store in Keychain" and enter your password |

> **Note:** Use `localhost` consistently rather than `127.0.0.1`. MySQL treats them differently internally, and authentication rules are host-specific.

### How macOS Keychain works with MySQL

- macOS Keychain **does NOT generate** a MySQL password
- It only **stores** the password you provide so you do not need to re-enter it each time
- MySQL Server is the **source of truth** for passwords; Keychain is just a secure vault
- To retrieve a saved password: open **Keychain Access**, search for `mysql` or `MySQLWorkbench`, double-click the entry, and tick **Show password**

### MySQL Workbench "Access Denied" error

If you see:

```
Access denied for user 'root'@'localhost' (using password: YES)
```

Try these in order:

1. Delete the old stored password in Workbench (click the wrench icon → Clear Password)
2. Verify terminal login works first: `mysql -u root -p`
3. Recreate the Workbench connection from scratch
4. Try `127.0.0.1` as hostname instead of `localhost`

## MySQL Command Categories

### Understanding MySQL Accounts

MySQL accounts are defined as `'user'@'host'`. These are **all different accounts**:

```sql
'root'@'localhost'
'root'@'127.0.0.1'
'root'@'%'
'godfrey'@'localhost'
```

Each can have different passwords, privileges, and allowed hosts. This is why a user may connect from the terminal but get rejected in Workbench — they may be connecting via a different host string.

Using `'%'` as the host allows connections from any host:

```sql
CREATE USER 'godfrey'@'%' IDENTIFIED BY 'Password123!';
```

## Database Management Commands

### SHOW DATABASES

Lists all databases on the server:

```sql
SHOW DATABASES;
```

### CREATE DATABASE

Creates a new database. Optionally specify character set and collation:

```sql
CREATE DATABASE sakila_test
CHARACTER SET utf8mb4
COLLATE utf8mb4_general_ci;
```

If a database with that name already exists, MySQL returns an error. Use `IF NOT EXISTS` to avoid the error:

```sql
CREATE DATABASE IF NOT EXISTS sakila_test;
```

### USE

Selects a database to run commands against. All subsequent queries apply to this database unless otherwise specified:

```sql
USE sakila_test;
```

### DROP DATABASE

Permanently deletes a database and all its contents. **This cannot be undone.**

```sql
DROP DATABASE sakila_test;
```

Use `IF EXISTS` to prevent errors if the database does not exist:

```sql
DROP DATABASE IF EXISTS sakila_test;
```

## Table Management Commands

### CREATE TABLE

Creates a new table with defined columns, data types, and constraints:

```sql
CREATE TABLE IF NOT EXISTS `phpecom`.`users` (
    `id`         INT NOT NULL AUTO_INCREMENT,
    `name`       VARCHAR(191) NOT NULL,
    `email`      VARCHAR(191) NOT NULL,
    `phone`      VARCHAR(191) NOT NULL,
    `password`   VARCHAR(191) NOT NULL,
    `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`)
);
```

Key points:

- `IF NOT EXISTS` must come **immediately after** `CREATE TABLE` — not before it
- `AUTO_INCREMENT` on `id` means MySQL automatically generates sequential IDs (1, 2, 3…) when inserting rows
- `PRIMARY KEY` ensures each row is uniquely identifiable
- Backticks `` ` `` around identifiers are optional but protect against reserved word conflicts

### SHOW TABLES

Lists all tables in the currently selected database:

```sql
SHOW TABLES;
```

### DESCRIBE

Shows the structure of a table — columns, data types, nullability, keys:

```sql
DESCRIBE users;
-- or shorthand:
DESC users;
```

### ALTER TABLE

Modifies an existing table's structure:

```sql
-- Add a column
ALTER TABLE users ADD age INT;

-- Drop a column
ALTER TABLE users DROP COLUMN age;

-- Modify a column's data type
ALTER TABLE users MODIFY phone VARCHAR(20);
```

### DROP TABLE

Permanently deletes a table and all its data. **Cannot be undone.**

```sql
DROP TABLE users;
```

## Data Manipulation Commands (DML)

### SELECT

Retrieves data from one or more tables:

```sql
-- All columns, all rows
SELECT * FROM users;

-- Specific columns
SELECT name, email FROM users;

-- Count total rows
SELECT COUNT(*) FROM users;

-- With a filter
SELECT name, email FROM users WHERE id = 1;
```

### INSERT

Adds new rows to a table:

```sql
INSERT INTO users (name, email, phone, password)
VALUES ('John Smith', 'john@example.com', '0712345678', 'hashed_password');
```

### UPDATE

Modifies existing rows. **Always include a `WHERE` clause** unless you intend to update every row:

```sql
UPDATE users
SET email = 'newemail@example.com'
WHERE id = 1;
```

### DELETE

Removes rows from a table. **Always include a `WHERE` clause** unless you intend to delete all rows:

```sql
DELETE FROM users WHERE id = 1;
```

## Query Filtering and Sorting

### WHERE

Filters rows based on a condition:

```sql
SELECT * FROM films WHERE release_year = 2007;
```

### ORDER BY

Sorts results by one or more columns:

```sql
-- Ascending (default)
SELECT * FROM films ORDER BY title ASC;

-- Descending
SELECT * FROM films ORDER BY film_id DESC;
```

### LIMIT

Restricts the number of returned rows:

```sql
-- First 5 rows
SELECT * FROM films LIMIT 5;

-- Last 5 rows (combine with ORDER BY DESC)
SELECT * FROM films ORDER BY film_id DESC LIMIT 5;
```

### GROUP BY

Groups rows with the same values in specified columns, used with aggregate functions:

```sql
-- Count rentals per customer
SELECT customer_id, COUNT(*) AS rental_count
FROM rentals
GROUP BY customer_id;
```

### HAVING

Filters results **after** grouping (unlike `WHERE`, which filters before grouping):

```sql
-- Customers with more than 30 rentals
SELECT customer_id, COUNT(*) AS rental_count
FROM rentals
GROUP BY customer_id
HAVING rental_count > 30;
```

## User & Privilege Management

### View all users

```sql
SELECT user, host, plugin FROM mysql.user;
```

### CREATE USER

```sql
CREATE USER 'php-user'@'localhost' IDENTIFIED BY 'http-and-session-pass';

-- Allow connection from any host
CREATE USER 'php-user'@'%' IDENTIFIED BY 'http-and-session-pass';
```

> **Common mistake:** `IDENTIFIED` is often misspelled as `indentified`. MySQL will return a syntax error. Type `\c` to cancel the current statement and start over.

### GRANT privileges

```sql
-- Full admin privileges (suitable for local development)
GRANT ALL PRIVILEGES ON *.*
TO 'php-user'@'localhost'
WITH GRANT OPTION;

-- Privileges on a specific database only
GRANT ALL PRIVILEGES ON phpecom.*
TO 'php-user'@'localhost';

-- Only SELECT and INSERT
GRANT SELECT, INSERT ON phpecom.*
TO 'php-user'@'localhost';

-- Only CREATE (allows creating new databases/schemas)
GRANT CREATE ON *.*
TO 'php-user'@'localhost';

-- Only PROCESS (fixes "view client connections" warning in Workbench)
GRANT PROCESS ON *.*
TO 'php-user'@'localhost';

-- Always apply changes
FLUSH PRIVILEGES;
```

### The "Insufficient Privileges" warning in MySQL Workbench

When connecting with a normal user like `php-user`, you may see:

```
The current MySQL user lacks administrative privileges needed to view
server/client connection information.
```

This happens because the user lacks the `PROCESS` privilege (or full admin rights) needed to view server connection information.

**Option 1 — Full admin privileges (easiest for local development):**

```sql
-- Login as root first
mysql -u root -p

GRANT ALL PRIVILEGES ON *.*
TO 'php-user'@'localhost'
WITH GRANT OPTION;

FLUSH PRIVILEGES;
```

**Option 2 — Minimal fix (PROCESS privilege only):**

```sql
GRANT PROCESS ON *.*
TO 'php-user'@'localhost';

FLUSH PRIVILEGES;
```

The `PROCESS` privilege allows:

- Viewing running connections
- Viewing server threads
- Viewing active queries

**Best practice:**

| Environment | Recommended approach |
|---|---|
| Local development / learning | Full privileges are fine |
| Production | Grant only the minimum required permissions; never use root for application connections |

### Check current privileges for a user

```sql
SHOW GRANTS FOR 'php-user'@'localhost';
```

### REVOKE privileges

```sql
-- Remove a specific privilege
REVOKE INSERT ON phpecom.users FROM 'php-user'@'localhost';

-- Remove all privileges
REVOKE ALL PRIVILEGES ON *.* FROM 'php-user'@'localhost';

FLUSH PRIVILEGES;
```

### Reset another user's password (while logged in as root)

```sql
ALTER USER 'php-user'@'localhost'
IDENTIFIED BY 'NewPhpPassword123!';

FLUSH PRIVILEGES;
```

Then test the new password:

```bash
mysql -u http-and-session-user -p
```

### DROP USER (delete a user)

```sql
DROP USER 'php-user'@'localhost';
FLUSH PRIVILEGES;
```

Verify the user is gone:

```sql
SELECT user, host FROM mysql.user;
```

## JOIN Operations

JOINs retrieve data from multiple tables based on related columns.

| JOIN Type | What it returns |
|---|---|
| `INNER JOIN` | Only rows with matching values in both tables |
| `LEFT JOIN` | All rows from left table + matching rows from right (NULLs for non-matches) |
| `RIGHT JOIN` | All rows from right table + matching rows from left (NULLs for non-matches) |
| `CROSS JOIN` | Every possible combination of rows from both tables |
| `SELF JOIN` | A table joined to itself using aliases, for hierarchical data |

> MySQL does not natively support `FULL OUTER JOIN`. Achieve the same result by combining `LEFT JOIN` and `RIGHT JOIN` with `UNION`.

```sql
-- INNER JOIN example
SELECT users.name, orders.total
FROM users
INNER JOIN orders ON users.id = orders.user_id;

-- LEFT JOIN example (includes users with no orders)
SELECT users.name, orders.total
FROM users
LEFT JOIN orders ON users.id = orders.user_id;
```

## Backup & Export Commands

### mysqldump (command-line backup)

Exports a database to an SQL file containing all CREATE and INSERT statements needed to recreate it:

```bash
mysqldump -u root -p database_name > backup.sql
```

Example:

```bash
mysqldump -u root -p phpecom > phpecom_backup.sql
```

### SELECT ... INTO OUTFILE

Exports query results to a file on the server:

```sql
SELECT * FROM users
INTO OUTFILE '/tmp/users_export.csv'
FIELDS TERMINATED BY ','
ENCLOSED BY '"'
LINES TERMINATED BY '\n';
```

## Resetting a Forgotten Password

MySQL does not have a "Forgot Password?" button. Passwords are stored in encrypted/hashed form and cannot be retrieved — only reset.

### If you forgot the root password

```bash
# Step 1: Stop MySQL
brew services stop mysql@8.0

# Step 2: Start MySQL without authentication
mysqld_safe --skip-grant-tables &

# Wait 15 to 20 seconds, then open a NEW terminal tab
```

```bash
# Step 3: Login without password
mysql -u root
```

```sql
-- Step 4: Reset the password
FLUSH PRIVILEGES;

ALTER USER 'root'@'localhost'
IDENTIFIED BY 'BrandNewPassword123!';

exit;
```

```bash
# Step 5: Stop the recovery-mode server
pkill mysqld

# Step 6: Start MySQL normally
brew services start mysql@8.0

# Step 7: Test login
mysql -u root -p
```

### If you forgot a normal user's password

Login as root and reset it:

```sql
ALTER USER 'php-user'@'localhost'
IDENTIFIED BY 'NewPassword123!';

FLUSH PRIVILEGES;
```

### Recovering from macOS Keychain

If you previously clicked "Store in Keychain" in MySQL Workbench:

1. Open **Keychain Access**
2. Search for `mysql` or `MySQLWorkbench`
3. Double-click the entry
4. Tick **Show password**
5. Enter your Mac login password to reveal the saved MySQL password

## Common Errors & Fixes

### Error 1045: Access denied (using password: YES)

```
ERROR 1045 (28000): Access denied for user 'root'@'localhost' (using password: YES)
```

**Cause:** Wrong password supplied.

**Fix:** Verify you are typing the correct password. Nothing appears on screen while typing — this is expected behavior.

### Error 1045: Access denied (using password: NO)

```
ERROR 1045 (28000): Access denied for user 'root'@'localhost' (using password: NO)
```

**Cause:** MySQL received no password — you pressed Enter without typing anything.

**Fix:** Run `mysql -u root -p` again and type the password before pressing Enter.

### MySQL prompt shows `'>` (stuck in multiline mode)

```
mysql> create user 'php-user'@localhost'
    ->
    '>
```

**Cause:** MySQL detected an unclosed quote and is waiting for you to finish the string.

**Fix:** Type `\c` and press Enter to cancel:

```sql
\c
```

Then re-enter the command with correct quoting.

### Error 1064: SQL Syntax error

```
ERROR 1064 (42000): You have an error in your SQL syntax...
near 'indentified by 'php-pass'' at line 2
```

**Cause:** `IDENTIFIED` was misspelled as `indentified`.

**Fix:**

```sql
CREATE USER 'php-user'@'localhost'
IDENTIFIED BY 'http-and-session-pass';
```

### Error 1044: Access denied to create database

```
ERROR 1044: Access denied for user 'php-user'@'localhost' to database 'demo'
```

**Cause:** The user lacks permission to create databases.

**Fix:** Login as root and grant the privilege:

```sql
mysql -u root -p

-- Full privileges
GRANT ALL PRIVILEGES ON *.*
TO 'php-user'@'localhost'
WITH GRANT OPTION;

-- Or only CREATE privilege
GRANT CREATE ON *.*
TO 'php-user'@'localhost';

FLUSH PRIVILEGES;
```

### IF NOT EXISTS syntax error in CREATE TABLE

**Wrong:**

```sql
IF DOES NOT EXISTS CREATE TABLE phpecom.users (...)
IF NOT EXISTS CREATE TABLE phpecom.users (...)
```

**Correct:**

```sql
CREATE TABLE IF NOT EXISTS `phpecom`.`users` (
    `id`         INT NOT NULL AUTO_INCREMENT,
    `name`       VARCHAR(191) NOT NULL,
    `email`      VARCHAR(191) NOT NULL,
    `phone`      VARCHAR(191) NOT NULL,
    `password`   VARCHAR(191) NOT NULL,
    `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`)
);
```

`IF NOT EXISTS` must immediately follow `CREATE TABLE` — it cannot come before it.

### MySQL Workbench "Insufficient Privileges" warning

**Cause:** The connected user lacks the `PROCESS` privilege.

**Fix:** Grant `PROCESS` or full privileges as root — see the [User & Privilege Management](#user--privilege-management) section above.

## Syntax Rules & Best Practices

### Case sensitivity

- SQL keywords (`SELECT`, `FROM`, `WHERE`) are **not case-sensitive** — but write them in UPPERCASE for readability
- Database and table names are **case-sensitive on Linux**, not on macOS/Windows
- Column names are generally not case-sensitive, but consistency helps readability

### Semicolons

Every SQL statement ends with `;`. Always include it, especially in scripts with multiple statements.

### Quoting rules

| Use | For |
|---|---|
| Single quotes `'` | String values: `'John'`, `'localhost'`, `'2024-01-01'` |
| Backticks `` ` `` | Identifiers (table/column names), especially if they are reserved words |

### Naming conventions

- Be descriptive but concise: `users`, `orders`, `created_at`
- Avoid spaces and special characters in names
- Avoid MySQL reserved words as identifiers (e.g., `ORDER`, `SELECT`) — if you must use them, wrap in backticks

### WHERE in UPDATE and DELETE

**Always** include a `WHERE` clause unless you intend to affect every row:

```sql
-- DANGEROUS: updates ALL users
UPDATE users SET password = 'oops';

-- CORRECT: updates only user with id 1
UPDATE users SET password = 'hashed_value' WHERE id = 1;
```

### Indentation and formatting

Break long queries across multiple lines for readability:

```sql
SELECT
    u.name,
    u.email,
    COUNT(o.id) AS order_count
FROM users u
LEFT JOIN orders o ON u.id = o.user_id
WHERE u.created_at >= '2024-01-01'
GROUP BY u.id
HAVING order_count > 0
ORDER BY order_count DESC
LIMIT 10;
```

### Common mistakes to avoid

| Mistake | Consequence | Fix |
|---|---|---|
| Missing semicolon | Statement does not execute | Always end with `;` |
| Mixing `'` and `"` quotes | Syntax error | Use `'` for strings consistently |
| Misspelled keywords (e.g., `indentified`) | Syntax error | Double-check spelling |
| Wrong data types | Insert/update errors | Match column types exactly |
| Missing `WHERE` in `DELETE`/`UPDATE` | All rows affected | Always include a condition |
