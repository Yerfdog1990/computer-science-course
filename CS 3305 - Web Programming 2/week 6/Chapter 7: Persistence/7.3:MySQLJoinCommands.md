## 1. What is a JOIN?

MySQL databases store large volumes of data organized across multiple tables. In real applications, related data is rarely kept in a single table — customer info lives in one table, orders in another, products in another.

A **JOIN** is a SQL clause that combines rows from two or more tables based on a **shared (related) column**, allowing you to retrieve all needed data in a single query.

**Example scenario:**

You have:
- A `customers` table with customer names
- A `orders` table with order dates linked by `customer_id`

Without a JOIN, you'd need two separate queries and manually match the results. With a JOIN, you get everything in one query.

---

## 2. Why JOINs Are Useful

| Advantage | Explanation |
|---|---|
| **Improved speed** | One JOIN query retrieves data from multiple tables faster than running multiple individual queries |
| **Increased efficiency** | JOINs utilize database indexes, improving performance and accuracy |
| **Reduced server load** | Fewer round trips between the application and MySQL server means less overall load |
| **Simplified code** | One clean query replaces complex application-side data merging logic |

---

## 3. Types of JOINs in MySQL

MySQL supports five JOIN types:

| JOIN Type | What It Returns |
|---|---|
| `INNER JOIN` | Only rows with **matching values** in both tables |
| `LEFT JOIN` | **All rows** from the left table + matching rows from the right (NULLs where no match) |
| `RIGHT JOIN` | **All rows** from the right table + matching rows from the left (NULLs where no match) |
| `CROSS JOIN` | **Every possible combination** of rows from both tables |
| `SELF JOIN` | A table **joined to itself** to compare rows within the same table |

> **Note:** MySQL does **not** support `FULL OUTER JOIN` natively. You can simulate it by combining `LEFT JOIN` and `RIGHT JOIN` with `UNION`.

## 4. INNER JOIN

### What it does

Returns **only the rows that have matching values in both tables**. If a row in either table does not satisfy the join condition, it is excluded from the result.

This is the most commonly used JOIN type.

### Visual representation

```
Table A        Table B
  ┌───┐          ┌───┐
  │   │ ████████ │   │
  │   │ ████████ │   │
  └───┘          └───┘
       ↑ Only the overlapping (matching) part is returned
```

### Syntax

```sql
SELECT columns
FROM tableA
INNER JOIN tableB
ON tableA.column = tableB.column;
```

### Example — Films with their categories and rental rates

```sql
SELECT
  film.title        AS Film_Title,
  category.name     AS Category_Name,
  film.rental_rate  AS Rental_Rate
FROM film
  INNER JOIN film_category
    ON film.film_id = film_category.film_id
  INNER JOIN category
    ON film_category.category_id = category.category_id
ORDER BY film.rental_rate
LIMIT 20;
```

**What this does:**

- Starts with the `film` table
- Joins `film_category` — the link table that connects films to categories
- Joins `category` — to get the actual category name
- Only films that have an associated category appear in the results
- Results are sorted by rental rate, limited to 20 rows

### Key behaviour

- A film with **no category** would be **excluded**
- A category with **no films** would be **excluded**
- Only rows satisfying `ON tableA.column = tableB.column` appear

### Multiple INNER JOINs

You can chain multiple INNER JOINs together:

```sql
SELECT columns
FROM tableA
INNER JOIN tableB ON tableA.id = tableB.a_id
INNER JOIN tableC ON tableB.id = tableC.b_id;
```

## 5. LEFT JOIN (LEFT OUTER JOIN)

### What it does

Returns **all rows from the left table** and the matching rows from the right table. Where there is no match in the right table, the result shows `NULL` for those columns.

The word `OUTER` is optional — `LEFT JOIN` and `LEFT OUTER JOIN` are identical.

### Visual representation

```
Table A        Table B
  ┌───┐          ┌───┐
  │███│ ████████ │   │
  │███│ ████████ │   │
  └───┘          └───┘
    ↑ Everything from left table is returned.
      Right table columns are NULL where there's no match.
```

### Syntax

```sql
SELECT columns
FROM tableA
LEFT [OUTER] JOIN tableB
ON tableA.column = tableB.column;
```

### Example — All films, including those never rented

```sql
SELECT
  film.title,
  rental.rental_date,
  rental.return_date
FROM film
  LEFT OUTER JOIN inventory
    ON film.film_id = inventory.film_id
  LEFT OUTER JOIN rental
    ON inventory.inventory_id = rental.inventory_id
ORDER BY film.title;
```

**What this does:**

- Returns **every film**, regardless of whether it has inventory or rental records
- For films never added to inventory or never rented, `rental_date` and `return_date` show as `NULL`
- Useful for finding films that have never been rented

### When to use LEFT JOIN

- You want **all records from the primary (left) table**
- You want to **include rows even when related data is missing**
- Finding records with **no matching entry** in the right table:

```sql
-- Find all films that have NEVER been rented
SELECT film.title
FROM film
LEFT JOIN inventory ON film.film_id = inventory.film_id
WHERE inventory.film_id IS NULL;
```

## 6. RIGHT JOIN (RIGHT OUTER JOIN)

### What it does

The mirror opposite of LEFT JOIN. Returns **all rows from the right table** and only the matching rows from the left table. Where there is no match in the left table, the result shows `NULL` for those columns.

The word `OUTER` is optional — `RIGHT JOIN` and `RIGHT OUTER JOIN` are identical.

### Visual representation

```
Table A        Table B
  ┌───┐          ┌───┐
  │   │ ████████ │███│
  │   │ ████████ │███│
  └───┘          └───┘
                   ↑ Everything from right table is returned.
                     Left table columns are NULL where there's no match.
```

### Syntax

```sql
SELECT columns
FROM tableA
RIGHT [OUTER] JOIN tableB
ON tableA.column = tableB.column;
```

### Example — All films with their category names

```sql
SELECT
  film.film_id,
  film.title,
  category.name AS category_name
FROM category
  RIGHT JOIN film_category
    ON category.category_id = film_category.category_id
  RIGHT JOIN film
    ON film_category.film_id = film.film_id;
```

**What this does:**

- Ensures **every film** appears in results (right table = film)
- Category is included where it matches; shown as `NULL` if a film has no category assigned

### LEFT JOIN vs RIGHT JOIN

In practice, most developers **prefer LEFT JOIN** and simply swap the table order rather than use RIGHT JOIN — the results are equivalent. For example:

```sql
-- These two queries return the same data:

-- Using RIGHT JOIN
SELECT * FROM category
RIGHT JOIN film ON category.category_id = film.film_id;

-- Using LEFT JOIN (same result, clearer to read)
SELECT * FROM film
LEFT JOIN category ON film.film_id = category.category_id;
```

## 7. Simulating FULL OUTER JOIN

### What FULL OUTER JOIN would do

Return **all rows from both tables** — matching rows combined, and non-matching rows from each table filled with NULLs. MySQL does not support this directly.

### Visual representation

```
Table A        Table B
  ┌───┐          ┌───┐
  │███│ ████████ │███│
  │███│ ████████ │███│
  └───┘          └───┘
    ↑ Everything from BOTH tables is returned.
```

### Syntax — Simulating with UNION

```sql
SELECT * FROM tableA
LEFT JOIN tableB ON tableA.id = tableB.id
UNION
SELECT * FROM tableA
RIGHT JOIN tableB ON tableA.id = tableB.id;
```

`UNION` automatically removes duplicate rows from the combined result.

### Example — All customers and all rentals, matched where possible

```sql
SELECT
  c.customer_id,
  c.first_name,
  c.last_name,
  r.rental_id,
  r.rental_date
FROM customer c
  LEFT JOIN rental r
    ON c.customer_id = r.customer_id

UNION

SELECT
  c.customer_id,
  c.first_name,
  c.last_name,
  r.rental_id,
  r.rental_date
FROM customer c
  RIGHT JOIN rental r
    ON c.customer_id = r.customer_id;
```

**What this does:**

- First query: all customers + their rentals (NULLs for customers with no rentals)
- Second query: all rentals + their customers (NULLs for rentals with no customer record)
- `UNION` merges and deduplicates the two result sets
- Final result: every customer and every rental appears, matched where possible

## 8. CROSS JOIN

### What it does

Also called a **Cartesian join**. Returns **every possible combination** of rows from both tables. If Table A has 5 rows and Table B has 10 rows, the result has 5 × 10 = 50 rows.

No `ON` condition is used — every row from the left is paired with every row from the right.

### Visual representation

```
Table A (3 rows)  ×  Table B (3 rows)  =  9 combinations

A1 + B1    A1 + B2    A1 + B3
A2 + B1    A2 + B2    A2 + B3
A3 + B1    A3 + B2    A3 + B3
```

### Syntax

```sql
SELECT columns
FROM tableA
CROSS JOIN tableB;
```

### Example — Every actor paired with every film

```sql
SELECT
  actor.actor_id,
  actor.first_name,
  actor.last_name,
  film.title
FROM actor
CROSS JOIN film;
```

**What this does:**

- Pairs every single actor with every single film in the database
- If there are 200 actors and 1000 films, the result has 200,000 rows

### When to use CROSS JOIN

- Generating **all possible combinations** (e.g., product + colour, size + style)
- Creating **test data** by combining sets
- Building **schedules** or **matrices** where every pair must be considered

> **Warning:** CROSS JOIN on large tables produces enormous result sets. Always be intentional when using it — add a `WHERE` clause if you only need a subset of combinations.

```sql
-- With a condition (acts similarly to INNER JOIN)
SELECT * FROM tableA
CROSS JOIN tableB
WHERE tableA.id = tableB.a_id;
```

## 9. SELF JOIN

### What it does

Joins a table **to itself**. This is not a separate JOIN keyword — it uses `INNER JOIN`, `LEFT JOIN`, or any other type, but both sides of the JOIN reference the **same table**.

Table **aliases** are required to tell MySQL which "copy" of the table you are referring to.

### Visual representation

```
         Same Table
  ┌────────────────────┐
  │  alias1  | alias2  │
  │  (copy1) | (copy2) │
  │    ↑           ↑   │
  │    └───────────┘   │
  │    compared here   │
  └────────────────────┘
```

### Syntax

```sql
SELECT columns
FROM tableA AS alias1
JOIN tableA AS alias2
ON alias1.column = alias2.column;
```

### Example — Find pairs of actors who share the same last name

```sql
SELECT
  a1.first_name AS First_Name_1,
  a1.last_name  AS Last_Name,
  a2.first_name AS First_Name_2
FROM actor a1
JOIN actor a2
  ON a1.last_name = a2.last_name
WHERE a1.actor_id != a2.actor_id;
```

**What this does:**

- Creates two "virtual copies" of the `actor` table: `a1` and `a2`
- Matches rows where the last name is the same
- `WHERE a1.actor_id != a2.actor_id` prevents an actor from being matched with themselves
- Each pair appears twice (A+B and B+A) — add `a1.actor_id < a2.actor_id` to show each pair once

### Refined version — Show each pair only once

```sql
SELECT
  a1.first_name AS First_Name_1,
  a1.last_name  AS Shared_Last_Name,
  a2.first_name AS First_Name_2
FROM actor a1
JOIN actor a2
  ON a1.last_name = a2.last_name
  AND a1.actor_id < a2.actor_id;
```

### When to use SELF JOIN

- Finding **duplicate or related entries** within a table
- Working with **hierarchical data** (e.g., employees and their managers stored in the same table):

```sql
-- List each employee with their manager's name
SELECT
  emp.first_name   AS Employee,
  mgr.first_name   AS Manager
FROM employees emp
LEFT JOIN employees mgr
  ON emp.manager_id = mgr.employee_id;
```

- Comparing **rows within the same table** based on a condition

## 10. JOIN Comparison Summary

| JOIN Type | Left Table | Right Table | Use Case |
|---|---|---|---|
| `INNER JOIN` | Matching rows only | Matching rows only | Only want confirmed matches |
| `LEFT JOIN` | **All rows** | Matching rows (NULLs for no match) | Keep all from left, add right where available |
| `RIGHT JOIN` | Matching rows (NULLs for no match) | **All rows** | Keep all from right, add left where available |
| `LEFT + RIGHT + UNION` | **All rows** | **All rows** | Full picture from both tables |
| `CROSS JOIN` | **All rows** | **All rows** (every combination) | All possible pairings |
| `SELF JOIN` | Same table | Same table | Compare rows within one table |

### NULL behaviour in JOINs

| Scenario | Result |
|---|---|
| Row in left table with no match in right | Right table columns = `NULL` (LEFT JOIN) |
| Row in right table with no match in left | Left table columns = `NULL` (RIGHT JOIN) |
| Row matches in both tables | All columns populated |
| INNER JOIN with no match | Row excluded entirely |

## 11. Best Practices

### Always use meaningful aliases

```sql
-- Hard to read
SELECT a.first_name, b.title
FROM actor a JOIN film_actor fa ON a.actor_id = fa.actor_id
JOIN film b ON fa.film_id = b.film_id;

-- Clearer
SELECT actor.first_name, film.title
FROM actor
INNER JOIN film_actor ON actor.actor_id = film_actor.actor_id
INNER JOIN film ON film_actor.film_id = film.film_id;
```

### Always specify the JOIN type explicitly

```sql
-- Avoid (implicit join, harder to read and maintain)
SELECT * FROM tableA, tableB WHERE tableA.id = tableB.id;

-- Prefer (explicit and clear)
SELECT * FROM tableA
INNER JOIN tableB ON tableA.id = tableB.id;
```

### Use indexes on JOIN columns

JOINs perform best when the columns used in `ON` conditions are **indexed**. Primary keys and foreign keys are usually indexed automatically.

### Be careful with CROSS JOIN on large tables

A CROSS JOIN on two tables with 10,000 rows each produces 100,000,000 rows. Always test with `LIMIT` first:

```sql
SELECT * FROM tableA
CROSS JOIN tableB
LIMIT 10;
```

### Check for NULLs when using OUTER JOINs

After a LEFT or RIGHT JOIN, filter for unmatched rows using `IS NULL`:

```sql
-- Find customers who have never placed an order
SELECT customers.name
FROM customers
LEFT JOIN orders ON customers.id = orders.customer_id
WHERE orders.customer_id IS NULL;
```

### Use UNION for FULL OUTER JOIN carefully

`UNION` removes duplicates automatically. If you want to keep duplicates, use `UNION ALL` instead:

```sql
SELECT * FROM tableA LEFT JOIN tableB ON tableA.id = tableB.id
UNION ALL
SELECT * FROM tableA RIGHT JOIN tableB ON tableA.id = tableB.id;
```

### Prefer LEFT JOIN over RIGHT JOIN for readability

Most developers find LEFT JOIN easier to reason about. Instead of RIGHT JOIN, swap the table order and use LEFT JOIN — the data returned is identical.

---

> **Key takeaway:** Choose your JOIN type based on what data you need to preserve. If every row from a table must appear in the result regardless of matches, use LEFT or RIGHT JOIN. If only confirmed matches matter, use INNER JOIN. If you need all combinations, use CROSS JOIN. If you need to compare a table against itself, use SELF JOIN with aliases.
