# Exceptions in PHP

## What is an Exception?

An **exception** is an event that occurs during the runtime of a program and disrupts its normal flow. When an error occurs in PHP, it can be transformed into an **exception object** — an object that contains:

- The error message
- The error code
- The file and line number where it was triggered
- The full call stack trace

Exceptions can be **thrown** (triggered) and **caught** (handled) in a PHP script.

---

## PHP 5 vs PHP 7: How Error Reporting Changed

| Version | Approach | Description |
|---|---|---|
| PHP 5 | Traditional error reporting | Errors reported via the error handler; exceptions introduced but limited |
| PHP 7+ | Object-oriented approach | Most fatal errors are now thrown as exceptions automatically |

Starting with **PHP 7**, many errors that previously halted a script silently are now thrown as exceptions, giving developers the opportunity to catch and handle them gracefully.

---

## How Exceptions Propagate: The Call Stack

When an exception is thrown, PHP hands it to the **runtime system**, which searches for a handler:

1. It first looks in the **current function** for a `catch` block
2. If not found, it moves **backwards through the call stack** (the list of functions called up to that point)
3. If an exception handler is found, PHP checks whether the handler **accepts the type** of exception thrown
4. If the types match, the script resumes execution inside the `catch` block
5. If **no handler is found** anywhere in the call stack, the **default PHP exception handler** is invoked and the script halts

This backward search through the call stack is called **exception bubbling**.

## The Exception Class Hierarchy

PHP 7 introduced a clean hierarchy to separate two kinds of throwable objects:

```
Throwable (interface)
├── Exception          ← For application/logic errors (PHP 5+)
│   ├── LogicException
│   ├── InvalidArgumentException
│   ├── RuntimeException
│   └── ... (many SPL exceptions)
└── Error              ← For PHP engine/fatal errors (PHP 7+)
    ├── TypeError
    ├── ArgumentCountError
    ├── ParseError
    ├── ArithmeticError
    └── ...
```

| Class/Interface | Purpose |
|---|---|
| `Throwable` | Interface implemented by both `Exception` and `Error`; catching `Throwable` catches everything |
| `Exception` | Base class for application-level exceptions (logic errors, invalid input, etc.) |
| `Error` | Base class for PHP engine errors converted to exceptions in PHP 7 |

> **Backward compatibility note:** The `Error` class was added in PHP 7 specifically so that libraries could be consistent across PHP 5.x and PHP 7.x. Existing `catch (Exception $e)` blocks in PHP 5 code would not accidentally catch engine-level errors in PHP 7.

## The Four Keywords: `try`, `throw`, `catch`, `finally`

```php
try {
    if (!isset($argv[1])) {
        throw new Exception('Argument #1 is required.');
    }
} catch (Exception $e) {
    echo $e->getMessage(), PHP_EOL;
} finally {
    echo "Done.", PHP_EOL;
}
```

### `try`

Wraps any block of code that **might throw an exception**. If an exception is thrown inside, PHP immediately exits the `try` block and looks for a matching `catch`.

Inside a `try` block, exceptions can be thrown:
- **Explicitly** — by you using `throw`
- **Implicitly** — by functions or methods you call that throw internally

### `throw`

Triggers a new exception. Requires an instance of a class that extends `Exception` or `Error`:

```php
throw new Exception('Something went wrong.');
throw new InvalidArgumentException('Expected an integer.');
throw new LogicException('Argument #1 is required.');
```

### `catch`

Handles a thrown exception. Specifies which **exception type** to handle and stores the caught object in a variable:

```php
catch (Exception $e) {
    echo $e->getMessage();
}
```

Key rules:

- Multiple `catch` blocks can be chained — only the **first matching** block runs
- The type can be a concrete class, an abstract class, or an interface name
- If no `catch` block matches, the exception bubbles up the call stack
- At least one of `catch` or `finally` is required when using `try`

### `finally`

Always runs — regardless of whether an exception was thrown, caught, or not caught at all:

```php
} finally {
    echo "This always runs.";
}
```

This is especially useful for **cleaning up resources** (closing files, database connections) after a task completes, no matter what happened.

## Useful Exception Methods

| Method | Return Type | Description |
|---|---|---|
| `$e->getMessage()` | string | The exception message |
| `$e->getCode()` | int | The exception code |
| `$e->getFile()` | string | Full path to the file where the exception was thrown |
| `$e->getLine()` | int | Line number where the exception was thrown |
| `$e->getTraceAsString()` | string | Full call stack trace as a formatted string |
| `get_class($e)` | string | The class name of the exception object |

## Exercise 8.5 — Implementing Exceptions (`basic-try.php`)

This script traces the execution path of `try`, `catch`, and `finally` to make the flow visible:

```php
<?php

echo 'SCRIPT START.', PHP_EOL;

try {
    echo 'Run TRY block.', PHP_EOL;

    if (!isset($argv[1])) {
        echo 'NO ARGUMENT: Will throw exception.', PHP_EOL;
        throw new LogicException('Argument #1 is required.');
    }

    echo 'ARGUMENT: ', $argv[1], PHP_EOL;
    var_dump(new $argv[1]);

} catch (Exception $e) {
    echo 'EXCEPTION: ', sprintf('%s in %s at line %d',
        $e->getMessage(), $e->getFile(), $e->getLine()), PHP_EOL;

} finally {
    echo "FINALLY block gets executed.\n";
}

echo "Outside TRY-CATCH.\n";
echo 'SCRIPT END.', PHP_EOL;
```

### Test runs and what they reveal

**No argument provided:**

```bash
http-and-session basic-try.http-and-session
```

```
SCRIPT START.
Run TRY block.
NO ARGUMENT: Will throw exception.
EXCEPTION: Argument #1 is required. in [basic-try.php] at line 9
FINALLY block gets executed.
Outside TRY-CATCH.
SCRIPT END.
```

The `LogicException` was thrown and caught. Execution resumed after the `catch` block.

**Valid class provided:**

```bash
http-and-session basic-try.http-and-session DateTime
```

```
SCRIPT START.
Run TRY block.
ARGUMENT: DateTime
object(DateTime)#1 ...
FINALLY block gets executed.
Outside TRY-CATCH.
SCRIPT END.
```

No exception was thrown. The `finally` block still ran.

**Class requiring constructor arguments (`DateTimeZone`):**

```bash
http-and-session basic-try.http-and-session DateTimeZone
```

```
SCRIPT START.
Run TRY block.
ARGUMENT: DateTimeZone
FINALLY block gets executed.
```

> `EXCEPTION:` is **not** printed, and `SCRIPT END.` is **not** reached.

**Why?** `new DateTimeZone` with no argument throws an `ArgumentCountError`, which extends `Error` — **not** `Exception`. The `catch (Exception $e)` block does not match, so the exception was handled by the **default exception handler**, which prints the full call stack and halts the script. The `finally` block still ran before halting.

### Fix: catch `Error` separately

```php
// basic-try-all.http-and-session
} catch (Exception $e) {
    echo 'EXCEPTION: ', sprintf('%s in %s at line %d',
        $e->getMessage(), $e->getFile(), $e->getLine()), PHP_EOL;

} catch (Error $e) {
    echo 'ERROR: ', sprintf('%s in %s at line %d',
        $e->getMessage(), $e->getFile(), $e->getLine()), PHP_EOL;

} finally {
    echo "FINALLY block gets executed.\n";
}
```

Now running `php basic-try-all.php DateTimeZone` catches the `ArgumentCountError` and the script completes normally.

> **To catch both `Exception` and `Error` in one block**, catch `Throwable`:

```php
catch (Throwable $e) {
    // Catches any exception or error
}
```

## Custom Exceptions

PHP allows you to define your own exception classes by extending `Exception` (or any of its subclasses). Custom exceptions:

- Give **meaningful names** to error conditions in your business logic
- Allow you to **bundle extra context** (data about what went wrong)
- Allow **precise catching** — catching only the exact exception type you expect

### Exercise 8.6 — Custom Exceptions: Email Validation (`validate-email.php`)

```php
<?php

// Define a custom exception with extra context support
class InvalidEmail extends Exception
{
    private $context = [];

    public function setContext(array $context): void
    {
        $this->context = $context;
    }

    public function getContext(): array
    {
        return $this->context;
    }
}

// Validation function — throws exceptions instead of returning error codes
function validateEmail(array $input): void
{
    if (!isset($input[1])) {
        throw new InvalidArgumentException('No value to check.');
    }

    $testInput = $input[1];

    if (!filter_var($testInput, FILTER_VALIDATE_EMAIL)) {
        $error = new InvalidEmail('The email validation has failed.');
        $error->setContext(['testValue' => $testInput]);
        throw $error;
    }
}

// Run with try-catch — catch the Throwable interface to capture everything
try {
    validateEmail($argv);
    echo 'The input value is valid email.', PHP_EOL;

} catch (Throwable $e) {
    echo sprintf(
        'Caught [%s]: %s (file: %s, line: %s, context: %s)',
        get_class($e),
        $e->getMessage(),
        $e->getFile(),
        $e->getLine(),
        $e instanceof InvalidEmail ? json_encode($e->getContext()) : 'N/A'
    ) . PHP_EOL;
}
```

### Test runs

| Command | Result |
|---|---|
| `php validate-email.php` | `Caught [InvalidArgumentException]: No value to check.` |
| `php validate-email.php john.doe` | `Caught [InvalidEmail]: The email validation has failed. ... context: {"testValue":"john.doe"}` |
| `php validate-email.php john.doe@mail.com` | `The input value is valid email.` |

> **Naming convention note:** Custom exception names do not require a specific format. Some developers use the `Exception` suffix (`InvalidEmailException`) for specificity; others omit it (`InvalidEmail`) for readability. The PHP engine does not enforce either convention.

## Custom Exception Handlers

When you want **all** unhandled exceptions to be dealt with consistently — not just specific ones in `catch` blocks — register a global handler using `set_exception_handler()`.

### Syntax

```php
set_exception_handler(callable $exception_handler): callable
```

The handler must accept a `Throwable` as its first parameter:

```php
set_exception_handler(function (Throwable $e) {
    // Handle all uncaught exceptions here
});
```

Passing `null` restores the default handler:

```php
set_exception_handler(null);
```

Just like the default error handler, the **default exception handler** prints the error and halts the script. Registering your own lets you:

- Format the output consistently
- Log exceptions with full trace information
- Show user-friendly messages instead of raw technical output

### Exercise 8.7 — Custom Exception Handler (`exception-handler.php`)

```php
<?php

set_exception_handler(function (Throwable $e) {
    $msgLength = mb_strlen($e->getMessage());
    $line      = str_repeat('-', $msgLength);  // Draw a separator line matching message length

    echo $line, PHP_EOL;
    echo $e->getMessage(), PHP_EOL;
    echo '> File:  ', $e->getFile(), PHP_EOL;
    echo '> Line:  ', $e->getLine(), PHP_EOL;
    echo '> Trace: ', PHP_EOL, $e->getTraceAsString(), PHP_EOL;
    echo $line, PHP_EOL;
});
```

The output is now clean and consistent — a formatted block with a separator, the message, the location, and the full trace.

## Translating Errors to Exceptions with `ErrorException`

PHP provides a bridge class called `ErrorException` that converts traditional PHP errors (caught in the error handler) **into exceptions**, so both errors and exceptions can be handled in a single place — the exception handler.

### `ErrorException` constructor

```php
public __construct(
    string    $message  = "",
    int       $code     = 0,
    int       $severity = E_ERROR,    // Use E_* constants
    string    $filename = __FILE__,
    int       $lineno   = __LINE__,
    Exception $previous = null
)
```

### Exercise 8.8 — Unified Error and Exception Handling (`all-errors-handler.php`)

```php
<?php

// Single exception handler — handles both exceptions and translated errors
$exceptionHandler = function (Throwable $e) {
    $msgLength = mb_strlen($e->getMessage());
    $line      = str_repeat('-', $msgLength);

    echo $line, PHP_EOL;
    echo get_class($e), sprintf(' [%d]: ', $e->getCode()), $e->getMessage(), PHP_EOL;
    echo '> File:  ', $e->getFile(), PHP_EOL;
    echo '> Line:  ', $e->getLine(), PHP_EOL;
    echo '> Trace: ', PHP_EOL, $e->getTraceAsString(), PHP_EOL;
    echo $line, PHP_EOL;
};

// Error handler: translate every PHP error into an ErrorException,
// then pass it to the exception handler
$errorHandler = function (int $code, string $message, string $file, int $line)
    use ($exceptionHandler)
{
    $exception = new ErrorException($message, $code, $code, $file, $line);
    $exceptionHandler($exception);

    // Fatal-level errors halt execution
    if (in_array($code, [E_ERROR, E_RECOVERABLE_ERROR, E_USER_ERROR])) {
        exit(1);
    }
};

// Register both handlers
set_error_handler($errorHandler);
set_exception_handler($exceptionHandler);
```

**Result:** All PHP errors and all exceptions are now handled and formatted in one consistent place. `E_USER_ERROR` (code 256) and `E_RECOVERABLE_ERROR` still halt execution; warnings (code 512) allow the script to continue.

## Controlling Flow with Specific Custom Exceptions

The real power of exceptions comes from using **precisely named custom exception classes** to control which errors are handled where, rather than using `trigger_error()` which sends errors directly to the handler.

### Exercise 8.9 — Simple Exception Handling: A Multipurpose Runner (`run.php`)

```php
<?php

require_once 'all-errors-handler.http-and-session';

// Custom exception for anticipated, user-visible errors
class Disposable extends Exception {}

function handle(array $input)
{
    // Throw if no function/class name provided
    if (!isset($input[1])) {
        throw new Disposable('A function/class name is required as the first argument.');
    }

    $calleeName      = $input[1];
    $calleeArguments = array_slice($input, 2); // Arguments start at index 2

    if (function_exists($calleeName)) {
        return call_user_func_array($calleeName, $calleeArguments);

    } elseif (class_exists($calleeName)) {
        return new $calleeName(...$calleeArguments);

    } else {
        throw new Disposable(sprintf('The [%s] function or class does not exist.', $calleeName));
    }
}

try {
    $output = handle($argv);
    // Print result — use var_export() if output is falsy to show the actual type
    echo 'Result: ', $output ? print_r($output, true) : var_export($output, true), PHP_EOL;

} catch (Disposable $e) {
    // Only catch our anticipated errors; let everything else reach the exception handler
    echo '(!) ', $e->getMessage(), PHP_EOL;
    exit(1);
}
```

| Command | What happens |
|---|---|
| `php run.php` | `Disposable` thrown — no function name |
| `php run.php unknownFnName` | `Disposable` thrown — function/class not found |
| `php run.php substr 'PHP Essentials' 0 3` | Returns `PHP` — valid function call |
| `php run.php substr 'PHP Essentials' 0 0` | Returns `""` — printed with `var_export()` |
| `php run.php substr 'PHP Essentials'` | `E_WARNING` — missing param, `NULL` returned |
| `php run.php DateTime` | Returns `DateTime` instance |
| `php run.php DateTime '1 day ago' UTC` | `TypeError` — not caught, handled by exception handler; script halts |

The last case shows the limit of a generic script — without precise input validation, uncaught exceptions reach the global handler.

## Better Exception Usage: Nested `try-catch` Blocks

### Exercise 8.10 — Precise DateTime Handling (`date.php`)

This exercise demonstrates converting internal exceptions into friendly user-facing messages using **nested try-catch blocks inside a function**:

```php
<?php

require_once 'all-errors-handler.http-and-session';

class Disposable extends Exception {}

function handle(array $input)
{
    if (!isset($input[1])) {
        throw new Disposable('A class name is required (DateTime or DateTimeImmutable).');
    }

    $calleeName = $input[1];

    // Validate: only allow DateTime or DateTimeImmutable
    if (!in_array($calleeName, [DateTime::class, DateTimeImmutable::class])) {
        throw new Disposable('One of DateTime or DateTimeImmutable is expected.');
    }

    $time     = $input[2] ?? 'now';    // Default: current time
    $timezone = $input[3] ?? 'UTC';    // Default: UTC

    // Try building the timezone object; catch any Exception and rethrow as Disposable
    try {
        $dateTimeZone = new DateTimeZone($timezone);
    } catch (Exception $e) {
        throw new Disposable(sprintf('Unknown/Bad timezone: [%s]', $timezone));
    }

    // Try building the DateTime object
    try {
        $dateTime = new $calleeName($time, $dateTimeZone);
    } catch (Exception $e) {
        throw new Disposable(sprintf('Cannot build date from [%s]', $time));
    }

    return $dateTime;
}

try {
    $output = handle($argv);
    echo 'Result: ', print_r($output, true);

} catch (Disposable $e) {
    // Expected, user-facing errors
    echo '(!) ', $e->getMessage(), PHP_EOL;
    exit(1);
    // Any other exception bubbles to the registered exception handler
}
```

### Test runs

| Command | Result |
|---|---|
| `php date.php` | `(!) A class name is required...` |
| `php date.php Date` | `(!) One of DateTime or DateTimeImmutable is expected.` |
| `php date.php DateTimeImmutable midnight` | Prints `DateTimeImmutable` object at midnight UTC |
| `php date.php DateTimeImmutable summer` | `(!) Cannot build date from [summer]` |
| `php date.php DateTimeImmutable yesterday Paris` | `(!) Unknown/Bad timezone: [Paris]` |
| `php date.php DateTimeImmutable yesterday Europe/Paris` | Prints yesterday's date at Europe/Paris |

**Key takeaway:** By wrapping `DateTimeZone` and `DateTime` instantiations in their own `try-catch` blocks inside `handle()`, technical PHP exceptions are caught internally and re-thrown as friendly `Disposable` exceptions with clear user messages. The outer `catch` only needs to handle `Disposable`.

## Summary

| Concept | Key Point |
|---|---|
| Exception object | Contains message, code, file, line, and trace |
| Call stack search | PHP searches backward through the call stack for a handler |
| `try` | Wraps code that might throw |
| `throw` | Triggers an exception — requires an `Exception` or `Error` instance |
| `catch` | Handles a specific exception type; multiple blocks allowed; first match wins |
| `finally` | Always runs — ideal for closing files, connections, and cleanup |
| `Exception` | Base class for application-level exceptions |
| `Error` | Base class for PHP 7+ engine-level errors |
| `Throwable` | Interface catching both `Exception` and `Error` |
| Custom exceptions | Named classes extending `Exception`; bundle context and business meaning |
| `set_exception_handler()` | Global handler for all uncaught exceptions |
| `ErrorException` | Bridges error handler and exception handler — translates errors to exceptions |
| Nested try-catch | Catch internal exceptions, re-throw as friendly custom ones |

### Exception flow diagram

```
throw new SomeException()
        │
        ▼
Search call stack backwards for catch (SomeException)
        │
        ├─ Match found → run catch block → continue after try-catch
        │                                        │
        │                                        └─ finally runs first
        │
        └─ No match found → bubble to set_exception_handler()
                                    │
                                    └─ Script halts
                                    └─ finally still runs
```
