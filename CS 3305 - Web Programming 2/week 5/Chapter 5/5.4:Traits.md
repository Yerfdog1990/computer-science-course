# 5.4: Traits

## Introduction to Traits

Traits are a mechanism for code reuse in PHP that allows developers to reuse sets of methods freely in several independent classes living in different class hierarchies. Unlike inheritance, a trait can be used by multiple classes without requiring a common parent class.

## What are Traits?

### Definition
- **Code Reuse**: Collections of methods that can be reused across classes
- **Horizontal Reuse**: Unlike inheritance (vertical reuse), traits provide horizontal reuse
- **Multiple Inclusion**: A class can use multiple traits
- **Composition**: Traits are composed into classes at compile time

### Key Characteristics
- **Methods Only**: Traits contain methods, not properties (though properties can be defined)
- **No Instantiation**: Traits cannot be instantiated directly
- **Stateless**: Don't maintain state between different classes
- **Conflict Resolution**: Provides mechanisms to resolve method name conflicts

## Trait Syntax

### Basic Trait Declaration
```php
<?php
trait TraitName {
    public function methodName($parameter) {
        // Method implementation
        return $parameter . " processed";
    }
    
    protected function helperMethod() {
        // Helper method for internal use
        return "Helper result";
    }
}
?>
```

### Using Traits in Classes
```php
<?php
class ClassName {
    use TraitName;
    
    // Class can also have its own methods
    public function classMethod() {
        return "Class method";
    }
}
?>
```

### Multiple Traits
```php
<?php
class ClassName {
    use Trait1, Trait2, Trait3;
    
    // Class gets methods from all three traits
}
?>
```

## Complete Trait Example

### Logger Trait
```php
<?php
trait Logger {
    private $logs = [];
    
    public function log($message) {
        $timestamp = date('Y-m-d H:i:s');
        $logEntry = "[$timestamp] $message";
        $this->logs[] = $logEntry;
        echo $logEntry . "\n";
    }
    
    public function getLogs() {
        return $this->logs;
    }
    
    public function clearLogs() {
        $this->logs = [];
    }
    
    protected function formatMessage($message) {
        return strtoupper($message);
    }
}
?>
```

### Validator Trait
```php
<?php
trait Validator {
    public function validateEmail($email) {
        return filter_var($email, FILTER_VALIDATE_EMAIL) !== false;
    }
    
    public function validateRequired($value) {
        return !empty($value) && trim($value) !== '';
    }
    
    public function validateNumeric($value) {
        return is_numeric($value);
    }
    
    public function validateLength($value, $min, $max = null) {
        $length = strlen($value);
        if ($length < $min) return false;
        if ($max !== null && $length > $max) return false;
        return true;
    }
}
?>
```

### Timestamp Trait
```php
<?php
trait Timestamp {
    protected $createdAt;
    protected $updatedAt;
    
    public function setCreatedAt() {
        $this->createdAt = date('Y-m-d H:i:s');
    }
    
    public function setUpdatedAt() {
        $this->updatedAt = date('Y-m-d H:i:s');
    }
    
    public function getCreatedAt() {
        return $this->createdAt;
    }
    
    public function getUpdatedAt() {
        return $this->updatedAt;
    }
    
    public function touch() {
        $this->setUpdatedAt();
    }
}
?>
```

### Classes Using Multiple Traits
```php
<?php
class User {
    use Logger, Validator, Timestamp;
    
    private $name;
    private $email;
    
    public function __construct($name, $email) {
        $this->name = $name;
        $this->email = $email;
        $this->setCreatedAt();
        $this->log("User created: $name");
    }
    
    public function updateProfile($name, $email) {
        if ($this->validateEmail($email)) {
            $this->name = $name;
            $this->email = $email;
            $this->setUpdatedAt();
            $this->log("User updated: $name");
            return true;
        }
        return false;
    }
    
    public function getName() {
        return $this->name;
    }
    
    public function getEmail() {
        return $this->email;
    }
}

class Product {
    use Logger, Validator, Timestamp;
    
    private $name;
    private $price;
    
    public function __construct($name, $price) {
        if ($this->validateNumeric($price) && $price > 0) {
            $this->name = $name;
            $this->price = $price;
            $this->setCreatedAt();
            $this->log("Product created: $name (\$$price)");
        }
    }
    
    public function updatePrice($newPrice) {
        if ($this->validateNumeric($newPrice) && $newPrice > 0) {
            $this->price = $newPrice;
            $this->setUpdatedAt();
            $this->log("Product price updated: $this->name (\$$newPrice)");
            return true;
        }
        return false;
    }
    
    public function getName() {
        return $this->name;
    }
    
    public function getPrice() {
        return $this->price;
    }
}
?>
```

## Advanced Trait Features

### Trait Properties
```php
<?php
trait Configuration {
    public $config = [];
    
    public function setConfig($key, $value) {
        $this->config[$key] = $value;
    }
    
    public function getConfig($key, $default = null) {
        return $this->config[$key] ?? $default;
    }
    
    // Abstract method that must be implemented by using class
    abstract public function getDefaultConfig();
}

class Database {
    use Configuration;
    
    public function getDefaultConfig() {
        return [
            'host' => 'localhost',
            'port' => 3306,
            'database' => 'test'
        ];
    }
}
?>
```

### Trait Inheritance
```php
<?php
trait BaseTrait {
    public function baseMethod() {
        return "Base trait method";
    }
}

trait ExtendedTrait {
    use BaseTrait;
    
    public function extendedMethod() {
        return "Extended trait method: " . $this->baseMethod();
    }
}

class UsingClass {
    use ExtendedTrait; // Gets both base and extended methods
}
?>
```

## Method Conflict Resolution

### Insteadof Operator
```php
<?php
trait Trait1 {
    public function commonMethod() {
        return "Trait1 implementation";
    }
}

trait Trait2 {
    public function commonMethod() {
        return "Trait2 implementation";
    }
}

class ConflictExample {
    use Trait1, Trait2;
    
    public function getTrait1Method() {
        return $this->commonMethod(); // Uses Trait1's method
    }
    
    public function getTrait2Method() {
        return Trait2::commonMethod(); // Explicitly calls Trait2's method
    }
}
?>
```

### Insteadof for Method Selection
```php
<?php
trait Trait1 {
    public function process() {
        return "Processing with Trait1";
    }
}

trait Trait2 {
    public function process() {
        return "Processing with Trait2";
    }
}

class Processor {
    use Trait1, Trait2 {
        // Resolve conflict by using Trait2's process method
        Trait2::process insteadof Trait1;
    }
    
    public function getTrait1Process() {
        return Trait1::process();
    }
}
?>
```

### Visibility Control
```php
<?php
trait Trait {
    public function publicMethod() { return "Public"; }
    protected function protectedMethod() { return "Protected"; }
    private function privateMethod() { return "Private"; }
}

class UsingClass {
    use Trait {
        // All trait methods are available with their original visibility
        // Private methods become private in the using class
        // Protected methods become protected in the using class
        // Public methods remain public
    }
    
    public function testAccess() {
        return $this->publicMethod(); // Accessible
        // return $this->privateMethod(); // Not accessible
        // return $this->protectedMethod(); // Accessible within class
    }
}
?>
```

## Best Practices for Traits

### When to Use Traits
1. **Code Reuse**: When multiple classes need same functionality
2. **Horizontal Sharing**: When classes aren't in same inheritance hierarchy
3. **Utility Functions**: For helper methods that don't belong to core class logic
4. **Cross-Cutting Concerns**: Logging, validation, caching, etc.

### Trait Design Guidelines
1. **Single Purpose**: Each trait should have one clear responsibility
2. **No State**: Avoid storing state that could conflict between classes
3. **Method Cohesion**: Keep related methods together
4. **Conflict Awareness**: Design to minimize naming conflicts
5. **Documentation**: Document trait purpose and usage

### Naming Conventions
```php
<?php
// Good trait names
trait Loggable { /* logging methods */ }
trait Validatable { /* validation methods */ }
trait Timestampable { /* timestamp methods */ }
trait Cacheable { /* caching methods */ }

// Bad trait names
trait Stuff { /* unclear purpose */ }
trait Helper { /* too generic */ }
trait Functions { /* misleading - not just functions */ }
?>
```

## Common Use Cases

### Logging Trait
```php
<?php
trait Loggable {
    private $logger;
    
    public function setLogger(LoggerInterface $logger) {
        $this->logger = $logger;
    }
    
    public function log($level, $message) {
        if ($this->logger) {
            $this->logger->log($level, $message);
        }
    }
}

class User {
    use Loggable;
    
    public function login() {
        $this->log('info', 'User login attempt');
        // Login logic
    }
}
?>
```

### Caching Trait
```php
<?php
trait Cacheable {
    private $cache = [];
    
    public function cache($key, $value, $ttl = 3600) {
        $this->cache[$key] = [
            'value' => $value,
            'expires' => time() + $ttl
        ];
    }
    
    public function getCached($key) {
        if (isset($this->cache[$key])) {
            $item = $this->cache[$key];
            if ($item['expires'] > time()) {
                return $item['value'];
            }
        }
        return null;
    }
}
?>
```

## Key Concepts Summary

1. **Traits**: Collections of reusable methods
2. **Horizontal Reuse**: Code sharing across class hierarchies
3. **Multiple Usage**: Classes can use multiple traits
4. **Conflict Resolution**: Mechanisms to handle method name conflicts
5. **Composition**: Traits are composed into classes
6. **No Instantiation**: Traits cannot be instantiated directly
7. **State Management**: Careful handling of properties in traits

## Benefits of Traits

- **Code Reuse**: Share functionality without inheritance constraints
- **Flexibility**: Mix and match functionality as needed
- **Organization**: Group related functionality together
- **Maintainability**: Update functionality in one place
- **Testing**: Test trait functionality independently
- **Performance**: No runtime overhead after composition

Traits provide a powerful way to achieve code reuse and modularity in PHP, enabling developers to share functionality across classes without the constraints of traditional inheritance hierarchies.
