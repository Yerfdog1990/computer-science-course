# 5.7: Embracing Polymorphism

## The Three Cornerstones of OOP

The three cornerstones of Object Oriented Programming (OOP) are:
1. **Encapsulation** - Data hiding within classes
2. **Inheritance** - Derived classes inheriting from base classes
3. **Polymorphism** - Classes with different functionality sharing a common interface

## Understanding Polymorphism

The term "polymorphism" (from Greek, meaning "many forms") describes the ability to assign a different meaning or purpose to an entity according to its context.

### Real-World Example

In the real world, everyone knows how to use a push button (entity) – you simply apply pressure to it. What that button does, however, depends on what is connected to it (context), but the result does not affect how that button is used.

### Programming Context

In the world of Object Oriented Programming, polymorphism allows classes to have different functionality while sharing a common interface. The interface does not need to know which class it is using because they are, like the real-world button, all used the same way, but can produce different contextual results.

## Benefits of Polymorphism

Embracing polymorphism enables the programmer to create:
- **Interchangeable objects** that can be selected according to requirement
- **Conditional-free code** - no need for if/else statements to check object types
- **Extensible systems** - new classes can be added without modifying existing code
- **Consistent interfaces** - different objects can be used through the same interface

## PHP Interfaces

A PHP interface is similar to a class but is declared using the `interface` keyword and can only contain method definitions, not any method statements to be executed.

### Interface Syntax

```php
interface InterfaceName {
    // Method definitions only go here
    public function methodName($parameter);
}
```

### Method Definitions in Interfaces

Method definitions in an interface declaration may also specify parameters but no implementation:

```php
interface Shape {
    public function area();
    public function perimeter();
}
```

## Implementing Interfaces

Each class that implements an interface must implement all methods it defines by specifying their statements to be executed. A class is attached to an interface by including the `implements` keyword and interface name in its declaration.

### Implementation Syntax

```php
class ClassName implements InterfaceName {
    // Method implementations go here
    public function methodName($parameter) {
        // Implementation statements
    }
}
```

## Complete Polymorphism Example

### Base Classes (from previous example)

```php
<?php
// Base class
class Polygon {
    private float $width;
    private float $height;
    
    function __construct(float $w = 10, float $h = 5) {
        $this->width = $w;
        $this->height = $h;
    }
    
    public function getWidth() {
        return $this->width;
    }
    
    public function getHeight() {
        return $this->height;
    }
}
?>
```

### Interface Definition

```php
<?php
interface Shape {
    public function area();
}
?>
```

### Derived Classes Implementing Interface

```php
<?php
// Rectangle class inherits from Polygon and implements Shape
class Rectangle extends Polygon implements Shape {
    public function area() {
        return ($this->getWidth() * $this->getHeight());
    }
}

// Triangle class inherits from Polygon and implements Shape
class Triangle extends Polygon implements Shape {
    public function area() {
        return ($this->getWidth() * $this->getHeight() / 2);
    }
}
?>
```

### Polymorphic Function

```php
<?php
// Function that accepts any Shape object
function getArea(Shape $shape) {
    return $shape->area();
}
?>
```

### Using Polymorphism

```php
<?php
// Create instances of different shapes
$rect = new Rectangle(8, 10);
$trio = new Triangle(8, 10);

// Use the same function for different object types
echo 'Rectangle Area: ' . getArea($rect) . '<br>';
echo 'Triangle Area: ' . getArea($trio);
?>
```

## Complete Working Example

```php
<?php
// Base class
class Polygon {
    private float $width;
    private float $height;
    
    function __construct(float $w = 10, float $h = 5) {
        $this->width = $w;
        $this->height = $h;
    }
    
    public function getWidth() {
        return $this->width;
    }
    
    public function getHeight() {
        return $this->height;
    }
}

// Interface defining the contract
interface Shape {
    public function area();
}

// Rectangle class implementing the interface
class Rectangle extends Polygon implements Shape {
    public function area() {
        return ($this->getWidth() * $this->getHeight());
    }
}

// Triangle class implementing the interface
class Triangle extends Polygon implements Shape {
    public function area() {
        return ($this->getWidth() * $this->getHeight() / 2);
    }
}

// Polymorphic function
function getArea(Shape $shape) {
    return $shape->area();
}

// Create instances
$rect = new Rectangle(8, 10);
$trio = new Triangle(8, 10);

// Use polymorphic function
echo 'Rectangle Area: ' . getArea($rect) . '<br>';
echo 'Triangle Area: ' . getArea($trio);

// Add more shapes to demonstrate extensibility
class Square extends Polygon implements Shape {
    public function area() {
        $side = $this->getWidth();
        return $side * $side;
    }
}

$square = new Square(6, 6);
echo '<br>Square Area: ' . getArea($square);
?>
```

## How Polymorphism Works

### The Process

1. Each call to the `getArea()` function passes an instance object as an argument
2. The `getArea()` function calls the `area()` method defined in the interface
3. The output is returned from the implementation of the `area()` method of the associated instance

### Type Safety

The function signature `function getArea(Shape $shape)` ensures that only objects implementing the `Shape` interface can be passed as arguments.

## Expected Output

When the complete example is run, it will output:
```
Rectangle Area: 80
Triangle Area: 40
Square Area: 36
```

## Key Concepts

### Interface Contract
- Defines what methods a class must implement
- Provides a common interface for different classes
- Ensures consistency across different implementations

### Implementation
- Each class provides its own implementation of interface methods
- The same method call can produce different results
- No need to know the specific class type

### Polymorphic Behavior
- Different objects respond to the same method call
- The appropriate method implementation is called automatically
- Enables code reusability and flexibility

## Advanced Polymorphism Examples

### Multiple Methods in Interface

```php
interface Drawable {
    public function draw();
    public function getArea();
    public function getPerimeter();
}

class Circle implements Drawable {
    private float $radius;
    
    public function __construct(float $radius) {
        $this->radius = $radius;
    }
    
    public function draw() {
        return "Drawing a circle";
    }
    
    public function getArea() {
        return pi() * $this->radius * $this->radius;
    }
    
    public function getPerimeter() {
        return 2 * pi() * $this->radius;
    }
}
```

### Multiple Interface Implementation

```php
interface Serializable {
    public function serialize();
}

interface Drawable {
    public function draw();
}

class Image implements Serializable, Drawable {
    public function serialize() {
        return "Serialized image data";
    }
    
    public function draw() {
        return "Drawing image";
    }
}
```

## Key Concepts Summary

1. **Polymorphism**: "Many forms" - different classes with common interface
2. **Interface**: Defines method contracts without implementation
3. **Implementation**: Classes provide specific implementations of interface methods
4. **Type Hinting**: Functions can specify interface types for parameters
5. **Interchangeable Objects**: Different objects can be used through same interface
6. **Extensibility**: New classes can be added without modifying existing code
7. **Code Reusability**: Same code works with different object types

## Best Practices

1. **Interface Design**: Create meaningful, focused interfaces
2. **Consistent Naming**: Use clear, consistent method names across implementations
3. **Single Responsibility**: Each interface should have a single purpose
4. **Documentation**: Document interface contracts clearly
5. **Type Safety**: Use type hints for interface parameters
6. **Testing**: Test all implementations of interfaces
7. **Separation of Concerns**: Keep interface definition separate from implementation

## When to Use Polymorphism

- **Plugin Systems**: When different plugins need common interface
- **Strategy Pattern**: When different algorithms can be used interchangeably
- **Database Abstractions**: When different database drivers share common interface
- **Payment Systems**: When different payment methods share common interface
- **Rendering Systems**: When different objects need to be rendered

## Common Polymorphism Patterns

### Strategy Pattern
```php
interface PaymentStrategy {
    public function pay(float $amount);
}

class CreditCardPayment implements PaymentStrategy {
    public function pay(float $amount) {
        return "Paid $amount via credit card";
    }
}

class PayPalPayment implements PaymentStrategy {
    public function pay(float $amount) {
        return "Paid $amount via PayPal";
    }
}
```

### Factory Pattern with Polymorphism
```php
class ShapeFactory {
    public static function create(string $type): Shape {
        switch ($type) {
            case 'rectangle':
                return new Rectangle(10, 5);
            case 'triangle':
                return new Triangle(10, 5);
            default:
                throw new Exception("Unknown shape type");
        }
    }
}

$shape = ShapeFactory::create('rectangle');
echo getArea($shape);
```
