## 1. How the PHP Parser Works

When the **PHP Engine** receives input from the web server, it processes it in a specific way:

- It reads the input **from top to bottom** — a process called **"parsing"**
- During parsing, the **PHP parser** (another name for the PHP Engine) scans through the entire file
- It looks specifically for **opening and closing PHP tags**
- Everything **between** those tags is treated as **PHP script code** that must be interpreted and executed
- Everything **outside** those tags is **completely ignored by PHP** — it is passed through untouched and displayed by the browser as-is

This behaviour is what makes it possible for PHP to be **embedded within HTML** — the parser only acts on what is inside the tags and leaves everything else alone.

---

## 2. Tag Rules — Opening and Closing Tags

### The standard PHP tags

Every block of PHP code must be enclosed within the standard opening and closing tags:

```php
<?php
    // PHP code goes here
?>
```

| Tag | Name | Purpose |
|---|---|---|
| `<?php` | Opening tag | Signals the start of a PHP code block — the parser begins interpreting everything after this |
| `?>` | Closing tag | Signals the end of a PHP code block — the parser stops interpreting and returns to pass-through mode |

### Why tags are essential

The tags act as **boundaries** that tell the parser exactly where PHP code begins and ends. Without them:
- The parser would not know which parts of the file to execute
- PHP code would be treated as plain text and displayed in the browser rather than being run

### The fundamental rule

> **All PHP script code must be enclosed between opening and closing tags when embedded in an HTML file.**

This is non-negotiable — any PHP code placed outside the tags will not be executed; it will simply be output as raw text to the browser.

---

## 3. PHP Embedded in HTML

Because the parser ignores everything outside the PHP tags, PHP code can be freely mixed with HTML in the same file. The HTML is displayed by the browser; the PHP is executed by the server.

### Example — PHP embedded in HTML

```php
<p>Ignored by PHP and displayed by the browser</p>

<?php
    // PHP code here — executed by the server
?>

<p>Also ignored by PHP and displayed by the browser</p>
```

### What happens at each part

| Part of file | Handled by | Result |
|---|---|---|
| HTML before the opening tag | Browser | Displayed as normal HTML |
| Content between `<?php` and `?>` | PHP Engine | Executed on the server; output (if any) is inserted into the HTML stream |
| HTML after the closing tag | Browser | Displayed as normal HTML |

### Practical example — dynamic greeting embedded in HTML

```php
<!DOCTYPE html>
<html>
<head>
    <title>My PHP Page</title>
</head>
<body>
    <h1>Welcome to my website</h1>

    <?php
        echo "Hello, this text was generated by PHP!";
    ?>

    <p>This paragraph is plain HTML and is ignored by PHP.</p>
</body>
</html>
```

The browser receives only the final HTML — it never sees any of the PHP code.

## 4. Pure PHP Files — Omitting the Closing Tag

### What is a pure PHP file?

A **pure PHP file** contains **only PHP code** — no HTML markup whatsoever. These are typically used for:
- Back-end logic files (application processing, functions, classes)
- Configuration files
- Files that are included or required by other PHP files

### The rule for pure PHP files

When a file contains **only PHP script** (no HTML), it is **preferable to omit the closing `?>` tag entirely**:

```php
<?php
    // All PHP code — no HTML anywhere in this file
    // No closing ?> tag at the end
```

### Why omit the closing tag?

Omitting the closing `?>` tag in a pure PHP file **prevents a very common and frustrating bug**:

- If there is any **whitespace or blank line after the closing `?>`** tag (even a single space or newline that is invisible in your editor), PHP will send that whitespace as output to the browser **before any HTML is generated**
- This causes **"headers already sent"** errors — HTTP headers must be sent before any output, and even invisible whitespace counts as output
- By simply omitting the closing tag, this entire class of bugs is avoided
- The PHP parser treats the end of the file as an implied close, so the closing tag is not needed

> **Best practice:** Always omit the closing `?>` tag in pure PHP files. Include it only when PHP is embedded within HTML.

## 5. Short Echo Tags

### What are short echo tags?

PHP provides a **shorthand syntax** specifically for the very common task of inserting a single value or string of text into an HTML document. Instead of writing a full `<?php echo ... ?>` block, you can use the **short echo tag**:

### Syntax

```php
<?= "some text" ?>
```

This is completely equivalent to:

```php
<?php echo "some text"; ?>
```

### When to use short echo tags

Short echo tags are ideal when you want to **insert a single value or expression** into an HTML document — for example, a variable, a function result, or a string — without writing a full PHP block.

### Example — comparison of both approaches

**Full syntax:**
```php
<p>Hello, <?php echo $username; ?>!</p>
```

**Short echo tag (equivalent):**
```php
<p>Hello, <?= $username ?>!</p>
```

Both produce exactly the same output. The short echo tag is simply more concise and readable when used inline within HTML.

### Important notes

- The short echo tag **always implies an echo** — you do not write `echo` explicitly
- It outputs the value of whatever expression follows it
- It is appropriate **only when outputting a single value** — for more complex logic, use the full `<?php ... ?>` tags

## 6. Conditional Output Tags

### What is conditional output?

More advanced PHP script can **insert text only when a specific condition is met**. This is done using PHP's conditional structures (`if`/`else`) combined with PHP tags to selectively output HTML.

### How it works

PHP tags can be opened and closed around HTML content so that the HTML is only output when the condition is true:

```php
<?php if ($expression == true): ?>
    Insert this text only if the expression is true.
<?php else: ?>
    Otherwise insert this text.
<?php endif; ?>
```

### What the parser does

- The PHP parser evaluates the condition (`if` statement)
- If the condition is **true**, it allows the HTML inside the `if` block to pass through to the browser
- If the condition is **false**, it skips that HTML and outputs the `else` block instead
- Only one branch of HTML ever reaches the browser — the other is suppressed entirely

### Practical example — personalised greeting

```php
<?php if ($hour < 12): ?>
    <p>Good morning!</p>
<?php else: ?>
    <p>Good afternoon!</p>
<?php endif; ?>
```

This technique is extremely powerful — it means that dynamic, conditional HTML can be written in a clean, readable way that clearly separates logic from presentation.

## 7. Statement Rules — The Semicolon

### The fundamental rule

Every **statement** in PHP must be **terminated by a semicolon** (`;`).

```php
<?php
    echo "First statement";
    echo "Second statement";
?>
```

### Why the semicolon is required

The semicolon is the character that the **PHP parser recognises as marking the end of an individual instruction**. It is analogous to the way a **period (`.`) marks the end of a sentence** in written English — without it, the parser cannot tell where one instruction ends and the next begins.

Without semicolons, the parser would be unable to distinguish between:
- The end of one statement and the beginning of the next
- Multi-line statements (which are allowed in PHP — a single statement can span multiple lines)

### Multiple statements in a block

A PHP code block can contain as many statements as needed — each must end with a semicolon:

```php
<?php
    $name = "Alice";
    $age = 30;
    echo "Name: " . $name;
    echo "Age: " . $age;
?>
```

Each line is a separate statement, and each is terminated by `;`.

### The exception — the last statement before a closing tag

The **closing `?>` tag automatically implies a semicolon**. This means the semicolon terminating the **last statement** of a PHP block can optionally be omitted:

```php
<?php
    echo "First statement";
    echo "Last statement — semicolon optional here"
?>
```

Both of the following are valid:

```php
<?php echo "Hello" ?>        <!-- semicolon omitted — valid -->
<?php echo "Hello"; ?>       <!-- semicolon included — also valid -->
```

> **Best practice:** Although you can omit the semicolon on the last statement before `?>`, it does **no harm** to include it. Including it is safer and more consistent — especially when you later add more statements to the block.

### Summary of semicolon rules

| Situation | Semicolon required? |
|---|---|
| Every statement except the last in a block | Yes — mandatory |
| Last statement before a closing `?>` tag | Optional — the closing tag implies one |
| Last statement in a pure PHP file (no closing tag) | Yes — mandatory |

## 8. Comment Rules

### What are comments?

**Comments** are notes written within PHP code that are intended to be read by humans — developers, teammates, or your future self. Comments explain what the code does, why certain decisions were made, or mark sections for later attention.

### How the parser handles comments

All comments (and all whitespace) are **completely ignored by the PHP parser**. They have:
- No effect on what the script does
- No effect on performance — adding many comments does not slow down your script
- No effect on the output sent to the browser

> You can add as many comments as you like, with no negative consequences whatsoever.

---

### Single-line comments

Single-line comments cause everything from the comment marker to the **end of the line** to be ignored by the parser. PHP supports two styles of single-line comment:

#### Style 1 — Hash character (`#`)

```php
<?php
    # This is a single-line comment using the hash style
    echo "Hello";  # This comment follows code on the same line
?>
```

#### Style 2 — Double-slash (`//`)

```php
<?php
    // This is a single-line comment using the double-slash style
    echo "Hello";  // This comment follows code on the same line
?>
```

Both styles are equally valid. The `//` style is more commonly seen in PHP code, as it is familiar to developers from languages like C, Java, and JavaScript.

---

### Multi-line (block) comments

When a comment needs to span **multiple lines**, it must be enclosed within `/*` and `*/` delimiters. This style comes from the **C programming language** and is common across many languages.

```php
<?php
    /*
        This is a multi-line comment.
        It can span as many lines as needed.
        Everything between the opening and closing
        delimiters is completely ignored by the parser.
    */
    echo "Hello";
?>
```

Block comments are especially useful for:
- Explaining a complex block of logic before it begins
- Temporarily disabling a section of code during development
- Writing detailed documentation at the top of a file or function

---

### Comparison of comment styles

| Style | Syntax | Spans multiple lines? | Common use |
|---|---|---|---|
| Hash single-line | `# comment` | No — ends at line break | Quick inline notes |
| Double-slash single-line | `// comment` | No — ends at line break | Most common style for single-line notes |
| Block / multi-line | `/* comment */` | Yes — ends at `*/` | Detailed explanations, disabling code blocks |

---

### Example — all comment styles together

```php
<?php

/*
    PHP Greeting Script
    This script outputs a personalised welcome message.
    Written by: A. Developer
*/

# Set the user's name
$name = "Alice";

// Output the greeting to the browser
echo "Welcome, " . $name . "!";  // Inline comment on same line as code

?>
```

## 9. Summary — Rules at a Glance

### Tag rules

| Rule | Detail |
|---|---|
| Opening tag | `<?php` — marks the start of a PHP block |
| Closing tag | `?>` — marks the end of a PHP block |
| Embedded in HTML | All PHP code must be between opening and closing tags |
| Pure PHP files | Omit the closing `?>` tag to avoid whitespace/header bugs |
| Short echo tag | `<?= value ?>` — shorthand for `<?php echo value; ?>` |
| Conditional output | PHP tags can wrap HTML inside `if`/`else` blocks to output HTML conditionally |

### Statement rules

| Rule | Detail |
|---|---|
| Semicolon required | Every PHP statement must end with `;` |
| Analogy | Semicolon in PHP = period in English — marks the end of an instruction |
| Last statement exception | The closing `?>` tag implies a semicolon — the last statement's `;` is optional |
| Best practice | Include the semicolon even on the last statement — consistency and safety |

### Comment rules

| Rule | Detail |
|---|---|
| Ignored by parser | All comments and whitespace are completely ignored — no performance impact |
| Single-line (hash) | `# comment` — ignored from `#` to end of line |
| Single-line (double-slash) | `// comment` — ignored from `//` to end of line |
| Multi-line (block) | `/* comment */` — ignored from `/*` to `*/`, can span many lines |
