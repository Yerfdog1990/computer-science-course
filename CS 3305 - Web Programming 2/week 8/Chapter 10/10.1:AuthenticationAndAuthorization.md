# Authentication and Authorization

---

## HTTP Headers Overview

Every HTTP request and response is sent with headers that facilitate communication between client and server. Some are generated automatically (such as `Host`, `User-Agent`, or `Content-Length`), while others you control explicitly.

### Key Headers Relevant to Authentication

| Header | Direction | Purpose |
|--------|-----------|---------|
| `Accept` | Request | Tells the server which content types the client can handle. e.g. `application/json`, `text/html` |
| `Content-Type` | Request | Required on POST/PUT to tell the server how the body is encoded. e.g. `application/json` |
| `Cache-Control` | Response | Whether the response can be cached and for how long (`max-age` in seconds) |
| `Authorization` | Request | Carries credentials or a token the client uses to prove its identity |

---

## Authentication vs Authorization

These two terms describe distinct steps in the security process.

**Authentication** — *Who are you?*
Verifying the identity of the user. Checking a password hash, API key, or token.

**Authorization** — *What are you allowed to do?*
Verifying that an already-authenticated user has permission to access the resource they are requesting.

```
User submits credentials
         │
         ▼
  AUTHENTICATION
  "Is this really user@example.com?"
  Check password hash, API key, or token
         │
         ▼
  AUTHORIZATION
  "Is user@example.com allowed to access /admin?"
  Check roles, permissions, or subscription level
         │
         ▼
  Grant or deny access
```

### Real-World Example

A paid streaming service:
- **Authentication** — log in with email and password to prove you are the account holder
- **Authorization** — check whether your account has an active subscription before allowing access to premium content

A multi-user application:
- **Authentication** — verify the user is logged in
- **Authorization** — verify the user can only edit their own posts, not other users' posts

## Authentication Schemes

### 1. Open Authentication (No Auth)

The web service accepts requests from anyone without verifying identity. Acceptable only for fully public data.

```
GET /public/cars HTTP/1.1
Host: api.example.com
```

No `Authorization` header is needed.

---

### 2. API Key Authentication

The user creates an account and receives a secret key. That key is sent with every request in a header. The server verifies the key belongs to a valid account before processing.

```
GET /cars HTTP/1.1
Host: api.example.com
X-API-Key: abc123secretkey
```

Most common scheme for public web APIs (weather services, maps, payment gateways).

---

### 3. HTTP Basic Authentication

Credentials (username and password) are Base64-encoded and sent in the `Authorization` header on every request. Requires HTTPS — Base64 is encoding, not encryption.

```
Authorization: Basic dXNlcjpwYXNzd29yZA==
```

The encoded value decodes to `user:password`.

---

### 4. Bearer Token / JWT

After a successful login, the server issues a token. The client sends it in every subsequent request. The server validates the token without looking up a session.

```
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

---

### 5. OAuth 2.0 + OpenID Connect

A two-protocol combination for delegated access and federated identity:

- **OpenID Connect** handles **authentication** — the user proves identity through a trusted provider (Google, Facebook, Microsoft, or a company's internal server)
- **OAuth 2.0** handles **authorization** — after authentication, a token grants the application access to specific resources on behalf of the user

```
User → Login with Google → Google issues ID token → App uses token to call resource server
```

This is the "Sign in with Google / Facebook" pattern. PHP League's `league/oauth2-client` Composer package provides a ready-made implementation.

## Implementation 1 — Session-Based Authentication (Login / Logout)

The most common pattern for web applications. After the user submits valid credentials, a session is started and their identity is stored server-side. The browser receives only a session ID cookie.

### How It Works

```
User submits email + password (POST)
         |
         v
Server fetches user record by email (prepared statement)
         |
         v
password_verify($submitted, $storedHash)
         |
    .----+----.
  false      true
    |          |
  Error    Store user_id + role in $_SESSION
             |
             v
           Redirect to protected page
```

### `auth/login.php`

```php
<?php
declare(strict_types=1);
session_start();
require_once '../Database.php';

$error = null;

// If already logged in, redirect to the dashboard
if (isset($_SESSION['user_id'])) {
    header('Location: /dashboard.php');
    exit;
}

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $email    = trim($_POST['email']    ?? '');
    $password = trim($_POST['password'] ?? '');

    if (empty($email) || empty($password)) {
        $error = 'Email and password are required.';
    } else {
        $pdo  = Database::getInstance()->getPdo();

        // Prepared statement — user input never concatenated into query
        $stmt = $pdo->prepare(
            "SELECT id, name, email, password_hash, role FROM users WHERE email = :email"
        );
        $stmt->execute([':email' => $email]);
        $user = $stmt->fetch();

        if ($user && password_verify($password, $user['password_hash'])) {
            // Regenerate session ID on login — prevents session fixation
            session_regenerate_id(true);

            // Store only what is needed — never store the password
            $_SESSION['user_id'] = $user['id'];
            $_SESSION['name']    = $user['name'];
            $_SESSION['role']    = $user['role'];

            header('Location: /dashboard.php');
            exit;
        }

        // Deliberately vague — do not reveal whether the email exists
        $error = 'Invalid email or password.';
    }
}
?>
<!DOCTYPE html>
<html lang="en">
<head><meta charset="UTF-8"><title>Login</title></head>
<body>
    <h1>Login</h1>

    <?php if ($error): ?>
        <p style="color:red"><?= htmlspecialchars($error) ?></p>
    <?php endif; ?>

    <form method="post" action="/auth/login.php">
        <label>Email:    <input type="email"    name="email"    required></label><br>
        <label>Password: <input type="password" name="password" required></label><br>
        <button type="submit">Login</button>
    </form>
</body>
</html>
```

### Key Security Points

| Practice | Why |
|----------|-----|
| `password_verify()` — never compare plain text | Passwords must be stored as bcrypt hashes via `password_hash()` |
| `session_regenerate_id(true)` on login and logout | Prevents session fixation — attacker cannot pre-set a known session ID |
| Vague error ("Invalid email or password") | Does not reveal whether the email exists in the database |
| Store only `user_id` and `role` in session | Minimises exposure if the session store is compromised |
| Prepared statement for the email lookup | Prevents SQL injection in the login query |

## Implementation 2 — Role-Based Authorization

Once authenticated, you check the user's role before granting access to sensitive resources.

### Roles

| Role | Permissions |
|------|-------------|
| `admin` | View, insert, update, and delete any car |
| `member` | View and insert cars |
| `guest` | View cars only |

### `auth/authorize.php` — Reusable Helper

```php
<?php
declare(strict_types=1);

/**
 * Require the user to be logged in.
 * Redirects to login page if not authenticated.
 */
function requireLogin(): void
{
    if (!isset($_SESSION['user_id'])) {
        header('Location: /auth/login.php');
        exit;
    }
}

/**
 * Require the user to have one of the allowed roles.
 * Returns a 403 error if the user does not have permission.
 */
function requireRole(string ...$roles): void
{
    requireLogin();

    if (!in_array($_SESSION['role'], $roles, strict: true)) {
        http_response_code(403);
        echo '<h1>403 Forbidden</h1>';
        echo '<p>You do not have permission to access this resource.</p>';
        exit;
    }
}
```

## Implementation 3 — API Key Authentication

Used when external systems or scripts need to call your API. No login form — the client sends its key in a header on every request.

### Generating an API Key

```php
<?php
declare(strict_types=1);
require_once 'Database.php';

function generateApiKey(int $userId): string
{
    // bin2hex(random_bytes(32)) produces a secure 64-character hex string
    $apiKey = bin2hex(random_bytes(32));

    $pdo  = Database::getInstance()->getPdo();
    $stmt = $pdo->prepare(
        "INSERT INTO api_keys (user_id, api_key) VALUES (:user_id, :api_key)"
    );
    $stmt->execute([':user_id' => $userId, ':api_key' => $apiKey]);

    return $apiKey;
}

// Generate a key for Alice (user ID 1)
$key = generateApiKey(1);
echo "Your API key: $key\n";
// Store this securely — it cannot be recovered if lost
```

### `api/cars.php` — API Key Protected Endpoint

```php
<?php
declare(strict_types=1);

// File is at api/cars.php — database class is one directory up
require_once '../Database.php';

header('Content-Type: application/json');

function authenticateApiKey(): array
{
    $apiKey = $_SERVER['HTTP_X_API_KEY'] ?? null;

    if (empty($apiKey)) {
        http_response_code(401);
        echo json_encode(['error' => 'API key missing. Provide X-API-Key header.']);
        exit;
    }

    $pdo  = Database::getInstance()->getPdo();
    $stmt = $pdo->prepare(
        "SELECT u.id, u.name, u.role
         FROM api_keys ak
         JOIN users u ON ak.user_id = u.id
         WHERE ak.api_key = :api_key"
    );
    $stmt->execute([':api_key' => $apiKey]);
    $user = $stmt->fetch();

    if (!$user) {
        http_response_code(401);
        echo json_encode(['error' => 'Invalid API key.']);
        exit;
    }

    return $user;
}

$user   = authenticateApiKey();
$method = $_SERVER['REQUEST_METHOD'];
$pdo    = Database::getInstance()->getPdo();

if ($method === 'GET') {
    $cars = $pdo->query("SELECT * FROM cars ORDER BY make")->fetchAll();
    echo json_encode(['data' => $cars, 'requested_by' => $user['name']]);

} elseif ($method === 'POST') {
    if (!in_array($user['role'], ['admin', 'member'], true)) {
        http_response_code(403);
        echo json_encode(['error' => 'Forbidden. Members and admins only.']);
        exit;
    }

    $body = json_decode(file_get_contents('php://input'), true);
    $stmt = $pdo->prepare(
        "INSERT INTO cars (make, model, year, color, price)
         VALUES (:make, :model, :year, :color, :price)"
    );
    $stmt->execute([
        ':make'  => $body['make']  ?? '',
        ':model' => $body['model'] ?? '',
        ':year'  => (int)($body['year']  ?? 0),
        ':color' => $body['color'] ?? '',
        ':price' => (float)($body['price'] ?? 0),
    ]);
    http_response_code(201);
    echo json_encode(['message' => 'Car created.', 'id' => $pdo->lastInsertId()]);

} elseif ($method === 'DELETE') {
    if ($user['role'] !== 'admin') {
        http_response_code(403);
        echo json_encode(['error' => 'Forbidden. Admins only.']);
        exit;
    }
    $id   = (int)($_GET['id'] ?? 0);
    $stmt = $pdo->prepare("DELETE FROM cars WHERE id = :id");
    $stmt->execute([':id' => $id]);
    echo json_encode(['message' => "Car $id deleted."]);

} else {
    http_response_code(405);
    echo json_encode(['error' => 'Method not allowed.']);
}
```

## Implementation 4 — HTTP Basic Authentication

The browser prompts for a username and password and sends them Base64-encoded in every request. This file lives at `api/basic-cars.php`, so the `Database` class is loaded from one level up using `../database.php`.

> **Why `../database.php`?** The file is inside the `api/` subdirectory. `require_once 'database.php'` would look for the file in the same folder and fail with a fatal error. Always use paths relative to the file's actual location.

### `api/basic-cars.php`

```php
<?php
declare(strict_types=1);

// File is at api/basic-cars.php — database class is one directory up
require_once '../Database.php';

/**
 * Parse and validate the HTTP Basic Auth credentials.
 * Sends a 401 challenge and exits if credentials are missing or invalid.
 *
 * @return array  The authenticated user record from the database
 */
function requireBasicAuth(): array
{
    // PHP exposes the Authorization header as HTTP_AUTHORIZATION in $_SERVER
    $authHeader = $_SERVER['HTTP_AUTHORIZATION'] ?? '';

    // Basic Auth header format: "Basic <base64(email:password)>"
    if (!str_starts_with($authHeader, 'Basic ')) {
        sendBasicAuthChallenge(); // No header at all — prompt the browser
    }

    // Strip the "Basic " prefix and decode the Base64 payload
    $decoded  = base64_decode(substr($authHeader, 6));

    // The decoded string is "email:password" — split on the first colon only
    $colonPos = strpos($decoded, ':');

    if ($colonPos === false) {
        sendBasicAuthChallenge(); // Malformed header
    }

    $email    = substr($decoded, 0, $colonPos);
    $password = substr($decoded, $colonPos + 1);

    // Look up the user by email using a prepared statement
    $pdo  = Database::getInstance()->getPdo();
    $stmt = $pdo->prepare(
        "SELECT id, name, email, password_hash, role
         FROM users
         WHERE email = :email"
    );
    $stmt->execute([':email' => $email]);
    $user = $stmt->fetch();

    // Verify the submitted password against the stored bcrypt hash
    if (!$user || !password_verify($password, $user['password_hash'])) {
        sendBasicAuthChallenge(); // Wrong credentials — challenge again
    }

    return $user;
}

/**
 * Send a 401 Unauthorized response with the WWW-Authenticate header.
 * The browser will show a native username/password dialog box.
 */
function sendBasicAuthChallenge(): never
{
    // WWW-Authenticate tells the browser to show its built-in login dialog
    header('WWW-Authenticate: Basic realm="Car API"');
    http_response_code(401);
    echo json_encode(['error' => 'Authentication required.']);
    exit;
}

// All responses from this endpoint are JSON
header('Content-Type: application/json');

// Authenticate — exits with 401 if credentials are missing or invalid
$user = requireBasicAuth();

// Authenticated — fetch and return the car list
$pdo  = Database::getInstance()->getPdo();
$cars = $pdo->query("SELECT * FROM cars ORDER BY make")->fetchAll();

echo json_encode([
    'authenticated_as' => $user['name'],
    'role'             => $user['role'],
    'total'            => count($cars),
    'data'             => $cars,
]);
```

**Testing with curl:**

```bash
# Using -u shorthand
curl -u alice@example.com:password123 http://localhost:8080/api/basic-cars.php

# Passing the header manually
curl -H "Authorization: Basic $(echo -n 'alice@example.com:password123' | base64)" \

```

> Always use HTTPS with Basic Auth. Base64 is encoding, not encryption — credentials are trivially decoded if intercepted.

## Authentication Schemes Comparison

| Scheme | Credentials travel | Session needed | Best for |
|--------|--------------------|---------------|---------|
| Open / No auth | Nowhere | No | Fully public APIs |
| Session + login form | Only on login (POST body) | Yes | Web apps with login pages |
| API Key (`X-API-Key`) | Every request (header) | No | Server-to-server, CLI tools, integrations |
| HTTP Basic Auth | Every request (Base64 header) | No | Simple internal APIs (HTTPS required) |
| Bearer Token / JWT | Every request (header) | No | Stateless APIs, mobile apps |
| OAuth 2.0 + OpenID Connect | Token exchange flow | Depends | "Sign in with Google", enterprise SSO |

## Quick Reference

```php
// Password hashing (at registration)
$hash = password_hash($plainTextPassword, PASSWORD_BCRYPT);

// Password verification (at login)
if (password_verify($submitted, $storedHash)) { /* authenticated */ }

// Start and regenerate session
session_start();
session_regenerate_id(true); // Always regenerate on login/logout

// Store in session
$_SESSION['user_id'] = $user['id'];
$_SESSION['role']    = $user['role'];

// Check if logged in
if (!isset($_SESSION['user_id'])) {
    header('Location: /auth/login.php');
    exit;
}

// Check role
if ($_SESSION['role'] !== 'admin') {
    http_response_code(403);
    exit;
}

// Generate a secure API key
$apiKey = bin2hex(random_bytes(32)); // 64-char hex string

// Read API key from request header
$apiKey = $_SERVER['HTTP_X_API_KEY'] ?? null;

// Send Basic Auth challenge
header('WWW-Authenticate: Basic realm="My App"');
http_response_code(401);
exit;
```
