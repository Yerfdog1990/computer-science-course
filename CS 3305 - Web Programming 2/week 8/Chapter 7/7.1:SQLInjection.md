# SQL Injection & Prepared Statements

---

## What is SQL Injection?

SQL injection is one of the most common and dangerous vulnerabilities on the web. It is a technique used to:

- **Steal data** — read records the attacker is not authorised to see
- **Gain account control** — bypass login forms by manipulating queries
- **Destroy data** — drop entire tables or databases
- **Modify data** — update or insert records without permission

It works by sending **malicious SQL fragments through HTML form inputs**. When the application builds a query by concatenating raw user input directly into the SQL string, the attacker's input becomes part of the query itself and is executed by the database.

---

## How SQL Injection Works — A Simple Example

Consider this vulnerable PHP code:

```php
$rawInput = $_POST['email'];
$query = "INSERT INTO users (email) VALUES ($rawInput)";
```

If the user submits a normal email address like `john@example.com`, the query becomes:

```sql
INSERT INTO users (email) VALUES (john@example.com)
```

But if the attacker submits `""); DROP TABLE users; /**` as the input, the query becomes:

```sql
INSERT INTO users (email) VALUES (""); DROP TABLE users; /**)
```

**What happens:**
1. `INSERT INTO users (email) VALUES ("")` — executes first, inserting an empty string
2. `DROP TABLE users` — executes next, **permanently deleting the entire users table**
3. `/**)` — ignored by MySQL because `/*` marks the start of a comment

The attacker has just destroyed your table by typing into a form field.

---

## The Solution — Prepared Statements with PDO

PDO (PHP Data Objects) provides **prepared statements** to prevent SQL injection. Instead of building a query string from user input, prepared statements use **placeholders** that PDO replaces with safely escaped values at execution time.

### How Prepared Statements Work

```
Step 1: Send the query template to MySQL — no data yet
        "INSERT INTO cars (make, model, year) VALUES (?, ?, ?)"

Step 2: MySQL parses and compiles the query once

Step 3: Send the actual data separately
        ['Toyota', 'Camry', 2023]

Step 4: MySQL substitutes values safely — injection is impossible
        because the data is never interpreted as SQL
```

### Two Types of Placeholders

**Positional placeholders — `?`**
```sql
INSERT INTO cars (make, model, year) VALUES (?, ?, ?)
```

**Named placeholders — `:name`**
```sql
INSERT INTO cars (make, model, year) VALUES (:make, :model, :year)
```

### Benefits of Prepared Statements

- **SQL injection is impossible** — data values are never parsed as SQL
- **No manual quoting or escaping** — PDO handles it automatically
- **Performance** — the query is parsed once and can be executed many times with different data
- **Lower bandwidth** — only the data is sent on subsequent executions, not the full query

> **Important:** Set `PDO::ATTR_EMULATE_PREPARES => false` to use true server-side prepared statements in MySQL. Without this, PDO emulates them client-side and does not send the query to the server for parsing.

## Database Setup

### Create the Database and Table

Run these SQL commands in MySQL to set up the `car_db` database and the `cars` table used in the demos below:

```sql
-- Create the database
CREATE DATABASE IF NOT EXISTS car_db
    CHARACTER SET utf8mb4
    COLLATE utf8mb4_unicode_ci;

USE car_db;

-- Create the cars table
CREATE TABLE IF NOT EXISTS cars (
    id       INT          NOT NULL AUTO_INCREMENT,
    make     VARCHAR(100) NOT NULL,
    model    VARCHAR(100) NOT NULL,
    year     YEAR         NOT NULL,
    color    VARCHAR(50)  NULL,
    price    DECIMAL(10,2) NOT NULL DEFAULT 0.00,
    PRIMARY KEY (id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### Create the MySQL User

```sql
-- Create user and grant access to car_db only
CREATE USER IF NOT EXISTS 'php-user'@'localhost' IDENTIFIED BY 'php-pass';
GRANT ALL PRIVILEGES ON car_db.* TO 'php-user'@'localhost';
FLUSH PRIVILEGES;
```

### `database.php` — Shared PDO Connection

```php
<?php
declare(strict_types=1);

class Database
{
    private static ?Database $instance = null;
    private PDO $pdo;

    private function __construct()
    {
        $dsn = "mysql:host=127.0.0.1;port=3306;dbname=car_db;charset=utf8mb4";

        $options = [
            PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
            PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION,
            PDO::ATTR_EMULATE_PREPARES   => false, // Use real prepared statements
        ];

        $this->pdo = new PDO($dsn, 'php-user', 'php-pass', $options);
    }

    public static function getInstance(): static
    {
        if (is_null(static::$instance)) {
            static::$instance = new static();
        }
        return static::$instance;
    }

    public function getPdo(): PDO
    {
        return $this->pdo;
    }
}
```

## Demo 1 — Vulnerable Insert (No Prepared Statement)

This script demonstrates how SQL injection succeeds when user input is concatenated directly into a query string.

### `insert-unprepared.php`

```php
<?php
declare(strict_types=1);
require_once 'Database.php';

$pdo = Database::getInstance()->getPdo();

// Read user input directly from POST — no sanitization, no escaping
$make  = $_POST['make']  ?? '';
$model = $_POST['model'] ?? '';
$year  = $_POST['year']  ?? '';
$color = $_POST['color'] ?? '';
$price = $_POST['price'] ?? '';

// ❌ VULNERABLE — user input concatenated directly into the query string
$query = "INSERT INTO cars (make, model, year, color, price)
          VALUES ('$make', '$model', '$year', '$color', '$price')";

echo "<h2>Query being executed:</h2>";
echo "<pre>" . htmlspecialchars($query) . "</pre>";

try {
    $result = $pdo->exec($query);
    echo "<p style='color:green'>✅ Row inserted. Affected rows: $result</p>";
} catch (PDOException $e) {
    echo "<p style='color:red'>❌ Error: " . htmlspecialchars($e->getMessage()) . "</p>";
}
```

**Normal input — submitting a legitimate car:**

```
make:  Toyota
model: Camry
year:  2023
color: Silver
price: 28000.00
```

Query built:
```sql
INSERT INTO cars (make, model, year, color, price)
VALUES ('Toyota', 'Camry', '2023', 'Silver', '28000.00')
```

Result: row inserted normally.

---

**Malicious input — SQL injection attack:**

An attacker submits this value in the `make` field:

```
Toyota', 'Supra', 2020, 'Red', 0.00); DROP TABLE cars; /*
```

Query built:
```sql
INSERT INTO cars (make, model, year, color, price)
VALUES ('Toyota', 'Supra', 2020, 'Red', 0.00); DROP TABLE cars; /*', 'Camry', '2023', 'Silver', '28000.00')
```

**What happens:**
1. `INSERT INTO cars ... VALUES ('Toyota', 'Supra', 2020, 'Red', 0.00)` — executes, inserting a fake record
2. `DROP TABLE cars` — executes, **permanently deleting the entire cars table**
3. `/*` — comments out the rest of the original query

The attacker has destroyed your data by submitting a form.

## Demo 2 — Safe Insert (Prepared Statement)

This script uses a prepared statement to safely insert the same data. The SQL injection attempt produces a harmless corrupt string instead of executing SQL.

### `insert-prepared.php`

```php
<?php
declare(strict_types=1);
require_once 'Database.php';

$pdo = Database::getInstance()->getPdo();

$make  = $_POST['make']  ?? '';
$model = $_POST['model'] ?? '';
$year  = $_POST['year']  ?? '';
$color = $_POST['color'] ?? '';
$price = $_POST['price'] ?? '';

// ✅ SAFE — query template with named placeholders
$stmt = $pdo->prepare(
    "INSERT INTO cars (make, model, year, color, price)
     VALUES (:make, :model, :year, :color, :price)"
);

// Bind each placeholder to its value — PDO escapes everything automatically
$stmt->bindParam(':make',  $make,  PDO::PARAM_STR);
$stmt->bindParam(':model', $model, PDO::PARAM_STR);
$stmt->bindParam(':year',  $year,  PDO::PARAM_INT);
$stmt->bindParam(':color', $color, PDO::PARAM_STR);
$stmt->bindParam(':price', $price, PDO::PARAM_STR);

echo "<h2>Placeholder values being bound:</h2>";
echo "<pre>" . htmlspecialchars(print_r([
    ':make'  => $make,
    ':model' => $model,
    ':year'  => $year,
    ':color' => $color,
    ':price' => $price,
], true)) . "</pre>";

try {
    $stmt->execute();
    echo "<p style='color:green'>✅ Row inserted safely. ID: " . $pdo->lastInsertId() . "</p>";
} catch (PDOException $e) {
    echo "<p style='color:red'>❌ Error: " . htmlspecialchars($e->getMessage()) . "</p>";
}
```

**Same malicious input submitted:**

```
make:  Toyota', 'Supra', 2020, 'Red', 0.00); DROP TABLE cars; /*
model: Camry
year:  2023
color: Silver
price: 28000.00
```

**What the prepared statement does:**

PDO treats the entire malicious string as a literal value for the `:make` placeholder. It is escaped automatically before being sent to MySQL. The query MySQL receives is:

```sql
INSERT INTO cars (make, model, year, color, price)
VALUES ('Toyota\', \'Supra\', 2020, \'Red\', 0.00); DROP TABLE cars; /*', 'Camry', '2023', 'Silver', '28000.00')
```

**What happens:**
- No `DROP TABLE` executes — it is treated as part of the string value
- The row is inserted with the full malicious string stored as the `make` value
- The `cars` table is untouched

The data stored is corrupt (the malicious string), which is why **validation should still be applied** — but the database and other data are safe from destruction.

## Demo 3 — Inserting Multiple Cars Using `execute()`

The shorter syntax passes values directly to `execute()` without `bindParam()`. All values are treated as `PDO::PARAM_STR`.

```php
<?php
declare(strict_types=1);
require_once 'Database.php';

$pdo = Database::getInstance()->getPdo();

// Prepare once — execute many times
$stmt = $pdo->prepare(
    "INSERT INTO cars (make, model, year, color, price)
     VALUES (:make, :model, :year, :color, :price)"
);

$cars = [
    ['make' => 'Toyota',    'model' => 'Camry',      'year' => 2023, 'color' => 'Silver',  'price' => 28000.00],
    ['make' => 'Honda',     'model' => 'Civic',      'year' => 2022, 'color' => 'Blue',    'price' => 24500.00],
    ['make' => 'Ford',      'model' => 'Mustang',    'year' => 2021, 'color' => 'Red',     'price' => 42000.00],
    ['make' => 'BMW',       'model' => '3 Series',   'year' => 2023, 'color' => 'Black',   'price' => 55000.00],
    ['make' => 'Tesla',     'model' => 'Model 3',    'year' => 2023, 'color' => 'White',   'price' => 48000.00],
];

foreach ($cars as $car) {
    $stmt->execute([
        ':make'  => $car['make'],
        ':model' => $car['model'],
        ':year'  => $car['year'],
        ':color' => $car['color'],
        ':price' => $car['price'],
    ]);
    echo "✅ Inserted: {$car['make']} {$car['model']} ({$car['year']})<br>";
}
```

**Output:**
```
✅ Inserted: Toyota Camry (2023)
✅ Inserted: Honda Civic (2022)
✅ Inserted: Ford Mustang (2021)
✅ Inserted: BMW 3 Series (2023)
✅ Inserted: Tesla Model 3 (2023)
```

The query is **prepared once** and **executed five times** — MySQL parses the template only once, making batch inserts faster than running five separate queries.

## Demo 4 — Reading Cars with a Prepared SELECT

```php

$pdo = Database::getInstance()->getPdo();

// User wants to filter by make — comes from a GET parameter
$filterMake = $_GET['make'] ?? '';

    // ✅ Safe — user input goes through a placeholder

    // No filter — fetch all
    $stmt = $pdo->query("SELECT * FROM cars ORDER BY make, year DESC");
```

## Positional vs Named Placeholders — Side by Side

```php
// --- Positional placeholders (?) ---
$stmt = $pdo->prepare("INSERT INTO cars (make, model, year) VALUES (?, ?, ?)");

// Method 1 — bindParam with position index (1-based)
$stmt->bindParam(1, $make);
$stmt->bindParam(2, $model);
$stmt->bindParam(3, $year, PDO::PARAM_INT);
$stmt->execute();

// Method 2 — pass values array to execute()
$stmt->execute(['Toyota', 'Camry', 2023]);
$stmt->execute(['Honda',  'Civic', 2022]); // reuse the same prepared statement


// --- Named placeholders (:name) ---
$stmt = $pdo->prepare("INSERT INTO cars (make, model, year) VALUES (:make, :model, :year)");

// Method 1 — bindParam with placeholder name
$stmt->bindParam(':make',  $make,  PDO::PARAM_STR);
$stmt->bindParam(':model', $model, PDO::PARAM_STR);
$stmt->bindParam(':year',  $year,  PDO::PARAM_INT);
$make = 'Ford'; $model = 'Mustang'; $year = 2021;
$stmt->execute();

// Method 2 — pass associative array to execute()
$stmt->execute([':make' => 'BMW',   ':model' => '3 Series', ':year' => 2023]);
$stmt->execute([':make' => 'Tesla', ':model' => 'Model 3',  ':year' => 2023]);
```

## `bindParam()` Reference

```php
PDOStatement::bindParam(
    mixed $parameter,            // :name  OR  position index (1-based for ?)
    mixed &$variable,            // PHP variable — passed BY REFERENCE
    int   $data_type = PARAM_STR,// PDO::PARAM_STR | PARAM_INT | PARAM_BOOL | PARAM_NULL
    int   $length = 0,           // Optional: max length (required for OUT params in stored procs)
)
```

> **By reference:** Because `$variable` is passed by reference, you can change its value after `bindParam()` and before `execute()` — the latest value will be used when `execute()` runs. This is what makes the batch insert pattern work.

## Summary Table

| Approach | SQL Injection Safe? | Performance | Use When |
|----------|-------------------|-------------|---------|
| String concatenation | ❌ **Never** | N/A | Never use with user input |
| `filter_input()` + concatenation | ⚠️ Partial | OK | Simple trusted inputs only |
| Prepared statement (positional `?`) | ✅ Yes | Best for batch inserts | Order matters, fewer params |
| Prepared statement (named `:name`) | ✅ Yes | Best for batch inserts | More readable, many params |
| `execute(['key' => 'value'])` | ✅ Yes | Good | Quick one-off inserts |

## Attack vs Defence — Side by Side

```
Malicious input:
  Toyota', 'Supra', 2020, 'Red', 0.00); DROP TABLE cars; /*

❌ Without prepared statement:
   Query: INSERT INTO cars ... VALUES ('Toyota', 'Supra', 2020, 'Red', 0.00); DROP TABLE cars; /*...
   Result: TABLE DROPPED — data destroyed

✅ With prepared statement:
   :make value = "Toyota', 'Supra', 2020, 'Red', 0.00); DROP TABLE cars; /*"
   MySQL receives it as a string literal — no SQL executes
   Result: Row inserted with the malicious string stored as the make value
           (corrupt data, but table is safe — validate input to prevent even this)
```

> **Final rule:** Always use prepared statements for any query that includes user-supplied data. Validate and sanitize input before passing it to PDO to avoid storing corrupt data even when injection is blocked.
