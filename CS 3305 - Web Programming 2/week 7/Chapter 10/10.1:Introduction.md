## What Are Web Services?

### Definition
A web service is an application service that is either publicly accessible or available within an intranet that can be programmatically interacted with to retrieve or alter data. In other words, it's a server or cluster of servers accessible via a network that processes requests generated by computer processes as opposed to a user entering a URL into a browser.

### Key Characteristics
- Uses HTTP protocol for communication (same as web browsers)
- Follows the request/response cycle
- Can be accessed programmatically
- Some require paid accounts, others are free with rate limits
- Enables leveraging data and systems built by others

### Examples of Web Services
- **Social Network APIs**: Facebook, Twitter - allow authorized applications to access user data
- **E-commerce Services**: FedEx web service for shipping address verification
- **Data Services**: Movie databases for looking up titles, actors, or directors

### PHP and Web Services
PHP is a language built specifically for the web in the age of web APIs. It has been called the "best glue" to piece together a collection of external services.

## Example Web Service: IP Address Lookup

A simple example of a web service is one that returns the public IP address of the requesting client. When you access a URL like `https://api.ipify.org/?format=json`, the service:

1. Receives the HTTP GET request from the client
2. Reads the public IP address of the network the request is coming from
3. Sends a response containing that IP address in JSON format

**Example Response:**
```json
{"ip":"67.142.203.141"}
```

This illustrates the core concepts without complicated business logic. Your browser makes an HTTP GET request, the server processes it, and returns a formatted response. PHP has tools to make these requests programmatically and parse the results for application use.

## Selecting Third-Party APIs

When you have a choice of which web service to integrate, consider these factors:

### 1. Documentation
- Clear, concise, and complete documentation is essential
- Without good documentation, you rely on slow support chains
- Always read through documentation before committing to a dependency

### 2. Stability
- Consider the service's reliability and uptime
- Paid services may offer Service Level Agreements (SLAs) with uptime guarantees
- Inquire about system maintenance procedures
- Understand how they roll out new API versions

### 3. Availability
- **Performance**: Ensure the service responds in a timely fashion (microseconds vs. seconds)
- **Rate Limits**: Some services limit requests per timeframe (e.g., Facebook's hourly limits)
- Ensure the service can handle your application's peak usage
- Consider caching data when possible to reduce API calls

### 4. Pricing
- Some services are free or require only account creation
- Others require paid access with tiered pricing structures
- Pricing models often specify number of requests per billing period
- Ensure the cost fits within your business model

## Benefits of Web Services

- **Don't need to own all data**: Leverage data and systems others have built
- **Build on top of existing services**: String services together to create unique functionality
- **Reduce development effort**: Benefit from open source solutions to solved problems
- **Innovation enablement**: Web services enable significant industry innovation

## Communication Protocol

Web services use HTTP, the same protocol web browsers use to request web pages from servers. The request/response cycle is identical to what you learned in Chapter 6 (Using HTTP), and some requests can even be made directly from a browser.
