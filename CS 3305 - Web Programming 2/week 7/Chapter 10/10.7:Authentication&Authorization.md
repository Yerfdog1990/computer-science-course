# 10.6 Authentication and Authorization of REST APIs

Every API serving more than purely public data must securely answer two fundamental questions: **"Who are you?"** and **"What are you allowed to do?"**. Confusing these two is one of the most common causes of serious vulnerabilities reaching production — **Broken Access Control** is consistently one of the top entries on the OWASP Top 10 list.

---

## 1. Core Concepts — Authentication vs Authorization

These two terms are frequently confused but describe completely separate processes:

| Concept | Abbreviation | Definition | Failure Status Code |
|---------|-------------|------------|-------------------|
| **Authentication** | *Authn* | Verifying that a user or client is who they claim to be | `401 Unauthorized` — *"I don't know who you are"* |
| **Authorization** | *Authz* | Verifying that an already-authenticated user has permission to access a specific resource | `403 Forbidden` — *"I know who you are, but you can't do this"* |

Authentication always comes first. Authorization only makes sense once identity is confirmed.

### Why the Distinction Matters

A user who is authenticated but not authorized is like someone who has a valid employee ID card but tries to enter a restricted server room they have no clearance for. The card is real — the access is still denied.

**Common authorization scenarios:**

- A user with a `user` role can read all records but cannot create, update, or delete them
- A premium subscriber can access endpoints that a free-tier account cannot
- A user can edit their own posts but not someone else's

---

## 2. Common API Authentication Strategies

### Strategy A — API Keys

The server generates a cryptographically random string and gives it to the client. The client includes this key in every request, typically in a custom header like `X-API-Key`.

```
X-API-Key: sk_admin_a3f9e2b1c7d4...
```

**Security rule — never store raw API keys.** Always store a cryptographic hash (SHA-256) of the key. If your database is breached, attackers cannot use the hashes to authenticate:

```php
// When saving a key — store only the hash
$keyHash = hash('sha256', $rawKey);

// When validating a request — hash the incoming key and compare
$incomingHash = hash('sha256', $_SERVER['HTTP_X_API_KEY'] ?? '');
// Then look up $incomingHash in the database
```

### Strategy B — Bearer Tokens (JWT)

Bearer tokens are sent in the standard `Authorization` header:

```
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

JSON Web Tokens (JWTs) are popular because they are **self-contained** and **stateless** — the token itself carries the user's identity, so the server can verify it without a database lookup on every request.

### Strategy C — OAuth 2.0 and OpenID Connect

- **OAuth 2.0** — a delegation framework that lets users grant third-party apps limited, time-bound access to act on their behalf, without sharing their password
- **OpenID Connect (OIDC)** — an identity layer built on top of OAuth 2.0 that handles authentication (verifying who the user is via providers like Google or GitHub), while OAuth handles the downstream authorization

---

## 3. Security Best Practices

| Practice | Why It Matters |
|----------|---------------|
| **Use HTTPS everywhere** | API keys and tokens travel in HTTP headers — without TLS they are visible to anyone intercepting network traffic |
| **Never store raw secrets** | Store SHA-256 hashes of API keys; store bcrypt hashes of passwords — raw values in a leaked database become immediate attack vectors |
| **Use timing-safe comparison** | Use `hash_equals()` in PHP instead of `===` when comparing hashes — prevents side-channel timing attacks that can reveal information about partial matches |
| **Separate authentication from authorization** | Keep the "who are you?" check separate from the "what can you do?" check — this makes both layers easier to test, maintain, and reuse |
| **Validate input before querying** | Authentication prevents SQL injection here, but always use prepared statements regardless |

## 5. Database Schema Changes

The `api_keys` table stores clients and their hashed keys. It is added alongside the existing `books` table.

### `api_keys` Table

```sql
CREATE TABLE api_keys (
    id           INT          NOT NULL PRIMARY KEY AUTO_INCREMENT,
    client_name  VARCHAR(100) NOT NULL,
    key_hash     VARCHAR(64)  NOT NULL UNIQUE,  -- SHA-256 hex = 64 characters
    client_role  VARCHAR(20)  NOT NULL DEFAULT 'user',
    created_at   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

| Column | Purpose |
|--------|---------|
| `client_name` | Human-readable label for the key owner |
| `key_hash` | SHA-256 hash of the raw key — the raw key is never stored |
| `client_role` | `'admin'` (full access) or `'user'` (read-only) |

## 7. Security Middleware (`security.php`)

This file contains all authentication and authorization logic, isolated from the routing code in `books.php`. Keeping these concerns separate makes both easier to test and maintain.

```php
<?php
/**
 * security.http-and-session — Authentication and Authorization Middleware
 *
 * Authentication: checks that the API key exists and is valid
 * Authorization:  checks that the client's role permits the requested operation
 */

require_once __DIR__ . '/../config/database.http-and-session';

/**
 * Sends a JSON error response and terminates the request immediately.
 * Used by both authentication and authorization failure paths.
 */
function authReject(int $statusCode, string $errorMessage): never
{
    http_response_code($statusCode);
    header('Content-Type: application/json; charset=utf-8');
    echo json_encode(
        ['error' => $errorMessage, 'status' => $statusCode],
        JSON_PRETTY_PRINT | JSON_UNESCAPED_UNICODE
    );
    exit;
}

/**
 * Runs the full authentication and authorization check for every incoming request.
 *
 * Authentication flow:
 *   1. Read the X-API-Key header from the request
 *   2. Hash it with SHA-256
 *   3. Look up that hash in the api_keys table
 *   4. If not found → 401 Unauthorized
 *
 * Authorization flow:
 *   5. Check the client's role
 *   6. If the request is a write operation (POST/PUT/DELETE) and the role is not 'admin' → 403 Forbidden
 *
 * @param string $method The HTTP method of the current request (GET, POST, PUT, DELETE)
 * @return array         Client identity array: ['name' => ..., 'role' => ...]
 */
function enforceSecurity(string $method): array
{
    // ── AUTHENTICATION ────────────────────────────────────────────────────────

    // Read the raw API key from the custom request header
    // $_SERVER['HTTP_X_API_KEY'] maps to the X-API-Key header
    $providedKey = $_SERVER['HTTP_X_API_KEY'] ?? '';

    // Reject immediately if the header is missing or empty
    if (empty($providedKey)) {
        authReject(401, "Unauthorized. Missing required 'X-API-Key' header.");
    }

    // Hash the incoming key before querying the database
    // We never store or compare raw keys — only their SHA-256 hashes
    $hashedKey = hash('sha256', $providedKey);

    $pdo  = Database::getInstance()->getPdo();
    $stmt = $pdo->prepare(
        "SELECT client_name, client_role FROM api_keys WHERE key_hash = :key_hash LIMIT 1"
    );
    $stmt->execute([':key_hash' => $hashedKey]);
    $client = $stmt->fetch();

    // If no record matches the hash, the key is invalid
    if (!$client) {
        authReject(401, "Unauthorized. The provided API key is invalid.");
    }

    // ── AUTHORIZATION ─────────────────────────────────────────────────────────

    $role = $client['client_role'] ?? 'user';

    // Write operations (state mutations) are restricted to admin role only
    // GET requests are permitted to both 'user' and 'admin' roles
    $writeMethods = ['POST', 'PUT', 'DELETE'];

    if (in_array($method, $writeMethods) && $role !== 'admin') {
        // 403 Forbidden — authenticated but not authorized for this operation
        authReject(403, "Forbidden. Your role ('$role') does not have write access.");
    }

    // Return the verified client identity for use in route handlers if needed
    return [
        'name' => $client['client_name'],
        'role' => $role,
    ];
}
```

### How the Two Layers Work Together

```
Incoming request
       │
       ▼
 X-API-Key present?  ─── No ──► 401 Unauthorized (missing header)
       │
      Yes
       │
       ▼
 Hash matches api_keys table?  ─── No ──► 401 Unauthorized (invalid key)
       │
      Yes
       │
       ▼
 Is this a write method (POST/PUT/DELETE)?  ─── No (GET) ──► ✅ Allow
       │
      Yes
       │
       ▼
 Is client_role 'admin'?  ─── No ──► 403 Forbidden
       │
      Yes
       │
       ▼
     ✅ Allow
```

## 8. Updated `books.php`

The only change to the routing file is adding `require_once 'security.php'` and calling `enforceSecurity($method)` before any route is processed. If the security check fails, `authReject()` terminates the request before any database query runs.

```php
<?php
/**
 * books.http-and-session — Secured RESTful Books API Router
 *
 * Security is enforced before any route logic runs.
 * - GET requests: accessible to both 'user' and 'admin' roles
 * - POST, PUT, DELETE: restricted to 'admin' role only
 */

require_once __DIR__ . '/../config/database.http-and-session';
require_once __DIR__ . '/security.http-and-session';   // ← pulls in enforceSecurity()

// ── Response helpers ──────────────────────────────────────────────────────────

function respond(int $status, mixed $data): never
{
    http_response_code($status);
    header('Content-Type: application/json; charset=utf-8');
    echo json_encode($data, JSON_PRETTY_PRINT | JSON_UNESCAPED_UNICODE);
    exit;
}

function badRequest(string $message): never
{
    respond(400, ['error' => $message]);
}

function notFound(string $message = 'Resource not found'): never
{
    respond(404, ['error' => $message]);
}

// ── Parse the request ─────────────────────────────────────────────────────────

$method = $_SERVER['REQUEST_METHOD'];

// ── Run security middleware ───────────────────────────────────────────────────
// enforceSecurity() calls exit() on failure — code below only runs if auth passes
$authenticatedClient = enforceSecurity($method);

// ── Extract resource ID from URI (/api/books or /api/books/5) ────────────────
$uri   = parse_url($_SERVER['REQUEST_URI'], PHP_URL_PATH);
$parts = explode('/', trim($uri, '/'));
$id    = isset($parts[2]) && is_numeric($parts[2]) ? (int) $parts[2] : null;

// ── Parse JSON body for write operations ─────────────────────────────────────
$body = [];
if (in_array($method, ['POST', 'PUT'])) {
    $raw  = file_get_contents('http-and-session://input');   // Read raw request body
    $body = json_decode($raw, true) ?? [];       // Decode JSON to array; default to empty array
}

$pdo = Database::getInstance()->getPdo();

// ── Route requests ────────────────────────────────────────────────────────────

match (true) {

    // GET /api/books — retrieve all books (user + admin)
    $method === 'GET' && $id === null => (function () use ($pdo) {
        $stmt = $pdo->query("SELECT * FROM books ORDER BY id ASC");
        respond(200, $stmt->fetchAll());
    })(),

    // GET /api/books/{id} — retrieve one book (user + admin)
    $method === 'GET' && $id !== null => (function () use ($pdo, $id) {
        $stmt = $pdo->prepare("SELECT * FROM books WHERE id = :id");
        $stmt->execute([':id' => $id]);
        $book = $stmt->fetch();
        if (!$book) {
            notFound("Book with id $id not found.");
        }
        respond(200, $book);
    })(),

    // POST /api/books — create a new book (admin only — enforced by security.http-and-session)
    $method === 'POST' => (function () use ($pdo, $body) {
        $required = ['title', 'author', 'genre', 'published', 'isbn'];
        foreach ($required as $field) {
            if (empty($body[$field])) {
                badRequest("Missing required field: '$field'.");
            }
        }

        $stmt = $pdo->prepare("
            INSERT INTO books (title, author, genre, published, isbn, available)
            VALUES (:title, :author, :genre, :published, :isbn, :available)
        ");
        $stmt->execute([
            ':title'     => $body['title'],
            ':author'    => $body['author'],
            ':genre'     => $body['genre'],
            ':published' => (int) $body['published'],
            ':isbn'      => $body['isbn'],
            ':available' => isset($body['available']) ? (int) $body['available'] : 1,
        ]);

        $newId = (int) $pdo->lastInsertId();  // Auto-generated primary key of the new row
        $fetch = $pdo->prepare("SELECT * FROM books WHERE id = :id");
        $fetch->execute([':id' => $newId]);

        header("Location: /api/books/$newId");  // Tells the client where to find the new resource
        respond(201, $fetch->fetch());
    })(),

    // PUT /api/books/{id} — replace a book record entirely (admin only)
    $method === 'PUT' && $id !== null => (function () use ($pdo, $id, $body) {
        $check = $pdo->prepare("SELECT id FROM books WHERE id = :id");
        $check->execute([':id' => $id]);
        if (!$check->fetch()) {
            notFound("Book with id $id not found.");
        }

        $required = ['title', 'author', 'genre', 'published', 'isbn'];
        foreach ($required as $field) {
            if (empty($body[$field])) {
                badRequest("Missing required field: '$field'.");
            }
        }

        $stmt = $pdo->prepare("
            UPDATE books
            SET title     = :title,
                author    = :author,
                genre     = :genre,
                published = :published,
                isbn      = :isbn,
                available = :available
            WHERE id = :id
        ");
        $stmt->execute([
            ':title'     => $body['title'],
            ':author'    => $body['author'],
            ':genre'     => $body['genre'],
            ':published' => (int) $body['published'],
            ':isbn'      => $body['isbn'],
            ':available' => isset($body['available']) ? (int) $body['available'] : 1,
            ':id'        => $id,
        ]);

        $fetch = $pdo->prepare("SELECT * FROM books WHERE id = :id");
        $fetch->execute([':id' => $id]);
        respond(200, $fetch->fetch());
    })(),

    // DELETE /api/books/{id} — remove a book (admin only)
    $method === 'DELETE' && $id !== null => (function () use ($pdo, $id) {
        $check = $pdo->prepare("SELECT id FROM books WHERE id = :id");
        $check->execute([':id' => $id]);
        if (!$check->fetch()) {
            notFound("Book with id $id not found.");
        }

        $stmt = $pdo->prepare("DELETE FROM books WHERE id = :id");
        $stmt->execute([':id' => $id]);
        respond(204, null);  // 204 No Content — success with empty body
    })(),

    default => respond(405, ['error' => 'Method not allowed or invalid endpoint.'])
};
```

## 10. Summary

| Layer | File | What It Does |
|-------|------|-------------|
| Authentication | `security.php` → `enforceSecurity()` | Reads `X-API-Key` header, hashes it, looks it up in `api_keys` → `401` if missing or invalid |
| Authorization | `security.php` → `enforceSecurity()` | Checks `client_role` — blocks write operations for `user` role → `403` if insufficient |
| Route handling | `api/books.php` | Calls `enforceSecurity()` first; only processes routes after auth passes |
| Key storage | `api_keys` table | Stores SHA-256 hashes only — raw keys are printed once at seed time and never persisted |
| Test clients | `seed/seed.php` | Generates two keys (admin + user) and outputs raw values to the console |

### Key Rules

1. **Authentication before authorization** — always verify identity first, then check permissions
2. **Never store raw secrets** — always hash API keys before saving to the database
3. **Use `hash_equals()`** when comparing hashes in security-critical paths to prevent timing attacks
4. **Separate concerns** — keep auth logic in its own file (`security.php`), not mixed into route handlers
5. **Return the correct status code** — `401` when identity is unknown, `403` when identity is known but access is denied
6. **HTTPS is non-negotiable** — API keys in headers are plaintext over HTTP; TLS encrypts the transport layer
