# 10.4 Request Formats

---

## Overview

When sending data to a server in a REST API request, the body of that request must be formatted in a way the server can understand. The two main formats used are:

- **XML** (Extensible Markup Language)
- **JSON** (JavaScript Object Notation)

Both provide hierarchical structures that are readable by both humans and machines. The format you use must match the `Content-Type` header you declare in your request. Some APIs support both formats and allow you to choose; others require a specific one.

---

## XML (Extensible Markup Language)

XML has been a standard for structured data since 1998. If you are familiar with HTML, XML will look immediately recognisable — they are closely related, with XML being a more general-purpose markup language that HTML is derived from.

### Structure

Data in XML is wrapped in **opening and closing tags**, each delimited by `<` and `>`. The closing tag includes a forward slash before the element name:

```xml
<elementName>Some Data Here</elementName>
```

Elements can be **nested** to create hierarchical structures. Each level of nesting is indented for readability:

```xml
<root>
  <item>
    <property>value</property>
    <otherProperty>some other value</otherProperty>
  </item>
</root>
```

Elements can also carry **attributes** inside the opening tag, which is useful for storing metadata without altering the data structure itself:

```xml
<user id="1234" active="true">
  <name>Jane Smith</name>
</user>
```

### Full XML Example — User Object

```xml
<user>
  <id>1234</id>
  <name>Jane Smith</name>
  <email>jane.smith@example.com</email>
  <roles>
    <role>admin</role>
    <role>developer</role>
  </roles>
  <isActive>true</isActive>
  <preferences>
    <theme>dark</theme>
    <notifications>true</notifications>
  </preferences>
  <lastLogin>2025-04-01T14:30:00Z</lastLogin>
</user>
```

### Advantages of XML

| Advantage | Detail |
|-----------|--------|
| Strong validation | Schema definition (XSD) allows strict validation of structure and data types |
| Namespace support | Prevents naming conflicts when combining data from multiple sources |
| Attribute metadata | Metadata can be stored in element attributes without affecting the data hierarchy |
| Mature tooling | Extensive support for transformation (XSLT) and querying (XPath, XQuery) |
| Comments | Supports inline comments — useful in configuration files |

### Disadvantages of XML

| Disadvantage | Detail |
|--------------|--------|
| Verbosity | Opening and closing tags for every element create large payloads |
| Parsing complexity | More resource-intensive to parse than JSON |
| Readability | Can become difficult to read with deeply nested structures |
| Steeper learning curve | More concepts to understand (namespaces, schemas, attributes vs elements) |

## JSON (JavaScript Object Notation)

JSON was invented as a way to express objects in JavaScript but is now a fully language-independent data format. It has become the dominant format for modern REST APIs because it is concise, fast to transfer, and easy to work with in code.

### Structure

JSON uses a small set of syntax rules:

| Syntax | Purpose |
|--------|---------|
| `{ }` | Wraps a data object |
| `" "` | Denotes property names and string values |
| `[ ]` | Wraps arrays |
| `:` | Separates a property name from its value |
| `,` | Separates items in a sequence (properties or array elements) |

```json
{
  "property": "value",
  "someArray": [
    "item 1",
    "item 2"
  ]
}
```

### Full JSON Example — User Object

```json
{
  "user": {
    "id": 1234,
    "name": "Jane Smith",
    "email": "jane.smith@example.com",
    "roles": ["admin", "developer"],
    "isActive": true,
    "preferences": {
      "theme": "dark",
      "notifications": true
    },
    "lastLogin": "2025-04-01T14:30:00Z"
  }
}
```

### Advantages of JSON

| Advantage | Detail |
|-----------|--------|
| Concise | Less verbose than XML — smaller payloads, faster over the wire |
| Easy to read and write | Minimal syntax, close to natural data structures |
| Native language support | Built into browsers; natively supported in nearly all programming languages |
| Easy object conversion | Simple round-trip between in-memory objects and JSON strings |
| Performance | Generally faster to parse and serialise than XML |

### Disadvantages of JSON

| Disadvantage | Detail |
|--------------|--------|
| No comments | Standard JSON does not support inline comments |
| No namespaces | Can lead to naming conflicts in complex schemas |
| Limited validation | No built-in schema validation (JSON Schema exists as a third-party solution) |
| Fewer data types | No distinction between integers and floats, no native date type |

---

## XML vs JSON — Side by Side

| Feature | XML | JSON |
|---------|-----|------|
| Syntax style | Tag-based markup | Key-value pairs with brackets |
| Verbosity | High | Low |
| Human readability | Moderate | High |
| Parsing speed | Slower | Faster |
| Comments | ✅ Supported | ❌ Not supported |
| Schema/validation | ✅ XSD (strong) | ⚠️ JSON Schema (optional) |
| Namespaces | ✅ Supported | ❌ Not supported |
| Metadata (attributes) | ✅ Element attributes | ❌ Must be a property |
| Browser support | Limited | ✅ Native |
| Recommended for modern APIs | Only when required | ✅ Yes |

> **Rule of thumb:** Default to JSON for modern REST APIs. Use XML only when the server requires it, you need strong schema validation, or you are integrating with enterprise/legacy systems.

## Working with JSON in PHP

PHP provides two built-in functions for converting between PHP objects/arrays and JSON strings:

| Function | Purpose |
|----------|---------|
| `json_encode($value)` | Converts a PHP object or array **into** a JSON string |
| `json_decode($json)` | Converts a JSON string **into** a PHP object (`stdClass`) or array |

> **Note:** When decoding JSON into objects with `json_decode`, you receive objects of the generic `stdClass` type — not the original class type used before encoding. To get an associative array instead, pass `true` as the second argument: `json_decode($json, true)`.

## Exercise 10.1 — JSON Encoding in PHP

**Scenario:** Prepare data for a fictitious email marketing API that accepts a `PUT` request with a JSON body at the endpoint `/recipient`.

### Step 1 — Create the Project Folder

Create a new folder named `json-example` and navigate into it:

```bash
mkdir json-example-example
cd json-example-example
```

### Step 2 — Create the `MailingListRecipient` Class

Create a file named `MailingListRecipient.php`:

```php
<?php

class MailingListRecipient
{
    public string $email;
    public string $firstName;
    public string $lastName;

    public function __construct(string $email, string $firstName, string $lastName)
    {
        $this->email     = $email;
        $this->firstName = $firstName;
        $this->lastName  = $lastName;
    }
}
```

- The class has three public properties: `$email`, `$firstName`, and `$lastName`
- All three are assigned through the constructor
- Using `public` properties means `json_encode` can access and serialise them directly

### Step 3 — Create `json.php`

Create a file named `json.php` that creates a recipient object and encodes it as JSON:

```php
<?php

require 'JsonMailingListRecipient.php';

// Create a new recipient object
$recipient = new JsonMailingListRecipient(
    'jane.smith@example.com',
    'Jane',
    'Smith'
);

// Encode the object as a JSON string
$requestBody = json_encode($recipient);

// Output the JSON string
echo $requestBody . PHP_EOL;
```

### Step 4 — Run the Script

```bash
php xml.php
```

**Expected output:**

```json
{"email":"jane.smith@example.com","firstName":"Jane","lastName":"Smith"}
```

This JSON string is now ready to be used as the body of an API request.

## Decoding JSON in PHP

To go the other direction — converting a JSON string back into a PHP structure:

```php
<?php

$json = '{"email":"jane.smith@example.com","firstName":"Jane","lastName":"Smith"}';

// Decode to stdClass object
$object = json_decode($json);
echo $object->email;       // jane.smith@example.com
echo $object->firstName;   // Jane

// Decode to associative array (pass true as second argument)
$array = json_decode($json, true);
echo $array['email'];      // jane.smith@example.com
echo $array['firstName'];  // Jane
```

## Working with XML in PHP

PHP provides the `SimpleXML` extension for reading XML and the `DOMDocument` class for creating it.

### Encoding to XML in PHP

```php
<?php

class MailingListRecipient
{
    public string $email;
    public string $firstName;
    public string $lastName;

    public function __construct(string $email, string $firstName, string $lastName)
    {
        $this->email     = $email;
        $this->firstName = $firstName;
        $this->lastName  = $lastName;
    }

    public function toXml(): string
    {
        $xml = new DOMDocument('1.0', 'UTF-8');
        $xml->formatOutput = true;

        $recipient = $xml->createElement('recipient');
        $xml->appendChild($recipient);

        $recipient->appendChild($xml->createElement('email',     $this->email));
        $recipient->appendChild($xml->createElement('firstName', $this->firstName));
        $recipient->appendChild($xml->createElement('lastName',  $this->lastName));

        return $xml->saveXML();
    }
}

$recipient = new JsonMailingListRecipient('jane.smith@example.com', 'Jane', 'Smith');
echo $recipient->toXml();
```

**Output:**

```xml
<?xml version="1.0" encoding="UTF-8"?>
<recipient>
  <email>jane.smith@example.com</email>
  <firstName>Jane</firstName>
  <lastName>Smith</lastName>
</recipient>
```

### Decoding XML in PHP

```php
<?php

$xml = '<?xml version="1.0" encoding="UTF-8"?>
<recipient>
  <email>jane.smith@example.com</email>
  <firstName>Jane</firstName>
  <lastName>Smith</lastName>
</recipient>';

$data = simplexml_load_string($xml);

echo $data->email;      // jane.smith@example.com
echo $data->firstName;  // Jane
echo $data->lastName;   // Smith
```

## Content-Type Headers

When sending a request body, you must declare the format in the `Content-Type` header so the server knows how to parse it:

| Format | Content-Type Header Value |
|--------|--------------------------|
| JSON | `application/json` |
| XML | `application/xml` or `text/xml` |

When requesting a response in a specific format, use the `Accept` header:

```
Accept: application/json      ← request a JSON response
Accept: application/xml       ← request an XML response
Accept: application/json, application/xml;q=0.9   ← prefer JSON, accept XML
```

---

## Key Takeaways

1. JSON and XML are the two main formats for REST API request and response bodies.
2. **JSON is the default choice** for modern APIs — it is concise, fast, and has native support across languages and browsers.
3. **XML is still relevant** in enterprise environments, legacy system integration, and when strong schema validation is required.
4. In PHP, `json_encode()` converts a PHP object/array to a JSON string; `json_decode()` does the reverse.
5. `json_decode()` returns `stdClass` objects by default — pass `true` as the second argument to get associative arrays instead.
6. The `Content-Type` request header must match the format of the body you are sending.
7. When integrating with an API, check its documentation to confirm which formats it accepts — some require JSON, some require XML, some support both via content negotiation.
